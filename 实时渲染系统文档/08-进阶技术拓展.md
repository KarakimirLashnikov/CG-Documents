# 实时渲染系统 — 进阶技术拓展

> 本文档是「实时渲染系统」系列文档的第 **8** 篇，标识当前渲染体系尚未覆盖但行业已在推进的前沿技术方向，为引擎下一阶段演进提供技术路线参考。

---

## 1. 渲染算法前沿

### 1.1 全局光照（GI）进阶

当前体系的光照计算主要依赖直接光照 + 简单环境光/AO，缺乏完整的全局光照方案。

#### 完整实时路径追踪

**目标**：替代所有光栅光照计算，实现物理精确的全局光照。

```
传统光栅光照: 直接光 + 环境光/AO + SSR ≈ 60%物理精度
路径追踪全局光: 递归射线 + 间接散射 + 自发光 ≈ 95%+物理精度
```

**技术要点**：

| 技术 | 原理 | 适用场景 | 性能开销 |
|------|------|---------|---------|
| 完整路径追踪 | 逐像素发射多条射线递归追踪 | 高端桌面端/主机 | 极高(4~16样本/像素) |
| 一样本路径追踪 | 每像素仅1条射线 + 时空降噪 | 中高端桌面端 | 中高 |
| 半分辨率路径追踪 | 低分辨率PT + 超分 | 中端桌面端 | 中 |

**落地挑战**：

- 降噪质量：NRD（NVIDIA Real-time Denoiser）或自研 AI 降噪器
- 动态场景：BVH 增量更新需高效实现
- 采样策略：重要性采样 + 多重要性采样（MIS）减少方差

#### ReSTIR 时空样本复用

**核心原理**：利用时空邻域的样本复用，以极少样本获得高质量结果：

```
传统: 每像素独立采样4~16条射线 → 高方差 → 降噪困难
ReSTIR: 每像素1条射线 + 复用邻域(空间+时间)样本 → 低方差 → 降噪轻松

样本复用链路:
  帧 N:   像素P采样射线R_N → 存储到样本池
  帧 N+1: 像素P复用R_N(时域) + 复用邻域像素样本(空域) → 权重重计算 → 合并输出
```

**ReSTIR 变体**：

| 变体 | 复用范围 | 适用场景 |
|------|---------|---------|
| ReSTIR DI (Direct Illumination) | 时空邻域复用直接光样本 | 大量局部光源直接光 |
| ReSTIR GI (Global Illumination) | 时空邻域复用间接光样本 | 一样本路径追踪间接光 |
| ReSTIR PT (Path Tracing) | 多级时域复用 + 路径分裂 | 完整路径追踪 |

#### NRD / AI 降噪器

**目标**：对光追/路径追踪的高方差输出进行降噪，获得平滑稳定的结果。

| 降噪方案 | 原理 | 依赖 | 适用 |
|---------|------|------|------|
| NVIDIA NRD | 空域+时域+虚方差降噪 | NVIDIA GPU | NVIDIA 平台 |
| Intel OIDN | AI卷积降噪 | Intel GPU / CPU | Intel 平台 |
| AMD FidelityFX Denoiser | 空域+时域滤波 | AMD GPU | AMD 平台 |
| 自研降噪器 | 基于Vulkan Compute的空域+时域滤波 | 跨平台 | 全平台 |

### 1.2 神经渲染

神经渲染是近年来快速发展的方向，利用神经网络增强或替代传统渲染管线中的特定环节。

| 技术 | 原理 | 替代传统环节 | 当前成熟度 |
|------|------|-------------|-----------|
| **神经材质** | 神经网络拟合复杂材质BRDF | 传统材质参数编码+纹理采样 | 实验阶段 |
| **神经超分** | AI模型从低分辨率推理高分辨率 | FSR/DLSS算法超分 | 成熟(DLSS/FSR已商用) |
| **神经辐照度缓存** | 神经网络缓存+插值间接光照 | 传统光照探针/Irradiance Volume | 实验阶段 |
| **可微渲染** | 渲染过程可微分，支持梯度优化 | 传统硬编码渲染管线 | 学术阶段 |
| **神经纹理压缩** | 神经网络压缩+解码纹理 | BCn/ASTC硬件压缩 | 实验阶段 |

**神经材质详细说明**：

```
传统材质: 参数编码(GBuffer) + 纹理采样(4~8次) → BRDF公式计算
神经材质: 低维编码(4~8参数) → 神经网络推理(1次) → 高质量外观

优势: 
  ├─ 极低GBuffer带宽 (仅4~8参数 vs 传统12+字节)
  ├─ 无限材质表达力 (网络可拟合任意复杂BRDF)
  └─ 无需大量纹理存储 (网络权重固定大小)

挑战:
  ├─ 神经网络推理性能 (需Tensor Core/ML加速)
  ├─ 训练数据获取 (需要大量真实材质扫描数据)
  └─ 跨平台兼容 (移动端缺乏ML加速硬件)
```

### 1.3 体积效果

#### 体积云/雾/烟尘 Ray Marching

```
体积渲染流程:
  1. 沿视线方向步进采样 (Ray Marching)
  2. 逐采样点计算:
     ├─ 密度 (从噪声纹理/密度函数采样)
     ├─ 光照 (直接光+散射+自阴影)
     ├─ 透射率 (Beer's Law: T = e^(-density×stepSize))
  3. 前向积分: 累积散射光 × 透射率
  4. 输出: 体积颜色 + 透射率 (与背景混合)
```

**性能优化**：

- 低分辨率体积渲染 + 时域累积 + 空域滤波
- 重要性采样（高密度区域步进更密）
- 空间重投影（利用运动矢量累积多帧样本）
- 半分辨率Ray Marching + 超分合成

#### 光追体积散射

```
光追体积:
  Raygen: 从相机发射射线
  Intersection: 自定义体积交叉(VK_SHADER_STAGE_INTERSECTION_BIT_KHR)
    ├─ 逐Step测试密度
    ├─ 找到足够密度的采样点
  Closest-Hit: 体积光照计算
    ├─ 从采样点向光源发射二次射线
    ├─ 计算直接光+间接散射
  Miss: 背景颜色
```

### 1.4 专用材质管线

#### 次表面皮肤散射（Subsurface Scattering）

```
皮肤渲染方案:
  ├─ 屏幕空间SSS (后处理模糊, 低成本)
  ├─ 预积分SSS (纹理LUT查找, 中等成本)
  ├─ 路径追踪SSS (光追+体积采样, 高成本高精度)
  └─ 神经SSS (神经网络拟合散射, 实验阶段)
```

#### 头发/毛发专用管线

```
毛发渲染挑战:
  ├─ 几何数量: 百万级毛发丝 → 需特殊几何生成
  ├─ 光照模型: Marschner/Bishari双层散射模型
  ├─ 自阴影: 深度切片/光追阴影
  └─ 性能: 逐丝计算不可行 → 集群/体积近似

方案:
  ├─ Hair Cluster: 毛发聚类为Volume → 体积渲染近似
  ├─ Strand Pipeline: 逐丝渲染 + 简化BRDF
  └─ Mesh Shader + Instance: GPU生成毛发几何
```

## 2. 几何与 GPU 自主调度

### 2.1 Nanite 式虚拟几何体

**目标**：消除传统 LOD 的切换伪影与手动 LOD 制作开销，实现像素级精确的几何体渲染。

```
Nanite核心流程:
  1. 离线: 将高模拆分为Meshlet集群(128三角形/集群)
  2. 离线: 为每个集群构建BVH + 多级LOD
  3. 运行时: Task Shader执行集群级剔除
     ├─ 视锥剔除 (集群粒度)
     ├─ 遮挡剔除 (Hi-Z深度测试)
     └─ LOD选择 (基于屏幕空间覆盖面积)
  4. 运行时: Mesh Shader渲染可见集群
  5. 运行时: Visibility Buffer输出(仅三角面ID+重心坐标)
  6. 后续: 材质Pass从VisBuffer反查材质 → 光照Pass计算
```

**关键技术**：

| 技术 | 说明 | Vulkan扩展 |
|------|------|-----------|
| Meshlet 集群拆分 | 离线将网格拆为128三角面集群 | 离线工具 |
| Task Shader 集群剔除 | GPU端集群级视锥/遮挡剔除 | `VK_EXT_mesh_shader` |
| 动态 LOD 选择 | 基于屏幕覆盖面积选择集群LOD级别 | Compute Shader |
| Visibility Buffer | 仅输出三角面ID+重心坐标 | 图形管线 |
| 群组边界（Group Bounds） | 每个集群的BVH用于剔除 | Compute Shader |

### 2.2 Vulkan 新扩展：GPU 自主生成绘制命令

#### VK_EXT_device_generated_commands

**目标**：让 GPU 自主生成绘制命令，**无需 CPU 录制 CommandBuffer**：

```
传统流程:
  CPU: 录制vkCmdDraw/vkCmdDrawIndirect → 提交到队列 → GPU执行
  瓶颈: CPU录制是串行瓶颈

VK_EXT_device_generated_commands:
  CPU: 提交"绘制命令生成参数" → GPU: 自主生成+执行绘制命令
  收益: CPU零干预，GPU自主调度绘制
```

#### Work Graphs（VK_KHR_work_graph）

**目标**：GPU 端 DAG 调度，实现**GPU 自主级联计算**：

```
Work Graph 流程:
  1. CPU: 提交初始Work节点(如剔除任务)
  2. GPU: 执行剔除 → 输出可见物体列表 → 自动触发下游Work节点(绘制)
  3. GPU: 执行绘制 → 输出GBuffer → 自动触发下游Work节点(光照)
  4. GPU: 自主级联执行全渲染流程

  CPU仅提交初始节点，GPU自主级联完成全部渲染
```

**Work Graph vs 传统流程对比**：

| 维度 | 传统流程 | Work Graph |
|------|---------|-----------|
| CPU干预 | 每个Pass需CPU提交 | 仅初始提交 |
| 同步开销 | CPU→GPU每Pass同步 | GPU内部自主级联，无同步 |
| 延迟 | 多Pass串行提交 | GPU内部零延迟级联 |
| 灵活性 | 中(预定义流程) | 高(GPU动态决定流程) |
| 成熟度 | 成熟 | 实验阶段(VK_KHR_work_graph草案) |

### 2.3 动态 BVH 增量更新

**目标**：适配大规模动态场景的光追加速结构高效更新。

```
传统BVH重建: 每帧完全重建TLAS → 高开销(大场景100ms+)
增量更新: 仅更新变换矩阵 + 局部重建 → 低开销(1~5ms)

Vulkan支持:
  vkCmdBuildAccelerationStructuresKHR(
    ...
    VK_BUILD_ACCELERATION_STRUCTURE_MODE_UPDATE_KHR  // 增量更新模式
  );

优化策略:
  ├─ 静态物体: BLAS不变, 仅TLAS实例矩阵更新
  ├─ 动态物体: BLAS增量更新(仅变化部分)
  ├─ 大规模场景: 分区BVH + 按区域增量更新
  └─ PLOC算法: 并行局部BVH重建, 适合GPU执行
```

## 3. 平台专项优化

### 3.1 移动端 TBDR 深度优化

| 技术 | 原理 | 收益 |
|------|------|------|
| **Subpass合并** | 多Pass合并为同一RenderPass的Subpass | 片上存储避免显存读写 |
| **Pixel Local Storage** | Subpass间通过片上存储传递数据 | 带宽节省50%~70% |
| **ASTC压缩** | 纹理硬件压缩 | 带宽节省75%~87% |
| **注视点渲染** | 中心高分辨率，边缘低分辨率 | 计算节省30%~50% |
| **Early-Z优化** | 深度预通道后逐物体渲染利用Early-Z | Overdraw减少 |
| **AFRC (Adaptive Frame Rate Control)** | 动态调整帧率平衡功耗与画质 | 功耗优化 |

**移动端渲染策略对比**：

```
高端移动 (旗舰手机):
  Clustered Forward+ + CSM + SSR(简化版) + TAA + ASTC 4×4
  目标: 60fps, 1080p

中端移动:
  Forward + ShadowMap + 简化光照 + ASTC 6×6
  目标: 30fps, 720p

低端移动:
  Forward + 简化材质 + 无阴影 + ASTC 8×8
  目标: 30fps, 540p
```

### 3.2 VR/AR 管线

#### Multiview 多视图渲染

```
传统VR: 左眼+右眼分别渲染 = 2×渲染开销
Multiview: 单Pass渲染多视图 = 渲染开销≈1.2×

Vulkan支持:
  VK_KHR_multiview
  VkRenderPassMultiviewCreateInfo
  viewMask = 0b11 (2个视图: 左眼+右眼)

Shader:
  gl_ViewIndex → 0(左眼) / 1(右眼)
  每顶点根据ViewIndex使用不同的投影矩阵
```

#### 眼球追踪注视点渲染

```
注视点渲染:
  ├─ 中心区域: 高分辨率 (如 100% 渲染分辨率)
  ├─ 中间区域: 中分辨率 (如 50% 渲染分辨率)
  └─ 边缘区域: 低分辨率 (如 25% 渲染分辨率)

  眼球追踪: 实时获取注视点 → 动态调整高分辨率区域中心
  合成: 逐区域超分到统一分辨率 → 混合输出
```

#### 预测时序渲染

```
问题: VR渲染到呈现有延迟 → 用户转头时画面滞后 → 不适
方案: 预测时序渲染(Asynchronous TimeWarp)

  1. 正常渲染帧(16.67ms延迟)
  2. 呈现前: 用最新头部姿态重新投影上一帧(2ms延迟)
  3. 重新投影: 深度缓冲+上一帧颜色 → 逐像素重投影

  Vulkan实现:
    ├─ 独立线程/队列执行ATW
    ├─ Timeline Semaphore同步主渲染帧完成
    └─ 深度+颜色纹理作为ATW输入
```

### 3.3 HDR 完整管线

```
HDR完整管线:
  1. 渲染: HDR色彩空间渲染 (R16G16B16A16_SFLOAT)
  2. 色调映射: PQ(Perceptual Quantizer)色彩空间映射
  3. 交换链: VK_FORMAT_A2B10G10R10_UNORM_PACK32 (HDR10)
              或 VK_FORMAT_R16G16B16A16_SFLOAT (Dolby Vision)
  4. 显示: HDR显示器接收10bit+色域信号

关键配置:
  ├─ VkSwapchainCreateInfoKHR.format → HDR10/Dolby Vision格式
  ├─ VkSwapchainCreateInfoKHR.colorSpace → VK_COLOR_SPACE_HDR10_ST2084_EXT
  ├─ 色调映射曲线 → PQ ST.2084 或 HLG ST.2086
  └─ 广色域: Rec.2020 (BT.2020) vs sRGB (BT.709)
```

## 5. 技术拓展路线图

### 5.1 按优先级排列的演进方向

```
Phase 1: 基础完善 (当前体系补全)
  ├─ Shader变体管理流水线
  ├─ GPU性能计数器+Pass耗时可视化
  ├─ 纹理压缩离线烘焙
  └─ PipelineCache持久化

Phase 2: 渲染质量提升
  ├─ Clustered Shading升级
  ├─ 体积云/雾Ray Marching
  ├─ 次表面皮肤散射
  ├─ ReSTIR DI (大量局部光源)
  └─ HDR完整管线

Phase 3: 光追混合管线
  ├─ 光追阴影 + NRD降噪
  ├─ 光追反射 + NRD降噪
  ├─ 动态BVH增量更新
  └─ 一样本路径追踪 + ReSTIR GI

Phase 4: GPU自主调度
  ├─ Nanite式虚拟几何体 + Mesh Shader
  ├─ Visibility Buffer渲染架构
  ├─ VK_EXT_device_generated_commands
  └─ Work Graphs级联调度

Phase 5: 神经渲染集成
  ├─ 神经超分(替代FSR/DLSS算法超分)
  ├─ 神经辐照度缓存
  ├─ 神经材质(实验性)

```
