# 实时渲染系统 — 总览与架构概览

> 本文档是「实时渲染系统」系列文档的第 **0** 篇，提供整体架构的宏观视角与设计理念，为后续各专题文档建立统一概念基础。

## 1. 文档目的与读者对象

### 1.1 文档目的

本系列文档旨在对自研 Vulkan 现代实时渲染引擎的**实时渲染系统**部分进行系统化、结构化的完整阐述。内容涵盖从底层 Vulkan API 管线封装到上层 FrameGraph 声明式帧图系统的全链路设计，兼顾理论辨析与工程落地细节。

**核心目标**：

- **标准化术语**：纠正常见的概念误区（如光追阴影归类错误、Multi-Draw Indirect 术语混淆、RDG/FrameGraph 辨析）
- **建立分层心智模型**：将渲染系统拆分为清晰的层级，避免"一坨代码"的认知混乱
- **工程指导**：提供 Vulkan 落地的具体方案（VMA 分配策略、Bindless 绑定、帧图编译优化等）
- **前沿拓展**：标识当前体系尚未覆盖但行业已在推进的技术方向

## 2. 实时渲染系统定位

实时渲染系统是游戏引擎中**视觉输出**的核心子系统。它接收场景数据（几何、材质、光照、相机）与用户交互，以**每帧 16.67ms（60fps）或更低**的时间预算，生成符合物理直觉与艺术意图的最终画面。

在引擎整体架构中的定位：

```
┌─────────────────────────────────────────────────────┐
│                    游戏引擎                          │
│  ┌───────────┐  ┌───────────┐  ┌──────────────────┐ │
│  │  场景管理  │  │  物理模拟  │  │  实时渲染系统    │ │
│  │  ECS/世界  │  │  碰撞/动力│  │  ┌─────────────┐ │ │
│  └───────────┘  └───────────┘  │  │渲染管线层    │ │ │
│                                  │  │资源管理层    │ │ │
│  ┌───────────┐  ┌───────────┐  │  │FrameGraph层  │ │ │
│  │  音频系统  │  │  网络系统  │  │  │执行调度层    │ │ │
│  └───────────┘  └───────────┘  │  └─────────────┘ │ │
│                                  └──────────────────┘ │
│  ┌───────────┐  ┌───────────┐                        │
│  │  UI/输入   │  │  资产管线  │                        │
│  └───────────┘  └───────────┘                        │
└─────────────────────────────────────────────────────┘
```

**关键边界**：

- **上游输入**：场景管理提供可见物体列表与变换数据，资产管线提供 GPU 资源（纹理、网格、Shader）
- **下游输出**：最终呈现到交换链（Swapchain）的像素阵列，以及为下一帧准备的中间资源（历史帧、运动矢量等）
- **横向协作**：物理模拟提供运动数据（用于运动模糊/TAA），UI 系统提供叠加渲染内容

## 3. 整体架构分层

实时渲染系统采用**四层递进架构**，每一层有明确的职责边界和接口约定：

```
┌──────────────────────────────────────────┐
│           Layer 4: 执行调度层             │
│  多线程CommandBuffer录制 → GPU队列提交     │
│  → 交换链呈现 → 帧延迟资源回收             │
├──────────────────────────────────────────┤
│           Layer 3: FrameGraph层           │
│  声明式Pass注册 → DAG构建 → 编译优化       │
│  → 自动屏障/布局转换 → 执行计划生成        │
├──────────────────────────────────────────┤
│           Layer 2: 渲染核心层             │
│  ├─ 资源子系统 (CPU加载 + VMA + Bindless) │
│  ├─ 管线子系统 (图形/计算/Mesh/光追缓存)   │
│  └─ 同步子系统 (屏障推导 + 多队列并行)     │
├──────────────────────────────────────────┤
│           Layer 1: 渲染架构选型层          │
│  Forward / Forward+ / Deferred / TDBR    │
│  / Clustered / Visibility Buffer / 混合  │
└──────────────────────────────────────────┘
```

### 各层职责说明

| 层级                      | 核心职责                        | 关键抽象                                 | 依赖方向                 |
| ----------------------- | --------------------------- | ------------------------------------ | -------------------- |
| **Layer 1 架构选型层**       | 确定整体渲染策略（光栅/光追/混合）、材质与光照模型  | 渲染路径配置                               | 仅依赖引擎高层决策            |
| **Layer 2 渲染核心层**       | Vulkan API 封装、资源生命周期、管线对象管理 | 虚拟资源句柄、PipelineCache                 | 依赖 Vulkan API        |
| **Layer 3 FrameGraph层** | Pass 依赖管理、自动优化、执行计划编排       | DAG有向无环图                             | 依赖 Layer 2 的资源/管线子系统 |
| **Layer 4 执行调度层**       | GPU 命令录制、多队列同步、帧轮转缓冲        | CommandPool、Fence、Timeline Semaphore | 依赖 Layer 3 的执行计划     |

**核心设计原则**：**上层不直接操作 Vulkan API 对象**。Layer 3/4 通过虚拟资源句柄与 Layer 2 交互，Layer 2 负责将虚拟句柄映射到实际的 VkImage/VkBuffer/VkPipeline。

## 4. 核心设计原则

### 4.1 声明式优于命令式

渲染系统采用**声明式设计**：

- Pass 声明自己需要什么资源、读写什么附件、依赖什么其他 Pass
- **不硬编码**具体的 VkImage/VkBuffer 句柄
- FrameGraph 编译器自动推导屏障、布局转换、执行顺序

> **原则**：工程师只关心"我要什么"，不关心"如何安排"。

### 4.2 GPU-Driven 优先

尽可能将决策推至 GPU：

- 遮挡剔除 → GPU 视锥/遮挡剔除
- 绘制命令 → GPU 生成间接绘制命令（Multi-Draw Indirect）
- 资源绑定 → Bindless 全局描述符数组

> **原则**：减少 CPU→GPU 同步点，降低 CPU 提交瓶颈。

### 4.3 数据驱动与零硬编码

- 渲染路径由场景配置/画质档位动态决定，不硬编码管线流程
- Shader 变体由材质参数驱动，不手写 switch-case
- 帧图每帧动态构建，根据开关/可见性剔除无效节点

> **原则**：系统行为由数据决定，而非代码流程。

### 4.4 显存是首要约束

GPU 显存带宽与容量是实时渲染的首要瓶颈：

- 纹理压缩（BCn/ASTC）优先于原始格式
- 资源别名复用（不同 Pass 分时共用同一块 RT/Buffer）
- 稀疏绑定分页加载避免全量驻留

> **原则**：带宽优化优先于计算优化。

## 7. 术语约定

本系列文档使用以下标准化术语，避免歧义：

| 术语 | 标准含义 | 常见误用 |
|------|---------|---------|
| **Multi-Draw Indirect (MDI)** | GPU 生成间接绘制命令，CPU 无逐物体提交 | ❌ "Multi-Draw Direct"（Direct 需逐物体提交） |
| **FrameGraph** | 行业通用术语，每帧动态构建的渲染 DAG | ❌ 与 RDG 混为一谈（RDG 是 UE 专属命名） |
| **光追阴影/反射** | 属于**主渲染阶段**（Ray Tracing Pipeline） | ❌ 归类至后处理（后处理仅屏幕空间滤波） |
| **Bindless** | 全局描述符数组，Shader 索引直接访问 | ❌ 等同于"无描述符"（实际使用描述符数组而非逐绑定） |
| **GPU-Driven** | GPU 自主完成剔除/绘制命令生成 | ❌ 仅指"GPU 计算加速"（核心是 CPU 零干预） |
