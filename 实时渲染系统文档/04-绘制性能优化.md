# 实时渲染系统 — 绘制性能优化

> 本文档是「实时渲染系统」系列文档的第 **4** 篇，详细阐述 GPU-Driven 绘制优化体系，涵盖 Multi-Draw Indirect、Bindless 资源索引、合批策略、状态排序与 Push Constant 优化。

---

## 1. 绘制性能瓶颈分析

实时渲染的 CPU→GPU 提交流程中，以下环节是典型性能瓶颈：

```
CPU 提交瓶颈:
┌──────────────────────────────────────────────────────────┐
│  for each object:                                         │
│    bind pipeline   ──▶ 管线切换开销                        │
│    bind descriptor ──▶ 描述符更新开销                      │
│    bind vertex     ──▶ 顶点绑定开销                        │
│    push constant   ──▶ 小数据推送                          │
│    vkCmdDraw       ──▶ 绘制命令提交                        │
│                                                          │
│  1000个物体 = 1000×上述流程 = CPU提交瓶颈                  │
└──────────────────────────────────────────────────────────┘

GPU 执行瓶颈:
┌──────────────────────────────────────────────────────────┐
│  Overdraw (重叠像素重复计算)                               │
│  Bandwidth (显存带宽饱和: GBuffer读写/纹理采样)            │
│  State Switch (管线/描述符切换导致GPU缓存失效)              │
│  Wave Occupancy (Shader分支导致GPU线程利用率低)             │
└──────────────────────────────────────────────────────────┘
```

**优化方向**：减少 CPU 提交次数 → GPU-Driven Pipeline；减少 GPU 状态切换 → 合批+排序；减少带宽消耗 → 压缩+Bindless。

## 2. Multi-Draw Indirect（MDI）

### 2.1 术语纠正

> ⚠️ **纠正**：常见误写为 "Multi-Draw **Direct**"。正确术语为 **Multi-Draw Indirect (MDI)**。
> - **Direct** = CPU 逐物体提交绘制命令（`vkCmdDraw`），每绘制一次需 CPU 调用
> - **Indirect** = GPU 生成绘制命令存储在 Buffer 中，CPU 仅一次 `vkCmdDrawIndirect` 提交

### 2.2 Indirect Draw 命令类型

Vulkan 提供以下间接绘制命令：

| 命令 | 结构体 | 说明 |
|------|--------|------|
| `vkCmdDrawIndirect` | `VkDrawIndirectCommand` | 无索引绘制，GPU 提供顶点范围和实例数 |
| `vkCmdDrawIndexedIndirect` | `VkDrawIndexedIndirectCommand` | 索引绘制，GPU 提供索引范围和实例数 |
| `vkCmdDispatchIndirect` | — | 计算管线间接调度 |
| `vkCmdDrawMeshTasksIndirectEXT` | — | Mesh Shader 间接绘制 |

### 2.3 GPU 生成间接绘制命令流程

```
┌─────────────────────────────────────────────────────────┐
│  GPU-Driven 全流程                                       │
│                                                          │
│  Step 1: GPU 剔除 (Compute Shader)                       │
│    输入: 全场景物体 AABB Buffer                           │
│    输出: 可见物体索引 + 间接绘制命令 Buffer                │
│                                                          │
│  Step 2: GPU 绘制 (图形管线)                              │
│    输入: 间接绘制命令 Buffer                              │
│    执行: vkCmdDrawIndexedIndirect(count=1)               │
│    GPU 自行读取 Buffer 中所有绘制命令并执行                │
│                                                          │
│  CPU 全帧干预: 仅 2 次 API 调用                           │
│    vkCmdDispatch(剔除) + vkCmdDrawIndexedIndirect(绘制)  │
└─────────────────────────────────────────────────────────┘
```

### 2.4 间接命令 Buffer 管理

```cpp
// 创建间接命令 Buffer
VkBufferCreateInfo indirectBufferInfo = {};
indirectBufferInfo.sType = VK_STRUCTURE_TYPE_BUFFER_CREATE_INFO;
indirectBufferInfo.size = maxDrawCount * sizeof(VkDrawIndexedIndirectCommand);
indirectBufferInfo.usage = VK_BUFFER_USAGE_INDIRECT_BUFFER_BIT |
                          VK_BUFFER_USAGE_STORAGE_BUFFER_BIT;  // GPU读写+间接绘制
indirectBufferInfo.sharingMode = VK_SHARING_MODE_EXCLUSIVE;

// VMA分配: HOST_VISIBLE允许CPU初始化, DEVICE_LOCAL优先GPU访问
VmaAllocationCreateInfo allocInfo = {};
allocInfo.usage = VMA_MEMORY_USAGE_CPU_TO_GPU;
allocInfo.flags = VMA_ALLOCATION_CREATE_MAPPED_BIT;

VmaAllocation allocation;
VkBuffer indirectBuffer;
vmaCreateBuffer(allocator, &indirectBufferInfo, &allocInfo, &indirectBuffer, &allocation, nullptr);

// 清零: 初始化可见物体数量为0
VkDrawIndexedIndirectCommand* cmds = (VkDrawIndexedIndirectCommand*)allocationInfo.pMappedData;
memset(cmds, 0, maxDrawCount * sizeof(VkDrawIndexedIndirectCommand));
```

### 2.5 间接命令 Buffer 的原子写入

```glsl
// Compute Shader: GPU 剔除 + 间接命令生成
layout(local_size_x = 256) in;

layout(std430, buffer_device_address) buffer IndirectCommands {
    VkDrawIndexedIndirectCommand commands[];
};

layout(std430) buffer VisibleCount {
    uint visibleCount;  // 原子计数器
};

void main() {
    uint objectID = gl_GlobalInvocationID.x;
    if (objectID >= totalObjectCount) return;

    // 视锥 + 遮挡剔除
    if (!isVisible(objectID)) return;

    // 原子分配可见物体索引
    uint visibleIndex = atomicAdd(visibleCount, 1);

    // 写入间接绘制命令
    commands[visibleIndex].indexCount    = meshIndexCounts[objectID];
    commands[visibleIndex].instanceCount = 1;
    commands[visibleIndex].firstIndex    = meshIndexOffsets[objectID];
    commands[visibleIndex].vertexOffset  = meshVertexOffsets[objectID];
    commands[visibleIndex].firstInstance  = 0;
}
```

## 3. GPU-Driven Rendering

### 3.1 设计理念

GPU-Driven Rendering 的核心目标是**消除 CPU 逐物体提交瓶颈**，让 GPU 自主完成从剔除到绘制的全流程：

```
传统流程 (CPU-Driven):
  CPU: 遍历场景物体 → 逐物体判断可见 → 逐物体提交Draw命令 → GPU执行
  瓶颈: CPU逐物体循环，N物体=N次API调用

GPU-Driven 流程:
  CPU: 提交全场景数据 (1次) → 提交剔除Dispatch (1次) → 提交DrawIndirect (1次)
  GPU: 自主剔除 → 生成间接命令 → 自主绘制
  瓶颈: CPU仅3次API调用，GPU自主处理N物体
```

### 3.2 GPU-Driven 数据流

```
┌──────────────────────────────────────────────────────────────┐
│  GPU-Driven Pipeline 全数据流                                 │
│                                                              │
│  ┌──────────────┐                                             │
│  │  场景数据     │  (CPU一次上传, 全帧驻留)                    │
│  │  ├─ AABB数组  │                                             │
│  │  ├─ Mesh数据  │  (顶点+索引, 全场景合并大Buffer)            │
│  │  ├─ 材质索引  │  (Bindless纹理索引+参数)                    │
│  │  └─ 变换矩阵  │  (逐物体世界变换)                          │
│  └──────────────┘                                             │
│         │                                                     │
│         ▼                                                     │
│  ┌──────────────┐                                             │
│  │  GPU 剔除    │  (Compute Shader)                           │
│  │  ├─ 视锥剔除 │                                             │
│  │  ├─ 遮挡剔除 │  (Hi-Z深度金字塔)                           │
│  │  └─ 输出     │  → 可见物体索引 + 间接绘制命令               │
│  └──────────────┘                                             │
│         │                                                     │
│         ▼                                                     │
│  ┌──────────────┐                                             │
│  │  GPU 绘制    │  (DrawIndexedIndirect)                     │
│  │  ├─ Mesh Shader / 传统VS+FS                              │
│  │  ├─ Bindless材质索引直接采样                               │
│  │  └─ Push Constant仅传物体索引                             │
│  └──────────────┘                                             │
│                                                               │
│  CPU全帧API调用: 3次 (Dispatch + Barrier + DrawIndirect)     │
└──────────────────────────────────────────────────────────────┘
```

### 3.3 GPU-Driven 核心配套组件

| 组件 | Vulkan 落地 | 说明 |
|------|-------------|------|
| **合并大Buffer** | 全场景顶点/索引合并到单一 Buffer | `VK_BUFFER_USAGE_VERTEX_BUFFER_BIT` + `VK_BUFFER_USAGE_INDEX_BUFFER_BIT` |
| **Bindless材质** | 全局纹理数组描述符集 | 详见 02 篇 Bindless 章节 |
| **Push Constant索引** | 仅推送物体索引而非变换矩阵 | 4 bytes per draw vs 128 bytes |
| **间接命令Buffer** | GPU 剔除后生成 | `VK_BUFFER_USAGE_INDIRECT_BUFFER_BIT` |
| **Hi-Z深度金字塔** | 计算着色器降采样 | 遮挡剔除核心输入 |

## 4. Bindless 资源索引优化

### 4.1 传统绑定模式开销

```
传统逐绑定模式 (Per-Draw Binding):
  Draw(obj0): vkCmdBindDescriptorSets(set_for_obj0) → vkCmdDraw
  Draw(obj1): vkCmdBindDescriptorSets(set_for_obj1) → vkCmdDraw
  Draw(obj2): vkCmdBindDescriptorSets(set_for_obj2) → vkCmdDraw
  ...
  N物体 = N次描述符绑定切换 = N次GPU状态失效

Bindless模式:
  1次: vkCmdBindDescriptorSets(bindless_global_set)
  Draw(all_visible): vkCmdDrawIndexedIndirect(count=1)
  Shader: materialIndex = push_constant → textureArray[materialIndex]
  N物体 = 1次描述符绑定 = GPU状态稳定
```

### 4.2 Bindless 资源索引策略

**全局纹理索引分配**：

| 索引范围 | 资源类型 | 更新频率 | 生命周期 |
|---------|---------|---------|---------|
| 0~4095 | 纹理（2D） | 加载时分配，帧延迟释放 | 跨帧 |
| 4096~6143 | 纹理（Cube） | 加载时分配 | 跨帧 |
| 6144~8191 | Buffer (SSBO) | 加载时分配 | 跨帧 |
| 8192~8447 | 加速结构 (AS) | 场景重建时更新 | 跨帧 |

**Shader 侧材质数据结构**：

```glsl
// 材质参数 Buffer（Bindless索引方式）
struct MaterialInfo {
    uint albedoTextureIndex;    // Bindless全局纹理索引
    uint normalTextureIndex;
    uint ormTextureIndex;       // Occlusion+Roughness+Metallic合并纹理
    uint emissiveTextureIndex;
    vec4 albedoFactor;          // 非纹理材质的纯色参数
    float roughnessFactor;
    float metallicFactor;
    float emissiveFactor;
    uint flags;                 // 材质特性标志位
};

layout(std430, set = 0, binding = 2) buffer Materials {
    MaterialInfo materials[];
} materialBuffer;

// Push Constant: 仅传物体索引
layout(push_constant) uniform PushConstants {
    uint objectID;      // 4 bytes! 极精简
    uint materialID;    // 4 bytes
} pc;

void main() {
    MaterialInfo mat = materialBuffer.materials[pc.materialID];
    vec3 albedo = texture(globalTextures[mat.albedoTextureIndex], uv).rgb;
    // ... 光照计算
}
```

## 5. 静态网格合并与合批策略

### 5.1 静态网格合并（Static Mesh Merging）

将使用相同材质的静态网格合并为单一绘制单位：

```
原始场景:
  Mesh_A (材质M0, 100三角形) → Draw #1
  Mesh_B (材质M0, 200三角形) → Draw #2  ← 同材质, 可合并
  Mesh_C (材质M0, 150三角形) → Draw #3  ← 同材质, 可合并
  Mesh_D (材质M1, 300三角形) → Draw #4  ← 不同材质, 不可合并

合并后:
  Mesh_ABC (材质M0, 450三角形) → Draw #1  ← 单一绘制
  Mesh_D   (材质M1, 300三角形) → Draw #2
  Draw命令数: 4 → 2
```

**合并条件**：

| 条件 | 说明 | 检查方式 |
|------|------|---------|
| 相同管线 | 相同 Shader 变体 | PipelineLayout + ShaderModule 匹配 |
| 相同材质 | 相同纹理+参数 | Bindless材质索引相等 |
| 相同渲染状态 | 相同混合/深度/剔除模式 | Pipeline CreateInfo 匹配 |
| 静态物体 | 不需要逐物体变换 | 物体标记为 static |
| 同区域 | 空间邻近（可选） | AABB 空间聚类 |

### 5.2 合批层级

```
Level 0: 无合批 (逐物体绘制)
  Draw数量 = 物体数量

Level 1: Instance批量绘制 (相同网格, 不同变换)
  vkCmdDrawIndexed(vertexCount, instanceCount=N)
  Draw数量 = 不同网格数量 (显著减少)

Level 2: 静态合并 (相同材质, 不同网格合并)
  顶点/索引合并到大Buffer + Instance ID索引变换
  Draw数量 = 不同材质数量 (大幅减少)

Level 3: GPU-Driven全场景单次绘制
  DrawIndexedIndirect(count=1) 包含全部可见物体
  Draw数量 = 1 (极致减少)
```

## 6. 管线与材质排序优化

### 6.1 状态切换代价

GPU 状态切换（管线/描述符/顶点绑定）会导致：

- **管线缓存失效**：切换管线后 GPU 需重建内部缓存
- **描述符缓存失效**：绑定切换导致 GPU 描述符查找表重载
- **顶点缓冲切换**：不同顶点布局需要重新配置输入装配

**代价排序**（从高到低）：

```
管线切换 (最昂贵) > 描述符集切换 > 顶点绑定切换 > Push Constant更新 (最廉价)
```

### 6.2 排序策略

**按状态切换代价从高到低排序绘制命令**：

```cpp
// 渲染排序策略
struct SortKey {
    uint64_t pipelineIndex  : 16;  // 最高优先级: 管线
    uint64_t materialIndex  : 16;  // 第二优先级: 材质(描述符)
    uint64_t vertexBufferID : 8;   // 第三优先级: 顶点Buffer
    uint64_t depth          : 24;  // 最后优先级: 深度(前后排序)
};

// 不透明物体: 从前到后 (减少Overdraw早期Z拒绝)
SortKey opaqueKey = {pipeline, material, vbuf, depth_sorted_front_to_back};

// 透明物体: 从后到前 (保证正确混合顺序)
SortKey transparentKey = {depth_sorted_back_to_front, pipeline, material, vbuf};
```

### 6.3 GPU 侧排序

在 GPU-Driven Pipeline 中，排序可在 Compute Shader 中完成：

```glsl
// Compute Shader: 绘制命令排序
// 按管线/材质/深度生成排序键
layout(local_size_x = 256) in;

void main() {
    uint visibleIndex = gl_GlobalInvocationID.x;
    if (visibleIndex >= visibleCount) return;

    uint objectID = visibleObjects[visibleIndex];

    // 生成排序键
    uint64_t sortKey = 0;
    sortKey |= (uint64_t(pipelineIDs[objectID]) << 48);  // 管线最高位
    sortKey |= (uint64_t(materialIDs[objectID]) << 32);  // 材质次高位
    sortKey |= (uint64_t(depthValues[objectID]) << 0);   // 深度最低位

    sortKeys[visibleIndex] = sortKey;
    sortIndices[visibleIndex] = objectID;
}

// 后续: GPU Bitonic Sort 排序 sortKeys[] → 重排间接命令Buffer
```

## 7. Dynamic UBO 与 Push Constant 优化

### 7.1 Dynamic Uniform Buffer

Dynamic UBO 允许多个物体共享同一 UBO Buffer，通过偏移切换不同物体的数据：

```cpp
// 创建 Dynamic UBO
VkBufferCreateInfo uboInfo = {};
uboInfo.size = ALIGN_UP(sizeof(PerObjectData), dynamicAlignment) * MAX_OBJECTS;
uboInfo.usage = VK_BUFFER_USAGE_UNIFORM_BUFFER_BIT;

// 绑定描述符时指定动态偏移
vkCmdBindDescriptorSets(cmdBuffer,
    VK_PIPELINE_BIND_POINT_GRAPHICS,
    pipelineLayout,
    1,  // 描述符集索引
    1, &descriptorSet,
    1, &dynamicOffset);  // 偏移 = objectIndex * alignment
```

```glsl
// Shader: Dynamic UBO
layout(std140, set = 1, binding = 0) uniform PerObjectUBO {
    mat4 modelMatrix;
    mat4 normalMatrix;
    uint materialIndex;
} perObject;
// 实际偏移由 vkCmdBindDescriptorSets 的 dynamicOffset 决定
```

**优势**：多个物体共享同一 Buffer，避免逐物体创建独立 UBO。

### 7.2 Push Constant 快速通道

Push Constant 是 Vulkan 中最轻量的数据传输通道，**无需描述符**：

```cpp
// Push Constant 范围声明
VkPushConstantRange pushRange = {};
pushRange.stageFlags = VK_SHADER_STAGE_VERTEX_BIT | VK_SHADER_STAGE_FRAGMENT_BIT;
pushRange.offset = 0;
pushRange.size = 128;  // 最小保证128字节

// 每次绘制推送
vkCmdPushConstants(cmdBuffer, pipelineLayout,
    VK_SHADER_STAGE_VERTEX_BIT | VK_SHADER_STAGE_FRAGMENT_BIT,
    0, sizeof(PushData), &pushData);
```

```glsl
layout(push_constant) uniform PushData {
    uint objectIndex;       // 4 bytes
    uint materialIndex;     // 4 bytes
    vec2 screenResolution;  // 8 bytes
    // 总计仅16 bytes，极致精简
} push;
```

**Push Constant vs Dynamic UBO 对比**：

| 维度 | Push Constant | Dynamic UBO |
|------|--------------|-------------|
| 数据大小 | 128~256 bytes（GPU限制） | 无限制 |
| 描述符开销 | **无**（直接推送） | 需描述符绑定 |
| 更新频率 | 每次绘制可更新 | 每次偏移切换 |
| 延迟 | 极低（直接命令流写入） | 低（Buffer读取） |
| 适用数据 | 物体索引、小参数 | 变换矩阵、大参数 |

**推荐策略**：

- **Push Constant**：物体索引、材质索引、屏幕参数、帧索引等极小数据
- **Dynamic UBO**：变换矩阵、光照参数等较大但需逐物体切换的数据
- **Bindless SSBO**：材质参数、场景数据等大体积全局数据

## 8. 优化策略综合对比表

| 优化手段 | CPU开销减少 | GPU开销减少 | 带宽减少 | 实现复杂度 |
|---------|-----------|-----------|---------|-----------|
| Multi-Draw Indirect | ★★★★★ | ★★ | — | 中 |
| GPU-Driven Pipeline | ★★★★★ | ★★★ | — | 高 |
| Bindless 描述符 | ★★★★★ | ★★★ | ★★ | 中 |
| 静态网格合并 | ★★★★ | ★★ | — | 低 |
| Instance批量绘制 | ★★★★ | ★★ | — | 低 |
| 管线/材质排序 | ★ | ★★★★ | ★★ | 低 |
| Dynamic UBO | ★★★ | — | — | 低 |
| Push Constant | ★★★★★ | ★ | — | 低 |

**推荐优化组合**：

1. **基础级**：Instance批量绘制 + 管线排序 + Push Constant + Dynamic UBO
2. **进阶级**：+ Bindless描述符 + 静态网格合并 + Multi-Draw Indirect
3. **极致级**：+ GPU-Driven全流程（GPU剔除+间接绘制+Bindless材质索引）
