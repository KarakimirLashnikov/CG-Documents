## 1. 引言：为什么同时讲 RHI 与 RDG

在 UE 的渲染架构中，RHI 与 RDG 是两个**不同抽象层级**的资源管理体系，但经常被混为一谈：

```
┌──────────────────────────────────────────────────────────────────┐
│  UE 渲染架构（自上而下）                                            │
│                                                                    │
│  渲染特性层 (SceneRenderer / MeshPassProcessor / 各 Pass)          │
│       │  声明"我要什么资源、做什么 Pass"                            │
│       ▼                                                            │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  RDG 层（声明式帧图）                                        │   │
│  │  FRDGBuilder / FRDGTexture / FRDGBuffer                     │   │
│  │  → 仅描述符，图执行时才分配底层 RHI 资源                       │   │
│  │  → 自动依赖追踪、别名复用、屏障推导                            │   │
│  └──────────────────────────────────────────────────────────┘   │
│       │  执行期把 RDG 资源"解引用"为 RHI 资源                       │
│       ▼                                                            │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  RHI 层（平台抽象）                                          │   │
│  │  FRHIResource / FRHITexture / FRHIBuffer / Views           │   │
│  │  → 对 D3D12 / Vulkan / Metal / OpenGL 的统一封装            │   │
│  │  → 持有真实 GPU 内存句柄（或池化引用）                       │   │
│  └──────────────────────────────────────────────────────────┘   │
│       │  命令列表下发                                             │
│       ▼                                                            │
│  底层图形 API（VkImage / ID3D12Resource / MTLTexture）           │
└──────────────────────────────────────────────────────────────────┘
```

**一句话定位**：

| 体系 | 抽象层级 | 回答的问题 | 资源是否持有 GPU 内存 |
|------|---------|-----------|----------------------|
| **RHI** | 平台抽象（贴近硬件） | "资源在 D3D12/Vulkan/Metal 上长什么样？" | **是**（直接封装底层句柄 / 池化引用） |
| **RDG** | 帧图调度（贴近算法） | "本帧的 Pass 之间如何共享/复用资源？" | **否**（仅描述符，执行期才落地为 RHI） |

> **与本系列的关系**：[06] 篇的 `VirtualResource → PhysicalResource` 是**自研 FrameGraph** 的通用抽象；UE 的对应物正是 **FRDGTexture/FRDGBuffer（虚拟）** → **FRHITexture/FRHIBuffer（物理）**。UE 是工业界最成熟的 Render Graph 实现之一，本篇以它为例，把 [06][07] 的概念落到真实引擎代码上。

## 2. RHI 资源体系：跨平台硬件抽象

### 2.1 RHI 是什么

**RHI（Render Hardware Interface）** 是 UE 对底层图形 API 的**统一封装层**。它把 D3D12、Vulkan、Metal、OpenGL/ES 等平台差异收敛成一套 C++ 接口（纯虚基类 + 全局函数 + 全局变量），让上层渲染逻辑无需关心具体平台 API。

```
上层渲染 (SceneRenderer / RDG Pass)
        │  调用统一 RHI 接口
        ▼
   ┌─────────────────────────────┐
   │  RHI 抽象层 (FRHICommandList)│  ← 对外接口不变
   └─────────────────────────────┘
        │  运行时分派到具体实现
   ┌────┴────┬──────────┬──────────┐
   ▼         ▼          ▼          ▼
 D3D12RHI  VulkanRHI  MetalRHI  OpenGLRHI
   │         │          │          │
 ID3D12…   VkImage…   MTLTexture  GLuint…
```

UE 内部有三条关键线程，RHI 是其中之一：

| 线程 | 职责 | 与资源的关系 |
|------|------|------------|
| **Game Thread** | 游戏逻辑、场景更新 | 持有 `UObject` 资源（UTexture、UStaticMesh），产生渲染指令 |
| **Render Thread** | 执行完整渲染管线（每帧构建 RDG） | 消费场景代理（`FPrimitiveSceneProxy`），构建 `FRDGBuilder` |
| **RHI Thread** | 把 RHI 命令翻译为具体图形 API 调用 | 真正触碰 `FRHIResource` 与底层句柄 |

> UE 的 RHI 刻意保持"低层次"封装（参数贴近现代 API），但内部仍隐藏了大量细节：纹理/着色器/RT 缓存池、多线程提交、资源延迟删除等。

### 2.2 FRHIResource 基类与继承体系

所有 RHI 资源都继承自 **`FRHIResource`**（`Runtime/RHI/Public/RHIResources.h`），它本身是一个**引用计数对象**：

```cpp
// RHI 资源基类（简化）
class FRHIResource {
public:
    uint32 AddRef();    // 引用计数 +1
    uint32 Release();   // 引用计数 -1，归零时进入延迟删除队列
    uint32 GetRefCount() const;
    bool   IsValid() const;
    ERHIResourceType GetType() const;
protected:
    FRHIResource(ERHIResourceType InResourceType);
    virtual ~FRHIResource();
};
```

**继承体系（节选）**：

```
FRHIResource
├─ FRHITexture ────────── FRHITexture2D / FRHITexture3D / FRHITextureCube / FRHITexture2DArray
├─ FRHIBuffer ─────────── FRHIVertexBuffer / FRHIIndexBuffer / FRHIStructuredBuffer
├─ FRHIViewableResource ─（纹理/缓冲的视图able 基类）
├─ FRHIUniformBuffer ──── 常量缓冲（含 FRHIUniformBufferLayout）
├─ FRHIView
│   ├─ FRHIShaderResourceView  (SRV，只读)
│   └─ FRHIUnorderedAccessView (UAV，可读写)
├─ FRHISamplerState ───── 采样器
├─ FRHIViewport ───────── 交换链/视口
├─ FRHIRenderQuery ────── 查询（遮挡/时间戳）
├─ FRHIRayTracingScene / FRHIRayTracingGeometry / FRHIRayTracingPipelineState
└─ FRHIComputePipelineState / FRHIGraphicsPipelineState
```

### 2.3 关键 RHI 资源类型

| 类型 | 头文件/模块 | 封装的底层对象 | 典型用途 |
|------|-----------|--------------|---------|
| `FRHITexture` | `RHIResources.h` | `VkImage` / `ID3D12Resource` / `MTLTexture` | 颜色/深度纹理、渲染目标 |
| `FRHITexture2D/3D/Cube` | `RHIResources.h` | 同上（按维度特化） | 贴图、体积纹理、环境贴图 |
| `FRHIBuffer` | `RHIResources.h` | `VkBuffer` / `ID3D12Resource` | 顶点/索引/结构化/常量缓冲 |
| `FRHIViewableResource` | `RHIResources.h` | 资源+视图信息基类 | SRV/UAV 的绑定源 |
| `FRHIUniformBuffer` | `RHIResources.h` | 常量缓冲（CBV/UBO） | 每帧/每物体常量数据 |
| `FRHIShaderResourceView` | `RHIResources.h` | SRV 描述 | 着色器只读访问 |
| `FRHIUnorderedAccessView` | `RHIResources.h` | UAV 描述 | 计算着色器读写 |
| `FRHISamplerState` | `RHIResources.h` | 采样器状态 | 纹理过滤/寻址 |
| `FRHIViewport` | `RHIResources.h` | 交换链 Surface | 最终呈现目标 |

**RHI 视图（View）** 与资源本身分离——同一块 `FRHITexture` 可以创建多个 SRV/UAV/RTV/DSV，决定着色器以何种方式访问它。这与本系列 [12] 篇"第三层：资源视图与绑定"完全一致。

### 2.4 资源生命周期：引用计数 + 延迟删除 + 池化

RHI 资源不靠 GC，而是**引用计数 + 延迟删除（deferred delete）**：

```cpp
// 资源销毁时机：引用计数归零后，并非立即释放
// 而是进入 RHI 线程的延迟删除队列，等 GPU 真正用完再回收
TRefCountPtr<FRHITexture> Tex = …;   // AddRef
Tex = nullptr;                        // Release → 计数归零
// → 不直接 delete，交由 FRHICommandListExecutor 在适当时机回收
```

```
资源释放时序：
  CPU: 引用计数归零 → 入延迟删除队列（不立即 free）
  RHI: 帧提交完成（Fence 确认 GPU 读完）→ 安全销毁底层句柄
        ↓
  避免"CPU 已释放，GPU 还在用"的悬垂访问
```

**池化 RHI 资源**（重要！RDG 会复用它们）：

| 池化类型 | 类名 | 含义 |
|---------|------|------|
| 池化渲染目标 | `IPooledRenderTarget` | 引用计数的池化纹理，跨帧可复用 |
| 池化缓冲 | `FRDGPooledBuffer` | 引用计数的池化缓冲（RDG 外部缓冲的载体） |

> 这两种池化资源是 RDG **外部（External）资源**的底层载体（详见 §3.8）。它们由渲染目标池/缓冲池统一管理，分配时机可控，且生命周期延伸到 RDG 图之外。

### 2.5 RHI 资源与底层 API 对象的映射

| RHI 概念 | D3D12 | Vulkan | Metal |
|---------|-------|--------|-------|
| `FRHITexture` | `ID3D12Resource`（含堆） | `VkImage` + `VmaAllocation` | `MTLTexture` |
| `FRHIBuffer` | `ID3D12Resource` | `VkBuffer` | `MTLBuffer` |
| `FRHIShaderResourceView` | `SRV`（Descriptor） | `VkImageView` + Descriptor | `MTLTextureView` |
| `FRHIUnorderedAccessView` | `UAV`（Descriptor） | Storage Descriptor | `MTLTexture`(usage) |
| `FRHIUniformBuffer` | `CBV` | `VkBuffer`（UBO） | `MTLBuffer`(uniform) |
| `FRHISamplerState` | `D3D12_SAMPLER` | `VkSampler` | `MTLSamplerState` |

## 3. RDG 资源体系：声明式帧图

### 3.1 RDG 是什么

**RDG（Render Dependency Graph）** 是 UE 每帧构建的**声明式渲染依赖图**（即本系列 [06][07] 中的 FrameGraph 在 UE 中的具体命名）。核心驱动类是 **`FRDGBuilder`**：

```
FRDGBuilder 生命周期（每帧）：
  ┌─────────────────────────────────────────────────────┐
  │  FRDGBuilder GraphBuilder(RHICmdList);               │
  │   1. CreateTexture / CreateBuffer  → 声明资源         │
  │   2. AddPass(...)                  → 声明 Pass 与依赖 │
  │   3. GraphBuilder.Execute();       → 编译+执行图      │
  │  // Execute 后，所有 FRDGTexture* 指针应视为失效       │
  └─────────────────────────────────────────────────────┘
```

> ⚠️ **单线程约束**：`FRDGBuilder` 的 API 是**单线程**的，同一时间只能有一个实例存在。延迟渲染器与移动渲染器在每个场景渲染调用中都使用单一构建器实例。

### 3.2 FRDGTexture / FRDGBuffer：仅描述符，无 GPU 内存

创建 RDG 资源时，**只分配描述符（descriptor），并不分配真实 GPU 内存**：

```cpp
// 创建 RDG 纹理（此时仅生成 FRDGTextureDesc，未触碰 GPU 内存）
FRDGTextureDesc TexDesc = FRDGTextureDesc::Create2D(
    RenderExtent, PF_FloatRGBA,
    TexCreate_RenderTargetable | TexCreate_ShaderResource);
FRDGTexture* SceneColor =
    GraphBuilder.CreateTexture(TexDesc, TEXT("SceneColor"));

// 创建 RDG 缓冲（同理，仅描述符）
FRDGBufferDesc BufDesc =
    FRDGBufferDesc::CreateBufferDesc(sizeof(FVector4), 1024);
FRDGBuffer* IndirectArgs =
    GraphBuilder.CreateBuffer(BufDesc, TEXT("IndirectArgs"));
```

```
CreateTexture/CreateBuffer 的真相：
  ┌───────────────────────┐
  │  FRDGTexture          │  ← 图构建期：只有 Desc + Name
  │   ├─ FRDGTextureDesc  │     （格式/尺寸/用途/标志）
  │   └─ Name = "..."     │
  └───────────────────────┘
         │  Execute() 时
         ▼
  ┌───────────────────────┐
  │  底层 FRHITexture*    │  ← 执行期：才真正分配/复用 RHI 资源
  │  （来自池化或瞬态分配）│
  └───────────────────────┘
```

**所有权与生命周期**：RDG 资源指针由 `GraphBuilder` 拥有；构建器销毁后指针失效，**图执行完毕后指针应为 null**。

### 3.3 视图：CreateSRV / CreateUAV

RDG 资源通过 `CreateSRV` / `CreateUAV` 创建视图（对应 RHI 的 SRV/UAV）：

```cpp
FRDGTextureSRV* SceneColorSRV = GraphBuilder.CreateSRV(SceneColor);
FRDGTextureUAV* SceneColorUAV = GraphBuilder.CreateUAV(SceneColor);
FRDGBufferSRV*  ArgsSRV       = GraphBuilder.CreateSRV(IndirectArgs);
```

| RDG 视图 | 对应 RHI 视图 | 访问方式 |
|---------|-------------|---------|
| `FRDGTextureSRV` | `FRHIShaderResourceView` | 只读采样/读取 |
| `FRDGTextureUAV` | `FRHIUnorderedAccessView` | 计算着色器读写 |
| `FRDGBufferSRV` | `FRHIShaderResourceView`（缓冲） | 只读结构化读取 |
| `FRDGBufferUAV` | `FRHIUnorderedAccessView`（缓冲） | 读写 |

### 3.4 Pass 声明与 AddPass

通过 `FRDGBuilder::AddPass` 声明一个渲染步骤，需提供：名称、参数结构体、Pass 标志、执行 Lambda。

```cpp
// 1) 用 AllocParameters 分配参数（内置线性分配器，自动管理生命周期）
FMyShaderCS::FParameters* PassParameters =
    GraphBuilder.AllocParameters<FMyShaderCS::FParameters>();

// 2) 用 RDG 专用宏声明资源依赖（SHADER_PARAMETER_RDG_TEXTURE 等）
PassParameters->InputSceneColor = SceneColor;        // 读
PassParameters->OutputUAV       = GraphBuilder.CreateUAV(Result); // 写

// 3) 添加 Pass
GraphBuilder.AddPass(
    RDG_EVENT_NAME("MyComputePass"),
    PassParameters,
    ERDGPassFlags::Compute,
    [PassParameters, ComputeShader, GroupCount]
    (FRHIComputeCommandList& RHICmdList)
    {
        FComputeShaderUtils::Dispatch(
            RHICmdList, ComputeShader, PassParameters, GroupCount);
    });
```

**Pass 标志（`ERDGPassFlags`）**：

| 标志 | 含义 | Lambda 接收 |
|------|------|-----------|
| `Compute` | 计算 Pass | `FRHIComputeCommandList&` |
| `Raster` | 光栅化 Pass | `FRHICommandList&`（自动管理 RenderPass 起止与 Load/Store） |
| `Copy` | 拷贝 Pass | `FRHICommandList&` |
| `AsyncCompute` | 异步计算（与图形队列并行） | `FRHIComputeCommandList&` |

> 光栅化 Pass 用 `RENDER_TARGET_BINDING_SLOTS()` 宏声明固定功能渲染目标，RDG **自动管理 RenderPass 的开始/结束与 Load Action**（`Load` / `Clear` / `NoAction`）——这正是本系列 [06] 篇"附件信息 + 自动屏障"的 UE 实现。

### 3.5 GetRHI() 的执行期约束 ⚠️

RDG 资源提供 `GetRHI()` 重载以获取底层 RHI 资源，但**严格限制在声明了该资源的 Pass 的执行 Lambda 中调用**：

```cpp
// ❌ 错误：在图构建时调用 → 触发验证层 assert
FRHITexture* Bad = SceneColor->GetRHI();   // 此时底层 RHI 尚未分配！

// ✅ 正确：仅在 Pass 执行 Lambda 内部调用
GraphBuilder.AddPass(
    RDG_EVENT_NAME("UseColor"),
    PassParameters, ERDGPassFlags::Compute,
    [PassParameters] (FRHIComputeCommandList& RHICmdList) {
        FRHITexture* TexRHI = PassParameters->InputSceneColor->GetRHI();
        // 此处安全：底层 RHI 已在 Execute 阶段分配
    });
```

> 调用 `SetShaderParameters` 时，所有非 null 的 RDG 参数会**自动解引用**为对应 RHI 资源并绑定到 RHI 命令列表——开发者无需手动 `GetRHI()` 再绑定。

### 3.6 资源分类：Transient（瞬态）vs External（外部）

| 特性 | 瞬态（Transient）RDG 资源 | 外部（External）RDG 资源 |
|------|--------------------------|--------------------------|
| **生命周期** | 局限于图内部，随 `Execute()` 结束 | 延伸到图之外（注册进图 / 提取出图） |
| **内存分配** | 描述符在 `Create` 时生成；RHI 内存在执行时按需分配，可能与其他瞬态资源**别名共享** | 基于引用计数的池化 RHI 资源（`IPooledRenderTarget` / `FRDGPooledBuffer`），分配时机可控 |
| **CPU 上传** | **不支持** CPU 上传（上传缓冲自动标记为非瞬态） | 支持（可 `RegisterExternal` 引入已含数据的资源） |
| **创建/引入** | `GraphBuilder.CreateTexture/CreateBuffer` | `RegisterExternalTexture`（注册进图）<br>`QueueTextureExtraction` / `ConvertToExternal`（提取出图） |

### 3.7 Transient Allocator 与别名化（Aliasing）

RDG 在图编译时使用**瞬态资源分配器（Transient Allocator）**，在执行时间线上规划分配。**生命周期不相交（disjointed lifetimes）的瞬态资源可以在内存中重叠（alias / 别名化）**：

```
无别名（各自独立分配）：
  GBuffer(100MB) ──▶ LightingOut(50MB) ──▶ BloomTemp(30MB) = 180MB

有别名（GBuffer 光照后不再被读 → BloomTemp 复用其显存）：
  GBuffer(100MB) ──┐ 生命周期结束
                   └─▶ BloomTemp 复用同一块物理显存(30MB < 100MB)
  LightingOut(50MB)
  实际显存: 100MB + 50MB = 150MB（节省 30MB）
```

> 这正是本系列 [06] 篇"资源别名复用"的 UE 落地。区别在于：默认资源池必须比较/匹配 RHI 描述符才能复用；瞬态分配器可**直接共享底层内存**，显著降低 GPU 内存水位（watermark）。

⚠️ **别名化陷阱**：使用瞬态分配器时，资源**先前内容是垃圾数据**，绝不能依赖其先前内容（资源池因复用相似资源通常会掩盖此问题）。调试时可关闭瞬态分配器排查：`r.RDG.TransientAllocator=0`。

### 3.8 外部资源桥接：Register / Extract / Convert

当资源需要跨越 RDG 图的边界时，使用以下桥接 API：

```
      图外产生，图内使用            图内产生，图外使用
   ┌──────────────────┐        ┌──────────────────────┐
   │ RegisterExternal │        │ QueueTextureExtraction│
   │  (Texture/Buffer)│        │  (Texture/Buffer)      │
   └────────┬─────────┘        └───────────┬────────────┘
            │                                │
   生命周期延长到图前端               生命周期延长到图末端
   （分配发生在图设置阶段）          （执行后用户持有指针）
```

```cpp
// 提取（图内产生，图外使用）
TRefCountPtr<IPooledRenderTarget> ExtractedSceneColor;
{
    FRDGBuilder GraphBuilder(RHICmdList);
    FRDGTexture* SceneColor = GraphBuilder.CreateTexture(Desc, TEXT("SceneColor"));
    GraphBuilder.QueueTextureExtraction(SceneColor, &ExtractedSceneColor);
    GraphBuilder.Execute();
}
// Execute 后，ExtractedSceneColor 持有池化 RHI 纹理，图外可用

// 注册（图外产生，图内使用）
{
    FRDGBuilder GraphBuilder(RHICmdList);
    FRDGTexture* SceneColor = GraphBuilder.RegisterExternalTexture(ExtractedSceneColor);
    // 在 Pass 中使用 SceneColor …
    GraphBuilder.Execute();
}
// 缓冲区同理：FRDGPooledBuffer + RegisterExternalBuffer / QueueBufferExtraction
```

**`ConvertToExternal` 替代方案**：`FRDGBuilder::ConvertToExternal{Texture, Buffer}` 立即分配底层池化资源并返回，**生命周期延至图开始**，且**不会**与帧内其他资源共享底层分配（与 `QueueTextureExtraction` 的池化共享行为不同）。

### 3.9 RDG Uniform Buffer 的当前限制（UE 5.8）⚠️

官方文档明确标注的当前主要短板：

- **不能包含 null 的资源参数**：RDG 统一缓冲区当前无法持有 null 的资源参数；
- **无反射剔除**：着色器无法反射并剔除未使用的参数，开发者必须为每组参数手动创建唯一的统一缓冲区（未来版本可能改进）。

## 4. RDG 资源与 RHI 资源的映射关系（核心）

### 4.1 时序图：从声明到落地

```
时间线 ─────────────────────────────────────────────────────────▶

[图构建期 Build]
  CreateTexture("SceneColor")  → 仅 FRDGTextureDesc（无 GPU 内存）
  AddPass("Lighting")          → 记录依赖：读 GBuffer / 写 SceneColor
  AddPass("Bloom")             → 记录依赖：读 SceneColor / 写 BloomTemp

[图编译期 Compile]
  ├─ 依赖分析 → 推导出屏障与执行顺序
  ├─ 生命周期计算 → 计算各资源首写/末读 Pass
  └─ 别名规划 → 生命周期不相交的资源共享底层内存

[图执行期 Execute]
  ├─ Transient Allocator 分配 FRHITexture*（或复用池化资源）
  ├─ 各 Pass Lambda 内：SetShaderParameters 自动解引用
  │     FRDGTexture* ──GetRHI()──▶ FRHITexture* ──▶ VkImage/ID3D12Resource
  └─ 资源屏障由 RDG 自动插入（对应本系列 [06] 自动屏障推导）
```

### 4.2 延迟绑定（Deferred Binding）

> **关键机制**：RDG 资源初始仅含 RHI 资源**描述符**；其底层 RHI 资源（`FRHITexture*`、`FRHIBuffer*`、`FRHIUnorderedAccessView*`）只有在图**执行阶段**才真正分配并绑定。所有跨 Pass 的"共享"在编译期只是逻辑引用，到执行期才解析为具体内存。

### 4.3 池化 RHI 资源作为载体

| RDG 资源形态 | 执行期底层载体 | 说明 |
|-------------|--------------|------|
| 瞬态纹理 | 瞬态分配器分配的 `FRHITexture`（帧内不留） | 不跨帧，执行完即回收 |
| 外部纹理 | `IPooledRenderTarget`（引用计数池化） | 跨帧可复用，生命周期受池管理 |
| 瞬态缓冲 | 瞬态分配器分配的 `FRHIBuffer` | 同上 |
| 外部缓冲 | `FRDGPooledBuffer`（引用计数池化） | 跨帧可复用 |

### 4.4 概念映射总表

| RDG 概念 | 底层 RHI 对象 | 本系列 FrameGraph 概念（[06]/[07]） |
|---------|--------------|--------------------------------------|
| `FRDGTexture*`（瞬态） | 执行期分配的 `FRHITexture` | `VirtualResource`（IMAGE） |
| `FRDGBuffer*`（瞬态） | 执行期分配的 `FRHIBuffer` | `VirtualResource`（BUFFER） |
| `FRDGTextureSRV/UAV` | `FRHIShaderResourceView` / `FRHIUnorderedAccessView` | 资源视图 |
| `RegisterExternalTexture` | `IPooledRenderTarget` | 跨帧持久资源声明 |
| `ConvertToExternal` | 立即分配的池化 `FRHITexture` | 资源提取出图 |
| `FRDGBuilder::AddPass` | `FRHICommandList` 录制 | Pass 声明 |
| RDG 自动屏障 | RHI 内部 `RHITransition` / 底层 Barrier | 自动屏障推导 |
| Transient Allocator 别名 | 共享 `FRHITexture` 物理内存 | 资源别名复用 |

## 5. UE 5.8 的版本背景与调试工具

### 5.1 5.8 定位

UE 5.8 于 2026 年 6 月发布，官方称为"最后一个计划中的 UE5 大版本"（随后转向 UE6）。本篇涉及的 **RDG / RHI 核心机制在 5.x 已长期稳定**，5.8 在此基础上叠加了 MegaLights（生产就绪）、Lumen Lite、Toon Shader、Movie Render Graph 等上层特性，并未对 RDG/RHI 资源模型做破坏性改动。

### 5.2 验证层与调试开关

| 工具/开关 | 作用 | 生效构建 |
|----------|------|---------|
| **Validation Layer** | 致命错误检查（如构建期误调 `GetRHI()`），Debug/Development 默认启用，Test/Shipping 编译剔除 | Debug/Development |
| `r.RDG.ImmediateMode` / `-rdgimmediate` | 绕过图编译直接执行 Pass，便于调试 | Debug/Development |
| `vis` 命令 | 把纹理 UAV/RTV 写入可视化到屏幕 | Development |
| **RDG Insights** 插件 | Unreal Insights 扩展，可视化图结构、异步计算栅栏、瞬态内存布局 | 需手动启用（Edit > Plugins > Insights），捕获用 `-trace=rdg,defaults` |
| `r.RDG.TransientAllocator` | 开启/关闭瞬态分配器（排查别名相关问题） | 全构建 |

### 5.3 内存水位与性能

瞬态分配器通过**重叠生命周期不相交的资源内存**，显著降低 GPU 内存峰值水位（watermark）。这对应本系列 [05] 篇"显存优化"与 [06] 篇"别名复用"——UE 把这套优化做成**默认开启的自动化机制**，开发者无需手动物理分配/释放瞬态资源。

## 6. 对比与坑清单（⚠️）

### 6.1 RDG vs RHI 一图速查

| 维度 | RHI 资源 | RDG 资源 |
|------|---------|---------|
| 抽象层级 | 平台抽象（贴近硬件） | 帧图调度（贴近算法） |
| 是否持有 GPU 内存 | **是**（直接封装句柄/池化引用） | **否**（仅描述符，执行期落地） |
| 生命周期 | 引用计数 + 延迟删除，可跨帧 | 瞬态（图内）或外部（跨图） |
| 典型代表 | `FRHITexture` / `FRHIBuffer` / `FRHIUniformBuffer` | `FRDGTexture` / `FRDGBuffer` |
| 池化载体 | `IPooledRenderTarget` / `FRDGPooledBuffer` | 自身无内存，借用 RHI 池 |
| 开发者直接 new？ | 平台 RHI 实现内部构造 | **禁止**——只能经 `FRDGBuilder` 创建 |

### 6.2 高频坑

> ⚠️ **坑 1 — 在图构建期调用 `GetRHI()`**：底层 RHI 尚未分配，验证层直接 assert。务必只在 Pass 执行 Lambda 内访问。

> ⚠️ **坑 2 — 依赖瞬态资源的先前内容**：瞬态分配器别名后，资源先前内容是**垃圾数据**，绝不能假设它保留了上一 Pass 的写入（除非通过外部资源/Extract 显式保留）。

> ⚠️ **坑 3 — 误以为 RDG 资源 = RHI 资源**：`FRDGTexture*` 只是图节点，跨帧复用必须走 `RegisterExternalTexture` / `QueueTextureExtraction`，否则每帧都是全新瞬态分配。

> ⚠️ **坑 4 — RDG Uniform Buffer 不可含 null 资源参数**：当前 5.8 限制，需为每组参数手动建唯一 UBO；着色器无法反射剔除未用参数。

> ⚠️ **坑 5 — 多线程构建 RDG**：`FRDGBuilder` 单线程，禁止并发 `Create/AddPass`。并行发生在 **Pass 执行期**（RDG 自动把无依赖的 Pass 并行录制到子命令列表）。

> ⚠️ **坑 6 — 上传缓冲被强制非瞬态**：CPU 上传数据到 RDG 缓冲时，该缓冲会被自动标记为非瞬态（瞬态不支持 CPU 上传），注意这会影响内存重叠策略。

## 7. 与本系列的关系与小结

| 本系列概念（[06]/[07]/[12]） | UE 5.8 对应实现 | 关系 |
|---------------------------|----------------|------|
| `VirtualResource`（虚拟句柄） | `FRDGTexture` / `FRDGBuffer` | 同一抽象：编译前用、不硬编码物理资源 |
| `PhysicalResource`（物理资源） | `FRHITexture` / `FRHIBuffer`（池化） | 编译/执行期落地 |
| 资源别名复用 | Transient Allocator 别名 | UE 默认自动化实现 |
| 自动屏障推导 | RDG 自动 `RHITransition` | 同一机制 |
| 跨帧持久资源 | `RegisterExternalTexture` / `IPooledRenderTarget` | 显式桥接 |
| 资源视图（SRV/UAV/RTV/DSV） | `FRDGTextureSRV/UAV` → RHI View | 完全一致 |

**核心结论**：

1. **RHI 是"地基"**：它封装平台差异，持有真实 GPU 内存（或池化引用），是被 RDG 复用的物理资源层。
2. **RDG 是"调度"**：它以声明式方式组织每帧 Pass 与资源依赖，本身**不分配物理内存**，执行期把虚拟资源解析为 RHI 资源，并通过瞬态分配器自动做别名复用与屏障推导。
3. **二者通过延迟绑定衔接**：`FRDGTexture*`（虚拟）→ `Execute()` 时解析为 `FRHITexture*`（物理）。
4. **UE 5.8 的 RDG/RHI 是工业级 FrameGraph 范本**，印证了本系列 [06] 的通用设计——区别仅在"UE 把它做成默认自动化机制"，而自研引擎需自行实现别名分配器与屏障推导。

> 一句话：**RHI 管理"资源是什么、存在哪"，RDG 管理"本帧谁在什么时候用、怎么复用"；RDG 资源是 RHI 资源在时间维度上的编排层。**
