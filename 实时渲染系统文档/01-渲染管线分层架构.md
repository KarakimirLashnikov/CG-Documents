# 实时渲染系统 — 渲染管线分层架构

> 本文档是「实时渲染系统」系列文档的第 **1** 篇，详细阐述三大渲染阶段的职责划分、标准 Pass 清单与阶段间的数据流转。

---

## 1. 三大渲染阶段概述

实时渲染管线的职责可以划分为**三个阶段**，每个阶段有明确的输入/输出边界与可用管线类型：

```
  场景数据                帧缓冲输出
     │                       │
     ▼                       ▼
┌──────────┐  ┌──────────┐  ┌──────────┐
│ 预处理    │─▶│ 主渲染    │─▶│ 后处理    │
│ (GPU预计算)│  │(画面基础  │  │(屏幕空间  │
│            │  │ 生成)     │  │ 合成)     │
└──────────┘  └──────────┘  └──────────┘
  计算管线     图形/Mesh/     图形/计算
  Mesh管线     光追管线       管线
```

### 阶段职责定义

| 阶段      | 职责定位               | 输入                | 输出                                  | 可用管线类型                |
| ------- | ------------------ | ----------------- | ----------------------------------- | --------------------- |
| **预处理** | GPU 预计算，为主渲染准备高效数据 | 场景可见集、材质参数        | 间接绘制命令、深度预通道、蒙皮矩阵、几何生成结果            | 计算管线、Mesh 着色图形管线      |
| **主渲染** | 画面基础内容生成，决定画面核心质量  | 预处理输出、场景光照数据      | GBuffer、ShadowMap、光照结果、透明物体、天空、运动矢量 | 标准图形管线、Mesh 管线、光线追踪管线 |
| **后处理** | 屏幕空间合成与滤波，提升最终观感   | 主渲染的 HDR 帧缓冲、运动矢量 | LDR 最终画面、UI 叠加                      | 图形管线、计算管线             |

> ⚠️ **关键纠正**：光追阴影与光追反射属于**主渲染阶段**（使用光线追踪管线），而非后处理。后处理仅负责屏幕空间滤波操作（TAA、Bloom 等）。

---

## 2. 预处理阶段详解

预处理阶段的核心目标是**将 CPU 逐物体的提交模式转化为 GPU 批量自主执行模式**。通过 GPU 预计算，为主渲染阶段生成高效的绘制指令和几何数据。

### 2.1 标准 Pass 清单

#### Pass 1: GPU 视锥与遮挡剔除（GPU Culling）

**职责**：在 GPU 上执行视锥剔除和遮挡剔除，过滤不可见物体，生成可见物体的间接绘制命令。

**工作流程**：

```
CPU 提交: 全场景物体 AABB/OBB 数据 → GPU Buffer
GPU 计算:
  1. 每个物体执行视锥六面测试
  2. 对通过视锥测试的物体执行 Hi-Z 遮挡测试
  3. 写入可见物体索引到 Indirect Draw Buffer
输出: VkDrawIndirectCommand Buffer (可见物体数量+偏移)
```

**Vulkan 落地细节**：

- 使用 **计算管线** 执行剔除 Shader
- 输入：物体 AABB 数组（Storage Buffer）、Hi-Z 深度金字塔（上一帧深度）
- 输出：间接绘制命令 Buffer（`VK_BUFFER_USAGE_INDIRECT_BUFFER_BIT`）
- 同步：计算管线完成后，图形管线消费间接绘制命令需 `vkCmdPipelineBarrier`

#### Pass 2: Depth Only 深度预通道

**职责**：提前渲染场景深度，为后续遮挡剔除提供 Hi-Z 深度金字塔源数据，同时为主渲染的 Early-Z 优化提供预填深度缓冲。

**工作流程**：

```
1. 渲染场景所有不透明物体到深度缓冲（无色彩输出）
2. 降采样深度缓冲生成 Hi-Z 深度金字塔（Mip Chain）
3. 深度金字塔用于下一帧的 GPU 遮挡剔除
```

**设计要点**：

- 深度预通道与主渲染的深度写入需保持一致性
- Hi-Z 生成使用计算管线逐级降采样（每级 2×2 深度取最大值）
- 对于移动端 TBDR 架构，深度预通道可以合并为 Subpass 0

#### Pass 3: 蒙皮/曲面/海洋几何生成

**职责**：对需要动态变形的几何体在 GPU 上预计算最终顶点位置。

**覆盖场景**：

| 几何类型 | 生成方式 | Vulkan 管线 |
|---------|---------|-------------|
| **骨骼蒙皮** | Compute Shader 逐顶点应用骨骼矩阵变换 | 计算管线 |
| **曲面细分** | TCS/TES 控制细分级别与顶点生成 | 图形管线（Tessellation） |
| **海洋波形** | Compute Shader 根据波形参数生成网格顶点 | 计算管线 |
| **粒子几何** | Compute Shader 生成粒子 Billboard 四边形顶点 | 计算管线 |

**输出**：变换后的顶点 Buffer，供主渲染阶段的图形管线直接消费。

#### Pass 4: 间接绘制命令 Buffer 生成

**职责**：汇总所有 GPU-Driven 绘制命令，生成最终的全场景间接绘制命令集。

**Buffer 结构**：

```cpp
// Vulkan 间接绘制命令结构
typedef struct VkDrawIndirectCommand {
    uint32_t vertexCount;    // 顶点数量
    uint32_t instanceCount;  // 实例数量（GPU 剔除后动态写入）
    uint32_t firstVertex;    // 起始顶点偏移
    uint32_t firstInstance;  // 起始实例偏移
} VkDrawIndirectCommand;

// Vulkan 间接索引绘制命令结构
typedef struct VkDrawIndexedIndirectCommand {
    uint32_t indexCount;
    uint32_t instanceCount;
    uint32_t firstIndex;
    int32_t  vertexOffset;
    uint32_t firstInstance;
} VkDrawIndexedIndirectCommand;
```

**GPU-Driven 全流程**：

```
CPU: 提交全场景数据 (1次) ──────────────────────────────────────▶ GPU
GPU: 剔除 ──▶ 生成间接命令 ──▶ 绘制 ──▶ 后处理 ──▶ 呈现
     (零CPU干预，全帧GPU自主执行)
```

## 3. 主渲染阶段详解

主渲染阶段是画面质量的核心决定层。它接收预处理阶段的高效绘制数据，执行所有需要 3D 场景信息的渲染操作。

### 3.1 标准 Pass 清单

#### Pass 1: GBuffer 生成

**职责**：将场景不透明物体的几何与材质属性写入多附件帧缓冲。

**标准 GBuffer 附件布局**：

| 附件 | 格式 | 内容 | 写入 Shader |
|------|------|------|-------------|
| RT0 | `VK_FORMAT_R8G8B8A8_UNORM` | 基础色 (RGB) + Alpha | Fragment Shader |
| RT1 | `VK_FORMAT_R8G8B8A8_UNORM` | 法线 (RGB) + 遮挡 (A) | Fragment Shader |
| RT2 | `VK_FORMAT_R8G8B8A8_UNORM` | 金属度 (R) + 粗糙度 (G) + AO (B) + 材质ID (A) | Fragment Shader |
| RT3 | `VK_FORMAT_R16G16_SFLOAT` | 运动矢量 (XY) | Fragment Shader |
| Depth | `VK_FORMAT_D32_SFLOAT` | 深度值 | Fragment Shader (内置) |

> **带宽优化**：ORM 三通道合并（金属度+粗糙度+AO 打包到同一纹理通道），法线使用八面体编码压缩为 2 通道。

#### Pass 2: ShadowMap / 光追阴影

**职责**：为场景光源生成阴影信息。

**光栅阴影（ShadowMap）**：

- 每个需要阴影的光源渲染一次深度
- 级联阴影（CSM）用于方向光源
- 点光源使用 Omni-Directional ShadowMap（深度立方体）

**光追阴影（Ray Traced Shadows）**：

- 使用光线追踪管线从光源发射射线
- 优势：自然软阴影、无 ShadowMap 分辨率限制、无 ShadowMap 伪影
- 需配合降噪（NRD / AI 降噪器）

> ⚠️ **归类纠正**：光追阴影使用 `VK_PIPELINE_BIND_POINT_RAY_TRACING_KHR`，属于**主渲染阶段**，不是后处理。

#### Pass 3: SSR / 光追反射

**职责**：为场景反射表面生成反射信息。

**屏幕空间反射（SSR）**：

- 从 GBuffer 深度/法线出发，在屏幕空间沿反射方向 Ray March
- 优势：低成本、兼容光栅管线
- 限制：仅能反射屏幕内可见内容

**光追反射（Ray Traced Reflections）**：

- 使用光线追踪管线从反射表面发射反射射线
- 优势：可反射屏幕外内容、精确物理反射
- 需配合降噪与空间滤波

#### Pass 4: 光照计算

**职责**：利用 GBuffer 与阴影/反射数据，计算场景最终光照。

**光照计算模式取决于架构选型**：

| 渲染架构 | 光照计算方式 | 依赖数据 |
|---------|-------------|---------|
| Deferred | 全屏 Pass 逐像素从 GBuffer 读取参数计算光照 | GBuffer + ShadowMap |
| Forward+ | 分簇光照数据上传，逐物体在 Fragment Shader 中计算 | Cluster 光照网格 |
| Clustered Deferred | 分簇光照网格 + GBuffer 联合计算 | GBuffer + Cluster |
| Visibility Buffer | 逐像素从 VisBuffer 取材质 ID，动态采样材质纹理计算 | VisBuffer + 材质索引 |

#### Pass 5: 透明物体渲染

**职责**：渲染半透明/透明物体（玻璃、水面、粒子等）。

**标准方案**：Depth-Prepass + 两遍 Alpha-To-Coverage / OIT

**进阶方案**：

- **加权混合 OIT（Weighted Blended OIT）**：一次渲染无需排序，近似正确混合
- **深度剥离（Depth Peeling）**：多 Pass 逐层剥离获取正确排序
- **光追透明**：光线追踪直接处理透射/折射

#### Pass 6: 天空与大气

**职责**：渲染天空穹顶、大气散射、云层。

**方案选型**：

- **预计算大气散射**：LUT 表预计算 Rayleigh/Mie 散射，运行时采样
- **实时 Ray Marching**：体积云/雾沿视线方向步进积分
- **光追大气**：光线追踪路径积分精确散射

#### Pass 7: 粒子系统

**职责**：渲染各类粒子效果（火焰、烟雾、魔法特效等）。

**GPU-Driven 粒子**：

- Compute Shader 管理粒子生命周期、物理模拟
- 生成 Billboard 顶点 → 间接绘制
- 支持百万级粒子密度

#### Pass 8: 运动矢量输出

**职责**：为后处理阶段的 TAA/运动模糊提供逐像素运动矢量。

**生成方式**：

- 不透明物体：GBuffer Pass 同时输出当前帧与前一帧的投影坐标差
- 透明物体：单独 Pass 输出运动矢量
- 动态物体：使用物体 ID 在运动矢量 Buffer 中写入专属矢量

## 4. 后处理阶段详解

后处理阶段在屏幕空间对主渲染输出的 HDR 帧缓冲进行滤波与合成，最终生成呈现到交换链的 LDR 画面。

### 4.1 标准 Pass 清单

#### Pass 1: 时域抗锯齿（TAA）

**职责**：利用历史帧信息消除渲染锯齿。

**核心原理**：

```
当前帧: 像素颜色 C_curr
历史帧: 像素颜色 C_hist (通过运动矢量回溯定位)
输出:   C_out = blend(C_curr, C_hist, weight)
```

**关键步骤**：

1. 运动矢量回溯：找到当前像素在历史帧中的对应位置
2. 颜色裁剪（Color Clipping/Variance Clipping）：防止历史帧颜色溢出当前帧邻域色域
3. 加权混合：通常权重 0.1~0.2 偏向当前帧

**Vulkan 落地**：

- 输入：当前帧 HDR 颜色 + 历史帧颜色 + 运动矢量
- 输出：TAA 后颜色 + 更新的历史帧颜色（供下一帧使用）
- 使用 `VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL` 读取历史帧

#### Pass 2: 超分辨率（FSR / DLSS / XeSS）

**职责**：以低分辨率渲染，通过 AI/算法超分到目标分辨率，大幅降低渲染开销。

**方案对比**：

| 方案 | 技术 | 依赖 | 质量 | 适用平台 |
|------|------|------|------|---------|
| FSR 1.0 | 空域上采样 + 边缘自适应 | 无 | 中 | 全平台 |
| FSR 2.0 | 时域超分 + 运动矢量 | 运动矢量 | 高 | 全平台 |
| DLSS | AI 时域超分 | NVIDIA Tensor Core | 极高 | NVIDIA 仅限 |
| XeSS | AI 时域超分 | Intel XMX / DP4a | 高 | Intel / 跨平台 |

#### Pass 3: 色调映射（Tone Mapping）

**职责**：将 HDR 高动态范围颜色映射到 LDR 显示范围。

**标准映射曲线**：

| 映射方式 | 特性 | 适用场景 |
|---------|------|---------|
| Reinhard | 简单压缩，低对比度 | 基础方案 |
| ACES Filmic | 电影级曲线，高对比度保留 | 通用推荐 |
| AgX | 数据可视化风格，中性映射 | 技术视觉 |
| HTC (Hejl Burgess) | 高光保留、暗部提亮 | HDR 显示器 |

#### Pass 4: Bloom

**职责**：模拟高光溢出的辉光效果。

**实现流程**：

```
1. 预过滤：提取亮度超过阈值的像素
2. 迭代降采样：逐级 2×2 降采样（通常 5~6 级）
3. 迭代上采样：逐级上采样合并，形成柔和辉光
4. 合成：叠加到色调映射后的画面
```

#### Pass 5: 景深（DOF）

**职责**：模拟相机光学景深效果，聚焦区域清晰，远离焦平面模糊。

**实现方式**：

- 散景 DOF（Bokeh DOF）：模拟光圈形状产生散景效果
- 优化：利用 Coc（Circle of Confusion）半径逐像素控制模糊强度

#### Pass 6: 运动模糊

**职责**：模拟高速运动物体的视觉模糊。

**两种方案**：

| 方案 | 原理 | 质量 | 开销 |
|------|------|------|------|
| 后处理运动模糊 | 沿运动矢量方向模糊 | 中 | 低 |
| Object-Based 运动模糊 | 物体在多子帧间渲染混合 | 高 | 高 |

#### Pass 7: 色彩调色（Color Grading）

**职责**：美术后期调色，控制画面色调与氛围。

**实现方式**：

- LUT（3D Lookup Table）：离线预计算色彩映射表，运行时 3D 纹理采样
- 实时参数调整：亮度/对比度/饱和度/色温等

#### Pass 8: UI 渲染

**职责**：叠加 HUD、菜单、文字等 UI 元素。

**实现方式**：

- 独立图形管线 Pass，覆盖在最上层
- UI 材质使用 Alpha Blend 或 Alpha-To-Coverage
- 分离 UI 渲染可以避免 TAA 对 UI 的错误混合

## 5. 各阶段间的数据流转

完整的帧渲染数据流向：

```
┌──────────────────── 预处理阶段 ────────────────────┐
│                                                     │
│  场景数据 ──▶ GPU剔除 ──▶ 间接绘制命令               │
│              Hi-Z生成 ──▶ 深度金字塔                 │
│              蒙皮Compute ──▶ 变换顶点Buffer           │
│              几何生成 ──▶ 海洋/曲面顶点               │
│                                                     │
└──────────┬──────────────────────────────────────────┘
           │  间接命令 + 变换顶点 + 深度金字塔
           ▼
┌──────────────────── 主渲染阶段 ────────────────────┐
│                                                     │
│  间接绘制命令 ──▶ GBuffer Pass ──▶ GBuffer 附件集   │
│  光源数据 ──▶ ShadowMap/光追阴影 ──▶ 阴影纹理        │
│  GBuffer+阴影 ──▶ 光照计算 ──▶ HDR光照结果           │
│  ──▶ SSR/光追反射 ──▶ 反射结果                       │
│  ──▶ 透明物体 ──▶ 透明层                              │
│  ──▶ 天空/粒子 ──▶ 大气/特效                          │
│  ──▶ 运动矢量 ──▶ Motion Vector Buffer               │
│                                                     │
│  输出: HDR帧缓冲 + 运动矢量 + 历史帧引用             │
└──────────┬──────────────────────────────────────────┘
           │  HDR帧缓冲 + 运动矢量
           ▼
┌──────────────────── 后处理阶段 ────────────────────┐
│                                                     │
│  HDR ──▶ TAA ──▶ 抗锯齿后HDR                        │
│  ──▶ 超分 ──▶ 目标分辨率HDR                          │
│  ──▶ 色调映射 ──▶ LDR画面                            │
│  ──▶ Bloom ──▶ 辉光叠加                              │
│  ──▶ DOF/运动模糊 ──▶ 特效叠加                       │
│  ──▶ 色彩调色 ──▶ 最终画面                           │
│  ──▶ UI ──▶ 呈现到Swapchain                         │
│                                                     │
└─────────────────────────────────────────────────────┘
```

### 关键数据接口

| 接口名 | 生产者 | 消费者 | 格式 | 生命周期 |
|--------|--------|--------|------|---------|
| 间接绘制命令 Buffer | 预处理·剔除 | 主渲染·GBuffer | `VK_BUFFER_USAGE_INDIRECT_BUFFER_BIT` | 单帧 |
| Hi-Z 深度金字塔 | 预处理·Depth Only | 预处理·剔除（下一帧） | 深度纹理 Mip Chain | 跨帧 |
| GBuffer 附件集 | 主渲染·GBuffer | 主渲染·光照 + 后处理 | 多附件帧缓冲 | 单帧 |
| ShadowMap | 主渲染·阴影 | 主渲染·光照 | 深度纹理 | 单帧 |
| 运动矢量 | 主渲染·GBuffer | 后处理·TAA/超分/运动模糊 | `R16G16_SFLOAT` | 单帧 |
| HDR 帧缓冲 | 主渲染·光照 | 后处理全链路 | `R16G16B16A16_SFLOAT` | 单帧 |
| 历史帧颜色 | 后处理·TAA（上一帧） | 后处理·TAA（当前帧） | 纹理 | 跨帧 |
| 最终 LDR 画面 | 后处理·调色 | 后处理·UI → Swapchain | `R8G8B8A8_UNORM` | 单帧 |

## 6. Pass 与 Vulkan 管线类型的对应总结

| Pass 名称 | 所属阶段 | Vulkan 管线类型 | 备注 |
|-----------|---------|----------------|------|
| GPU 视锥/遮挡剔除 | 预处理 | 计算管线 | Write 间接命令 Buffer |
| Hi-Z 深度金字塔 | 预处理 | 计算管线 | 逐级降采样深度 |
| Depth Only 预通道 | 预处理 | 图形管线 | 无色彩附件 |
| 蒙皮矩阵变换 | 预处理 | 计算管线 | 输出变换顶点 |
| GBuffer | 主渲染 | 图形管线 / Mesh 管线 | 多附件渲染 |
| ShadowMap | 主渲染 | 图形管线 | 光栅阴影 |
| 光追阴影 | 主渲染 | 光线追踪管线 | 需加速结构 |
| SSR | 主渲染 | 计算管线 | 屏幕空间 Ray March |
