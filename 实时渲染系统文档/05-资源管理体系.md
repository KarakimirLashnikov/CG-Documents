## 2. CPU 端资源管理

### 2.1 加载调度系统

#### LRU 缓存策略

最近最少使用（LRU）缓存管理已加载资源，避免重复加载与内存膨胀：

```cpp
template<typename Key, typename Resource>
class LRUCache {
    size_t maxCapacity;
    std::list<std::pair<Key, std::shared_ptr<Resource>>> usageList;
    std::unordered_map<Key, typename std::list<...>::iterator> lookupMap;

public:
    std::shared_ptr<Resource> Get(const Key& key) {
        if (auto it = lookupMap.find(key); it != lookupMap.end()) {
            // 命中: 移到链表前端(最近使用)
            usageList.splice(usageList.begin(), usageList, it->second);
            return it->second->second;
        }
        return nullptr;  // 未命中: 需加载
    }

    void Put(const Key& key, std::shared_ptr<Resource> resource) {
        if (lookupMap.size() >= maxCapacity) {
            // 淘汰: 移除链表尾部(最久未使用)
            auto last = usageList.back();
            lookupMap.erase(last.first);
            usageList.pop_back();
        }
        usageList.push_front({key, resource});
        lookupMap[key] = usageList.begin();
    }
};
```

**缓存层级**：

| 层级 | 存储位置 | 容量 | 响应速度 | 更新频率 |
|------|---------|------|---------|---------|
| L0: 热资源 | GPU Device Local | 受限 | 最快 | 常驻 |
| L1: 活跃缓存 | CPU RAM (LRU) | 中等 | 快 | 动态 |
| L2: 冷缓存 | 磁盘/SSD | 大 | 慢 | 低频 |

#### 大世界流式加载

大世界场景需要**流式加载（Streaming）**，仅加载玩家周围区域的资源：

```
玩家位置 ──▶ 计算加载区域 (周围N个Chunk)
──▶ 检查当前已加载Chunk列表
──▶ 加载新进入区域的Chunk (异步IO)
──▶ 驱逐离开区域的Chunk (LRU淘汰)
──▶ GPU资源异步上传 (Staging Buffer DMA)
```

**流式加载关键机制**：

1. **Chunk 划分**：世界按空间划分为固定大小的 Chunk，每个 Chunk 包含网格/纹理/光照数据
2. **优先级调度**：近处 Chunk 优先加载，远处 Chunk 降级/驱逐
3. **异步加载线程**：独立 IO 线程加载资源，不阻塞渲染主线程
4. **渐进呈现**：资源逐步上传到 GPU，低品质先行呈现，高品质后续替换

#### 虚拟资源句柄

上层代码通过**虚拟资源句柄（Virtual Resource Handle）**引用资源，无需关心实际加载状态：

```cpp
class VirtualResourceHandle {
    ResourceID id;
    ResourceState state;  // LOADING / READY / EVICTED / FAILED

public:
    bool IsReady() const { return state == ResourceState::READY; }

    // 透明异步加载: 上层首次使用时触发加载
    GPUResource* Get() {
        if (state == ResourceState::EVICTED) {
            RequestReload(id);  // 异步请求重新加载
            return fallbackResource;  // 返回占位资源
        }
        if (state == ResourceState::LOADING) {
            return fallbackResource;  // 返回占位资源
        }
        return actualResource;  // 返回真实资源
    }
};
```

**设计原则**：上层代码**永远不等待**资源加载，始终有 fallback 可用。

### 2.2 内存池化分配器

避免频繁 `malloc/free` 导致的内存碎片与分配延迟：

```cpp
class PoolAllocator {
    size_t blockSize;
    size_t poolSize;
    std::vector<void*> freeBlocks;
    void* poolBase;

public:
    void* Allocate() {
        if (freeBlocks.empty()) {
            // 扩展池或返回nullptr
            return ExpandPool();
        }
        void* block = freeBlocks.back();
        freeBlocks.pop_back();
        return block;
    }

    void Free(void* block) {
        freeBlocks.push_back(block);  // 归还到池，不真正释放
    }
};

// 按资源类型分池
PoolAllocator meshPool(4 * 1024 * 1024);    // 4MB网格池
PoolAllocator texturePool(64 * 1024 * 1024); // 64MB纹理池
PoolAllocator shaderPool(1 * 1024 * 1024);   // 1MB着色器池
```

**空闲链表（Free List）**：

```cpp
class FreeListAllocator {
    struct Block {
        size_t offset;
        size_t size;
        Block* next;
    };

    Block* freeListHead;  // 空闲块链表

    void* Allocate(size_t size) {
        // 最佳适配: 找最接近请求大小的空闲块
        Block* best = FindBestFit(size);
        if (!best) return nullptr;

        // 分割空闲块
        if (best->size > size + MIN_BLOCK_SIZE) {
            Block* remainder = new Block{best->offset + size, best->size - size, best->next};
            best->size = size;
            best->next = remainder;
        }
        return poolBase + best->offset;
    }
};
```

## 3. GPU 端显存管理

### 3.1 VMA 显存分配器

**Vulkan Memory Allocator (VMA)** 是 Vulkan 显存管理的标准开源库：

```cpp
// 初始化 VMA
VmaAllocatorCreateInfo allocatorInfo = {};
allocatorInfo.instance = instance;
allocatorInfo.physicalDevice = physicalDevice;
allocatorInfo.device = device;
allocatorInfo.vulkanApiVersion = VK_API_VERSION_1_3;

VmaAllocator allocator;
vmaCreateAllocator(&allocatorInfo, &allocator);

// Buffer分配示例: 优先DEVICE_LOCAL
VkBufferCreateInfo bufferInfo = {};
bufferInfo.sType = VK_STRUCTURE_TYPE_BUFFER_CREATE_INFO;
bufferInfo.size = 1024 * 1024;  // 1MB
bufferInfo.usage = VK_BUFFER_USAGE_VERTEX_BUFFER_BIT |
                  VK_BUFFER_USAGE_STORAGE_BUFFER_BIT;

VmaAllocationCreateInfo allocInfo = {};
allocInfo.usage = VMA_MEMORY_USAGE_AUTO_PREFER_DEVICE;  // 优先设备本地
allocInfo.flags = VMA_ALLOCATION_CREATE_DEDICATED_MEMORY_BIT;  // 独立分配(大Buffer)

VmaAllocation allocation;
VkBuffer buffer;
vmaCreateBuffer(allocator, &bufferInfo, &allocInfo, &buffer, &allocation, nullptr);
```

**VMA 内存类型选择策略**：

| 用途 | VMA_USAGE | 说明 | 典型资源 |
|------|-----------|------|---------|
| GPU专用读写 | `AUTO_PREFER_DEVICE` | DEVICE_LOCAL显存，CPU不可直接访问 | 顶点/索引Buffer、RT纹理 |
| CPU→GPU上传 | `AUTO_PREFER_HOST` | HOST_VISIBLE内存，可映射写入 | Staging上传Buffer |
| CPU频繁更新 | `CPU_TO_GPU` | HOST_VISIBLE+CACHED | Dynamic UBO、每帧更新Buffer |
| GPU→CPU回读 | `GPU_TO_CPU` | HOST_VISIBLE+COHERENT | GPU剔除结果回读、查询结果 |

### 3.2 环形 Staging Buffer DMA 传输

批量上传资源到 GPU，避免逐资源同步等待：

```cpp
class RingStagingBuffer {
    VkBuffer stagingBuffer;
    VmaAllocation stagingAllocation;
    size_t bufferSize;      // 总大小 (如 256MB)
    size_t currentOffset;   // 当前写入偏移
    size_t alignment;       // 对齐要求 (通常256字节)

    // 帧轮转: 每帧有自己的偏移区间
    struct FrameRegion {
        size_t startOffset;
        size_t size;
        VkFence completionFence;  // GPU完成后才能回收
    };
    std::deque<FrameRegion> pendingRegions;  // 待GPU确认的传输区域

public:
    // 上传一段数据到Staging Buffer
    UploadResult Upload(const void* data, size_t dataSize) {
        size_t alignedSize = ALIGN_UP(dataSize, alignment);

        // 检查剩余空间
        if (currentOffset + alignedSize > bufferSize) {
            // 回收已完成的帧区域
            RecycleCompletedRegions();
            if (currentOffset + alignedSize > bufferSize) {
                return UploadResult::NO_SPACE;  // 需等待
            }
        }

        // 映射写入
        void* mapped = vmaMapMemory(allocator, stagingAllocation);
        memcpy((uint8_t*)mapped + currentOffset, data, dataSize);
        vmaUnmapMemory(allocator, stagingAllocation);

        // 记录传输命令
        VkBufferCopy copyRegion = {currentOffset, 0, dataSize};
        vkCmdCopyBuffer(cmdBuffer, stagingBuffer, destBuffer, 1, &copyRegion);

        UploadResult result = {currentOffset, alignedSize};
        currentOffset += alignedSize;
        return result;
    }
};
```

**DMA传输优化**：

- 批量传输：一帧内所有上传合并到同一 Staging Buffer
- 帧轮转：3帧缓冲，确保 GPU 完成后才回收 Staging 空间
- 异步传输：利用 Transfer Queue 独立于 Graphics Queue 执行上传

### 3.3 纹理压缩

| 格式 | 压缩比 | 块大小 | 适用平台 | 色彩质量 |
|------|--------|--------|---------|---------|
| BC1 (DXT1) | 6:1 | 4×4像素 | PC/Xbox | 低(1bit alpha) |
| BC3 (DXT5) | 4:1 | 4×4像素 | PC/Xbox | 高(8bit alpha) |
| BC5 | 4:1 | 4×4像素 | PC | 法线/双通道 |
| BC7 | 3:1~4:1 | 4×4像素 | PC/Xbox | 极高(灵活alpha) |
| ASTC 4×4 | 8:1 | 4×4像素 | **移动端** | 高 |
| ASTC 8×8 | 16:1 | 8×8像素 | **移动端** | 中 |
| ASTC 6×6 | 12:1 | 6×6像素 | **移动端** | 平衡 |

**纹理压缩选择原则**：

- PC端：BCn 系列（BC7 高质量、BC5 法线、BC3 带Alpha）
- 移动端：ASTC 系列（6×6 平衡质量/带宽、4×4 高质量、8×8 极低带宽）
- 不使用未压缩格式（RGBA32 占 4字节/像素 vs BC1 占 0.5字节/像素）

### 3.4 显存优化方案

#### 稀疏绑定（Virtual Texture / Sparse Binding）

`VK_EXT_sparse_binding` 实现虚拟纹理分页加载，仅驻留当前需要的 Mip 页面：

```
完整纹理 (2048×2048, 8级Mip):
  总显存占用: 2048²×4 = 16MB (全部驻留)

虚拟纹理分页加载 (仅加载可见区域):
  当前可见: Mip 0~3 的部分页面 + Mip 4~7 (完整低分辨率)
  实际驻留: ~2MB (节省87.5%显存)
```

```cpp
// 稀疏绑定纹理创建
VkImageCreateInfo imageInfo = {};
imageInfo.flags = VK_IMAGE_CREATE_SPARSE_BINDING_BIT |
                 VK_IMAGE_CREATE_SPARSE_RESIDENCY_BIT;
imageInfo.extent = {2048, 2048, 1};
imageInfo.mipLevels = 8;
imageInfo.format = VK_FORMAT_R8G8B8A8_UNORM;

VkImage sparseImage;
vkCreateImage(device, &imageInfo, nullptr, &sparseImage);

// 计算稀疏页面要求
VkSparseImageMemoryRequirements sparseReq;
vkGetImageSparseMemoryRequirements(device, sparseImage, 1, &sparseReq);

// 仅绑定需要的页面
VkSparseImageMemoryBind imageBinds[] = {
    {  // 绑定可见区域的Mip 0页面
        .subresource = {VK_IMAGE_ASPECT_COLOR_BIT, 0, 0, visiblePageOffset},
        .memory = pageMemory,
        .memoryOffset = 0,
        .flags = 0
    },
};
vkQueueBindSparse(sparseQueue, 1, &bindInfo, fence);
```

#### 热点数据压缩

减少 GBuffer 和常用数据的带宽占用：

**八面体法线编码**：将 3 通道法线压缩为 2 通道：

```glsl
// 八面体法线编码 (3通道→2通道)
vec2 OctahedralEncode(vec3 normal) {
    // 投射到八面体平面
    vec2 p = normal.xy / (abs(normal.x) + abs(normal.y) + abs(normal.z));
    // 负半球映射到正半球外围
    p = (normal.z < 0.0) ? ((1.0 - abs(p.yx)) * sign(p) * (1.0 - step(0.0, p))) : p;
    return p;
}

vec3 OctahedralDecode(vec2 encoded) {
    vec3 normal = vec3(encoded, 1.0 - abs(encoded.x) - abs(encoded.y));
    if (normal.z < 0.0) {
        normal.xy = (1.0 - abs(normal.yx)) * sign(normal.xy) * (1.0 - step(0.0, normal.xy));
    }
    return normalize(normal);
}
```

**ORM 三通道合并纹理**：将 Occlusion + Roughness + Metallic 合并到单一纹理的 RGB 通道：

```
原始: 3张独立纹理 × R8格式 × 每像素1字节 = 3字节/像素
合并: 1张ORM纹理 × R8G8B8格式 × 每像素3字节 = 3字节/像素
收益: 3次纹理采样 → 1次纹理采样 (带宽减少2/3采样开销)
```

**Bindless 索引分配器**：

```cpp
class BindlessResourceManager {
    // 全局描述符集
    VkDescriptorSet bindlessSet;

    // 索引分配
    FreeList textureIndexPool;     // 纹理索引池
    FreeList bufferIndexPool;      // Buffer索引池

    // 延迟释放队列
    struct PendingFree {
        uint32_t index;
        ResourceType type;
        uint64_t frameIndex;  // 安全回收帧号
    };
    std::vector<PendingFree> pendingFreeQueue;

public:
    uint32_t RegisterTexture(VkImageView view, VkSampler sampler) {
        uint32_t index = textureIndexPool.Allocate();

        // 更新描述符集
        VkDescriptorImageInfo imageInfo = {sampler, view, VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL};
        VkWriteDescriptorSet write = {};
        write.sType = VK_STRUCTURE_TYPE_WRITE_DESCRIPTOR_SET;
        write.dstSet = bindlessSet;
        write.dstBinding = 0;
        write.dstArrayElement = index;
        write.descriptorCount = 1;
        write.descriptorType = VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER;
        write.pImageInfo = &imageInfo;
        vkUpdateDescriptorSets(device, 1, &write, 0, nullptr);

        return index;
    }

    void UnregisterTexture(uint32_t index) {
        // 延迟释放: 不立即回收，等GPU帧完成
        pendingFreeQueue.push_back({index, ResourceType::TEXTURE, currentFrameIndex + FRAME_LATENCY});
    }

    void ProcessPendingFree(uint64_t completedFrame) {
        for (auto& pending : pendingFreeQueue) {
            if (pending.frameIndex <= completedFrame) {
                textureIndexPool.Free(pending.index);
            }
        }
        // 清除已处理项
        pendingFreeQueue.erase(/*completed items*/);
    }
};
```

## 4. 运行时资源生命周期规则

### 4.1 描述符池管理

**策略：每帧重置描述符池**

```cpp
// 帧开始: 重置描述符池
vkResetDescriptorPool(device, frameDescriptorPool, 0);

// 帧内: 动态分配描述符集
VkDescriptorSetAllocateInfo allocInfo = {};
allocInfo.descriptorPool = frameDescriptorPool;
allocInfo.descriptorSetCount = 1;
allocInfo.pSetLayouts = &passSetLayout;

VkDescriptorSet passSet;
vkAllocateDescriptorSets(device, &allocInfo, &passSet);

// 帧结束: 整池重置回收所有描述符集
// 不需要逐个vkFreeDescriptorSets，整池重置更高效
```

**为什么每帧重置**：

- 避免描述符池碎片化（逐个释放导致池内空洞）
- 零逐个释放开销（一次重置回收全帧所有描述符）
- 保证每帧描述符集数量可控

### 4.2 命令池循环复用

```cpp
// N帧轮转命令池 (通常N=2或3)
struct FrameContext {
    VkCommandPool commandPool;
    VkCommandBuffer commandBuffer;
    VkFence submissionFence;
    // ... 其他帧级资源
};

FrameContext frameContexts[FRAME_LATENCY_COUNT];

// 帧开始: 重置当前帧的命令池
vkResetCommandPool(device, frameContexts[currentFrameIndex].commandPool,
                   VK_COMMAND_POOL_RESET_RELEASE_RESOURCES_BIT);

// 从命令池分配命令缓冲
VkCommandBufferBeginInfo beginInfo = {};
beginInfo.flags = VK_COMMAND_BUFFER_USAGE_ONE_TIME_SUBMIT_BIT;
vkBeginCommandBuffer(frameContexts[currentFrameIndex].commandBuffer, &beginInfo);
```

### 4.3 延迟释放队列

GPU 帧完成前不能回收正在使用的显存资源：

```
帧 0: 提交渲染命令 → 资源A被GPU使用
帧 1: CPU发现资源A不再需要 → 加入延迟释放队列(安全回收帧号=帧0完成+2)
帧 2: GPU确认帧0完成 → 安全回收资源A
```

```cpp
class DeferredReleaseQueue {
    struct ReleaseEntry {
        VkBuffer buffer;        // 或 VkImage
        VmaAllocation allocation;
        uint32_t bindlessIndex; // Bindless索引回收
        uint64_t safeFrame;     // 安全回收帧号
    };

    std::deque<ReleaseEntry> queue;
    uint64_t currentFrame = 0;

public:
    void Enqueue(VkBuffer buffer, VmaAllocation allocation, uint32_t bindlessIndex) {
        queue.push_back({
            buffer, allocation, bindlessIndex,
            currentFrame + FRAME_LATENCY  // 当前帧+延迟帧数
        });
    }

    void ProcessCompleted(uint64_t completedFrame) {
        while (!queue.empty() && queue.front().safeFrame <= completedFrame) {
            auto& entry = queue.front();
            vmaDestroyBuffer(allocator, entry.buffer, entry.allocation);
            bindlessManager.FreeIndex(entry.bindlessIndex);
            queue.pop_front();
        }
    }
};
```

### 4.4 环形缓冲（Ring Buffer）

Per-frame 动态 Uniform 数据使用环形缓冲复用内存块：

```cpp
class RingUniformBuffer {
    VkBuffer ringBuffer;
    VmaAllocation ringAllocation;
    size_t bufferSize;          // 总大小 (如 16MB)
    size_t currentOffset;       // 当前帧写入偏移
    size_t frameSize;           // 每帧最大消耗

    struct FrameSegment {
        size_t startOffset;
        size_t size;
        uint64_t frameIndex;
    };
    std::deque<FrameSegment> activeSegments;

public:
    uint32_t AllocatePerFrameUniform(size_t dataSize) {
        size_t alignedSize = ALIGN_UP(dataSize, minUboAlignment);

        // 回收已完成的帧段
        RecycleCompletedSegments();

        if (currentOffset + alignedSize > bufferSize) {
            currentOffset = 0;  // 绕回开头（所有帧段已完成）
        }

        uint32_t offset = currentOffset;
        activeSegments.push_back({offset, alignedSize, currentFrameIndex});
        currentOffset += alignedSize;
        return offset;  // 作为Dynamic UBO偏移使用
    }
};
```
