# 实时渲染系统 — 整体架构与工作流总览

> 本文档是「实时渲染系统」系列文档的第 **9** 篇（终篇），提供全链路数据流、模块协作与执行流程的全景视图，将前 8 篇文档的专题内容整合为完整的系统运作图景。

---

## 1. 整体架构总流程

从引擎层到执行层的完整渲染流程：

```
引擎层（渲染架构选型 → 材质/光照模型确定）
    │
    │ 场景数据 + 画质配置 + 硬件能力
    ▼
渲染核心层（FrameGraph 声明式 Pass 管理）
    ├─ 资源子系统（CPU 加载 + VMA 显存分配 + Bindless 全局资源）
    ├─ 管线子系统（图形/计算/Mesh/光追管线缓存）
    └─ 同步子系统（自动屏障、多队列并行、帧延迟释放）
    │
    │ 编译后的执行计划 + 物理资源映射
    ▼
执行层（多线程录制 CommandBuffer → GPU 队列提交 → 交换链呈现）
```

│                                                                  │
│  ┌─ Step 8: GPU执行 ────────────────────────────────────────┐  │

│  │  ├─ 预处理: GPU剔除 → HiZ生成 → 蒙皮 → 间接命令生成       │  │

│                                                                  │

│  │  ├─ Swapchain呈现 (vkQueuePresentKHR)                      │  │
│  │  ├─ 更新历史帧资源 (TAA历史帧交换)                          │  │
│  │  ├─ 记录延迟释放请求 (当前帧不再需要的资源)                 │  │
│  │  ├─ 更新帧计数器                                            │  │
│  │  └─ 返回Step 1 (下一帧)                                    │  │
│  │  模块: 执行层(呈现) + 资源子系统(帧延迟回收)               │  │
│  └───────────────────────────────────────────────────────────┘  │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

## 5. 多队列并行执行时序图

```
时间 ──────────────────────────────────────────────────────────────────▶

Transfer Queue:
  ├─ 资源上传DMA ─┤                  ├─ 下一帧资源上传 ─┤
  └─ AS构建      ─┤                  ├─ AS增量更新     ─┤
                  │ Signal(sem_t1)    │ Signal(sem_t2)

Compute Queue:
  ├─ GPU剔除 ─────┤ ├─ HiZ ─┤ ├─ SSR ─┤ ├─ Bloom降采样 ─┤
  │ Wait(sem_t1)  │ Signal(sem_c1) │ Signal(sem_c2) │

Graphics Queue:
  │ Wait(sem_c1)  │ ├─ GBuffer ─┤ ├─ Shadow ─┤ ├─ Lighting ─┤ Wait(sem_c2) │ ├─ TAA ─┤ ├─ 合成 ─┤
                  │              │           │             │               │          │
Present Queue:
                  │              │           │             │               │          ├─ Present ─┤
                  │              │           │             │               │          │
Fence:           │              │           │             │               │          │ Signal(fN)

Timeline Semaphores:
  sem_t1: ──── Signal ───────────────────────────────────────────────────
  sem_c1: ──────────── Signal ──────────────────────────────────────────
  sem_c2: ──────────────────────────────── Signal ──────────────────────
  fenceN: ──────────────────────────────────────────── Signal ──────────

关键同步点:
  ① Compute Wait(sem_t1): 资源上传完成后开始GPU剔除
  ② Graphics Wait(sem_c1): GPU剔除完成后开始GBuffer渲染
  ③ Graphics Wait(sem_c2): SSR完成后合成反射
  ④ Present: 全Pass完成后呈现
  ⑤ Fence(fN): GPU确认帧完成 → CPU可回收资源
```

## 6. 系统关键设计决策总结

| 决策维度 | 推荐方案 | 核心理由 |
|---------|---------|---------|
| **渲染架构** | Clustered Deferred + 混合RT | 大量光源+屏幕空间效果+光追质量增强 |
| **Pass管理** | FrameGraph声明式帧图 | 自动依赖编排+资源优化+消除手动屏障 |
| **资源管理** | VMA + Bindless + 延迟释放 | 显存高效+零逐绑定开销+安全回收 |
| **绘制优化** | GPU-Driven + MDI + Bindless | CPU仅3次API调用+GPU自主全流程 |
| **帧轮转** | 2~3帧延迟缓冲 | GPU完成前不回收资源+环形Buffer复用 |
| **同步机制** | Timeline Semaphore + Fence | 多队列精确同步+帧完成确认 |
| **纹理压缩** | PC: BC7, 移动: ASTC 6×6 | 硬件压缩减少带宽75%~87% |
| **Shader变体** | 离线编译+PipelineCache+反射 | 避免运行时编译+自动绑定代码生成 |

## 7. 系统边界与扩展接口

### 7.1 与引擎其他子系统的接口

| 接口方向 | 接口内容 | 数据格式 |
|---------|---------|---------|
| 场景→渲染 | 可见物体列表+变换矩阵+材质索引 | Structured Buffer (GPU消费) |
| 物理→渲染 | 运动数据(用于运动模糊/TAA) | Uniform Buffer |
| AI→渲染 | 神经网络权重(神经渲染) | SSBO |
| UI→渲染 | UI元素+布局数据 | 独立前向Pass |
| 资产管线→渲染 | GPU资源(网格/纹理/Shader) | VMA分配+Bindless注册 |
