# 实时渲染系统 — 渲染架构选型与对比

> 本文档是「实时渲染系统」系列文档的第 **3** 篇，详细对比主流渲染架构的设计原理、优劣分析与适用场景，为引擎架构决策提供量化参考。

---

## 1. 渲染架构概述

渲染架构决定了**光照计算的时机与方式**，是引擎最核心的架构决策。不同的架构选择将影响：

- 光照计算的粒度（逐像素 vs 逐物体）
- 光照数量上限（少量 vs 大量光源）
- 材质表达力（简单 vs 复杂）
- GPU 带宽消耗（低 vs 高）
- 移动端适配性（优 vs 差）

---

## 2. Forward Rendering（前向渲染）

### 2.1 基本原理

前向渲染是最经典的渲染架构，**逐物体逐像素计算光照**：

```
对每个物体:
  对每个像素:
    采样材质纹理 → 计算所有光照 → 输出最终颜色
```

### 2.2 渲染流程

```
┌──────────────────────────────────────────────────────┐
│  前向渲染管线                                         │
│                                                      │
│  场景物体 ──▶ 逐物体绑定材质 ──▶ Fragment Shader       │
│              ├─ 采样基础色纹理                         │
│              ├─ 采样法线纹理                           │
│              ├─ 计算光照（逐光源循环）                   │
│              ├─ 计算阴影（逐光源采样ShadowMap）         │
│              └─ 输出最终像素颜色                       │
└──────────────────────────────────────────────────────┘
```

### 2.3 优劣势分析

| 优势 | 劣势 |
|------|------|
| 实现简单，代码直观 | 光照数量受限于 Shader 循环，多光源性能衰减 |
| 天然支持透明物体 | 需逐物体绑定材质纹理，CPU 提交开销大 |
| 材质灵活度高（逐物体 Shader 变体） | 无 GBuffer 数据，屏幕空间效果受限 |
| 带宽消耗低（无 GBuffer 读写） | Overdraw 问题：重叠像素重复计算光照 |
| 移动端友好 | 无法与延迟光照技术兼容 |

**适用场景**：少量光源的简单场景、移动端基础方案、透明物体必需的场景。

---

## 3. Forward+ / Clustered Forward（分簇前向渲染）

### 3.1 基本原理

Forward+ 在前向渲染基础上引入**分簇光照网格**，将光照计算从逐物体 Shader 循环升级为逐像素空间查询：

```
1. 将视锥体沿深度切分为 K 个深度切片
2. 沿 X/Y 方向切分为网格簇（Cluster）
3. 每帧计算每个簇包含哪些光源 → 簇光源列表
4. Fragment Shader 从簇列表中获取该像素对应的所有光源
```

### 3.2 簇光照网格结构

```
视锥体 3D 簇划分:

          ┌──────────────────────────┐ 近平面
          │  │  │  │  │  │  │  │  │  │
          │──┼──┼──┼──┼──┼──┼──┼──┼──│ Cluster Row
          │  │  │  │  │  │  │  │  │  │
          └──────────────────────────┘
                    │ 深度切片
                    ▼
          ┌──────────────────────────────────┐
          │         远平面（更大簇）          │
          │                                  │
          └──────────────────────────────────┘

每个 Cluster: 包含该空间范围内所有光源的索引列表
```

### 3.3 渲染流程

```
┌──────────┐    ┌───────────────┐    ┌────────────────────┐
│ 深度预通道 │──▶ │ 簇光照构建     │──▶ │ 前向渲染           │
│ (可选)    │    │ (Compute)     │    │ (逐物体)           │
└──────────┘    └───────────────┘    │ └─ Fragment Shader   │
                                      │    ├─ 确定像素所属簇 │
                                      │    ├─ 获取簇光源列表 │
                                      │    ├─ 逐光源计算光照 │
                                      │    └─ 输出最终颜色  │
                                      └────────────────────┘
```

### 3.4 优劣势分析

| 优势 | 劣势 |
|------|------|
| 支持大量光源（数百~数千） | 需额外深度预通道或 GBuffer |
| 光照计算高效（簇内光源有限） | 簇构建有额外 Compute 开销 |
| 保留前向渲染材质灵活性 | Overdraw 仍存在（深度预通道可缓解） |
| 透明物体兼容 | 需为透明物体单独处理簇光源查询 |
| 移动端可适配 | 簇列表内存占用随光源数量增长 |

**适用场景**：大量局部光源的场景（室内、城市夜景）、需材质灵活性的中高端项目。

## 4. Deferred Rendering（延迟渲染）

### 4.1 基本原理

延迟渲染将渲染拆分为两个阶段：**几何阶段**（写入 GBuffer）和**光照阶段**（从 GBuffer 读取计算光照）：

```
几何阶段: 逐物体写入材质属性到 GBuffer
光照阶段: 全屏 Pass 逐像素从 GBuffer 读取 + 计算光照
```

### 4.2 渲染流程

```
┌────────────┐    ┌────────────┐    ┌────────────┐    ┌────────────┐
│ GBuffer Pass │──▶│ ShadowMap   │──▶│ 光照计算    │──▶│ 透明物体   │
│ (写入材质)   │    │ (阴影生成)   │    │ (全屏Pass)  │    │ (前向渲染) │
└────────────┘    └────────────┘    └────────────┘    └────────────┘
                                         │
                                    GBuffer读取
                                    ├─ 基础色
                                    ├─ 法线
                                    ├─ ORM参数
                                    ├─ 世界坐标
                                    └─ 深度
```

### 4.3 优劣势分析

| 优势 | 劣势 |
|------|------|
| 光照与几何解耦，光照开销仅与像素数相关 | GBuffer 带宽消耗大（多附件读写） |
| 支持大量光源（全屏Pass逐像素独立计算） | 透明物体需前向渲染单独处理 |
| 屏幕空间效果丰富（SSR/SSAO/SSS等） | 材质灵活性受限（GBuffer编码有限通道数） |
| 无 Overdraw（仅 GBuffer Pass） | 移动端带宽瓶颈严重 |
| 后处理依赖数据完整 | MSAA 困难（需 Multi-Sample GBuffer） |

**适用场景**：大量光源+复杂屏幕空间效果的桌面端场景、3A 级游戏标准方案。

---

## 5. TDBR（移动端瓦片延迟渲染）

### 5.1 基本原理

TDBR（Tile-Based Deferred Rendering）是延迟渲染的**移动端优化变体**，利用 TBDR 架构的片上存储（On-Chip Memory）避免 GBuffer 读写到主显存：

```
传统Deferred: GBuffer → 写入主显存 → 光照读取主显存 → 写回主显存
    带宽: 2× GBuffer写入 + 2× GBuffer读取 = 4×带宽

TDBR: GBuffer → 写入片上存储 → 光照读取片上存储 → 输出到主显存
    带宽: 仅最终输出1×写入 = 显著带宽节省
```

### 5.2 Vulkan Subpass 实现

```cpp
// Subpass 0: GBuffer写入（片上存储）
VkSubpassDescription subpass0 = {};
subpass0.pipelineBindPoint = VK_PIPELINE_BIND_POINT_GRAPHICS;
subpass0.colorAttachmentCount = 4;
subpass0.pColorAttachments = gbufferAttachments; // RT0~RT3
subpass0.pDepthStencilAttachment = &depthAttachment;

// Subpass 1: 光照计算（读取Subpass 0的片上数据）
VkSubpassDescription subpass1 = {};
subpass1.pipelineBindPoint = VK_PIPELINE_BIND_POINT_GRAPHICS;
// 通过 InputAttachment 读取上一 Subpass 的输出
VkAttachmentReference inputAttachments[] = {
    {0, VK_IMAGE_LAYOUT_INPUT_ATTACHMENT_BIT},  // RT0
    {1, VK_IMAGE_LAYOUT_INPUT_ATTACHMENT_BIT},  // RT1
    {2, VK_IMAGE_LAYOUT_INPUT_ATTACHMENT_BIT},  // RT2
    {3, VK_IMAGE_LAYOUT_INPUT_ATTACHMENT_BIT},  // RT3
};
subpass1.inputAttachmentCount = 4;
subpass1.pInputAttachments = inputAttachments;
subpass1.colorAttachmentCount = 1;
subpass1.pColorAttachments = &outputAttachment; // 最终光照输出
```

**Shader 侧读取 Subpass 输入**：

```glsl
// 通过 subpassInput 读取片上 GBuffer 数据
layout(input_attachment_index = 0) uniform subpassInput albedoInput;
layout(input_attachment_index = 1) uniform subpassInput normalInput;
layout(input_attachment_index = 2) uniform subpassInput ormInput;
layout(input_attachment_index = 3) uniform subpassInput motionInput;

void main() {
    vec3 albedo = subpassLoad(albedoInput).rgb;
    vec3 normal = subpassLoad(normalInput).rgb;
    vec3 orm    = subpassLoad(ormInput).rgb;
    // 光照计算...
}
```

### 5.3 优劣势分析

| 优势 | 劣势 |
|------|------|
| 显存带宽大幅节省（片上存储替代主显存读写） | 仅 TBDR 架构 GPU 支持（Mali/Apple GPU） |
| 延迟渲染优势保留（大量光源+屏幕空间效果） | Subpass 限制灵活性（附件格式受限） |
| 移动端最优延迟方案 | Pixel Local Storage 非 Vulkan 标准（需扩展） |
| 功耗降低（减少显存访问） | PC 端 IMR 架构无片上存储收益 |

**适用场景**：移动端（Mali/Apple GPU）延迟渲染、低功耗优先场景。

## 6. Clustered Shading（分簇光照渲染）

### 6.1 基本原理

Clustered Shading 是 Clustered Forward 和 Deferred 的**统一升级方案**，将分簇光照网格与延迟渲染结合：

```
Clustered Deferred = Deferred GBuffer + Cluster光照网格
Clustered Forward+ = Forward + Cluster光照网格
```

核心思想：无论采用前向还是延迟架构，光照计算都通过分簇网格索引，**光照数量不再成为性能瓶颈**。

### 6.2 簇构建流程

```cpp
// Compute Shader: 簇光照构建
layout(local_size_x = 256) in;

void main() {
    uint lightIndex = gl_GlobalInvocationID.x;
    Light light = lights[lightIndex];

    // 计算光源影响的深度切片范围
    float minDepth = computeSliceDepth(light.position, light.radius);
    float maxDepth = computeSliceDepth(light.position, light.radius);

    // 将光源索引写入对应簇的光源列表
    for (uint slice = minSlice; slice <= maxSlice; ++slice) {
        for (uint cluster in affectedClusters) {
            atomicAdd(clusterLightCounts[cluster], 1);
            clusterLightLists[cluster].push(lightIndex);
        }
    }
}
```

### 6.3 优劣势分析

| 优势 | 劣势 |
|------|------|
| 光照数量几乎无上限（数千光源） | 簇构建有额外 Compute 开销 |
| 前向/延迟均可搭载 | 簇数据内存占用 |
| 移动端可适配（Clustered Forward+） | 簇划分参数需调优 |
| 局部光源精确影响范围 | 点光源/聚光灯簇效率高，方向光需特殊处理 |

**适用场景**：大量局部光源的现代引擎标准方案，3A 级游戏主流选择。

## 7. Visibility Buffer（可见性缓冲渲染）

### 7.1 基本原理

Visibility Buffer 是近年来新兴的渲染架构，**仅存储最精简的可见信息（三角面ID + 重心坐标）**，材质/光照计算全部延迟到后续 Pass：

```
VisBuffer Pass: 逐像素仅写入
  ├─ Mesh ID (三角面所属网格索引)
  ├─ Triangle ID (三角面索引)
  ├─ Barycentric Coords (重心坐标)
  └─ (可选) Primitive ID

后续 Pass: 从 VisBuffer 反查几何+材质数据
  ├─ 材质 Pass: 从 MeshID+TriangleID 反查材质参数 → 动态采样纹理
  ├─ 光照 Pass: 从 VisBuffer 反查法线/位置 → 计算光照
```

### 7.2 VisBuffer 优势

```
传统 GBuffer: 4~8 附件 × 128bit+ 每像素 = 高带宽
VisBuffer:     1 附件 × 32~64bit 每像素 = 极低带宽
```

| 优势 | 劣势 |
|------|------|
| 极低带宽（仅 1 个精简附件） | 需 Mesh Shader / GPU-Driven Pipeline 配合 |
| 材质灵活性无上限（动态采样） | 反查几何数据需额外 Buffer 查询 |
| 天然支持多材质混合 | 实现复杂度高 |
| 配合 Nanite 式虚拟几何体最佳 | 透明物体需单独处理 |
| 适合 Mesh Shader 管线 | 行业实践较少，参考资料有限 |

**适用场景**：Mesh Shader + GPU-Driven 大规模场景、带宽敏感平台、虚拟几何体（Nanite 类）系统。

## 8. 光栅 + 光追混合管线

### 8.1 基本原理

混合管线将光栅化（高性能基础画面）与光线追踪（高质量特定效果）结合：

```
光栅化: GBuffer + 光照计算 → 基础画面 (快速)
光追:   阴影 + 反射 + GI → 高质量增强 (慢速，选择性)
混合:   光追结果与光栅画面融合 → 最终输出
```

### 8.2 混合策略

| 混合场景 | 光栅部分 | 光追部分 | 融合方式 |
|---------|---------|---------|---------|
| 阴影 | ShadowMap 主光源 | 光追阴影局部光源 | ShadowMap + RT Shadow 降噪混合 |
| 反射 | SSR（屏幕内反射） | 光追反射（屏幕外反射） | SSR + RT Reflection 权重混合 |
| GI | 环境光/AO | 光追间接光照/路径追踪 | RT GI 降噪 → 替换环境光 |
| 透明 | 前向渲染透明物体 | 光追透射/折射 | RT Translucency 替换 Alpha Blend |

### 8.3 优劣势分析

| 优势 | 劣势 |
|------|------|
| 画面质量接近全光追 | 光追部分性能开销大 |
| 基础画面性能保底（光栅兜底） | 需维护两套渲染路径 |
| 按画质档位灵活开关光追效果 | 光追降噪（NRD/AI）引入额外延迟 |
| 适配不同硬件能力 | 光追需加速结构构建/更新开销 |

**适用场景**：3A 级游戏标准方案、支持 RT 的桌面端/高端主机。

## 9. 渲染架构决策矩阵

### 9.1 综合对比表

| 维度 | Forward | Forward+ | Deferred | TDBR | Clustered | VisBuffer | 混合管线 |
|------|---------|----------|----------|------|-----------|-----------|---------|
| **光源上限** | 少量(4~8) | 中量(64~128) | 大量 | 大量 | 极大量(1000+) | 取决于后续 | 极大量 |
| **材质灵活性** | 极高 | 高 | 中(GBuffer编码限制) | 中 | 中 | 极高 | 高 |
| **透明物体** | 天然支持 | 支持(需额外处理) | 需单独前向Pass | 需单独Pass | 需额外处理 | 需单独处理 | 光追替代 |
| **Overdraw** | 有 | 有(深度预通道缓解) | 无 | 无 | 无 | 无 | 光栅部分有 |
| **带宽消耗** | 低 | 中 | 高(GBuffer读写) | 低(片上存储) | 高(同Deferred) | 极低 | 高 |
| **MSAA兼容** | 天然 | 可支持 | 困难 | 困难 | 困难 | 需特殊处理 | 困难 |
| **移动端适配** | ★★★★★ | ★★★★ | ★★ | ★★★★★ | ★★★ | ★★ | ★ |
| **桌面端适配** | ★★ | ★★★ | ★★★★★ | ★★ | ★★★★★ | ★★★★ | ★★★★★ |
| **实现复杂度** | 低 | 中 | 中 | 中高 | 中高 | 高 | 高 |

### 9.2 选型决策流程

```
                    ┌─ 移动端? ──────────── Yes ──▶ Forward 或 Forward+ 或 TDBR
                    │
                    │                        └─ 少量光源 → Forward
                    │                        └─ 中量光源 → Forward+
                    │                        └─ TBDR GPU → TDBR
                    │
场景平台 ──────────┤─ 桌面端/主机? ── Yes ─┤
                    │                        └─ 大量光源+材质简单 → Deferred + Clustered
                    │                        └─ 大量光源+材质复杂 → Clustered Deferred
                    │                        ┌─ 支持 RT GPU → 混合管线
                    │                        └─ Mesh Shader + 虚拟几何 → Visibility Buffer
                    │
                    └─ VR/AR ──▶ Forward+ (Multiview) 或 Clustered Forward
```

### 9.3 推荐组合方案

| 目标场景 | 推荐架构 | 理由 |
|---------|---------|------|
| **移动端中等画质** | Forward + 简单阴影 | 实现简单、带宽低、光源少 |
| **移动端高画质** | Clustered Forward+ | 支持更多光源、材质灵活 |
| **移动端 TBDR 延迟** | TDBR (Subpass) | 延迟优势+带宽优化 |
| **PC 3A 级** | Clustered Deferred + 混合 RT | 光源大量+屏幕空间效果丰富+光追质量 |
| **PC 下一代引擎** | VisBuffer + Mesh Shader + 混合 RT | 极低带宽+材质无限灵活+虚拟几何体 |
| **VR/AR** | Clustered Forward+ (Multiview) | 低延迟+多视图+单Pass渲染 |
