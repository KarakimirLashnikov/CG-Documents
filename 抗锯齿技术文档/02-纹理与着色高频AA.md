# 抗锯齿技术 — 纹理与着色高频 AA

> 本文档是「抗锯齿（AA）技术」系列文档的第 **2** 篇。本篇专讲**着色/纹理高频混叠**——MSAA 完全管不到的那一类。核心结论是：**这类混叠必须在采样之前预过滤**，后处理无从恢复。

---

## 1. 成因：为什么 MSAA 在这里失效

### 1.1 三种典型场景

```
┌──────────────────────────────────────────────────────────────────────────┐
│  场景 A：纹理缩小（Texture Minification）                                  │
│                                                                          │
│   远处地面：一个屏幕像素覆盖了 100×100 个纹素                               │
│                                                                          │
│   纹理空间                屏幕空间（1 个像素）                             │
│   ┌─────────────────┐     ┌─────┐                                       │
│   │▨▨▤▤▨▨▤▤▨▨▤▤▨▨▤▤│     │  ?  │  ← 只在中心取样 1 个纹素               │
│   │▤▤▨▨▤▤▨▨▤▤▨▨▤▤▨▨│     └─────┘     剩下的 9999 个纹素被忽略             │
│   │▨▨▤▤▨▨▤▤▨▨▤▤▨▨▤▤│                                                  │
│   └─────────────────┘     结果：摩尔纹 + 纹理闪烁                          │
├──────────────────────────────────────────────────────────────────────────┤
│  场景 B：法线贴图高频（Specular Aliasing）                                 │
│                                                                          │
│   远处被法线贴图调制的高光表面                                              │
│   · 像素覆盖了几十个法线纹素，法线方向差异巨大                              │
│   · 但只采样一个法线 → 得到一条锐利的高光条                                │
│   · 换个视角/移动一下，高光条跳到别处                                       │
│                                                                          │
│   结果：**高光碎斑、闪烁**（这是最刺眼的一类走样）                            │
├──────────────────────────────────────────────────────────────────────────┤
│  场景 C：程序化图案 / 高频着色                                              │
│                                                                          │
│   · 棋盘格、条纹、噪声程序化纹理                                            │
│   · 计算出的高频图案（如基于 UV 的图案、fract() 边界）                       │
│   · 屏幕空间的锐利函数边界（如 step() 边缘）                                 │
│                                                                          │
│   结果：规律性的摩尔纹、边缘抖动                                            │
└──────────────────────────────────────────────────────────────────────────┘
```

### 1.2 为什么 MSAA 帮不上忙

```
        MSAA 提高了什么？                   需要提高什么？
   ┌──────────────────────────┐      ┌──────────────────────────┐
   │ · 覆盖率采样率            │      │ · 纹理采样率              │
   │ · 深度/模板采样率          │      │ · 法线的空间采样率         │
   │                          │      │ · 着色求值的采样率         │
   └──────────────────────────┘      └──────────────────────────┘
              │                                  │
              │        两者交集 = 空              │
              └──────────────────┬───────────────┘
                                 ▼
                     MSAA 对着色/纹理高频无能为力
           （除非开启 sample shading，让着色也按采样点执行）
```

⚠️ **关键**：MSAA 的片元着色**在像素中心执行一次**，纹理采样也只有一次。所以纹理空间的高频信息根本没有被采样到——**没有信息，后处理也无法恢复**。

这就是为什么「开了 TAA 还是有噪点」——TAA 只能处理**已经被采样到**的信息的时序不稳定，无法凭空造出没被采样的高频。

## 2. 路径一：Mipmap 与纹理过滤

### 2.1 Mipmap 的本质是预过滤

Mipmap 不是「换个更小的贴图」，而是**在离线/加载时预先把纹理做高斯式的低通滤波**，让每个 mip 层的采样率与它的显示尺寸匹配。

```
┌──────────────────────────────────────────────────────────────────────────┐
│  Mipmap 链                                                                │
│                                                                          │
│  Level 0  ████████████████  1024×1024   （原始）                          │
│  Level 1  ████████          512×512    （低通 + 降采样）                  │
│  Level 2  ████              256×256                                      │
│  Level 3  ██                128×128                                      │
│  ...                                                                     │
│                                                                          │
│  采样时按 LOD 选择（并做三线性插值）。                                      │
│  LOD 由屏幕空间 UV 导数决定：                                              │
│      LOD = log2( max( |dUV/dx|, |dUV/dy| ) × texSize )                   │
└──────────────────────────────────────────────────────────────────────────┘
```

| 优点 | 缺点 |
|------|------|
| 显存仅增加约 33% | 只用各向同性过滤会模糊斜向表面 |
| 采样成本几乎不变 | 需要离线生成（动态纹理需运行时生成，有成本） |
| 根治缩小时的摩尔纹与闪烁 | 对非纹理高频（法线、程序化）无效 |

### 2.2 各向异性过滤（Anisotropic Filtering）

**为什么需要**：一个像素在屏幕上的投影是一个**椭圆**，mipmap 只能选各向同性的方形区域。

```
┌──────────────────────────────────────────────────────────────────────────┐
│  斜向观察地面时的纹理足迹                                                   │
│                                                                          │
│   屏幕像素的纹理投影：                                                     │
│                                                                          │
│       ┌──────┐            ← 各向同性 mipmap 用一个方形覆盖                │
│       │ ┌──┐ │               → 沿长轴方向欠采样（保留模糊）                │
│       │ └──┘ │                                                            │
│       └──────┘            ← 各向异性过滤沿椭圆长轴取多个样本               │
│                                  2x / 4x / 8x / 16x                      │
└──────────────────────────────────────────────────────────────────────────┘
```

| 倍率 | 沿长轴的额外采样 | 相对纹理带宽 | 视觉收益 |
|------|----------------|------------|---------|
| 1x（三线性） | 0 | 1x | 基线 |
| 2x | 2 | ~1.5–2x | 中等 |
| 4x | 4 | ~2–3x | 明显 |
| 8x | 8 | ~3–6x | 高 |
| 16x | 16 | ~4–8x | 边际递减 |

⚠️ **移动端建议 4x**。8x/16x 在移动端的纹理带宽成本往往不抵视觉收益，且移动端屏幕小、视距近，斜向纹理的走样不那么显眼。

### 2.3 纹理过滤能做什么、不能做什么

| 能 | 不能 |
|----|------|
| 纹理缩小时的摩尔纹 | 三角形边缘（几何问题） |
| 纹理闪烁 | 法线贴图的高光走样 |
| 斜向表面的细节保留（各向异性） | 程序化图案的走样 |
| — | 亚像素几何丢失 |

⚠️ **一个常见的错误认知**：「既然有 mipmap，那纹理就不会走样了」。实际上——

- Mipmap 只处理**纹理层内**的平均
- **法线贴图即使有 mipmap 也会走样**，因为线性平均法线会``丢失方差``（见下节）

## 3. 路径二：法线贴图与高光走样（Specular AA）

⚠️ **这是本篇最重要的一节，也是原分类框架里缺专门技术的一节。**

### 3.1 问题的真正来源：线性平均法线会抹掉方差

```
┌──────────────────────────────────────────────────────────────────────────┐
│  为什么法线贴图的 mipmap 反而会制造走样                                   │
│                                                                          │
│  高细节法线贴图的局部区域（例如鹅卵石表面）：                                │
│                                                                          │
│     ↗  ↖  ↗    法线方向杂乱，方差大                                        │
│     ↖  ↗  ↖    → 应用 roughness 低（很光滑）                              │
│     ↗  ↖  ↗    → 正确的渲染结果：**温和的、扩散的高光**                     │
│                                                                          │
│  mipmap 线性平均之后：                                                     │
│                                                                          │
│     →  →  →    平均后得到一个**近似垂直的单一法线**                          │
│     →  →  →    长度 < 1（因为平均时方向互相抵消）                          │
│                                                                          │
│  但渲染时如果**归一化**这个法线：                                           │
│                                                                          │
│     ↑  ↑  ↑    长度被拉回 1，方向变得"确定"                                │
│                → 配上低 roughness → **镜面般的锐利高光**                    │
│                → 远处表面出现闪烁的高光碎斑 ← 走样！                        │
│                                                                          │
│  本质：**mipmap 抹掉了法线方差，但 roughness 还在说"很光滑"**                │
│        正确的做法是把丢失的方差**折进 roughness**                           │
└──────────────────────────────────────────────────────────────────────────┘
```

Far Cry 3 的 SIGGRAPH 2012 课程笔记对此表述得很清楚：

> "The major reason for these problems is that **we do not factor the variance of the normal map into our specular roughness**. As we move into the distance, we sample lower mip-levels of the normal map, which are increasingly smooth and give the material the appearance of **increased gloss**. Instead, this variance that is lost in our normal map **should be fed into our specular roughness**, ensuring that appearance is preserved."

### 3.2 Toksvig AA（2004）

**Michael Toksvig, "Mipmapping Normal Maps", NVIDIA, 2004**

**核心思想**：利用「平均法线的长度」来估计法线方差。向量平均时方向越分散，合成长度越短。

**主公式（Far Cry 3 采用的实用形式）**：

\[
m' = \frac{\|\mathbf{n}_a\| \, m}{\|\mathbf{n}_a\| + m\,(1 - \|\mathbf{n}_a\|)}
\]

其中：
- \(\mathbf{n}_a\) = 从（已 mipmap 过滤的）法线贴图读出的**平均法线**（**不归一化**）
- \(m\) = 原始的高光指数（specular power）
- \(m'\) = 修正后的高光指数
- \(\|\mathbf{n}_a\|\) 越接近 1 → 方差越小 → 修正越小；越接近 0 → 方差越大 → 高光被大幅削弱

注意这个公式的行为：随着 mip 层升高，\(\|\mathbf{n}_a\|\) 下降，\(m'\) 随之下降 → 远处高光自然变宽变柔。**外观得以保持**。

**Stephen Hill 给出的完整代码版**（含强度调制）：

```hlsl
// 输入：Na = 从法线贴图读出的平均法线（未归一化）
//       s  = 原始高光指数
//       H  = 半角向量
float len   = length(Na);
float ft    = len / lerp(s, 1, len);      // ★ Toksvig Factor
float scale = (1 + ft * s) / (1 + s);     // 整体强度缩放
float spec  = scale * pow(saturate(dot(Na, H)) / len, ft * s);
```

**优缺点**：

| ✅ 优点 | ❌ 缺点 |
|--------|--------|
| 依赖已有的 mipmap + 硬件纹理过滤，成本几乎为零 | **要求法线贴图不被压缩**（压缩算法要求法线是单位长度，而 Toksvig 依赖长度 < 1） |
| 天然适用于**动态生成**的法线贴图（水面波纹、变形动画） | 即使不压缩，存储"变短的法线"也有精度问题 |
| 实现极简单 | 只处理各向同性方差，不表达各向异性高光 |
| 在 Blinn-Phong 下有严格理论依据 | 与 GGX 结合时理论基础不严（见 §3.5） |

**Far Cry 3 的实战折中**（很有参考价值）：

```
原始方案：把 Toksvig 计算出的 gloss 存进 DXT5 法线贴图的 R 通道
          （DXT5 只用 G 和 A 通道存法线的 y/x 分量，R 通道空闲）
              │
              ▼
         问题：严重损害 Y 通道的压缩质量 → 不可接受
              │
              ▼
最终方案：在 R 通道里填一个**单一颜色**（即"平均 Toksvig factor"）
          → 不影响压缩
          → 仍然提供了一定程度的外观保持与抗锯齿
          → 甚至没有被法线贴图的材质也能受益
```

⚠️ **这个折中方案的价值**：它把「精确的逐像素方差」降级为「材质级的平均方差」，用几乎零成本换取了走样的大幅缓解。对于预算紧张的移动端项目，这是非常实用的起点。

### 3.3 LEAN Mapping（2010）

**Olano & Baker, "LEAN Mapping", I3D 2010**（GDC 2011 演讲 "Spectacular Specular"）

**LEAN = Linear Efficient Antialiased Normal Mapping**

**核心思想**：不只是记录平均法线，而是记录法线分布的**协方差矩阵**（二阶矩）。

| 特性 | 说明 |
|------|------|
| 表达内容 | 法线分布的均值 + 协方差矩阵 |
| 精度 | 能表达**各向异性**的高光（例如拉丝金属、山脊状法线） |
| 兼容性 | 兼容 mipmap 与硬件纹理过滤 |
| 动态法线 | 支持（可以运行时叠加多层 bump） |
| ⚠️ 存储 | **需要两张贴图替代一张法线图**；精度要求高（类似 Variance Shadow Map 的问题）；**不兼容 DXT1/DXT5**；总存储成本可能达 8 倍 |
| 额外数学 | 着色时运算量更大；在 deferred 里还需要额外存一个切线向量 |

**首用于《文明 5》**（Civ V 的水面材质）。

### 3.4 CLEAN Mapping（2011）与 LEADR

| 技术 | 关系 | 取舍 |
|------|------|------|
| **CLEAN** | LEAN 的廉价版（**C**heap LEAN，Dan Baker, GDC 2011） | 牺牲各向异性，**存储约为 LEAN 的一半**，性能略高 |
| **LEADR** | LEAN 的扩展 | 额外考虑位移贴图（displacement mapping）的可见性影响 |
| Hery et al.（Pixar） | 独立提出的类似技术 | 用于渲染亚像素级细节（金属薄片 metal flakes、小划痕） |

**LEAN/CLEAN 的实践困境**（Stephen Hill 的分析）：存储需求是主要障碍。对 deferred 渲染更麻烦——G-Buffer 空间本来就紧张，而 LEAN 的参数量让它几乎放不下。

### 3.5 关键改进：方差映射（Variance Map）

⚠️ **这是让这类技术真正可用的关键一步**，出自 Stephen Hill 的建议（PBR 相关文献有整理）：

> "Hill 指出，Toksvig 技术、LEAN 映射和 CLEAN 映射等技术，**都可以使用这种方法来预先计算方差**，从而消除这些技术在原始形式下的许多缺点。"

**做法**：在**生成法线贴图 mipmap 的离线阶段**，就计算出法线平均化带来的方差损失，直接写入一个额外的通道（或直接烘焙进 gloss）。

```
┌──────────────────────────────────────────────────────────────────────────┐
│  预计算方差 vs 运行时计算                                                   │
├──────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│  运行时（Toksvig 原始形式）：                                              │
│    · 需要法线贴图保持未压缩 → 存储飙升                                      │
│    · 依赖平均法线长度 → 精度问题                                          │
│    · 只能处理各向同性                                                    │
│                                                                          │
│  预计算（variance map）：                                                 │
│    · 离线阶段算好方差 → 压缩算法可以正常工作                                │
│    · 运行时只需读一个额外的通道                                            │
│    · 可以扩展到各向异性（存 2~3 个方差项）                                  │
│    · 可以任意压缩格式（8 位够用）                                          │
│                                                                          │
│  → 这是现代引擎的主流做法                                                  │
└──────────────────────────────────────────────────────────────────────────┘
```

### 3.6 工业界实践：Call of Duty: WWII（SIGGRAPH 2018）

动视/大锤在《Material Advances in WWII》中给出了一套完整的方案，命名为 **"Mipmapping Normal and Gloss (NDF)"**：

| 要点 | 说明 |
|------|------|
| 基础 | 基于 **Toksvig 2004** 的思想 |
| 目标 NDF | **专门针对 GGX**，但方法可扩展到任何**可重要性采样**的 NDF |
| 做法 | 在生成法线贴图 mipmap 时，计算法线平均化造成的方差损失，用这个**修改 gloss 的 mip** |
| 效果 | 远处表面的 gloss 值自动下降，「镜面般的鹅卵石」变成正常的粗糙表面 |
| 引用前作 | LEAN (Olano 2010)、CLEAN (Baker 2011)、Rock-Solid Shading (Baker 2012)、Toksvig (2004) |

**方案的核心伪代码**：

```hlsl
// 离线：生成 mipmap 时计算方差
for (int mip = 1; mip < mipCount; ++mip) {
    // 1. 对上一层法线做线性平均（不归一化）
    vec3 avgN = averageOfPreviousMip(mip - 1);

    // 2. 平均长度平方用于估方差
    float lenSq = dot(avgN, avgN);          // ∈ [0, 1]

    // 3. 法线分布的"角度方差"近似（1 - lenSq 越大越粗糙）
    float normalVariance = 1.0 - lenSq;

    // 4. 把方差折进 roughness（具体映射按 NDF 推导，此处为示意）
    float alpha = roughnessToAlpha(glossValue);
    float alphaFiltered = sqrt(alpha * alpha + normalVariance * k);
    glossValue = alphaToRoughness(alphaFiltered);

    // 5. 写回该 mip 的 gloss 通道
    writeGloss(mip, glossValue);
}
```

### 3.7 Toksvig 与 GGX 的理论问题（必须知道的边界）

⚠️ **诚实地说**：Toksvig 的方法严格基于 **Blinn-Phong 的高光指数**，与 **GGX** 结合时**理论基础并不牢固**。

PBR 相关文献的表述：

> "更加麻烦的是，**GGX 分布中并没有定义法线分布的方差**，因此在与 GGX 分布一起使用的时候，这种基于方差的技术并没有扎实的理论基础。尽管有这些理论上的困难，但是在 GGX 分布中使用方程 9.76 的情况是相当普遍的，通常是令 \(\alpha_p = 2\alpha_g^{-2} - 2\)，这样做在实践中还是相当有效的。"

⚠️ **务实结论**：

| 事项 | 说明 |
|------|------|
| 理论状态 | 严格推导不成立（GGX 没有定义法线方差） |
| 实践状态 | **广泛使用且效果良好**，通过近似换算把方差折算成 GGX 的 roughness |
| 建议 | 把它当作**经验性的外观保持手段**，而不是精确的物理推导。参数需要在目标内容上实测调校 |
| 版本注意 | 具体换算公式随引擎/文献而异，**以实现所用引擎或论文为准** |

### 3.8 高光 AA 方案的完整对照

| 方案 | 表达内容 | 存储代价 | 各向异性 | 动态法线 | 移动端可行性 |
|------|---------|---------|---------|---------|------------|
| 无处理 | — | 0 | — | — | — |
| **平均 Toksvig factor**（Far Cry 3 折中） | 材质级方差 | 1 个通道（单色） | ❌ | ⚠️ 部分 | ✅✅ 推荐起点 |
| **Toksvig（逐像素）** | 各向同性方差 | 需**未压缩**法线 | ❌ | ✅ | ⚠️ 存储受限 |
| **方差映射（variance map）** | 预计算方差 | 1 个额外通道 | ⚠️ 可扩展 | ⚠️ 动态需另算 | ✅✅ 现代主流 |
| **CLEAN Mapping** | 均值 + 各向同性方差 | 约为 LEAN 一半 | ❌ | ✅ | ❌ 存储仍偏大 |
| **LEAN Mapping** | 均值 + 协方差矩阵 | 约 8× / 两张图 | ✅ | ✅ | ❌ 移动端不可行 |
| **CoD WWII NDF 方案** | 针对 GGX 的方差 | 烘焙进 gloss | ❌ | ⚠️ | ✅ 思路可借鉴 |
| **运行时降 roughness**（美术手工） | 无（手调） | 0 | — | — | ✅ 粗糙但可用 |

### 3.9 与 TAA 的关系（重要）

⚠️ **高光 AA 不能被 TAA 替代**，原因：

```
TAA 处理的是「已采样信息的时序不稳定」
高光走样是「未采样高频被错误重建」
        │
        └── 两者是不同问题。TAA 只能让闪烁变得不那么刺眼，
            无法恢复正确的外观（远处镜面鹅卵石依然错）
```

反过来说：**TAA + 高光 AA 是最佳组合**。高光 AA 让远处高光在物理上变得更宽更柔（正确的），TAA 再抹掉残余的时序噪声。

## 4. 路径三：程序化图案与 SDF

### 4.1 解析 AA（`fwidth` 法）

对能解析表达的高频图案，用屏幕空间导数自适应地确定平滑宽度：

```glsl
// 棋盘格：用 fwidth 做解析抗锯齿
float checkerAA(vec2 uv) {
    vec2 w = fwidth(uv);                 // 屏幕空间导数（近似 1 像素的 uv 变化量）
    vec2 i = 2.0 * (abs(fract(uv) - 0.5) - 0.5);
    float wa = max(w.x, w.y);
    vec2 a = 1.0 - smoothstep(0.0, wa, abs(i));
    return a.x * a.y + (1.0 - a.x) * (1.0 - a.y);
}

// 圆环 / 线条：用固定宽度 + 导数
float lineAA(vec2 p, vec2 a, vec2 b, float thickness) {
    float d = distanceToSegment(p, a, b);
    float w = fwidth(d);                 // 边缘的像素宽度
    return 1.0 - smoothstep(thickness - w, thickness + w, d);
}
```

⚠️ **`fwidth`/`ddx`/`ddy` 的三个坑**：

| 坑 | 说明 | 对策 |
|----|------|------|
| **2×2 quad 语义** | 导数在同一 quad 的 4 个片元间共享，**分支分歧时会得到错误值** | 避免在导数计算路径上有条件分支 |
| **高频处过度模糊** | `fwidth` 在陡变处会很大，导致过度平滑 | 用 `clamp` 限制 `w` 的上界 |
| **与 VRS 冲突** | 降采样率会放大导数，导致过度模糊 | VRS 场景下需重新调参 |

### 4.2 SDF（Signed Distance Field）

**SDF 用「到最近边界的距离」表示形状**，因此天然支持任意缩放下的抗锯齿。

```
┌──────────────────────────────────────────────────────────────────────────┐
│  SDF 的表示与 AA 原理                                                     │
│                                                                          │
│  形状（如字形 "A"）→ 距离场（每像素存到边界的带符号距离）                     │
│                                                                          │
│     -3 -2 -1  0  1  2  3        d < 0 → 形状内                            │
│     -2 -1  0  1  2  3  4        d > 0 → 形状外                            │
│     -1  0  1  2  3  4  5        d = 0 → 边界                              │
│                                                                          │
│  渲染时：                                                                │
│     alpha = smoothstep(-w, +w, d)   // w = fwidth(d)                    │
│     → 得到亚像素精度的边缘覆盖率                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

**Valve 2007 的奠基论文**：《Improved Alpha-Tested Magnification for Vector Textures and Special Effects》（Chris Green）—— 把 SDF 用于矢量纹理的放大，质量远超 alpha test。

| 变体 | 说明 |
|------|------|
| **SDF** | 单通道，圆角化（丢失尖角） |
| **MSDF**（Multi-channel SDF） | 多通道，保留尖角，适合字形、图标 |
| **PSDF**（Pseudo-SDF） | 折中方案 |

**应用场景与限制**：

| ✅ 适合 | ❌ 不适合 |
|--------|---------|
| 字体（任意字号） | 照片级纹理 |
| 图标 / UI 元素 | 复杂有机形状 |
| 矢量风格图形 | 需要精确几何的地方 |
| 需要极端缩放的 UI | 存储受限且形状简单的场景 |

⚠️ **SDF 的精度边界**：距离场从原始形状生成，若原始分辨率不足，极端放大时会丢失细节。MSDF 能保留尖角但仍受原始精度限制。

### 4.3 高频图案的其他策略

| 策略 | 说明 |
|------|------|
| **降低图案频率** | 最原始也最有效——很多走样来自美术设定了过高的细节频率 |
| **把图案烘进纹理** | 用 mipmap 自动处理，而不是运行时算 |
| **Blue Noise 抖动** | 用蓝噪声代替规则图案，把走样转成不易察觉的噪声（配合 TAA 去噪） |
| **预积分** | 对可解析积分的图案（如球谐光照、BRDF LUT）离线预计算 |

## 5. 路径四：预积分 BRDF 与 IBL

⚠️ 这一类属于「预过滤」路径，解决的问题是**环境光照与 BRDF 的高频走样**。

| 技术 | 说明 |
|------|------|
| **Split-sum 近似**（Karis 2013, UE4） | 把 \(\int f_r L_i\) 拆成「预过滤环境图 × 预积分 BRDF LUT」，两项都可离线/预计算 |
| **预过滤环境图（PMREM）** | 按 roughness 分层模糊 cubemap，每层对应一个粗糙度 |
| **BRDF LUT** | 把 \(\int f_r (N\cdot V, \text{roughness})\) 预积分成一张 2D 查找表 |
| **球谐（SH）** | 用低阶球谐系数表示低频环境光，天然无高频走样 |
| **球面高斯（SG）** | 比 SH 更能表达高频，近年常用 |

**为什么这算 AA**：它们把「运行时的高频积分」转成「离线的预计算 + 低成本的查找」。这与 mipmap 的思路完全一致——**都在采样之前完成滤波**。

## 6. 工程实践清单

### 6.1 纹理侧

```
□ 所有会缩小的纹理都生成 mipmap（不要用 NONE）
□ 各向异性过滤开启（移动端建议 4x，桌面 8~16x）
□ 检查是否有纹理用了 CLAMP + 高频率图案（会加剧走样）
□ 分辨率对齐（避免非常规尺寸破坏压缩与 mip 生成）
□ 检查压缩格式：BC7 / ASTC 对法线贴图的处理是否正确
□ 确认没有禁用显存压缩的标志（如 MUTABLE_FORMAT 会禁用 UBWC/AFBC）
```

### 6.2 材质与法线侧

```
□ 法线贴图必须有对应的 roughness/gloss 处理方差的机制
    · 最简方案：材质级平均 Toksvig factor（单色通道）
    · 标准方案：方差映射（variance map），离线预计算
□ 检查远处是否有"镜面化"的表面（法线方差被 mipmap 抹掉）
□ 检查高光在运动时是否闪烁（specular shimmering）
□ 确认法线贴图的 mip 生成方式（是否做了未归一化平均）
□ 若使用了 IBL：确认 PMREM 分层正确，BRDF LUT 分辨率够
```

### 6.3 程序化图案侧

```
□ 屏幕空间的锐利边界（step / fract）都要用 fwidth 或 SDF 做 AA
□ 限制 fwidth 的平滑宽度上界，避免过度模糊
□ 避免在导数计算路径上放置条件分支
□ 高频程序化纹理考虑烘焙进贴图，让 mipmap 代管
□ UI / 矢量图形用 SDF（含 MSDF 保留尖角）
```

### 6.4 验证手段

| 检查项 | 方法 |
|--------|------|
| 纹理走样 | 相机缓慢平移，观察远处地面/墙面是否有闪烁 |
| 高光走样 | 相机缓慢移动，观察远处高光是否有"碎斑跳动" |
| 法线方差处理 | 把 roughness 强制为很低（近似镜面），看远处是否出现不该有的锐利高光 |
| 程序化 AA | 用 RenderDoc / 框架截帧，看 `fwidth` 输出是否合理 |
| SDF 质量 | 极端放大字号，看边缘是否平滑、尖角是否保留 |

## 7. 小结

| 要点 | 说明 |
|------|------|
| **着色/纹理高频混叠必须在采样前预过滤** | 高频信息在采样时已丢失，后处理无法恢复。这是「开了 TAA 还有噪点」的根因 |
| **MSAA 完全管不到这一类** | 因为它的片元着色与纹理采样都只在像素中心执行一次 |
| **Mipmap 是预过滤，不是缩图** | 它按 LOD 选择已低通滤波的层，根治纹理缩小时的摩尔纹 |
| **各向异性过滤解决的是「足迹是椭圆」问题** | 移动端建议 4x，8x/16x 收益递减而带宽成本高 |
| **法线贴图的 mipmap 反而会制造走样** | 线性平均抹掉了法线方差，但 roughness 还在说"很光滑" → 远处表面镜面化 |
| **正解是把丢失的方差折进 roughness** | 这就是 Toksvig（2004）的核心洞察，也是 LEAN/CLEAN/CoD WWII 方案的共同基础 |
| **Toksvig 的要求是法线不压缩** | 因为压缩算法要求法线单位长度，而 Toksvig 依赖平均法线长度 < 1。这是它的主要实用障碍 |
| **预计算方差（variance map）是让这类技术落地的关键** | 离线算好方差写入额外通道，压缩可以正常工作 |
| **LEAN 表达各向异性但存储代价高** | 需两张贴图、不兼容 DXT1/D5、总存储可能 8 倍 → 移动端不可行。CLEAN 是它的廉价版 |
| **Toksvig 与 GGX 的结合理论基础不严** | GGX 没定义法线方差，实践中通过近似换算把方差折成 roughness。**当经验手段用，别当精确推导** |
| **高光 AA 不能被 TAA 替代** | 两者解决不同问题；高光 AA 让高光物理上正确地变宽，TAA 再抹掉残余时序噪声。**组合使用最佳** |
| **程序化图案有廉价解** | `fwidth` + `smoothstep` 的解析 AA，但要注意 2×2 quad 语义、过度模糊、与 VRS 的冲突 |
| **SDF 是 UI/字体的标准解** | 天然支持任意缩放下的抗锯齿；MSDF 保留尖角 |
| **预积分 BRDF 与 IBL 属于同一思路** | 把运行时的高频积分转成离线预计算 + 低成本查找 |
| **最简单有效的第一步** | 材质级平均 Toksvig factor：一个通道、近乎零成本、能大幅缓解远处高光走样 |
