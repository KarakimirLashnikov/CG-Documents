# 抗锯齿技术 — 图像空间后处理 AA

> 本文档是「抗锯齿（AA）技术」系列文档的第 **3** 篇。本篇讨论 FXAA / SMAA / MLAA / CMAA 这一类**纯图像空间**的后处理抗锯齿：它们不改变几何采样、不改变着色采样，只在最终图像上"找边缘、再糊一下"。理解它们的**结构性上限**，比记住参数更重要。

---

## 1. 定位：后处理 AA 是「修图」不是「采样」

这是本篇最重要的一句话。前两篇讨论的技术（MSAA、SSAA、mipmap、SDF）都在**采样阶段**做工作：提高采样率，或在采样前把高频滤掉。后处理 AA 完全不同：

```
┌──────────────────────────────────────────────────────────────────────────┐
│  两类完全不同的干预时机                                                    │
│                                                                          │
│  ── 前两篇（采样侧）─────────────────────────────────────────────────    │
│                                                                          │
│    真实信号 ──► [ 采样 / 预过滤 ] ──► 像素 ──► [ 重建 ] ──► 显示          │
│                      ▲                                                   │
│                      └── 在这里干预：增加样本 / 提前滤高频                 │
│                          信息是"多出来的"，之后无法再创造                  │
│                                                                          │
│  ── 本篇（后处理侧）─────────────────────────────────────────────────    │
│                                                                          │
│    真实信号 ──► [ 采样 ] ──► 像素 ──► [ 重建 ] ──► 显示                   │
│                                        ▲                                 │
│                                        └── 在这里干预：看出这是"阶梯"，     │
│                                            把阶梯两侧的颜色混一混          │
│                                            信息已经丢了，只能"猜"          │
└──────────────────────────────────────────────────────────────────────────┘
```

由此推出后处理 AA 的四条硬边界：

| 边界 | 原因 |
|------|------|
| **无法恢复几何信息** | 三角形与像素的覆盖关系已经丢失，只能靠亮度梯度"猜"边缘在哪 |
| **无法解决时间混叠** | 只看当前帧，运动时的高频闪烁照旧 |
| **无法解决纹理内部高频** | 纹理里的摩尔纹在像素上已是"随机噪点"，不是"阶梯"，边缘检测反而会把它当成噪声或错误边缘 |
| **必然引入模糊** | 混合就是低通滤波，低通滤波就是模糊 |

⚠️ **但不要因此低估它**：它便宜、无状态、无历史依赖、无运动矢量依赖、不占用额外渲染目标带宽。在"几何本身很简单但边缘很脆"的场景（UI 密集、卡通风、平面色块、低端设备）它反而是最优解。

## 2. MLAA：这一族的源头（Intel 2009）

MLAA（Morphological Anti-Aliasing）由 Intel 实验室提出，最初是 **CPU** 算法（用于延迟渲染管线的图像空间处理）。它是后来一切的模板。

### 2.1 四个步骤

```
┌──────────────────────────────────────────────────────────────────────────┐
│  MLAA 的处理链                                                            │
│                                                                          │
│  ① 边缘检测（Edge Detection）                                            │
│     比较相邻像素亮度差 → 超过阈值视为"存在边缘"                             │
│     只检测每个像素的左边界与上边界（避免重复，省一半算力）                    │
│                                                                          │
│  ② 模式分类（Pattern Classification）                                    │
│     沿边缘向两侧搜索，找到边缘段的"端点"（转向或中断处）                      │
│     把边缘段归类为 Z 形 / U 形 / L 形                                     │
│                                                                          │
│  ③ 重矢量化（Re-vectorization）                                          │
│     由 Z/U/L 形状反推"原始边缘线"的走向 → 一条斜线                          │
│     计算每个边缘像素被这条斜线截断的面积比例（= 权重因子）                     │
│                                                                          │
│  ④ 混合（Blending）                                                      │
│     按权重因子与邻接像素混合，把"阶梯"抹成"斜坡"                             │
└──────────────────────────────────────────────────────────────────────────┘
```

### 2.2 用图讲清「重矢量化」

```
      屏幕像素（俯视）× 表示边缘像素，亮度已跳变

      实际图像（锯齿）              推断的原始几何（斜线）
      ┌───┬───┬───┬───┐            ┌───┬───┬───┬───┐
      │   │   │ ● │ ● │            │   │ ╱ │   │   │
      ├───┼───┼───┼───┤            ├───┼───┼───┼───┤
      │   │ ● │ ● │   │            │   │   │ ╱ │   │
      ├───┼───┼───┼───┤            ├───┼───┼───┼───┤
      │ ● │ ● │   │   │            │   │   │   │ ╱ │
      ├───┼───┼───┼───┤            ├───┼───┼───┼───┤
      │ ● │   │   │   │            │   │   │   │   │
      └───┴───┴───┴───┘            └───┴───┴───┴───┘
                                           │
        每个 ● 像素被斜线截断的比例            │
        → 就是它与背景混合的权重（0~0.5）      │
                                           ▼
                              权重 0.0  →  纯前景色
                              权重 0.5  →  前景/背景各半
```

**权重因子的计算只需两个量**：当前像素到边缘段两端的距离 `d_left` / `d_right`，以及端点的朝向。这两者组合后查表即可。

### 2.3 从 CPU 到 GPU：Jimenez 的移植（2011）

原始 MLAA 在 CPU 上跑不动实时。Jorge Jimenez 把它移植到 GPU，并做了三件事：

| 改造 | 原因 |
|------|------|
| **预计算 `AreaTex`** | 把"形状 + 距离 → 权重"的解析计算烘进一张查找表，运行时只做一次纹理采样 |
| **预计算 `SearchTex`** | 加速"沿边缘搜索端点"的过程 |
| **利用 GPU 的规则性** | 每个像素独立处理，无分支发散依赖（但搜索循环仍是主要开销） |

`AreaTex` 是这一族的标志性产物：**它不是艺术资源，而是一张数学查找表**（每个像素的 R/G 通道分别存当前像素和共享边缘的邻接像素的权重）。

⚠️ **常见误区**：`AreaTex` / `SearchTex` 不是"噪声图"也不是"边缘图"，不要试图用图像编辑器去"优化"它们。

## 3. FXAA：快，但只做一件事

FXAA（Fast Approximate Anti-Aliasing）由 NVIDIA 的 Timothy Lottes 提出（2009 年 GDC / 2011 年论文版本），设计目标极其明确：**用最少的采样次数和 ALU，尽可能地抹掉可见的几何锯齿**。它是"够用就好"的工程典范。

### 3.1 算法骨架

```
┌──────────────────────────────────────────────────────────────────────────┐
│  FXAA 3.x 主干流程                                                        │
│                                                                          │
│  ① 亮度转换（luma）                                                      │
│     luma = dot(color, vec3(0.299, 0.587, 0.114))                        │
│     （早期 GPU 没有点积指令时用近似式）                                     │
│                                                                          │
│  ② 局部对比度检测                                                        │
│     取 3×3 邻域 luma 的 min/max                                          │
│     contrast = max - min                                                 │
│     if (contrast < threshold) → 非边缘，直接输出                          │
│                                                                          │
│  ③ 判断边缘朝向（水平还是垂直）                                           │
│     比较中心行/列与邻行的 luma 变化量                                      │
│     → 决定后续沿哪个方向搜索                                               │
│                                                                          │
│  ④ 沿边缘搜索端点                                                        │
│     沿垂直于边缘的方向逐像素步进，最多 N 步（N 可配）                        │
│     步长可自适应（边缘越长步长越大），并用 luma 差做收敛判据                   │
│     → 得到边缘段长度与端点位置                                             │
│                                                                          │
│  ⑤ 计算混合方向与偏移量                                                   │
│     把"沿边缘的亮度梯度"映射成"亚像素偏移"                                  │
│     → 决定采样位置与权重（可能取两三个模糊核）                              │
│                                                                          │
│  ⑥ 输出：按权重混合邻域颜色                                               │
└──────────────────────────────────────────────────────────────────────────┘
```

### 3.2 版本谱系与"选哪个版本"

| 版本 | 说明 | 现状 |
|------|------|------|
| **FXAA 1** | 最早的实现，质量较差 | 已淘汰 |
| **FXAA 2** | 加入了"subpixel aliasing"处理，能缓解一部分高频噪声 | 少量老项目 |
| **FXAA 3（PC 版）** | 主版本，参数众多（`FXAA_QUALITY__PRESET 10~39`），质量/性能档位跨度大 | 主流参考实现 |
| **FXAA 3 Console 版** | 为 Xbox 360 / PS3 缩放输出优化，采样点更少 | 历史 |
| **引擎内置版** | UE 的 `FXAA` / Unity 的 `FXAA` 都是同一族的不同简化实现 | **实际用得最多** |

⚠️ **实用提醒**：直接抄论文里的 `FXAA_QUALITY__PRESET` 到现代硬件上通常性能过剩。中低端移动端用 `Preset 10~12` 往往就够了，把省下的 ALU 给别的 pass 更划算。

### 3.3 FXAA 的真实优劣

| ✅ 优点 | ❌ 缺点 |
|--------|--------|
| 极便宜（一次全屏 pass，约 8~12 次纹理采样） | **边缘检测基于亮度，会漏掉等亮度边缘**（如红/绿同亮度的边界） |
| 无额外渲染目标、无历史、无运动矢量 | 高强度时明显模糊整幅图（"肥皂感"） |
| 实现短（几百行，可直接内联） | 细窄结构（栅栏、天线、头发）会被抹断或加粗 |
| 与任何管线兼容（前向/延迟/移动端） | 不解决时间混叠，反而会放大闪烁（模糊掉的是细节而不是采样噪声） |
| 对 alpha 边缘（树叶、栅栏）有一定效果 | 在 HDR 上直接跑会失效，必须先做 tonemap/压缩 |

⚠️ **FXAA 的"过度模糊"是可调的**：`FXAA_QUALITY__PRESET` 里的 `FXAA_REDUCE_MIN` / `FXAA_REDUCE_MUL` 控制模糊量。很多人抱怨 FXAA 糊，其实是用错了 preset。

## 4. SMAA：把 MLAA 做到工程可用

SMAA（Enhanced Subpixel Morphological Anti-Aliasing）由 Jorge Jimenez、Jose I. Echevarria、Tiago Sousa（Crytek）、Diego Gutierrez 发表于 **Eurographics 2012**（《SMAA: Enhanced Subpixel Morphological Antialiasing》，Computer Graphics Forum Vol.31 No.2）。它针对 MLAA 的五个具体缺陷做了补强。

### 4.1 SMAA 修了 MLAA 的哪些问题

| MLAA 的问题 | SMAA 的对策 |
|------------|------------|
| 只看像素数值差，忽略人眼对**局部对比度**的感知 | **局部对比度自适应**：双重阈值，压制"旁边有更强边缘"的弱边缘 |
| 尖锐特征（拐角）被**过度圆滑化** | 检测两像素长的**交叉边缘**，用可调圆滑因子 `r ∈ [0,1]` 控制拐角修正强度 |
| **对角线模式**处理能力差 | 独立的对角线模式识别与查表 |
| 无法重建**亚像素级特征** | 引入"亚像素特征重建"路径（这也是名字里 subpixel 的由来） |
| 高光/着色锯齿 | 作为独立模块处理（与时间重投影模块可组合） |

### 4.2 三阶段流程（**这是 SMAA 的骨架，务必记牢**）

```
┌──────────────────────────────────────────────────────────────────────────┐
│  SMAA 三阶段                                                              │
│                                                                          │
│  阶段 1：边缘检测（Edge Detection）                                       │
│    · 输入：颜色（默认；也可用 luma / 深度）                                 │
│    · 关键：局部对比度自适应双重阈值                                         │
│        e'_l = e_l ∧ (c_l > 0.5 · max(c_t, c_r, c_b, c_l, c_2l))        │
│      → 若邻域存在更强边缘，则当前弱边缘被丢弃                                │
│    · 只检测左、上边界（省算力）                                            │
│    · 输出：边缘图（RG 通道编码水平/垂直边缘）                                │
│    · 可选：depth predication（用深度调制阈值）                             │
│                                                                          │
│  阶段 2：计算混合权重（Blending Weights）                                  │
│    · 沿边缘线搜索端点（最多 MaxSearchSteps 步）                              │
│    · 分类交叉模式 → 查 AreaTex 得覆盖面积（权重）                            │
│    · 搜索步数用 SearchTex 加速                                            │
│    · 处理对角线（MaxDiagSearchSteps）                                     │
│    · 输出：权重图（R/G/B/A 对应上/下/左/右）                                │
│                                                                          │
│  阶段 3：邻域混合（Neighborhood Blending）                                 │
│    · 按权重把当前像素向邻接像素（或其混合结果）靠拢                           │
│    · 输出：抗锯齿后的颜色                                                  │
└──────────────────────────────────────────────────────────────────────────┘
```

### 4.3 AreaTex 与 SearchTex 的编码

| 纹理 | 尺寸（参考实现） | 内容 | 作用 |
|------|----------------|------|------|
| **AreaTex** | 160×560 | 每像素存**两个**权重值（R/G 通道） | 给定"边缘段长度 + 距离"，直接查出覆盖面积权重 |
| **SearchTex** | 64×16 | 8 位编码的搜索步长信息 | 加速阶段 2 的端点搜索 |

⚠️ **对角线处理的边界**：`AreaTex` 覆盖的距离范围有限（对角区域约 20 像素）。搜索步数超过这个范围时收益归零。

### 4.4 变体谱系

| 变体 | 含义 | 适用 |
|------|------|------|
| **SMAA 1x** | 纯空间，单次处理 | 标准后处理路径（最常用） |
| **SMAA S2x** | 输入来自 MSAA 的 2 个样本，分别处理后平均 | 前向渲染 + MSAA 2x |
| **SMAA 4x** | 结合 MSAA 4x 与时间重投影 | 质量优先，成本高 |
| **SMAA T2x** | 1x + 时间重投影（需运动矢量） | 兼顾质量与成本 |
| **Filmic SMAA**（Jimenez 2016） | 针对 HDR/电影化管线的调优版本 | 高质量 HDR 项目 |

**为什么 S2x / 4x 有意义**：MSAA 只解决**几何边缘**，SMAA 只解决**图像空间可见的边缘**。两者结合可以同时获得"真实的几何覆盖信息"和"对纹理/着色边缘的清理"。这也是 SMAA 各变体存在的原因——它们不是同一件事的强弱版本，而是**覆盖不同的信号源**。

### 4.5 实现要点与代价

| 项 | 说明 |
|----|------|
| **在什么空间做** | 必须在 **LDR / tonemap 之后**，或用压缩曲线（如 `t = s/(1+s)`）先把 HDR 压到感知空间 |
| **边缘检测输入** | luma 最简单；颜色更准；深度可作 predication 辅助（不要单独用深度当主判据） |
| **成本结构** | 阶段 1、2 是固定成本；阶段 3 与边缘像素数量相关 |
| **优化手段** | 用 append buffer 收集边缘像素 + indirect dispatch，只让真正有边缘的像素付阶段 2 的代价 |
| **调参三件套** | `Threshold`（边缘灵敏度）、`MaxSearchSteps`（长直边质量）、`CornerRounding`（拐角锐度，默认 0.25） |

## 5. 其他图像空间方案

### 5.1 CMAA / CMAA2

Intel 提出的 Conservative Morphological Anti-Aliasing（保守形态抗锯齿），设计目标是"**只处理确定为锯齿的地方，绝不误伤正常细节**"——名字里的 conservative 就是"保守"。CMAA2 是其在 DX12/Vulkan 上的重写版，主打**低开销 + 低模糊**，常用于集显平台。

| 特点 | 说明 |
|------|------|
| 本地形状分析 | 通过 Z 形/U 形模式判断，且要求模式在多个方向一致才处理 |
| 抗过度模糊 | 与 FXAA 相比整体更锐利，误检更少 |
| 成本 | 介于 FXAA 与 SMAA 之间，通常低于 SMAA |

### 5.2 与"几何感知后处理"的区别

有一类技术**在图像空间工作，但会使用几何信息辅助**，容易被混进这一族，实际不是：

| 技术 | 用的额外信息 | 本质 |
|------|-------------|------|
| **SMAA + depth predication** | 深度缓冲 | 仍是图像空间滤波，深度只用于调阈值 |
| **MLAA/SMAA + 法线缓冲** | G-Buffer | 同上 |
| **Analytic AA / 覆盖率输出** | 三角形几何 | ❌ 不算后处理——它在光栅化阶段直接算覆盖面积（见第 01 篇） |
| **TAA** | 运动矢量 + 历史帧 | ❌ 不算纯后处理——它是时间采样（见第 04 篇） |

## 6. 这一族的六个结构性缺陷

⚠️ 这一节是本篇的核心。理解了这六条，就不会再对后处理 AA 抱有不切实际的期待。

| # | 缺陷 | 机制 | 表现 |
|---|------|------|------|
| 1 | **本质是模糊，不是重建** | 用低通滤波抹掉高频 | 整体锐度下降，纹理细节变软（4K 下尤其明显） |
| 2 | **边缘检测是启发式的** | 靠亮度阈值猜边缘位置 | 漏检（等亮度边缘）、误检（高频纹理当边缘）、错向（细窄结构） |
| 3 | **不解决时间混叠** | 只看当前帧 | 运动时细几何仍闪烁；且因为模糊了细节，闪烁反而"更均匀地糊" → 有些人觉得更难看 |
| 4 | **对纹理内部高频无解** | 摩尔纹在像素上呈现为噪点而非阶梯 | 开 FXAA 后摩尔纹变成"模糊的噪点"，噪点还在 |
| 5 | **细结构会被破坏** | 栅栏、天线、电线、头发宽度接近 1 像素 | 被加粗、断裂或抹掉（"天线消失"是经典投诉） |
| 6 | **必须在正确的位置做** | HDR / HUD / 分辨率任意一项错位就失效 | 详见 §7 |

```
┌──────────────────────────────────────────────────────────────────────────┐
│  缺陷 1/3 的共同后果：为什么"开了 FXAA 还是闪"                            │
│                                                                          │
│   闪烁 = 时间维度上的采样不足                                              │
│   后处理 AA 只做空间维度的平滑                                             │
│   → 空间平滑无法替代时间采样                                               │
│                                                                          │
│   类比：把一张模糊的照片连拍 30 张循环播放，前景依然会抖                    │
│        模糊只是让抖动幅度看起来小一点，抖动本身没被解决                      │
└──────────────────────────────────────────────────────────────────────────┘
```

## 7. 工程实现要点

### 7.1 位置：三处必须对齐

```
┌──────────────────────────────────────────────────────────────────────────┐
│  正确的 pass 顺序                                                          │
│                                                                          │
│  HDR 场景渲染                                                            │
│      │                                                                   │
│      ▼                                                                   │
│  [ Bloom / DoF 等空间后处理 ]  ← 这些通常在 HDR 中                        │
│      │                                                                   │
│      ▼                                                                   │
│  [ Tonemap + 颜色分级 ]        ← 到这里才是 LDR / 感知空间                 │
│      │                                                                   │
│      ▼                                                                   │
│  [ 后处理 AA：FXAA / SMAA ]    ← ⚠️ 必须在这里                            │
│      │                                                                   │
│      ▼                                                                   │
│  [ 分辨率还原（如果是低分辨率渲染） ]                                       │
│      │                                                                   │
│      ▼                                                                   │
│  [ UI / HUD 以原生分辨率合成 ]  ← ⚠️ 必须在 AA 之后                       │
│      │                                                                   │
│      ▼                                                                   │
│  输出                                                                     │
└──────────────────────────────────────────────────────────────────────────┘
```

| 错位 | 后果 |
|------|------|
| **在 tonemap 之前做** | HDR 亮度范围巨大，固定阈值失效 → 要么漏检、要么误检满屏 |
| **在 UI 之前做**（错误顺序：AA 在 UI 之后） | UI 文字/图标被模糊、被误判为边缘而扭曲 |
| **在 UI 之前做**（正确顺序，但 UI 画在低分辨率层） | UI 被放大变糊——这是**分辨率**问题，不是 AA 顺序问题 |
| **在 bloom 之前做** | Bloom 从模糊过的图像取亮度，光晕形态失真（一般可接受，但不推荐） |

### 7.2 边缘检测阈值的调法

| 参数 | 调高 | 调低 |
|------|------|------|
| `EdgeThreshold`（局部对比度下限） | 更少误检、更少模糊，但漏掉弱边缘 | 边缘更全，但噪点/纹理可能被当边缘 |
| `LocalContrastAdaptation`（适应强度） | 强边缘附近的弱边缘被压制（SMAA 的强项） | 弱边缘也能处理，但会更糊 |
| `MaxSearchSteps` | 长直边更平滑 | 长直边出现"断裂式"处理 |

**实用调参流程**：

```
① 先设 LocalContrastAdaptation，压制纹理误检（这是最常见的伪影来源）
② 再调 EdgeThreshold，直到"噪点不被当边缘"且"真实几何边缘被保住"
③ 最后调 MaxSearchSteps，只需覆盖画面中最长的直线边缘
④ 若仍模糊：检查是否在 tonemap 之后；若已正确，则这是该方案的固有上限
```

### 7.3 与锐化配合（sharpen 的定位）

后处理 AA 之后加一个轻量 sharpen（如 CAS、unsharp mask）是常见组合：

| 组合 | 效果 | 风险 |
|------|------|------|
| FXAA + 轻 sharpen | 找回部分锐度，观感明显改善 | 过锐会出现白边/黑边（halo） |
| SMAA + 轻 sharpen | 最佳平衡，SMAA 本身模糊较少 | 同上 |
| 强 sharpen + 任何 AA | 会把 AA 的梯度放大成"描边" | 强烈不建议 |

⚠️ **sharpen 不能恢复信息**。它只增强已有的梯度对比，本质是"把模糊做成锐利的模糊"。

### 7.4 编译器 / 平台注意事项

| 项 | 说明 |
|----|------|
| **HDR 输出格式** | 用 `R11G11B10F` 或 `RGBA16F` 存色调映射后的图像，避免二次量化损失 |
| **采样点数量** | FXAA 的 8~12 次采样在移动端也可能显著（TBR 下每次采样都是带宽） |
| **导数不可用** | 若某个实现依赖 `ddx/ddy`，注意 2×2 quad 语义与 VRS 的冲突（见第 02 篇） |
| **与 VRS 冲突** | VRS 降采样率会放大导数、破坏边缘检测精度；建议后处理 AA 阶段禁用 VRS |
| **和 TAA 的顺序** | 若两者共存，通常 **TAA 在后处理 AA 之前**（TAA 负责时间+几何，后处理 AA 清理残差），但要避免重复模糊 |

## 8. 选型速查

| 场景 | 推荐 | 理由 |
|------|------|------|
| 低端移动设备，几何简单 | **FXAA** | 成本最低，效果够用 |
| 卡通风 / 平面色块 / 矢量风 | **SMAA 1x** | 边缘锐利，不糊平面色块 |
| 前向渲染 + 有 MSAA 预算 | **MSAA + SMAA（S2x）** | 两条信号线各管一段，质量最高 |
| 有运动矢量、追求综合质量 | **TAA（见第 04 篇）**，不用本族 | 本族不解决时间混叠 |
| 有 ray tracing / 随机采样噪声 | **TAA / 降噪器**，本族只做收尾 | 本族的边缘检测会把噪声误判为边缘 |
| 纯 UI / 2D 场景 | **SDF / 解析 AA（见第 02、05 篇）** | 本族会糊掉字形 |

## 9. 小结

| 要点 | 说明 |
|------|------|
| **后处理 AA 是"修图"不是"采样"** | 它改变不了采样率，只能把已产生的阶梯混成斜坡 |
| **MLAA → SMAA 的演进主线是"减少误检与误伤"** | 局部对比度自适应、拐角保持、对角模式是三个关键补丁 |
| **SMAA 的三阶段要记牢** | 边缘检测（含局部对比度自适应）→ 权重计算（AreaTex/SearchTex）→ 邻域混合 |
| **SMAA 变体不是强弱版本** | 1x / S2x / 4x / T2x 覆盖不同的信号源与预算组合 |
| **FXAA 的关键是 preset** | 抱怨"糊"通常是用错了 `FXAA_QUALITY__PRESET` |
| **必须在 LDR 且 tonemap 之后做** | 且必须在 UI 之前；UI 分辨率与 AA 顺序是两个独立问题 |
| **六个结构缺陷无法通过调参消除** | 模糊、误检、时间混叠、纹理高频、细结构破坏、位置依赖 |
| **它是"无状态"的，这是优点** | 无历史、无运动矢量、无额外 RT → 廉价、鲁棒、易集成；代价是质量上限低 |
| **现代管线的常见搭配** | TAA 负责时间与几何，SMAA/FXAA 只做残差收尾（或干脆不用） |
| **别忘 mipmap** | 纹理摩尔纹这类问题后处理 AA 完全无解，必须在采样侧解决（第 02 篇） |
