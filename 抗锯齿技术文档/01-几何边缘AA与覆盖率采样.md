# 抗锯齿技术 — 几何边缘 AA 与覆盖率采样

> 本文档是「抗锯齿（AA）技术」系列文档的第 **1** 篇。本篇专讲**几何边缘混叠**及其对策：MSAA 的真实机制、CSAA/EQAA 的准确定义、SSAA 家族的变体、Alpha-to-Coverage 的硬限制，以及 Vulkan 侧的完整 API 路径。

---

## 1. 几何边缘锯齿的成因

光栅化的核心判定是**二值的**：一个像素要么被三角形覆盖，要么不覆盖。

```
┌──────────────────────────────────────────────────────────────────────────┐
│  光栅化的二值化                                                           │
│                                                                          │
│      三角形边界（理想情况是连续的）                                        │
│              ╲                                                           │
│    ┌────┬────┬────┐                                                      │
│    │    │ ▓▓ │ ▓▓ │   ▓ = 完全覆盖（1）                                    │
│    ├────┼────┼────┤   ░ = 完全未覆盖（0）                                  │
│    │    │ ░▓ │ ▓▓ │   ▓░ = 部分覆盖 —— 问题就出在这里                       │
│    ├────┼────┼────┤                                                      │
│    │    │ ░░ │ ░▓ │      部分覆盖被判成 0 或 1，产生"阶梯"                   │
│    └────┴────┴────┘                                                      │
│                                                                          │
│  本质：每个像素只有一个采样点（通常是中心），覆盖率只有 0/1 两种取值          │
└──────────────────────────────────────────────────────────────────────────┘
```

**关键量化**：一个像素的覆盖率精度只有 1 位 → 边缘位置误差可达 ±0.5 像素。

**解决思路**：让每个像素能表达**多级覆盖率**。这就是整个「覆盖率采样」家族的目标。

## 2. MSAA：机制全景

### 2.1 一句话定义

**MSAA 为每个像素维护 N 个采样点，覆盖判定、深度、模板都按采样点存储，但片元着色通常只在像素中心执行一次。**

### 2.2 完整机制拆解

```
┌──────────────────────────────────────────────────────────────────────────┐
│  一个 4x MSAA 像素的内部结构                                              │
│                                                                          │
│  ┌────────────────────────────────┐                                      │
│  │  像素（1 个）                   │                                      │
│  │                                │                                      │
│  │   s0 ○        ○ s1            │  ← 4 个采样点（按硬件定义的分散网格）    │
│  │         ● 着色点               │  ← 片元着色在这一个点上执行            │
│  │   s2 ○        ○ s3            │                                      │
│  │                                │                                      │
│  └────────────────────────────────┘                                      │
│                                                                          │
│  每个采样点独立存储：                                                      │
│    · coverage（是否被该图元覆盖）→ 二进制                                 │
│    · depth / stencil                                                     │
│    · color（该采样点的颜色值）                                             │
│                                                                          │
│  着色：整个像素**只着色一次**（在 ● 处）                                     │
│        着色结果按 coverage 复制到被覆盖的采样点                              │
│                                                                          │
│  Resolve：把 N 个采样点的颜色按权重平均 → 1 个最终像素颜色                    │
└──────────────────────────────────────────────────────────────────────────┘
```

### 2.3 与 SSAA 的机制对比

```
        MSAA 4x                          SSAA 4x
  ┌────────────────────┐          ┌────────────────────┐
  │                    │          │                    │
  │  ○   ○             │          │  ●   ●             │  ● = 完整着色
  │       ●            │  ← 1 次  │                    │  ← 4 次着色
  │  ○   ○             │    着色   │  ●   ●             │
  │                    │          │                    │
  └────────────────────┘          └────────────────────┘

  存储：4 × (cov + depth + color)   存储：4 × (depth + color)
  着色：1 次                        着色：4 次
  纹理采样：1 次                     纹理采样：4 次
  → 几何边缘质量接近，纹理/着色质量差很远
```

### 2.4 MSAA 的采样位置

采样点是**硬件定义的分散网格**，常见为旋转网格（rotated grid）以打散规律性伪影。

⚠️ **MSAA 的一个固有局限**：采样位置**固定**。如果几何比一个像素还细（亚像素宽度），且刚好穿过采样点之间的空隙，它会**完全丢失**（subpixel geometry dropout）。

这正是：
- 细铁丝网、远距离栅栏、细树枝在 MSAA 下会「闪烁消失」
- 必须靠 TAA 或 SSAA 才能缓解

**Vulkan 侧的相关能力**：

| 能力 | 扩展 / 接口 | 说明 |
|------|-----------|------|
| 查询多样本属性 | `vkGetPhysicalDeviceMultisamplePropertiesEXT` | 查询 `maxSampleLocationGridSize`（采样位置网格上限） |
| **自定义采样位置** | `VK_EXT_sample_locations` | 允许应用**指定**采样位置，可用于可编程 AA / 可编程 resolve |
| 标准采样位置 | `VK_EXT_sample_locations` 的 `VkSampleLocationEXT` | 也可用于查询实现的标准采样位置 |

⚠️ `VK_EXT_sample_locations` 需要运行时查询支持，且不是所有移动端 GPU 都支持。

### 2.5 Sample Shading：让 MSAA 也能提高着色采样率

⚠️ 这是原分类框架没提的一个关键开关，它把 MSAA 和 SSAA 之间的界限变得模糊了。

| 模式 | 行为 | 效果 |
|------|------|------|
| **默认（sample shading off）** | 每像素着色一次 | 只解决几何边缘 |
| **Sample shading on**（`minSampleShading` 提高） | 按采样点着色，着色次数随覆盖率上升 | 部分解决着色/纹理高频，向 SSAA 靠拢，代价上升 |

Vulkan 侧：

```cpp
// 开启 sample shading：让片元着色按采样点执行
VkPipelineMultisampleStateCreateInfo ms{};
ms.sampleShadingEnable = VK_TRUE;
// minSampleShading = 1.0 → 强制每个被覆盖的采样点都着色
// minSampleShading = 0.25 → 允许实现在采样点足够多时按像素着色（性能更好）
ms.minSampleShading   = 1.0f;
ms.rasterizationSamples = VK_SAMPLE_COUNT_4_BIT;
```

⚠️ **代价**：`minSampleShading = 1.0` 会让着色成本随覆盖率上升（最坏情况接近 ×N），MSAA 的成本优势会被吃掉。所以实践中很少全局开启。

**但有一个高价值的应用场景**：只对**特定的高频材质**（如植被、水、金属）使用 `minSampleShading = 1.0`，其他地方保持默认。这比全局 SSAA 便宜得多。

### 2.6 MSAA 的存储与带宽账本

以 1080p、4x MSAA、`RGBA8` 颜色 + `D32F` 深度为例：

```
┌──────────────────────────────────────────────────────────────────────────┐
│  单像素存储                                                                │
│                                                                          │
│  ┌─────────────────┬──────────┬──────────┬──────────────┐               │
│  │ 项目            │ 无 MSAA   │ 4x MSAA  │ 倍数          │               │
│  ├─────────────────┼──────────┼──────────┼──────────────┤               │
│  │ Color           │ 4 B      │ 16 B     │ ×4           │               │
│  │ Depth           │ 4 B      │ 16 B     │ ×4           │               │
│  │ Stencil         │ (含在上)  │ (含在上)  │ ×4           │               │
│  │ 合计            │ 8 B      │ 32 B     │ ×4           │               │
│  └─────────────────┴──────────┴──────────┴──────────────┘               │
│                                                                          │
│  1080p 全屏：8 B → 32 B/px                                               │
│    无 MSAA：约 16.6 MB                                                  │
│    4x MSAA：约 66.4 MB                                                  │
│                                                                          │
│  ⚠️ 加上 UBWC / AFBC 压缩，实际占用会更小；                            │
│     但 MSAA 数据的压缩效率通常低于单采样数据，所以压缩收益会打折。           │
└──────────────────────────────────────────────────────────────────────────┘
```

**带宽账本（关键差异点）**：

| 架构 | Resolve 行为 | 带宽代价 |
|------|-------------|---------|
| **桌面 IMR** | 把 N 个样本从显存读出、平均、写回 | **读写主存 ×N + 写回 1x** |
| **移动 TBDR** | 在**片上 tile memory** 内完成 resolve，只把最终像素写出 | **几乎为零的额外总线流量** |

⚠️ **这就是「MSAA 在移动端反而相对便宜」的硬件原因**。相关细节见本工作区《移动端 GPU 架构文档》。

### 2.7 MSAA 的能力边界

| 能解决 | 不能解决 |
|--------|---------|
| 三角形边界阶梯 | 纹理缩小时的摩尔纹 |
| 几何边缘的时序闪烁（部分） | 高光走样（specular aliasing） |
| 与 A2C 配合时的 alpha 边缘 | 法线贴图高频噪点 |
| — | 亚像素几何的 dropout |
| — | 透明物体的混合边缘（顺序相关） |

## 3. 覆盖率采样的增强变体

### 3.1 CSAA 与 EQAA

**核心思想**：MSAA 的成本主要来自**颜色/深度样本**的存储。那就把「覆盖率样本」和「颜色/深度样本」解耦——多存覆盖率，少存颜色。

```
┌──────────────────────────────────────────────────────────────────────────┐
│  CSAA / EQAA 的样本结构（以 16x CSAA 为例）                                │
│                                                                          │
│  ┌────────────────────────────────────┐                                  │
│  │  颜色/深度样本：4 个（●）             │  ← 决定混合的精度               │
│  │                                    │                                  │
│  │   ● ○ ○ ○ ○ ○ ○ ○                 │  ← 覆盖率样本：16 个（○）        │
│  │   ○ ○ ○ ○ ○ ○ ○ ○                 │     只存二进制覆盖值，不存颜色    │
│  │   ○ ○ ○ ○ ○ ○ ○                   │                                  │
│  │                                    │                                  │
│  └────────────────────────────────────┘                                  │
│                                                                          │
│  覆盖率样本用来**引导** 4 个颜色/深度样本的混合                            │
│  → 覆盖率精度接近 16x MSAA，存储代价接近 4x MSAA                          │
└──────────────────────────────────────────────────────────────────────────┘
```

**具体模式**（Beyond3D 的整理，格式为「颜色/深度样本数 / 覆盖率样本数」）：

| NVIDIA CSAA 模式 | 颜色/深度样本 | 覆盖率样本 |
|-----------------|-------------|-----------|
| 8x CSAA | 4x | 8 |
| 16x CSAA | 4x | 16 |
| 16xQ CSAA | 8x | 16 |
| 32x CSAA | 8x | 32 |

| AMD EQAA 模式 | 颜色/深度样本 | 覆盖率样本 |
|--------------|-------------|-----------|
| 4x EQAA | 2x | 4 |
| 8x EQAA | 4x | 8 |
| 16x EQAA | 8x | 16 |

⚠️ **关键限制**：CSAA/EQAA 提高的是**覆盖率精度**，但颜色混合仍然基于有限的颜色样本。所以：

- ✅ 在**细边几何**（栅栏、树叶、细线）上明显优于同颜色样本数的 MSAA
- ❌ 在**高频颜色内容**上仍不如真正的高倍 MSAA
- ⚠️ 额外覆盖率样本对性能影响很小（Beyond3D 的结论）

**当前状态**：

| 技术 | 厂商 | 引入 | 现状 |
|------|------|------|------|
| CSAA | NVIDIA | GeForce 8000 系（2006） | **Maxwell（GTX 750 Ti / 800M / 900 系）及更新已移除支持** |
| QCSAA | NVIDIA | 同上 | 同上 |
| EQAA | AMD | Radeon HD 6900 系（2010） | 新架构不再宣传 |
| **MFAA** | NVIDIA | GTX 900 系起 | CSAA 的**后继**，用 MSAA + 时序采样位置抖动模拟更高倍 MSAA |
| QSAA（Quincunx） | NVIDIA | 早期 | 2x QSAA ≈ 3x MSAA 质量 |

⚠️ **MFAA 的两个坑**（PCGamingWiki 整理）：
1. **低于 40 FPS 时工作不正常**，运动时会出现涂抹和模糊
2. 可能禁用 D3D11 的 Driver Command Lists，**破坏多线程渲染**（在 CPU-bound 时反而变慢）

**实践结论**：CSAA/EQAA/MFAA 属于**历史技术**，在现代 GPU 上要么已移除，要么被 TAA/超分取代。了解它们的价值在于理解「覆盖率样本与颜色样本可以解耦」这个设计思想——这个思想在移动端的 `VK_EXT_multisampled_render_to_single_sampled` 里以另一种形式回来了。

## 4. SSAA 家族

### 4.1 SSAA 的本质

**SSAA 让每个子像素完整走一遍管线**（几何、着色、纹理采样全部 ×N）。因此它同时解决几何边缘、着色高频、纹理高频——代价是**全管线 ×N**。

### 4.2 变体全景

| 变体 | 全称 | 说明 |
|------|------|------|
| **SSAA / FSAA** | Super-Sampling / Full-Screen AA | 通用称呼 |
| **OGSSAA** | Ordered Grid SSAA | 规则网格。模式有 2x1 / 1x2 / 2x2 / 3x3 / 4x4（NVIDIA Profile Inspector 可配） |
| **SGSSAA** | Sparse Grid SSAA | 稀疏网格，质量更高但代价极大。驱动侧仅 DX9 与较老 OpenGL 后端支持全覆盖版本 |
| **TrSSAA** | Transparency SGSSAA | **只对透明物体**做稀疏网格超采样，用于 alpha test 植被。性价比高得多 |
| **HSAA** | Hybrid Sampling AA | SSAA + MSAA 混合。在 SGSSAA 不工作或过于模糊时可用 |
| **RGSS** | Rotated Grid SSAA | 旋转网格，经典 4x RGSS 是早期常用方案 |
| **DSR / VSR** | Dynamic / Virtual Super Resolution | 在更高分辨率渲染再降采样——**本质就是 SSAA**，只是通过显示分辨率机制实现 |

### 4.3 与其他方案的关系

```
┌──────────────────────────────────────────────────────────────────────────┐
│  SSAA 的定位：质量上限，成本上限                                           │
│                                                                          │
│   质量  ▲                                                                │
│         │   SSAA 16x ────────── 最贵，质量最好                            │
│         │       │                                                        │
│         │   SSAA 4x ──┐                                                  │
│         │       │     │  TAA / DLSS 4 在这个区间（用时间/先验换质量）        │
│         │   MSAA 8x ──┼───────┐                                          │
│         │       │     │       │                                          │
│         │   MSAA 4x ──┘   FXAA/SMAA 在这里（最便宜，质量最低）             │
│         │       │                                                        │
│         │   无 AA ─┘                                                     │
│         └────────────────────────────────────────▶ 成本                  │
└──────────────────────────────────────────────────────────────────────────┘
```

**什么时候还值得用 SSAA**：

| 场景 | 理由 |
|------|------|
| 静态截图 / 视频录制 / 离线渲染 | 不计实时成本 |
| VR 的高端 PC 方案 | 延迟敏感，不能容忍 TAA 的鬼影 |
| 有免费性能余量的独立游戏 | 简单可靠，无时序伪影 |
| 与 TAA 组合做「参考基准」 | 用于验证 TAA 的质量 |

## 5. Alpha-to-Coverage（A2C）

### 5.1 机制

A2C 把片元着色器输出的 **alpha 值转换为 MSAA 的 coverage mask**：

```
┌──────────────────────────────────────────────────────────────────────────┐
│  Alpha-to-Coverage 的转换                                                  │
│                                                                          │
│  shader 输出 alpha = 0.75，MSAA 4x                                       │
│         │                                                                │
│         ▼                                                                │
│  4 个采样点中，按 alpha 比例随机/规律地设置 coverage                          │
│      ● ●       （3/4 个采样点被覆盖 → 覆盖率 75%）                          │
│      ● ○                                                                │
│         │                                                                │
│         ▼                                                                │
│  深度/模板写入只针对被覆盖的采样点 → **深度是正确的**                         │
└──────────────────────────────────────────────────────────────────────────┘
```

### 5.2 价值：解决 alpha test 的两个老大难

| 问题 | A2C 的改善 |
|------|-----------|
| alpha test 的**硬边**（只有一个阈值，边缘锯齿严重） | 用覆盖率表达中间值 |
| alpha test 物体的**排序问题**（写深度但半透明的部分被剔掉） | 深度按覆盖采样点写入，物理正确 |

### 5.3 两个硬限制

⚠️ **限制一：质量受 MSAA 采样数限制**

| MSAA 采样数 | 可表达的覆盖率级数 | 视觉效果 |
|------------|-----------------|---------|
| 2x | 3 级（0 / 0.5 / 1） | 很差 |
| 4x | 5 级 | 明显条带 |
| 8x | 9 级 | 可用 |
| 16x | 17 级 | 较好 |

**所以 A2C 通常需要 8x 或更高的 MSAA 才能达到可接受质量**——这在移动端不现实。

⚠️ **限制二：在移动端破坏隐面剔除**

A2C 相当于**修改 coverage mask**。ARM 官方把它归入 Mali Offline Compiler 的 `Modifies coverage` 检查项：

> "This shows if a fragment shader has a coverage mask that the shader program can change, for example by using a `discard` statement. **Shaders with modifiable coverage must use a late ZS update, which reduces efficiency of early ZS testing for later fragments at the same coordinate.**"

后果：

```
A2C 开启
    │
    ▼
coverage mask 可变 → 必须 late ZS update
    │
    ▼
early ZS 测试与 HSR 效率下降
    │
    ▼
   在移动端 TBDR 上直接损失核心优化
```

**移动端对策**：
1. 优先用 **alpha test + TAA**（TAA 能很好地处理 alpha test 边缘）
2. 或者用**预乘 alpha + 不透明排序**（如果能接受）
3. 或者用 **dithered alpha + TAA**（stochastic transparency），让 TAA 去噪
4. 只有在 Forward 管线 + 高倍 MSAA + 非移动端时，A2C 才是好选择

### 5.4 Vulkan 侧

```cpp
// Alpha-to-Coverage 需要同时满足：
// 1. 管线的 multisample state 开启 alphaToCoverageEnable
// 2. 渲染目标必须是多采样的
VkPipelineMultisampleStateCreateInfo ms{};
ms.rasterizationSamples  = VK_SAMPLE_COUNT_4_BIT;   // ≥4x，否则质量太差
ms.alphaToCoverageEnable = VK_TRUE;                  // ★ 开启 A2C
// ⚠️ alphaToOneEnable 与 A2C 语义不同：
//    alphaToOne 把 alpha 强制为 1（用于旧式 alpha 处理），现代代码不应使用
ms.alphaToOneEnable      = VK_FALSE;

// shader 侧只需正常输出 alpha
// layout(location = 0) out vec4 outColor;
// outColor = vec4(rgb, alphaFromTexture);
```

## 6. 解析 AA（Analytic / Coverage AA）

### 6.1 机制

不采样、不后处理，而是**解析地计算覆盖面积**，直接输出正确的覆盖率或 alpha。

### 6.2 三个主要应用场景

| 场景 | 做法 |
|------|------|
| **字体光栅化** | 计算字形轮廓与像素的相交面积 → 生成灰度 alpha 图（这就是系统字体 AA 的原理） |
| **程序化图形 / SDF** | 用距离场 + `smoothstep` 算出边缘覆盖率 |
| **Shader 内的解析导数 AA** | 用 `fwidth` / `ddx` / `ddy` 估算变化率，做自适应平滑 |

```glsl
// 程序化图案的解析 AA：用导数自适应半宽
float checkerboardAA(vec2 uv) {
    vec2 w = fwidth(uv);                          // 屏幕空间导数
    vec2 i = 2.0 * (abs(fract(uv) - 0.5) - 0.5);
    float wa = max(w.x, w.y);
    vec2 a = 1.0 - smoothstep(0.0, wa, abs(i));
    return a.x * a.y + (1.0 - a.x) * (1.0 - a.y);
}
// ⚠️ fwidth 在一个 2x2 quad 内计算，如果 shader 有分支分歧会出错
//    且在高频区域会过度模糊，需要与实际需求权衡
```

### 6.3 优缺点

| ✅ 优点 | ❌ 缺点 |
|--------|--------|
| 成本极低（没有额外采样） | 只适用于能解析表达的形状/图案 |
| 结果**精确**（不是猜的） | 需要专用实现（字体栈、SDF 生成管线） |
| 无时序伪影 | 对复杂几何无能为力 |
| 天然支持任意缩放（SDF） | — |

## 7. Vulkan 实践：MSAA 的完整配置

### 7.1 基础配置

```cpp
// ── 1. 创建多采样渲染目标 ─────────────────────────────────────────────────
VkImageCreateInfo ici{ VK_STRUCTURE_TYPE_IMAGE_CREATE_INFO };
ici.imageType     = VK_IMAGE_TYPE_2D;
ici.format        = VK_FORMAT_R8G8B8A8_UNORM;
ici.extent        = { width, height, 1 };
ici.samples       = VK_SAMPLE_COUNT_4_BIT;          // ★ 多采样
// ⚠️ 移动端 TBDR 上多采样附件的 usage 仍是 COLOR_ATTACHMENT
ici.usage         = VK_IMAGE_USAGE_COLOR_ATTACHMENT_BIT;
ici.tiling        = VK_IMAGE_TILING_OPTIMAL;
// ⚠️ 不要加 MUTABLE_FORMAT，会禁用 UBWC/AFBC 压缩

// ── 2. 创建单采样 resolve 目标（这是最终被采样的那张）──────────────────────
VkImageCreateInfo resolveIci = ici;
resolveIci.samples = VK_SAMPLE_COUNT_1_BIT;
resolveIci.usage   = VK_IMAGE_USAGE_COLOR_ATTACHMENT_BIT |
                     VK_IMAGE_USAGE_SAMPLED_BIT;     // ★ 之后要采样

// ── 3. 附件描述：多采样附件的 storeOp 可以 DONT_CARE ──────────────────────
VkAttachmentDescription msaa{};
msaa.format         = VK_FORMAT_R8G8B8A8_UNORM;
msaa.samples        = VK_SAMPLE_COUNT_4_BIT;
msaa.loadOp         = VK_ATTACHMENT_LOAD_OP_CLEAR;
msaa.storeOp        = VK_ATTACHMENT_STORE_OP_DONT_CARE;  // ★★ 关键：多样本数据不写回
msaa.initialLayout  = VK_IMAGE_LAYOUT_UNDEFINED;
msaa.finalLayout    = VK_IMAGE_LAYOUT_COLOR_ATTACHMENT_OPTIMAL;

VkAttachmentDescription resolve{};
resolve.format      = VK_FORMAT_R8G8B8A8_UNORM;
resolve.samples     = VK_SAMPLE_COUNT_1_BIT;
resolve.loadOp      = VK_ATTACHMENT_LOAD_OP_DONT_CARE;
resolve.storeOp     = VK_ATTACHMENT_STORE_OP_STORE;      // ★ resolve 结果要留
resolve.initialLayout = VK_IMAGE_LAYOUT_UNDEFINED;
resolve.finalLayout   = VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL;

VkAttachmentReference colorRef{ 0, VK_IMAGE_LAYOUT_COLOR_ATTACHMENT_OPTIMAL };
VkAttachmentReference resolveRef{ 1, VK_IMAGE_LAYOUT_COLOR_ATTACHMENT_OPTIMAL };

VkSubpassDescription subpass{};
subpass.pipelineBindPoint    = VK_PIPELINE_BIND_POINT_GRAPHICS;
subpass.colorAttachmentCount = 1;
subpass.pColorAttachments    = &colorRef;
subpass.pResolveAttachments  = &resolveRef;   // ★ 自动 resolve
```

⚠️ **注意多采样附件的 `storeOp = DONT_CARE`**：这是移动端的关键优化——多样本数据不需要写回主存，因为 resolve 已经在片上完成了。在桌面 IMR 上这个设置同样有意义（省一次写回带宽）。

### 7.2 手动 Resolve 的替代路径

某些场景（如需要在 resolve 前插入额外操作）用 `vkCmdResolveImage`：

```cpp
// 手动 resolve：把一个多采样 image 解析到单采样 image
VkImageResolve region{};
region.srcSubresource = { VK_IMAGE_ASPECT_COLOR_BIT, 0, 0, 1 };
region.dstSubresource = { VK_IMAGE_ASPECT_COLOR_BIT, 0, 0, 1 };
region.extent         = { width, height, 1 };

// ⚠️ 使用 vkCmdResolveImage 时，多采样附件必须 storeOp = STORE（否则数据已丢）
vkCmdResolveImage(cmd, msaaImage, VK_IMAGE_LAYOUT_TRANSFER_SRC_OPTIMAL,
                       resolveImage, VK_IMAGE_LAYOUT_TRANSFER_DST_OPTIMAL,
                       1, &region);
```

**两种路径的取舍**：

| 路径 | 优点 | 缺点 |
|------|------|------|
| `pResolveAttachments`（自动） | 驱动可优化（TBDR 上完全片上） | 位置固定在 subpass 结束 |
| `vkCmdResolveImage`（手动） | 灵活，可插入中间操作 | 强制多样本数据 store，移动端代价大 |

### 7.3 省存储的现代方案：`VK_EXT_multisampled_render_to_single_sampled`

⚠️ **这个扩展对移动端特别有价值**：它让应用以 MSAA 方式渲染，但**只分配单采样存储**（resolve 隐式发生在片上/片内）。

```
┌──────────────────────────────────────────────────────────────────────────┐
│  传统 MSAA  vs  multisampled_render_to_single_sampled                     │
├──────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│  传统：                                                                  │
│    · 分配 4x 多采样 image（存储 ×4）                                       │
│    · 分配 1x resolve image                                               │
│    · 或使用 LAZILY_ALLOCATED（memoryless）内存类型省存储                   │
│                                                                          │
│  新扩展：                                                                │
│    · 只分配 1x image，声明它作为多采样渲染的目标                             │
│    · 多样性只在片上/内部存在，不占显存                                      │
│    · 自动 resolve                                                         │
│                                                                          │
│  → 存储节省可达 75%（4x 场景），带宽也显著下降                              │
└──────────────────────────────────────────────────────────────────────────┘
```

**用法骨架**：

```cpp
// ① 查询特性
VkPhysicalDeviceMultisampledRenderToSingleSampledFeaturesEXT feat{};
feat.sType = VK_STRUCTURE_TYPE_PHYSICAL_DEVICE_MULTISAMPLED_RENDER_TO_SINGLE_SAMPLED_FEATURES_EXT;
// feat.multisampledRenderToSingleSampled 必须为 VK_TRUE

// ② 在 VkRenderingInfo / VkRenderPass 上声明
VkMultisampledRenderToSingleSampledInfoEXT msrtss{};
msrtss.sType = VK_STRUCTURE_TYPE_MULTISAMPLED_RENDER_TO_SINGLE_SAMPLED_INFO_EXT;
msrtss.multisampledRenderToSingleSampledEnable = VK_TRUE;
msrtss.rasterizationSamples = VK_SAMPLE_COUNT_4_BIT;  // ★ 逻辑上按 4x 光栅化
// 挂到 VkRenderingInfo::pNext（或 subpass 的 pNext）

// ③ image 本身是单采样的
// ici.samples = VK_SAMPLE_COUNT_1_BIT;   ← 注意这里是 1x
// ⚠️ 管线创建时 VkPipelineMultisampleStateCreateInfo::rasterizationSamples
//    仍按 4x 设置，但要求 rasterizationSamples 与 image samples 的兼容性
//    需参考扩展的 valid usage（这是个容易配置错的地方）
```

⚠️ **注意事项**：
- 需要同时支持 `VK_EXT_multisampled_render_to_single_sampled` 与深度/模板的对应能力
- 该扩展与 `LAZILY_ALLOCATED`（memoryless）内存类型是两个不同机制，实践中常配合使用
- 部分 SDK / 驱动组合对该扩展的支持不完整，**必须做回退路径**

### 7.4 MSAA 相关的其他实用扩展

| 扩展 | 作用 |
|------|------|
| `VK_EXT_sample_locations` | 自定义/查询采样位置 |
| `VK_EXT_multisampled_render_to_single_sampled` | MSAA 渲染但单采样存储 |
| `VK_QCOM_render_pass_shader_resolve` | 在片元着色器内执行 resolve（**无 dynamic rendering 等价物**） |
| `VK_KHR_depth_stencil_resolve`（Vulkan 1.2 核心） | 深度/模板的 resolve |
| `VK_EXT_rasterization_order_attachment_access` | 无需 barrier 的 framebuffer fetch |

## 8. 选型与决策

### 8.1 几何边缘 AA 选型表

| 方案 | 覆盖率质量 | 着色质量 | 存储代价 | 时间稳定性 | 移动端适用性 |
|------|----------|---------|---------|-----------|------------|
| 无 AA | — | — | 1x | 差 | — |
| MSAA 2x | 中低 | 无改善 | 2x | 中 | ✅ 近乎免费（Adreno 官方） |
| MSAA 4x | 中 | 无改善 | 4x | 较好 | ⚠️ Forward 可用，Deferred 不可用 |
| MSAA 8x/16x | 高 | 无改善 | 8x/16x | 好 | ❌ 移动端不现实 |
| MSAA + sample shading | 中 | **有改善** | 2x~4x | 较好 | ⚠️ 只对高频材质局部开启 |
| CSAA/EQAA | 高（细边尤佳） | 无改善 | 接近 4x | 好 | ❌ 历史技术，现代 GPU 已移除 |
| SSAA 4x | 极高 | **有改善** | 4x | 极好 | ❌ 移动端不可行 |
| SGSSAA | 最高 | 有改善 | 高 | 极好 | ❌ |
| A2C | 受采样数限制 | — | 复用 MSAA | 好 | ⚠️ 破坏 HSR，移动端慎用 |
| **TAA** | 高 | **有改善** | 1 历史帧 + MV | **差（鬼影）** | ✅ 主流 |
| **超分重建**（DLSS/FSR/XeSS/ASR） | 高 | 有改善 | 模型/硬件 | 好 | ✅ 移动端有 ASR/GSR |
| FXAA/SMAA | 中 | 无改善 | 1~3 pass | 差 | ✅ 便宜兜底 |

### 8.2 决策树

```
                       开始

                         ▼

       └──────────┘         │ 是                │ 否
                            ▼                   ▼

              │ 现代主流：TAA 或超分   │  │ 只需几何边缘：           │
              │ · PC 高端：DLSS 4/FSR4 │  │ · PC：MSAA 4x/8x       │
```

### 8.3 常见配置组合（实战）

| 场景 | 推荐组合 |
|------|---------|
| PC 3A（有运动矢量） | TAA（或 DLSS/FSR/XeSS Quality）+ mipmap + 各向异性 16x + 法线方差 AA |
| PC 竞技（要清晰度） | MSAA 4x（如果管线允许）+ FXAA 轻微叠加；或 DLSS 原生（DLAA） |
| PC 老游戏/无 MV | SMAA 1x + OGSSAA 2x（如果有余量） |
| **移动 Forward** | MSAA 2x/4x + mipmap + 各向异性 4~8x + 可选 Arm ASR |
| **移动 Deferred** | TAA（或 Arm ASR）+ mipmap + 各向异性 + 法线方差 AA，**无 MSAA** |
| 移动 VR（Quest 类） | MSAA 4x + Forward + mipmap；TAA 需谨慎（延迟与鬼影） |
| 2D / UI 为主 | SDF 字体 + 预乘 alpha + 后处理 AA（但 UI 在最后合成） |
| Web / 低端 | FXAA 或 SMAA 1x + mipmap |

## 9. 小结

| 要点 | 说明 |
|------|------|
| **几何边缘混叠的本质是覆盖率只有 1 位** | 整个覆盖率采样家族的目标就是让覆盖率有多级取值 |
| **MSAA 的关键是「解耦」** | 覆盖率/深度/模板按采样点存储，但**着色每像素一次**。这是它能便宜于 SSAA 的原因 |
| **MSAA 的多采样颜色不是 shader 算的** | 是硬件在 resolve 时按覆盖率与权重生成的 |
| **MSAA 的一个固有缺陷是采样位置固定** | 亚像素几何可能完全穿过采样点空隙而丢失，这是 TAA/SSAA 的必要性来源 |
| **Sample shading 是 MSAA 与 SSAA 之间的开关** | `minSampleShading = 1.0` 让着色也按采样点执行，代价上升但质量改善。适合**局部**用于高频材质 |
| **MSAA 在移动端反而相对便宜** | TBDR 的 resolve 在片上完成，不额外走总线。这与桌面 IMR 的认知相反 |
| **多采样附件应设 `storeOp = DONT_CARE`** | 省掉多样本数据的写回带宽，尤其在移动端 |
| **CSAA/EQAA 的思想仍有价值** | 「覆盖率样本与颜色样本解耦」在 `VK_EXT_multisampled_render_to_single_sampled` 里以另一种形式回归 |
| **A2C 有两个硬限制** | 质量受 MSAA 采样数限制（需 8x+）；且**修改 coverage 会破坏移动端 HSR/early-Z** |
| **解析 AA 是唯一「精确」的方案** | 但只适用于能解析表达的形状（字体、SDF、程序化图案） |
| **MSAA 管不到纹理与着色高频** | 必须配合 mipmap、各向异性、法线方差 AA，且这些没有替代关系 |
| **现代趋势是覆盖率采样让位于时间采样** | TAA/超分覆盖面更广，代价从存储转移到延迟与伪影 |
