抗锯齿技术文档

把「抗锯齿」这个伞形词拆开：按信号来源、处理阶段、采样机制、代价结构四维分类；讲清 MSAA / mipmap / TAA / SMAA / SDF / 超分分别解决什么、不解决什么，以及在移动端该选哪个。

7 篇 四问框架 MSAA · SSAA · FXAA · SMAA · TAA DLSS 4 · FSR 4 · XeSS 2 Arm ASR · NSS SDF / MSDF

基础

先建立统一分类框架，后面每一篇才不会互相混淆。

00 OVERVIEW

分类总览与信号原理

  • 第一性原理：采样与重建；奈奎斯特与混叠
  • 空间混叠 vs 时间混叠——同一件事的两个维度
  • 四问法：来源 / 阶段 / 机制 / 代价
  • 完整分类总表：十余种技术各归其位
  • 四条解决路径：提高采样率、预过滤、后处理重建、模型重建
  • 八个最容易混淆的点逐条辨析
  • 命名规范：以后不说「开抗锯齿」，说什么
  • 术语表：含 Resolve / VRS 等易误用词

采样侧

在采样阶段干预：提高采样率，或在采样前把高频滤掉。

01 COVERAGE

几何边缘 AA 与覆盖率采样

  • MSAA 机制全景：覆盖率、样本、resolve
  • MSAA 的真实账本：存储 ×N、着色通常 ×1
  • CSAA / EQAA：覆盖率样本多、颜色样本少
  • SSAA 家族：唯一真正的全管线超采样
  • Alpha-to-Coverage：质量上限 ≈ MSAA 采样级数
  • 解析 AA：直接算覆盖面积（字体光栅化同源）
  • Vulkan 中 MSAA 的完整配置与 resolve 语义
  • 选型与决策表
02 PRE-FILTER

纹理与着色高频 AA

  • 成因：为什么 MSAA 在这里完全失效
  • Mipmap 是预过滤，不是「缩图」
  • 各向异性过滤解决的是「足迹是椭圆」
  • 法线贴图的 mipmap 反而会制造走样
  • Toksvig（2004）→ LEAN / CLEAN / 方差映射
  • 程序化 AA：fwidth + smoothstep 三坑
  • SDF / MSDF：一次烘焙、任意缩放
  • 预积分 BRDF 与 IBL 属于同一思路

重建侧

在图像空间修补：从「找边缘糊一下」到「时间采样 + 神经网络重建」。

03 POST-FX

图像空间后处理 AA

  • 定位：「修图」不是「采样」，四道硬边界
  • MLAA 原始思路：检测 → 分类 → 重矢量化 → 混合
  • AreaTex / SearchTex 是数学查找表，不是美术资源
  • FXAA 版本谱系与 FXAA_QUALITY__PRESET 的正确用法
  • SMAA 三阶段：边缘检测 / 权重计算 / 邻域混合
  • SMAA 变体不是强弱版本（1x / S2x / 4x / T2x）
  • 六个结构性缺陷，调参无法消除
  • pass 顺序三处必须对齐（HDR / HUD / 分辨率）
04 TEMPORAL

时间 AA 与超分重建

  • TAA 是时间采样，不是后处理滤波
  • 全链路：抖动 → 重投影 → 校验 → 混合 → 锐化
  • 忘记从 MV 减去 jitter → 画面缓慢「爬行」
  • 鬼影抑制两条正解：Karis 2014 邻域截断 / Salvi 2016 方差截断
  • YCoCg 空间 + μ ± γσ + 按速度动态调 γ
  • 九种伪影图鉴（含 UI 鬼影、去遮挡 fizzle）
  • 2026 超分阵营：DLSS 4 / FSR 4 / XeSS 2 / TSR / STP
  • 移动端：Arm ASR / NSS、Snapdragon GSR、MetalFX
  • 帧生成不降低延迟：延迟账本图解

UI 与平台

另一条独立的技术线，以及移动端该怎么选。

05 UI / TEXT

UI 与字体 AA

  • UI 边缘在 alpha 里，不在几何里 → MSAA 无效
  • 字体管线：轮廓 → hinting → 覆盖率 → 合成
  • 灰度 AA vs LCD 子像素 AA（四条前提 + 三个伪影）
  • Hinting 与 AA 的张力：按字号分档
  • 色彩空间决定字的胖瘦（线性 vs sRGB）
  • SDF / MSDF 的实用边界与 pxRange
  • 预乘 alpha / 图集 padding / 半像素偏移
  • UI 必须在 AA 之后 + 上采样之后合成
  • 各 AA 方案与 UI 的冲突表（含帧生成、VRS）
06 MOBILE

移动端 AA 选型与工程实践

  • 反直觉 1：MSAA 在移动端反而划算（片上 resolve）
  • 反直觉 2：TAA 贵在带宽（3~5 次全分辨率访问/帧）
  • 15 种方案在移动端的代价对照表
  • 五级决策树：瓶颈 → MV → 上采样 → 渲染路径 → UI
  • UE5 r.Mobile.AntiAliasing 取值与 MSAA 的前向限制
  • 纠正：二手文档对 r.Mobile.AntiAliasing=1 的矛盾说法
  • Unity 6 STP 的两条硬限制
  • Vulkan 要点：LAZILY_ALLOCATED + load/store op + 片上 resolve
  • 与《移动端 GPU 架构文档》的五处咬合结论

速查

用词前扫一眼，避免把不同阶段的方案放在一起比较。

命名

以后这么说（不说「开抗锯齿」）

  • 几何边缘 AA：MSAA、CSAA/EQAA、解析 AA
  • 全管线超采样：SSAA
  • 图像空间后处理 AA：FXAA、SMAA、MLAA、CMAA
  • 时间 AA：TAA、TAAU
  • 时间重建 / 超分：DLSS 4、FSR 4、XeSS 2、TSR、STP、ASR
  • 纹理过滤：Mipmap、各向异性
  • 着色高频 AA：Toksvig、LEAN/CLEAN、方差映射
  • UI / 字体 AA：灰度 AA、LCD 子像素、SDF/MSDF、预乘 alpha
  • 覆盖率 AA：Alpha-to-Coverage、解析覆盖
误区

十个必须纠正的说法

  • 「MSAA 是几何抗锯齿的全部」→ 它只管覆盖率
  • 「MSAA 能解决纹理摩尔纹」→ 采样在像素中心只做一次
  • 「开了 TAA 就不用 mipmap」→ 高频信息在采样时已丢失
  • 「法线贴图做 mipmap 是标准做法」→ 反而制造高光走样
  • 「FXAA 就是糊」→ 多数是 preset 用错
  • 「TAA 是后处理 AA」→ 它改变采样位置，属时间采样
  • 「帧生成能提升手感」→ 显示帧率↑，延迟不变或更差
  • 「UI 也应该开 MSAA」→ UI 边缘在 alpha 里，MSAA 看不到
  • 「UI 画在低分辨率层再放大」→ 字必糊，必须原生分辨率合成
  • 「移动端 MSAA 一定贵」→ 片上 resolve，通常反而划算
口诀

看到「AA」先问四句

  • Q1 它作用在哪个阶段？（采样 / 光栅 / 像素 / 后处理 / 时间 / 合成）
  • Q2 它解决哪类信号？（几何 / 纹理 / 着色 / 时间 / 字体）
  • Q3 它是否多样本？着色是否也 ×N？
  • Q4 代价结构是什么？（存储 / 带宽 / ALU / 延迟 / 伪影）
  • 四问答完，方案自然归位，不会再把 MSAA 和 mipmap 放在一起比
时间线

关键节点

  • 2004 Toksvig：把法线方差折进 roughness
  • 2007 Valve：SDF 用于矢量纹理放大
  • 2009 Intel MLAA（CPU）／ NVIDIA FXAA
  • 2011 Jimenez：MLAA 移植 GPU
  • 2012 SMAA（Eurographics）
  • 2014 Karis：TAA 参考实现（UE4）
  • 2016 Salvi：方差截断／Filmic SMAA
  • 2018+ DLSS / FSR / XeSS 时代开始
  • 2024 Arm ASR（MIT，基于 FSR 2）
  • 2025 Arm NSS 公布（神经加速器，2026 年底硬件）
