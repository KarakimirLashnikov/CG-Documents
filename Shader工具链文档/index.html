流水线速查

源码 → [元编程展开] → dxc/glslang → spirv-val → spirv-opt → spirv-val
                                                          ↓
        spirv-dis (.txt)   spirv-reflect (.refl.txt)   自研反射 (.refl.bin + .h)
                                                          ↓
        DescriptorSetLayout / PipelineLayout / 池定额 / DescriptorWriter
        / PushConstantRange / 顶点输入 / Bindless 注册 / C++ 绑定头
                                                          ↓
                    布局哈希 → 缓存 → PSO 预热 → 热重载

核心命令

# 编译
dxc -T ps_6_6 -E PSMain -spirv -fspv-target-env=vulkan1.3 -Fo out.spv in.hlsl
glslangValidator -V --target-env vulkan1.3 -S frag -o out.spv in.frag
clang --target=spirv64 -O1 -c kernel.cl -o kernel.spv

# 校验 + 优化 + 反射
spirv-val --target-env vulkan1.3 out.spv
spirv-opt -O --strip-nonsemantic -o out.spv out.spv
spirv-reflect out.spv > out.refl.txt

八条铁律（坑清单浓缩版）

#铁律违反后果
1spvReflectCreateShaderModule 的 size 是字节数解析失败或崩溃
2反射前必须先 spirv-val错误信息毫无帮助
3改写绑定后必须用 spvReflectGetCode() 建 ShaderModule描述符不匹配、黑屏
4不要依赖 name（会被 strip debug 掉）Release 构建布局错乱
5count == 0 是 Bindless 信号，需容量兜底0 大小的绑定
6set 号 < 64，PushConstant ≤ 128B管线创建失败
7模块销毁后所有 const char* 失效 → 拷成 std::string悬垂指针 UB
8热重载旧对象延迟 N 帧销毁；布局变了要重填描述符崩溃 / 数据错乱
最容易踩的一条：SPIR-V 只有事实（set/binding/offset），没有语义 （这是 PerFrame 还是 PerMaterial）。语义必须由命名约定或额外元数据补齐 —— 详见 06 篇 S2。

落地路线图

阶段做什么产出
P0引入 SPIRV-Reflect，跑通"加载 → 枚举 → 打印"能看见 shader 绑定表
P1反射生成 DescriptorSetLayout / PipelineLayout不再手写描述符布局
P2spirv-val + spirv-opt 接入构建编译期拦截非法 shader
P3生成 C++ 绑定头 + static_assert双重维护问题消失
P4命名约定 → set 自动分配语义自动化
P5布局哈希缓存 + Bindless描述符开销下降
P6变体 Cooker + 二进制去重 + PSO 预热构建与加载提速
P7热重载迭代速度质变
一句话总结：反射给你事实，约定给你语义，代码生成把二者钉进编译期 —— shader 与 C++ 的契约从"靠人保证"变成"靠编译器保证"。
