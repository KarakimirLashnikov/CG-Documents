# 实战：反射驱动的布局与描述符生成

> 系列第 **6** 篇，也是整套系列的**落点**。前面五篇都是铺垫：本文将反射数据一路推到底——生成 `DescriptorSetLayout`、`PipelineLayout`、描述符池定额、描述符写入器、PushConstant 范围、顶点输入布局、Bindless 注册、C++ 绑定头，并串起哈希缓存与热重载。

## 1. 目标与产物清单

**输入**：N 个 `.spv`（VS / PS / CS / MS / AS ...）

**输出**：

```
┌──────────────────────────────────────────────────────────┐
│ ① VkDescriptorSetLayout × M   （每个 set 一个）             │
│ ② VkPipelineLayout × 1        （set 布局数组 + PC 范围）     │

│ ⑨ 布局哈希                     （缓存 key / 热重载判据）       │
└──────────────────────────────────────────────────────────┘
```

## 3. S1：逐模块反射（产出引擎 POD）

## 4. S2：语义标注（最关键的一步）

### 4.1 问题：SPIR-V 只有事实，没有语义

反射告诉你：

```
set=1, binding=2, UNIFORM_BUFFER, name="PerMaterial"
```

但它**不知道**这个 UBO 该每帧更新还是每材质更新，也不知道该放哪个 set。这个"语义"必须由**约定**补齐。

### 4.2 方案 A：约定式 set 分配（推荐给自研引擎）

定义"更新频率 → set 号"的固定映射：

| set | 频率 | 典型内容 | 更新时机 |
|:---:|------|---------|---------|
| 0 | **PerFrame** | 相机矩阵、时间、屏幕参数、全局 Bindless 表 | 每帧 1 次 |
| 1 | **PerView** | 视图相关（多视图/VR/阴影级联） | 每视图 1 次 |
| 2 | **PerPass** | 当前 Pass 的输入 RT、光照列表、Cluster 数据 | 每 Pass 1 次 |
| 3 | **PerMaterial** | 材质纹理、材质参数 UBO | 每材质 1 次 |
| 4 | **PerDraw** | 实例数据、骨骼矩阵（通常用 SSBO 大数组） | 每绘制 1 次 |
| 5 | **Bindless** | 全局无界数组（`Texture2D g_Tex[]`） | 按需增量写 |

**命名约定**（shader 侧必须遵守）：

```hlsl
cbuffer PerFrame    : register(b0) { float4x4 viewProj; float4 cameraPos; };
cbuffer PerMaterial : register(b0) { float4 baseColor; float roughness; };

Texture2D     g_Albedo;      // 前缀 g_ + 语义后缀
Texture2D     g_Normal;
```

**识别规则**（优先级从高到低）：

```cpp
enum class Frequency { PerFrame, PerView, PerPass, PerMaterial, PerDraw, Bindless, Unknown };

Frequency ClassifyByName(std::string_view name) {
    // ① 名字前缀匹配：PerFrame / PerView / PerPass / PerMaterial / PerDraw
    if (name.starts_with("PerFrame"))    return Frequency::PerFrame;
    if (name.starts_with("PerView"))     return Frequency::PerView;
    if (name.starts_with("PerPass"))     return Frequency::PerPass;
    if (name.starts_with("PerMaterial")) return Frequency::PerMaterial;
    if (name.starts_with("PerDraw"))     return Frequency::PerDraw;
    // ② 后缀匹配：xxx_Frame / xxx_Material
    if (name.ends_with("_Frame"))        return Frequency::PerFrame;
    if (name.ends_with("_Material"))     return Frequency::PerMaterial;
    // ③ 已知全局绑定（bindless 表名白名单）
    if (name.starts_with("g_Bindless"))  return Frequency::Bindless;
    return Frequency::Unknown;
}

// 回退：按描述符类型猜
Frequency FallbackByType(VkDescriptorType t, bool runtimeSized) {
    if (runtimeSized) return Frequency::Bindless;
    switch (t) {
    case VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER:
    case VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER_DYNAMIC:   return Frequency::PerFrame;
    case VK_DESCRIPTOR_TYPE_SAMPLED_IMAGE:
    case VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER:
    case VK_DESCRIPTOR_TYPE_SAMPLER:                  return Frequency::PerMaterial;
    case VK_DESCRIPTOR_TYPE_STORAGE_BUFFER:
    case VK_DESCRIPTOR_TYPE_STORAGE_IMAGE:            return Frequency::PerPass;
    default:                                          return Frequency::Unknown;
    }
}

uint32_t SetForFrequency(Frequency f) {
    switch (f) {
    case Frequency::PerFrame:    return 0;
    case Frequency::PerView:     return 1;
    case Frequency::PerPass:     return 2;
    case Frequency::PerMaterial: return 3;
    case Frequency::PerDraw:     return 4;
    case Frequency::Bindless:    return 5;
    default:                     return 3;   // 未知统一落到 PerMaterial
    }
}
```

> ⚠️ **名字可能丢失**（`spirv-opt -O` 会 strip `OpName`）。所以：
> 1. 约定优先用**显式 `[[vk::binding(set, binding)]]`** 写在源码里（DXC 支持），这样不依赖名字
> 2. 名字只作为"校验与日志"用途，不作为唯一依据
> 3. Release 构建里断言名字存在，让问题在构建期暴露

### 4.3 方案 B：反射后重映射（不改源码）

若 shader 来自第三方、无法改源码，就在反射后用 `Change*` 重排：

```cpp
void RemapToEngineLayout(SpvReflectShaderModule& m) {
    uint32_t n = 0;
    spvReflectEnumerateDescriptorBindings(&m, &n, nullptr);
    std::vector<SpvReflectDescriptorBinding*> all(n);
    spvReflectEnumerateDescriptorBindings(&m, &n, all.data());

    for (auto* b : all) {
        auto freq = ClassifyByName(b->name ? b->name : "");
        if (freq == Frequency::Unknown) freq = FallbackByType(
            static_cast<VkDescriptorType>(b->descriptor_type), b->count == 0);

        spvReflectChangeDescriptorBindingNumbers(
            &m, b, b->binding, SetForFrequency(freq));
    }
    // ★ 之后必须用 spvReflectGetCode() 的 SPIR-V 建 VkShaderModule
}
```

### 4.4 两种方案对比

| 维度 | A：源码里写 `[[vk::binding]]` | B：反射后 `Change*` |
|------|------------------------------|---------------------|
| 依赖名字 | ❌ 不依赖 | ✅ 依赖（或靠类型回退） |
| 第三方 shader | ❌ 改不了 | ✅ 可用 |
| 流程复杂度 | 低（编译即定稿） | 中（多一步改写） |
| 出错点 | 编译期 | 运行/构建期 |
| **推荐度** | ⭐⭐⭐⭐⭐（自有 shader） | ⭐⭐⭐（第三方 shader） |

## 5. S3：跨阶段合并与冲突检测

### 5.1 数据结构

```cpp
struct DescriptorSlot {
    VkDescriptorType  type     = VK_DESCRIPTOR_TYPE_MAX_ENUM;
    uint32_t          count    = 1;
    VkShaderStageFlags stages  = 0;
    bool              runtimeSized = false;
    bool              partiallyBound = false;
    bool              updateAfterBind = false;
    std::string       name;                       // 第一个遇到的名字
    std::vector<std::string> aliases;             // 各阶段的名字（用于冲突诊断）
    std::vector<VkShaderStageFlags> reportedBy;   // 诊断用
};

// set -> (binding -> slot)
using SetSlots = std::map<uint32_t, DescriptorSlot>;
using MergedLayout = std::map<uint32_t, SetSlots>;
```

### 5.2 合并

```cpp
class LayoutMerger {
public:
    void Add(const shader::ModuleData& m);

    const MergedLayout& Result() const { return sets_; }
    const std::vector<std::string>& Errors() const { return errors_; }

private:
    MergedLayout             sets_;
    std::vector<std::string> errors_;
};

void LayoutMerger::Add(const shader::ModuleData& m) {
    for (const auto& b : m.bindings) {
        auto& slot = sets_[b.set][b.binding];

        // 第一次遇到 → 初始化
        if (slot.type == VK_DESCRIPTOR_TYPE_MAX_ENUM) {
            slot.type         = b.type;
            slot.count        = b.count;
            slot.runtimeSized = b.runtimeSized;
            slot.name         = b.name;
        } else {
            // ★ 冲突检测
            if (slot.type != b.type) {
                errors_.push_back(std::format(
                    "Descriptor type conflict at set={} binding={}: "
                    "existing={}, incoming={} (resource '{}', stage=0x{:x})",
                    b.set, b.binding, (int)slot.type, (int)b.type,
                    b.name, (unsigned)m.stage));
            }
            if (slot.count != b.count) {
                errors_.push_back(std::format(
                    "Descriptor count conflict at set={} binding={}: "
                    "existing={}, incoming={} ('{}')",
                    b.set, b.binding, slot.count, b.count, b.name));
            }
            if (!b.name.empty() && b.name != slot.name)
                slot.aliases.push_back(b.name);
        }

        // 阶段位累加（OR）
        slot.stages |= m.stage;
        slot.reportedBy.push_back(m.stage);

        // Bindless 标志
        if (b.runtimeSized) {
            slot.partiallyBound   = true;
            slot.updateAfterBind  = true;
        }
    }
}
```

### 5.3 必须检测的冲突

| 冲突 | 严重性 | 说明 |
|------|-------|------|
| **类型冲突** | 🔴 致命 | 同一 (set,binding) 在 VS 里是 UBO、在 PS 里是 SAMPLED_IMAGE → 布局无法确定 |
| **数量冲突** | 🔴 致命 | 数组长度不一致 |
| **stage 位缺失** | 🟠 警告 | 某绑定只被 VS 使用，但你给了 `ALL_GRAPHICS` → 无害但浪费描述符 |
| **名字不一致** | 🟡 提示 | 各阶段命名不同，通常是笔误 |
| **set 空洞** | 🟡 提示 | set 0 和 set 3 用了，1/2 空 → PipelineLayout 仍要按顺序给全 |
| **PushConstant 区间重叠** | 🟠 警告 | 多个 block offset 重叠，数据会互相踩 |
| **超过设备限制** | 🔴 致命 | `maxPerStageDescriptorUniformBuffers` 等 |

```cpp
void ValidateAgainstDevice(const MergedLayout& L,
                           const VkPhysicalDeviceLimits& lim) {
    std::map<VkDescriptorType, uint32_t> perType;
    for (auto& [set, slots] : L)
        for (auto& [binding, s] : slots)
            perType[s.type] += s.count;

    auto check = [&](VkDescriptorType t, uint32_t maxv, const char* what) {
        if (perType[t] > maxv)
            throw std::runtime_error(std::format(
                "{}: {} > device limit {}", what, perType[t], maxv));
    };
    check(VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER,        lim.maxPerStageDescriptorUniformBuffers, "UBO");
    check(VK_DESCRIPTOR_TYPE_STORAGE_BUFFER,        lim.maxPerStageDescriptorStorageBuffers, "SSBO");
    check(VK_DESCRIPTOR_TYPE_SAMPLED_IMAGE,         lim.maxPerStageDescriptorSampledImages,  "sampled image");
    check(VK_DESCRIPTOR_TYPE_STORAGE_IMAGE,         lim.maxPerStageDescriptorStorageImages,  "storage image");
    check(VK_DESCRIPTOR_TYPE_SAMPLER,               lim.maxPerStageDescriptorSamplers,       "sampler");
    check(VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER,lim.maxPerStageDescriptorSampledImages,  "combined");
}
```

## 6. S4/S5：规范化、哈希与缓存

### 6.1 规范化

把 `MergedLayout` 序列化成**规范字节流**，保证语义等价的布局得到相同哈希：

```cpp
std::string Canonicalize(const MergedLayout& L) {
    std::string s;
    auto put = [&](auto v) {
        s.append(reinterpret_cast<const char*>(&v), sizeof(v));
    };
    // set 号已由 std::map 保证升序；binding 同理
    for (const auto& [setIdx, slots] : L) {
        put(setIdx);
        put(static_cast<uint32_t>(slots.size()));
        for (const auto& [b, slot] : slots) {
            put(b);
            put(static_cast<uint32_t>(slot.type));
            put(slot.count);
            put(static_cast<uint32_t>(slot.stages));
            put(static_cast<uint32_t>(slot.runtimeSized));
            // ★ 不要哈希 name —— 名字丢失会导致缓存失效
        }
    }
    return s;
}

uint64_t LayoutHash(const MergedLayout& L) {
    return blake3_64(Canonicalize(L));
}
```

### 6.2 缓存

```cpp
class DescriptorLayoutCache {
public:
    DescriptorLayoutCache(VkDevice dev, uint32_t bindlessCapacity)
        : dev_(dev), bindlessCapacity_(bindlessCapacity) {}

    VkDescriptorSetLayout GetOrCreate(const SetSlots& slots);

private:
    struct Entry { uint64_t hash; VkDescriptorSetLayout layout; };
    VkDevice dev_;
    uint32_t bindlessCapacity_;
    std::vector<Entry> cache_;                 // 小规模线性查找即可
    std::mutex mu_;
};

VkDescriptorSetLayout DescriptorLayoutCache::GetOrCreate(const SetSlots& slots) {
    // 单 set 的哈希
    MergedLayout tmp; tmp[0] = slots;          // 复用 Canonicalize
    uint64_t h = LayoutHash(tmp);

    {
        std::lock_guard lk(mu_);
        for (auto& e : cache_) if (e.hash == h) return e.layout;
    }

    std::vector<VkDescriptorSetLayoutBinding> bindings;
    std::vector<VkDescriptorBindingFlags>     flags;

    for (const auto& [binding, s] : slots) {
        uint32_t count = s.runtimeSized ? bindlessCapacity_ : std::max(1u, s.count);

        bindings.push_back(VkDescriptorSetLayoutBinding{
            .binding            = binding,
            .descriptorType     = s.type,
            .descriptorCount    = count,
            .stageFlags         = s.stages,
            .pImmutableSamplers = nullptr,
        });

        VkDescriptorBindingFlags f = 0;
        if (s.runtimeSized) {
            f |= VK_DESCRIPTOR_BINDING_PARTIALLY_BOUND_BIT
               | VK_DESCRIPTOR_BINDING_UPDATE_AFTER_BIND_BIT
               | VK_DESCRIPTOR_BINDING_VARIABLE_DESCRIPTOR_COUNT_BIT;
        }
        flags.push_back(f);
    }

    VkDescriptorSetLayoutBindingFlagsCreateInfo flagsCI{
        .sType         = VK_STRUCTURE_TYPE_DESCRIPTOR_SET_LAYOUT_BINDING_FLAGS_CREATE_INFO,
        .bindingCount  = (uint32_t)flags.size(),
        .pBindingFlags = flags.data(),
    };

    VkDescriptorSetLayoutCreateInfo ci{
        .sType        = VK_STRUCTURE_TYPE_DESCRIPTOR_SET_LAYOUT_CREATE_INFO,
        .pNext        = &flagsCI,
        .flags        = VK_DESCRIPTOR_SET_LAYOUT_CREATE_UPDATE_AFTER_BIND_POOL_BIT,
        .bindingCount = (uint32_t)bindings.size(),
        .pBindings    = bindings.data(),
    };

    VkDescriptorSetLayout layout = VK_NULL_HANDLE;
    if (vkCreateDescriptorSetLayout(dev_, &ci, nullptr, &layout) != VK_SUCCESS)
        throw std::runtime_error("vkCreateDescriptorSetLayout failed");

    std::lock_guard lk(mu_);
    cache_.push_back({ h, layout });
    return layout;
}
```

> **三个 Bindless 标志的含义**：
> - `PARTIALLY_BOUND`：允许数组中的部分元素未绑定（未使用的槽位不报错）
> - `UPDATE_AFTER_BIND`：允许在描述符集已提交到命令缓冲之后继续更新
> - `VARIABLE_DESCRIPTOR_COUNT`：分配时才能确定实际大小（配合 `VkDescriptorSetVariableDescriptorCountAllocateInfo`）

## 7. 生成 PipelineLayout

```cpp
struct PipelineLayoutResult {
    VkPipelineLayout               layout;
    std::vector<VkDescriptorSetLayout> setLayouts;   // 顺序 = set 号
    std::vector<VkPushConstantRange>   pushRanges;
};

PipelineLayoutResult BuildPipelineLayout(VkDevice dev,
                                         const MergedLayout& L,
                                         std::span<const shader::ModuleData> modules,
                                         DescriptorLayoutCache& cache) {
    PipelineLayoutResult r;

    // ① 找出最大 set 号，空洞也要填 VK_NULL_HANDLE
    uint32_t maxSet = 0;
    for (auto& [s, _] : L) maxSet = std::max(maxSet, s);
    r.setLayouts.assign(maxSet + 1, VK_NULL_HANDLE);

    for (auto& [s, slots] : L)
        r.setLayouts[s] = cache.GetOrCreate(slots);

    // ② 合并所有阶段的 PushConstant
    r.pushRanges = MergePushConstants(modules);

    VkPipelineLayoutCreateInfo ci{
        .sType                  = VK_STRUCTURE_TYPE_PIPELINE_LAYOUT_CREATE_INFO,
        .setLayoutCount         = (uint32_t)r.setLayouts.size(),
        .pSetLayouts            = r.setLayouts.data(),
        .pushConstantRangeCount = (uint32_t)r.pushRanges.size(),
        .pPushConstantRanges    = r.pushRanges.data(),
    };

    if (vkCreatePipelineLayout(dev, &ci, nullptr, &r.layout) != VK_SUCCESS)
        throw std::runtime_error("vkCreatePipelineLayout failed");
    return r;
}
```

### 7.1 PushConstant 合并

Vulkan 允许多个 `VkPushConstantRange`，但**总和受 `maxPushConstantsSize` 限制**（通常 128 字节），且多个 range **不能重叠**。反射出的多个 block 需要合并成不重叠区间：

```cpp
std::vector<VkPushConstantRange>
MergePushConstants(std::span<const shader::ModuleData> modules) {
    // 收集所有 (offset, size, stages)，按 offset 排序后合并相邻/重叠区间
    struct Span { uint32_t lo, hi; VkShaderStageFlags stages; };
    std::vector<Span> spans;

    for (auto& m : modules)
        for (auto& pc : m.pushConstants)
            spans.push_back({ pc.offset, pc.offset + pc.size, m.stage });

    std::sort(spans.begin(), spans.end(), [](auto& a, auto& b) {
        return a.lo != b.lo ? a.lo < b.lo : a.hi < b.hi;
    });

    std::vector<Span> merged;
    for (auto& s : spans) {
        if (!merged.empty() && s.lo <= merged.back().hi) {
            // 重叠 → 合并（stages 取并集）
            merged.back().hi     = std::max(merged.back().hi, s.hi);
            merged.back().stages |= s.stages;
        } else {
            merged.push_back(s);
        }
    }

    std::vector<VkPushConstantRange> out;
    for (auto& s : merged)
        out.push_back({ .stageFlags = s.stages, .offset = s.lo, .size = s.hi - s.lo });
    return out;
}
```

> ⚠️ 合并会让"不同 block"共享一段区间。若两个 block 在不同 stage 且语义不同，这在 Vulkan 里是合法的（各自 stage 写各自的），但要确保 CPU 侧推送时知道"这个 stage 期待什么布局"。

## 8. 描述符池定额计算

```cpp
struct PoolSizes {
    std::map<VkDescriptorType, uint32_t> counts;

    void Add(VkDescriptorType t, uint32_t n) { counts[t] += n; }
};

PoolSizes ComputePoolSizes(const MergedLayout& L, uint32_t framesInFlight,
                           uint32_t bindlessCapacity) {
    PoolSizes ps;
    for (auto& [set, slots] : L) {
        // Bindless set 通常单独一个常驻池，不随帧轮转
        bool isBindlessSet = std::any_of(slots.begin(), slots.end(),
            [](auto& kv) { return kv.second.runtimeSized; });
        uint32_t multiplier = isBindlessSet ? 1 : framesInFlight;

        for (auto& [binding, s] : slots) {
            uint32_t n = s.runtimeSized ? bindlessCapacity : std::max(1u, s.count);
            ps.Add(s.type, n * multiplier);
        }
    }
    return ps;
}

VkDescriptorPool CreatePool(VkDevice dev, const PoolSizes& ps,
                            uint32_t maxSets, bool updateAfterBind) {
    std::vector<VkDescriptorPoolSize> sizes;
    for (auto& [t, c] : ps.counts)
        sizes.push_back({ .type = t, .descriptorCount = c });

    VkDescriptorPoolCreateInfo ci{
        .sType         = VK_STRUCTURE_TYPE_DESCRIPTOR_POOL_CREATE_INFO,
        .flags         = updateAfterBind
                         ? VK_DESCRIPTOR_POOL_CREATE_UPDATE_AFTER_BIND_BIT
                         : VkDescriptorPoolCreateFlags(0),
        .maxSets       = maxSets,
        .poolSizeCount = (uint32_t)sizes.size(),
        .pPoolSizes    = sizes.data(),
    };
    VkDescriptorPool pool;
    vkCreateDescriptorPool(dev, &ci, nullptr, &pool);
    return pool;
}
```

> **实践建议**：不要一个全局大池。分池策略：
> - **池 A（Bindless 常驻）**：`UPDATE_AFTER_BIND`，长期存活，不 reset
> - **池 B（每帧轮转）**：每帧 reset，分配 PerFrame/PerView/PerPass/PerMaterial 集
> - **池 C（临时）**：小对象、短生命周期

## 9. DescriptorWriter（类型安全的数据填充器）

反射知道每个 binding 的类型 → 写入器可以在**编译期**就约束"这个槽位只能写 buffer，不能写 image"。

### 9.1 运行时版本（通用）

```cpp
class DescriptorWriter {
public:
    // ---- 各类型写入接口 ----
    DescriptorWriter& UniformBuffer(VkDescriptorSet dst, uint32_t binding,
                                    VkBuffer buf, VkDeviceSize off,
                                    VkDeviceSize range, uint32_t elem = 0) {
        bufferInfos_.push_back({ .buffer = buf, .offset = off, .range = range });
        return Emit(dst, binding, VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER, elem);
    }

    DescriptorWriter& StorageBuffer(VkDescriptorSet dst, uint32_t binding,
                                    VkBuffer buf, VkDeviceSize off,
                                    VkDeviceSize range, uint32_t elem = 0) {
        bufferInfos_.push_back({ .buffer = buf, .offset = off, .range = range });
        return Emit(dst, binding, VK_DESCRIPTOR_TYPE_STORAGE_BUFFER, elem);
    }

    DescriptorWriter& SampledImage(VkDescriptorSet dst, uint32_t binding,
                                   VkImageView view, VkImageLayout layout,
                                   uint32_t elem = 0) {
        imageInfos_.push_back({ .sampler = VK_NULL_HANDLE, .imageView = view,
                                .imageLayout = layout });
        return Emit(dst, binding, VK_DESCRIPTOR_TYPE_SAMPLED_IMAGE, elem);
    }

    DescriptorWriter& Sampler(VkDescriptorSet dst, uint32_t binding,
                              VkSampler s, uint32_t elem = 0) {
        imageInfos_.push_back({ .sampler = s, .imageView = VK_NULL_HANDLE,
                                .imageLayout = VK_IMAGE_LAYOUT_UNDEFINED });
        return Emit(dst, binding, VK_DESCRIPTOR_TYPE_SAMPLER, elem);
    }

    // ★ COMBINED_IMAGE_SAMPLER 必须同时提供 image 与 sampler
    DescriptorWriter& CombinedImageSampler(VkDescriptorSet dst, uint32_t binding,
                                           VkImageView view, VkSampler s,
                                           VkImageLayout layout, uint32_t elem = 0) {
        imageInfos_.push_back({ .sampler = s, .imageView = view, .imageLayout = layout });
        return Emit(dst, binding, VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER, elem);
    }

    DescriptorWriter& StorageImage(VkDescriptorSet dst, uint32_t binding,
                                   VkImageView view, VkImageLayout layout,
                                   uint32_t elem = 0) {
        imageInfos_.push_back({ .sampler = VK_NULL_HANDLE, .imageView = view,
                                .imageLayout = layout });
        return Emit(dst, binding, VK_DESCRIPTOR_TYPE_STORAGE_IMAGE, elem);
    }

    DescriptorWriter& AccelerationStructure(VkDescriptorSet dst, uint32_t binding,
                                            VkAccelerationStructureKHR as,
                                            uint32_t elem = 0) {
        asRefs_.push_back(as);
        auto& info = asInfos_.emplace_back();
        info.sType = VK_STRUCTURE_TYPE_WRITE_DESCRIPTOR_SET_ACCELERATION_STRUCTURE_KHR;
        info.accelerationStructureCount = 1;
        info.pAccelerationStructures     = &asRefs_.back();
        return Emit(dst, binding, VK_DESCRIPTOR_TYPE_ACCELERATION_STRUCTURE_KHR, elem);
    }

    void Flush(VkDevice dev) {
        // ★ 关键：写回真实的指针（容器扩容后地址会变）
        size_t bi = 0, ii = 0, ai = 0;
        for (auto& w : writes_) {
            switch (w.descriptorType) {
            case VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER:
            case VK_DESCRIPTOR_TYPE_STORAGE_BUFFER:
            case VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER_DYNAMIC:
            case VK_DESCRIPTOR_TYPE_STORAGE_BUFFER_DYNAMIC:
                w.pBufferInfo = &bufferInfos_[bi++]; break;
            case VK_DESCRIPTOR_TYPE_SAMPLER:
            case VK_DESCRIPTOR_TYPE_SAMPLED_IMAGE:
            case VK_DESCRIPTOR_TYPE_STORAGE_IMAGE:
            case VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER:
            case VK_DESCRIPTOR_TYPE_INPUT_ATTACHMENT:
                w.pImageInfo = &imageInfos_[ii++]; break;
            case VK_DESCRIPTOR_TYPE_ACCELERATION_STRUCTURE_KHR:
                w.pNext = &asInfos_[ai++]; break;
            default: break;
            }
        }
        vkUpdateDescriptorSets(dev, (uint32_t)writes_.size(), writes_.data(), 0, nullptr);
        Clear();
    }

private:
    DescriptorWriter& Emit(VkDescriptorSet dst, uint32_t binding,
                           VkDescriptorType type, uint32_t elem) {
        writes_.push_back(VkWriteDescriptorSet{
            .sType           = VK_STRUCTURE_TYPE_WRITE_DESCRIPTOR_SET,
            .dstSet          = dst,
            .dstBinding      = binding,
            .dstArrayElement = elem,
            .descriptorCount = 1,
            .descriptorType  = type,
        });
        return *this;
    }
    void Clear() { writes_.clear(); bufferInfos_.clear();
                   imageInfos_.clear(); asInfos_.clear(); asRefs_.clear(); }

    std::vector<VkWriteDescriptorSet> writes_;
    std::vector<VkDescriptorBufferInfo> bufferInfos_;
    std::vector<VkDescriptorImageInfo>  imageInfos_;
    std::deque<VkWriteDescriptorSetAccelerationStructureKHR> asInfos_;  // 需稳定地址
    std::deque<VkAccelerationStructureKHR>                   asRefs_;
};
```

> ⚠️ **经典 bug**：`std::vector` 扩容会导致已记录的指针失效。两种解法：
> 1. **先收集数据，最后统一填指针**（上面 `Flush()` 的做法）✅ 推荐
> 2. 用 `std::deque`（元素地址稳定）

### 9.2 编译期类型安全版本（代码生成）

有了反射信息，可以在**构建期**生成一个强类型的写入器：

// ⚠ GENERATED — shader_bindings.h

## 10. 顶点输入布局生成

```cpp
struct VertexLayoutResult {
    std::vector<VkVertexInputAttributeDescription> attributes;
    VkVertexInputBindingDescription                 binding;
};

VertexLayoutResult BuildVertexLayout(const shader::ModuleData& vs,
                                     uint32_t vertexBufferBinding = 0) {
    std::vector<VkVertexInputAttributeDescription> attrs;

    for (auto& a : vs.attributes) {
        attrs.push_back(VkVertexInputAttributeDescription{
            .location = a.location,
            .binding  = vertexBufferBinding,
            .format   = a.format,
            .offset   = 0,    // 下面算
        });
    }

    // 按 location 排序后紧凑排列
    std::sort(attrs.begin(), attrs.end(),
              [](auto& x, auto& y) { return x.location < y.location; });

    uint32_t stride = 0;
    for (auto& a : attrs) {
        a.offset = stride;
        stride  += FormatByteSize(a.format);
    }

    return { attrs, VkVertexInputBindingDescription{
        .binding   = vertexBufferBinding,
        .stride    = stride,
        .inputRate = VK_VERTEX_INPUT_RATE_VERTEX,
    }};
}
```

> | 策略 | 适用 |
> |------|------|
> | 语义约定硬编码表 | 网格格式固定 |
> | 按 location 紧凑排列 | 通用（上面代码） |
> | `[[vk::location(n)]]` 显式指定 | ⭐ 推荐 |

## 11. Bindless 注册

反射知道哪些 binding 是运行时长度数组 → 引擎维护一个"槽位分配器"：

```cpp
class BindlessRegistry {
public:
    // 从反射结果中登记所有运行时长度数组
    void Register(const MergedLayout& L) {
        for (auto& [set, slots] : L)
            for (auto& [binding, s] : slots)
                if (s.runtimeSized)
                    arrays_.push_back({ set, binding, s.type, {} });
    }

    // 分配一个槽位（返回 shader 里可用的索引）
    uint32_t Allocate(VkDescriptorType type, VkImageView view,
                      VkSampler sampler = VK_NULL_HANDLE,
                      VkImageLayout layout = VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL) {
        auto& slot = FindOrCreateArray(type);
        uint32_t idx = slot.freeList.empty()
                     ? slot.next++ : PopBack(slot.freeList);

        DescriptorWriter w;
        if (type == VK_DESCRIPTOR_TYPE_SAMPLED_IMAGE)
            w.SampledImage(slot.set_, slot.binding_, view, layout, idx);
        else if (type == VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER)
            w.CombinedImageSampler(slot.set_, slot.binding_, view, sampler, layout, idx);
        else if (type == VK_DESCRIPTOR_TYPE_STORAGE_IMAGE)
            w.StorageImage(slot.set_, slot.binding_, view, layout, idx);
        w.Flush(device_);
        return idx;
    }

    void Free(VkDescriptorType type, uint32_t idx) {
        FindOrCreateArray(type).freeList.push_back(idx);
    }

private:
    struct Array {
        VkDescriptorSet   set_; uint32_t binding_;
        VkDescriptorType  type_;
        uint32_t          next = 0;
        std::vector<uint32_t> freeList;
    };
    VkDevice device_;
    std::vector<Array> arrays_;
    // ...
};
```

**shader 侧对应**：

```hlsl
Texture2D g_BindlessTex[] : register(t0, space5);   // set 5
SamplerState g_Sampler;

uint albedoIdx = material.albedoMapIdx;              // 来自 PerMaterial 数据
float4 c = g_BindlessTex[albedoIdx].Sample(g_Sampler, uv);
```

> ⚠️ **必须加 `NonUniform`**：当索引来自运行时数据（不同 lane 不同值）时，HLSL 要写 `NonUniformResourceIndex(idx)` 或 `g_BindlessTex[NonUniformResourceIndex(idx)]`，否则在部分硬件上是未定义行为。SPIR-V 侧对应 `OpDecorate %var NonUniform`。

## 12. 光线追踪：着色器绑定表（SBT）

反射能给你每个入口点的**执行模型**，据此自动分组：

```cpp
enum class RayGroupKind { RayGen, Miss, HitGroup, Callable };

struct RayGroup {
    RayGroupKind kind;
    std::string  closestHit, anyHit, intersection;   // HitGroup 专用
    std::string  name;                                // RayGen / Miss / Callable 专用
};

std::vector<RayGroup> BuildRayGroups(std::span<const shader::ModuleData> modules) {
    std::map<std::string, RayGroup> groups;

    for (auto& m : modules) {
        for (auto& ep : m.entryPoints) {
            // 约定命名：GroupName_ClosestHit / GroupName_AnyHit / GroupName_Intersection
            auto [base, role] = SplitRayEntryName(ep);   // "Shadow" + "ClosestHit"

            if (role.empty()) {
                // 单段：按 stage 判定
                if (m.stage == VK_SHADER_STAGE_RAYGEN_BIT_KHR)
                    groups[base] = { RayGroupKind::RayGen, {}, {}, {}, base };
                else if (m.stage == VK_SHADER_STAGE_MISS_BIT_KHR)
                    groups[base] = { RayGroupKind::Miss, {}, {}, {}, base };
                else if (m.stage == VK_SHADER_STAGE_CALLABLE_BIT_KHR)
                    groups[base] = { RayGroupKind::Callable, {}, {}, {}, base };
            } else {
                auto& g = groups[base];
                g.kind = RayGroupKind::HitGroup;
                if (role == "ClosestHit")   g.closestHit   = ep;
                if (role == "AnyHit")       g.anyHit       = ep;
                if (role == "Intersection") g.intersection = ep;
            }
        }
    }

    std::vector<RayGroup> out;
    for (auto& [_, g] : groups) out.push_back(g);
    return out;
}
```

SBT 内存布局（按 `VkPhysicalDeviceRayTracingPipelinePropertiesKHR`）：

```
┌────────────────────────────────────────────────────┐
│ RayGen 区      : stride = shaderGroupHandleSize     │
├────────────────────────────────────────────────────┤
│ Miss 区        : stride = shaderGroupHandleSize     │
├────────────────────────────────────────────────────┤
│ HitGroup 区    : stride = shaderGroupHandleSize     │
│                  （可能含 shaderGroupHandleAlignment 对齐）│
├────────────────────────────────────────────────────┤
│ Callable 区                                          │
└────────────────────────────────────────────────────┘
```

> 反射**不提供** SBT 本身，但提供"有哪些入口点、各是什么执行模型"——这正是构造 SBT 所需的全部输入。剩余工作是按句柄大小与对齐做字节排布。

## 13. C++ 绑定头代码生成

### 13.1 类型映射表

从 `SpvReflectTypeDescription` / `BlockMember` 映射到 C++ 类型：

```cpp
std::string MapCppType(const shader::BlockMember& m) {
    if (m.isMatrix) {
        // HLSL float4x4 = 4 列 × 4 行（row-major 存储时内存也是行主序）
        if (m.matrixCols == 4 && m.matrixRows == 4) return "glm::mat4";
        if (m.matrixCols == 3 && m.matrixRows == 3) return "glm::mat3";
        if (m.matrixCols == 4 && m.matrixRows == 3) return "glm::mat4x3";
        if (m.matrixCols == 3 && m.matrixRows == 4) return "glm::mat3x4";
        return std::format("glm::mat{}x{}", m.matrixCols, m.matrixRows);
    }
    // 标量/向量：靠 typeName 或 size + 分量数
    auto base = ScalarBase(m);        // "float" / "int" / "uint" / "half"
    uint32_t comps = m.size / ScalarByteSize(m);
    if (comps == 1) return base;
    return std::format("glm::{}{}", base, comps);   // glm::vec4 / glm::ivec2 ...
}
```

| SPIR-V 类型 | size | C++ 类型 |
|------------|------|---------|
| `OpTypeFloat 32` | 4 | `float` |
| `OpTypeInt 32 signed` | 4 | `int32_t` |
| `OpTypeInt 32 unsigned` | 4 | `uint32_t` |
| `OpTypeVector<float,2>` | 8 | `glm::vec2` |
| `OpTypeVector<float,3>` | 12 | `glm::vec3` |
| `OpTypeVector<float,4>` | 16 | `glm::vec4` |
| `OpTypeMatrix<vec4,4>` | 64 | `glm::mat4` |
| `OpTypeInt 16` | 2 | `int16_t` / `glm::i16vec*` |

### 13.2 发射器

```cpp
std::string EmitBindingHeader(std::string_view shaderName,
                              std::span<const shader::BlockInfo> blocks,
                              std::span<const shader::BindingInfo> bindings,
                              std::span<const shader::SpecConstantInfo> specs) {
    std::string o;
    auto line = [&](auto&&... a) {
        ((o += std::forward<decltype(a)>(a)), ...) += '\n';
    };

    line("// ⚠ GENERATED FILE — DO NOT EDIT");
    line("// source: ", shaderName);
    line("#pragma once");
    line("#include <glm/glm.hpp>");
    line("#include <cstdint>");
    line("#include <cstddef>");
    line();
    line("namespace shader::", Sanitize(shaderName), " {");
    line();

    // ---- 常量：set / binding ----
    line("// ---- descriptor slots ----");
    for (auto& b : bindings) {
        std::string id = Sanitize(b.name.empty() ? std::format("b{}_{}", b.set, b.binding)
                                                 : b.name);
        line("constexpr uint32_t k", id, "_Set     = ", b.set, ";");
        line("constexpr uint32_t k", id, "_Binding = ", b.binding, ";");
    }
    line();

    // ---- 结构体 ----
    line("// ---- uniform block layouts ----");
    for (auto& blk : blocks) {
        line("struct ", Sanitize(blk.name), " {");
        for (auto& m : blk.members) {
            line("    ", MapCppType(m), " ", Sanitize(m.name), ";",
                 "   // offset ", m.offset, ", size ", m.size);
        }
        line("};");
        line();
        // ★ 静态断言：把反射事实钉死在编译期
        for (auto& m : blk.members)
            line("static_assert(offsetof(", Sanitize(blk.name), ", ", Sanitize(m.name),
                 ") == ", m.offset, ");");
        line("static_assert(sizeof(", Sanitize(blk.name), ") == ", blk.size, ");");
        line();
    }

    // ---- 特化常量 ----
    if (!specs.empty()) {
        line("// ---- specialization constants ----");
        for (auto& s : specs)
            line("constexpr uint32_t kSpec_", Sanitize(s.name), " = ", s.id, ";");
        line();
    }

    line("} // namespace shader::", Sanitize(shaderName));
    return o;
}
```

## 14. 布局哈希与热重载

### 14.1 三级哈希

```
┌────────────────────────────────────────────────────┐
│ H1  源码哈希   = hash(source + keywords + flags)     │
│     → 判断"要不要重新编译"                            │
├────────────────────────────────────────────────────┤
│ H2  SPIR-V 哈希 = hash(spv bytes)                    │
│     → 判断"编译产物是否变化"（二进制去重也用它）        │
├────────────────────────────────────────────────────┤
│ H3  布局哈希   = hash(canonical layout)              │
│     → 判断"描述符布局是否变化"                        │
│     ★ 决定是否要重建 PipelineLayout / 重分配描述符集   │
└────────────────────────────────────────────────────┘
```

### 14.2 热重载决策

```cpp
struct ReloadDecision {
    bool rebuildShaderModule = false;   // H2 变了
    bool rebuildPipeline     = false;   // H2 变了（PSO 依赖 shader module）
    bool rebuildLayout       = false;   // H3 变了
    bool reallocDescriptors  = false;   // H3 变了
};

ReloadDecision Plan(const ShaderRecord& oldR, const ShaderRecord& newR) {
    ReloadDecision d;
    d.rebuildShaderModule = (oldR.spvHash  != newR.spvHash);
    d.rebuildPipeline     = d.rebuildShaderModule;
    d.rebuildLayout       = (oldR.layoutHash != newR.layoutHash);
    d.reallocDescriptors  = d.rebuildLayout;
    return d;
}
```

### 14.3 热重载流程

```
文件监听（ReadDirectoryChangesW / inotify / efsw）
   │ 检测到 .hlsl 修改
   ▼
① 计算 H1 → 与缓存比较 → 未变则忽略
   ▼
② 重新编译（dxc）→ spirv-val → spirv-opt
   ▼
③ 计算 H2 → 未变则忽略（可能是注释改动）
   ▼
④ 反射 → 合并 → 计算 H3
   ▼
⑤ 决策
   ├─ 只变了 H2（逻辑改，布局未变）
   │     → 创建新 VkShaderModule → 重建 PSO（可用旧 PipelineLayout）
   │     → 原子替换 → 旧对象延迟 N 帧销毁
   │
   └─ H3 也变了（改了资源）
         → 重建 DescriptorSetLayout / PipelineLayout
         → 重新分配并重新填充所有描述符集  ★
         → 重建 PSO
         → 原子替换 → 旧对象延迟 N 帧销毁
   ▼
⑥ 重新生成 C++ 绑定头（提示：需要重新编译 C++ 才能生效）
```

```cpp
class ShaderHotReloader {
public:
    void Reload(const ShaderKey& key) {
        auto newRec = Cook(key);                       // 编译 + 反射
        auto& oldRec = records_.at(key);
        auto d = Plan(oldRec, newRec);

        if (!d.rebuildShaderModule && !d.rebuildLayout) return;   // 无实质变化

        // 在 GPU 空闲时替换（等当前帧的 fence）
        pending_.push_back({ key, std::move(newRec), d });

        if (d.rebuildLayout)
            LogWarn("Layout changed for {} — descriptor sets will be reallocated", key.source);
    }

    void OnFrameEnd(uint64_t completedFrame) {
        for (auto it = pending_.begin(); it != pending_.end(); ) {
            if (it->readyFrame > completedFrame) { ++it; continue; }
            Apply(*it);                     // 原子替换
            deferredDelete_.emplace_back(completedFrame + kFramesInFlight,
                                         it->oldObjects);
            it = pending_.erase(it);
        }
        // 延迟销毁
        for (auto it = deferredDelete_.begin(); it != deferredDelete_.end(); ) {
            if (it->frame > completedFrame) { ++it; continue; }
            DestroyAll(it->objects);
            it = deferredDelete_.erase(it);
        }
    }
private:
    struct Pending { ShaderKey key; ShaderRecord rec; ReloadDecision d;
                     uint64_t readyFrame; std::vector<VulkanObject> oldObjects; };
    std::unordered_map<ShaderKey, ShaderRecord> records_;
    std::vector<Pending> pending_;
    std::vector<std::pair<uint64_t, std::vector<VulkanObject>>> deferredDelete_;
};
```

> ⚠️ **热重载的三条铁律**：
> 1. **绝不立即销毁**正在被 GPU 使用的对象 → 延迟 `FramesInFlight` 帧
> 2. **H3 变化要重填描述符**：新布局的 binding 号/类型可能完全不同
> 3. **C++ 绑定头变化需要重编 C++**：热重载只能救 shader 逻辑，救不了结构体定义

```cpp
// ---- 一次完整的管线构建 ----
PipelineBundle BuildPipeline(VkDevice dev,
                             std::span<const std::vector<uint32_t>> spvBlobs,
                             DescriptorLayoutCache& layoutCache) {

    // S1：逐模块反射
    std::vector<shader::ModuleData> mods;
    for (auto& spv : spvBlobs) {
        rt::ShaderModule m(spv);
        mods.push_back(Bake(m));
    }

    // S2：语义标注（可选：先做 Change* 重映射）
    for (auto& m : mods)
        for (auto& b : m.bindings)
            if (b.set == 0) {   // DXC 默认全在 set0 → 按约定重排
                auto f = ClassifyByName(b.name);
                b.set  = SetForFrequency(f);
            }

    // S3：合并 + 冲突检测
    LayoutMerger merger;
    for (auto& m : mods) merger.Add(m);
    if (!merger.Errors().empty()) {
        for (auto& e : merger.Errors()) LogError(e);
        throw std::runtime_error("shader layout conflict");
    }
    const auto& L = merger.Result();

    // S4：设备能力校验
    ValidateAgainstDevice(L, deviceLimits);

    // S5：PipelineLayout
    auto plr = BuildPipelineLayout(dev, L, mods, layoutCache);

    // S6：顶点布局（取 VS 模块）
    VertexLayoutResult vertexLayout;
    for (auto& m : mods)
        if (m.stage & VK_SHADER_STAGE_VERTEX_BIT)
            vertexLayout = BuildVertexLayout(m);

    // S7：池定额
    auto poolSizes = ComputePoolSizes(L, kFramesInFlight, kBindlessCapacity);
    VkDescriptorPool pool = CreatePool(dev, poolSizes, kMaxSets, /*updateAfterBind=*/true);

    // S8：绑定头（构建期调用，这里仅演示）
    std::vector<shader::BlockInfo> blocks;
    for (auto& m : mods) blocks.insert(blocks.end(), m.blocks.begin(), m.blocks.end());
    WriteFile("generated/shader_bindings.h",
              EmitBindingHeader("gbuffer", blocks, mods[0].bindings, mods[0].specConstants));

    return PipelineBundle{
        .pipelineLayout = plr.layout,
        .setLayouts     = std::move(plr.setLayouts),
        .pushRanges     = std::move(plr.pushRanges),
        .pool           = pool,
        .vertexLayout   = std::move(vertexLayout),
        .layoutHash     = LayoutHash(L),
    };
}
```

## 17. 常见错误速查

| 现象 | 根因 | 排查 |
|------|------|------|
| 画面全黑，无报错 | `COMBINED_IMAGE_SAMPLER` 只写了 image 未写 sampler | 查写入器 |
| 校验层报 "descriptor type mismatch" | 跨阶段冲突 | `LayoutMerger` 错误日志 |
| UBO 数据错位 | C++ 结构体与 shader 布局不一致 | `static_assert` / `spirv-reflect` dump |
| 矩阵转置了 | glslang vs DXC 主序不同 | 反射的 `ROW_MAJOR` 标志 |
| 绑定"凭空多一个" | HLSL counter buffer | `uav_counter_binding` |
| 描述符写入报类型不匹配 | 反射类型与写入类型不符 | 用生成的强类型写入器 |
| 热重载后崩溃 | 立即销毁了在用对象 | 延迟销毁 |
| 热重载后数据错乱 | H3 变了但没重填描述符 | 检查 `reallocDescriptors` |
| 首次 draw 卡顿 | PSO 未预热 | `PipelineWarmer` + 持久化 `VkPipelineCache` |
| Bindless 结果随机错误 | 缺 `NonUniformResourceIndex` | 加 `NonUniform` |

## 18. 小结

| 环节 | 核心产出 | 关键陷阱 |
|------|---------|---------|
| S1 反射 | `ModuleData` POD | 名字可能缺失 |
| S2 语义 | set / 频率分配 | SPIR-V 无语义，必须约定 |
| S3 合并 | `MergedLayout` + 冲突列表 | 类型/数量冲突是致命的 |
| S4 哈希 | 布局指纹 | 不要哈希 name |
| S5 布局 | `DescriptorSetLayout` / `PipelineLayout` | PushConstant 要合并 |
| 池定额 | 按类型统计 | Bindless 单独池 |
| 写入器 | 类型安全填充 | vector 扩容导致指针失效 |
| 顶点布局 | attribute + stride | 过滤 BuiltIn |
| Bindless | 槽位分配器 | `NonUniformResourceIndex` |
| 代码生成 | `.h` + `static_assert` | `offsetof` 需标准布局 |
| 热重载 | 三级哈希决策 | 延迟销毁 + H3 变化重填 |

**一句话总结**：

> 反射给你**事实**（set/binding/offset），约定给你**语义**（PerFrame/PerMaterial），代码生成把二者**钉进编译期**——三者结合，shader 与 C++ 的契约就从"靠人保证"变成了"靠编译器保证"。
