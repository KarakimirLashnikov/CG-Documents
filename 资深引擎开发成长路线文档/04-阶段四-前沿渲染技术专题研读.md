# 阶段四（M10–M12）— 前沿渲染技术专题研读与Capstone

> 本文档是「资深引擎开发成长路线」系列文档的第 **4** 篇。覆盖能力域 **E（前沿技术判断力）+ 综合能力收束**。研读对象：虚拟几何体（Nanite）、虚拟纹理（VT）、全局光照（Lumen）、阴影（VSM）、纹理映射技术，以及 3A/GDC 渲染技术体系。终点是 **Capstone 项目**。

> ⚠️ 论文/演讲出处以原文为准；GDC Vault 部分幻灯片免费、视频需订阅，SIGGRAPH 论文走 ACM DL 或作者主页。

## 1. 研读方法论：怎么读才不算白读

每个专题按统一模板产出文档（直接落工作区新系列或并入对应已有系列）：

```
专题文档骨架（每篇 ≤2 周）：
  ① 问题定义：它解决了什么、前人方案死在哪
  ② 核心思想：一页 ASCII 图说清数据结构与算法骨架
  ③ 关键细节：3~5 个「魔鬼在细节」（往往是工程而非数学）
  ④ UE 5.8 落地位置：源码模块/关键类型/开关 cvar
  ⑤ 量化特征：开销来自哪、随什么缩放、硬件门槛
  ⑥ 评估：什么项目该用、什么项目别碰、替代方案
```

**精读纪律**：原始论文/官方演讲 > 二手博客；读完必须能回答「如果让我在 RenderToy 里实现一个简化版，第一步做什么」。

## 2. M10：虚拟几何体与阴影（Nanite + VSM）

### 2.1 Nanite 专题（W37–W39）

| 子题 | 核心问题 | 关键材料 |
|------|---------|---------|
| Cluster 构建 | 网格如何切成 ~128 三角形 cluster，DAG 层级 LOD 如何构建 | SIGGRAPH 2021 "A Deep Dive into Nanite Virtualized Geometry"（Brian Karis 等） |
| 软件光栅化 | 为什么小三角形用 compute 软件光栅比硬件光栅快 | 同上 + `Runtime/Renderer/Private/Nanite/` 源码 |
| 可见性缓冲 | Visibility Buffer 思路：先写 (cluster, tri) ID 再材质化 | 源码 `NaniteShadingPipeline` |
| 流送 | 运行时如何按视距请求 cluster 数据页 | `NaniteStreaming` |

**实验（W39）**：RenderDoc 截 Nanite 帧，逐个 Pass 对应论文管线阶段；在 UE 里开关 `r.Nanite` 对比同一重几何场景的 GPU 分解。

### 2.2 Virtual Shadow Maps 专题（W40）

- 核心：16K×16K 虚拟阴影页 + 按需渲染 + 页缓存跨帧复用；
- 与传统 CSM / 逐灯 shadow atlas 的对比表（内存/质量/动态更新成本）；
- ⚠️ 已知弱点：细薄几何走样、页面失效风暴；UE 的 OnePassProjection 等缓解手段以源码为准。

**里程碑 M10**：两篇专题文档（Nanite、VSM），各含「简化版实现思路」一节。

## 3. M11：全局光照、虚拟纹理与纹理映射（W41–W44）

### 3.1 Lumen 专题（W41–W42）

```
Lumen 数据流（理解顺序）：
  Surface Cache（近场几何的材质属性缓存）
      │ 捕获：Multi-view 卡片（Cards）投影
      ▼
  Radiance Cache / Voxel Lighting
      │
      ▼
  Screen Space Probe Tracing（屏幕空间探针追踪，主力路径）
      │ 不够时回退 → Global Distance Field Tracing（SW）
      │ 高端路径   → HW Ray Tracing
      ▼
  时序滤波 + 上采样合成
```

- 关键论文/演讲：SIGGRAPH 2021/2022 Lumen 分享（Karis/ Epic 团队），5.8 的 Lumen Lite 走 release notes；
- 评估重点：Surface Cache 对**动态几何更新**的成本、薄几何漏光的工程缓解、HW RT 档位划分。

### 3.2 虚拟纹理专题（W43）

| 层次 | 内容 |
|------|------|
| 概念谱系 | id Software MegaTexture（Carmack, Rage 2011 前后）→ Adaptive/ Sparse Texture → UE Virtual Texture |
| UE 形态 | Runtime VT（地形/贴花混合） vs Streaming VT（省显存） |
| 反馈回路 | 渲染时记录所需 page → CPU 回读 → 加载 → 更新 page table —— 延迟一帧的代价与缓解 |
| 对照 | 与自研 Vulkan sparse binding（`VK_KHR_sparse_binding`）思路对照 |

### 3.3 纹理映射技术专题（W44）

选 3 个深入（按简历价值排序）：

1. **虚拟化纹理采样**：Sampler Feedback / 纹理空间着色（Texture Space Shading, SIGGRAPH 2019 前后工业方案）；
2. **过滤与高频抗锯齿**：各向异性过滤原理、TAA 下的纹理 shimmer（衔接 `抗锯齿技术文档/02`）；
3. **纹理压缩与带宽工程**：BC7/ASTC 选型、Mali/Adreno 差异（衔接 `移动端GPU架构文档/`）。

**里程碑 M11**：Lumen + VT + 纹理映射三篇文档；GDC/论文精读笔记累计 ≥15 篇（笔记模板：问题/思想/细节/可用性 四栏）。

## 5. M12：Capstone——UE Vulkan RHI 新特性落地（W45–W48）

### 5.1 选题原则

- **综合前三阶段**：必须同时动用 RDG 实操（M2）、Shader 类型（M4）、性能量化（M8/M9）；
- **范围可控**：48 小时内能跑通最小版本，剩余时间迭代；
- **有量化评估**：没有数字的 Capstone 等于没做。

候选题目（择一）：

| 题目 | 动用的能力 | 亮点 |
|------|-----------|------|
| A. RDG 内嵌 ReSTIR DI 简化版（单次重采样） | RDG + CS Shader + 光照 | 论文落地，简历含金量高 |
| B. 自定义 HiZ 遮挡剔除管线接入主线 | RDG + RHI + 间接绘制 | 与 M2 实验衔接，工程完整 |
| C. GPU-Driven 渲染原型：MDI + bindless 重构一个子管线 | RDG + VulkanRHI + 性能分析 | 与 RenderToy 特性互相印证 |
| D. 自定义阴影缓存方案（页式缓存简化版） | RDG + VT 思想 + VSM 研读 | 专题直接变现 |

### 5.2 四周节奏

| 周 | 动作 | 检查点 |
|----|------|--------|
| W45 | 技术方案设计：数据流图 + Pass 划分 + 风险清单 | 方案评审（自问：最坏情况能砍到什么） |
| W46 | 最小可运行版本（画面正确即可，不管性能） | 能跑 + RenderDoc 可见 |
| W47 | 正确性加固 + 性能测量 + 优化一轮 | Insights/Nsight 数据齐全 |
| W48 | 技术报告 + 演示视频/截图 + 简历化描述 | **M12 里程碑验收** |

### 5.3 Capstone 技术报告骨架

```
1. 问题与动机（为什么值得做）
2. 方案设计（数据流图、Pass 划分、关键取舍）
3. 实现要点（源码结构、踩坑与对策——⚠️ 清单）
4. 量化评估（帧时间分解、与基线对比、硬件适配范围）
5. 局限与后续（诚实写做不到什么）
6. 附录：复现步骤
```
