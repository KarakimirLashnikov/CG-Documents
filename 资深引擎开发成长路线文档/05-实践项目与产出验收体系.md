# 实践项目与产出验收体系（贯穿全年）

> 本文档是「资深引擎开发成长路线」系列文档的第 **5** 篇（末篇）。学习计划不失败的关键不在内容，而在**执行系统**：项目载体、产出物清单、验收标准、复盘机制、简历化表达。本篇是全年各阶段的公共支撑。

---

## 1. 项目载体：三轨并行

```
轨 A：UE 插件工程（主战场）          轨 B：RenderToy 自研引擎（对照组）
  └ MyRenderingPlugin                 └ Vulkan + FrameGraph + Bindless
    ├ SceneViewExtension                └ 每个 UE 概念的「极简对照实现」
    ├ 自定义 RDG Pass
    └ 自定义 Shader 类型
                    │
                    ▼
        轨 C：工具链（效率放大器）
          └ Shader 变体统计/裁剪工具
          └ SPIRV-Reflect 双向核对工具
          └ 性能回归采集脚本
```

| 轨道 | 作用 | 维护成本 |
|------|------|---------|
| A UE 插件 | 所有 UE 侧实践的落点；可演示、可面试展示 | 中 |
| B RenderToy | 概念对照实现，逼自己想清「本质 vs 引擎巧合」 | 低（每周 ≤2h，防沉迷） |
| C 工具链 | 产出可复用工具，资深工程师的标志性产出 | 低 |

⚠️ 防坑：RenderToy 只做**对照性小实验**，不开新大功能——它是学习工具不是产品，沉迷自研引擎是本计划最大的沉没成本风险。

## 3. 验收标准：什么叫「学会了」

每个知识点按四级验收，**达到 L3 才算完成，L4 择优冲刺**：

| 级别 | 标准 | 检验方式 |
|------|------|---------|
| L1 知道 | 能复述概念 | —（不计入） |
| L2 理解 | 能画出数据流图，说清「谁填数据、谁消费」 | 自绘图与源码核对 |
| L3 能做 | 有可运行代码 + 量化数据 + 文档 | 三项齐全 |
| L4 能教 | 能向他人做 30 分钟分享并答出边界问题 | 实际分享一次（组内/线上） |

**月度复盘清单**（每月末周日，30 分钟）：

```
□ 本月里程碑达成了吗？没达成：砍深度还是砍范围？（见 00 篇风险表）
□ 产出物对账：文档/代码/数据各几件？
□ 时间账：有效投入几小时？输入:实践:产出 比例是否 ≈ 4:4:2？
□ 下月计划校准：是否有发现更好的切入点需要调整？
```

### 欠账清偿机制

连续两周无 commit 触发「48h 最小实验冲刺」：选一个 2 小时内能跑起来的最小实验（如改一个 cvar 对比截帧），**只为恢复手感与节奏**，不追求完美。

## 4. 简历化表达（每次大产出同步更新）

产出的同时就写成简历语言，避免年底补写失真。模板：**动作 + 技术栈 + 量化结果 + 影响**。

| 阶段 | 简历条目示例（随实际数据更新） |
|------|------------------------------|
| M2 | 基于 UE5 RDG 与 ISceneViewExtension 实现自定义渲染 Pass 插件，零引擎源码侵入接入延迟渲染主线，经 RenderDoc 验证资源依赖正确 |
| M3 | 在 UE Vulkan RHI 层注入逐 Pass GPU 时间戳统计，与 Unreal Insights 数据对拍误差 <5%，定位 X 个同步气泡 |
| M5 | 构建 Shader 变体治理工具链（统计/裁剪/PSO 预热），裁剪无效排列 N%，包体 Shader 库缩减 N MB，编译时间下降 N% |
| M6 | 完成 Lumen / GPU Lightmass / MegaLights 同场景双维度（画质+性能）对比评估，输出选型决策树 |
| M8 | 主导 XX 场景帧时间优化：GPU 从 12ms 降至 7.8ms（-35%），方法论为预算分解→最小验证→回归固化 |
| M12 | 在 UE Vulkan RHI 上设计并落地 XXX 渲染特性（Capstone），含完整量化评估与技术报告 |

⚠️ 数字先占位（N），验收时回填真实值——**简历里的每个数字都必须能拿出截图**。
