# 资深引擎开发成长路线 — 总览与能力模型

> 本文档是「资深引擎开发成长路线」系列文档的第 **0** 篇（总览篇）。本系列是一份**可执行**的 12 个月学习-实践-产出计划，目标岗位为**资深引擎/渲染开发程序员**。计划基于如下起点定制：已能编译完整 UE 项目，具备图形学基础、扎实的 C++、Vulkan 与 CUDA 基础，了解 GPU 架构与异构系统设计，使用过 RenderDoc / Snapdragon Profiler / Android Studio Profiler / Nsight Graphics。
>
> ⚠️ **版本声明**：计划以 **UE 5.8（当前生产版，5.8.2 hotfix，2026-08 状态）** 为基准；UE6 Early Access 预计 2027 年底，本计划末期需安排一次迁移评估。涉及 cvar / 源码路径处均以本地源码树为准。

---

## 1. 目标岗位能力模型

资深引擎开发（渲染方向）的胜任力可拆为 **5 个能力域**，每个能力域给出「资深」与「中级」的判别线：

| 能力域 | 中级（现状附近） | 资深（目标） |
|--------|----------------|--------------|
| A. 渲染管线架构 | 会用引擎默认管线、能写后处理材质 | 能搭建/改造自定义渲染管线，理解每一 Pass 的数据流与取舍，能做管线级性能权衡 |
| B. Shader 与材质体系 | 会写 Shader、会用材质编辑器 | 掌握 Shader 编译/排列爆炸治理、参数数据流布局、反射机制，能维护上千个 Shader 变体的工程 |
| C. RHI 与平台层 | 熟悉 Vulkan API | 能在 UE RHI（Vulkan backend）上落地新渲染特性，理解 RDG→RHI→驱动 全链路 |
| D. 性能分析与优化 | 会用 RenderDoc/Nsight 截帧看耗时 | 有方法论：预算分解→定位→验证闭环；熟练使用 Unreal Insights + 厂商工具链；能量化优化收益 |
| E. 前沿技术储备 | 知道 Nanite/Lumen 是什么 | 精读过核心论文/GDC 分享，能评估「该不该用、怎么改、代价是什么」，能向团队布道 |

```
                     资深引擎开发（渲染方向）
        ┌──────────────┬──────────────┬──────────────┐
        ▼              ▼              ▼              ▼
   A 管线架构      B Shader体系    C RHI/平台     D 性能优化
        └──────────────┴──────┬───────┴──────────────┘
                              ▼
                    E 前沿技术判断力（贯穿全年）
```

**关键认知**：资深与中级的差距不在「会多少 API」，而在**数据流思维**（这个数据谁填的、何时填的、在哪个时间尺度存活）和**量化决策**（每一毫秒花在哪、省哪一笔最划算）。

## 3. 与已有知识资产的复用关系

本计划**不重复造轮子**，大量复用工作区已有文档系列作为各阶段的「教材」：

| 已有系列 | 在本计划中的角色 |
|---------|----------------|
| `UE渲染源码导读文档/` | 阶段一的**主教材**：Scene/View/Primitive 概念、延迟渲染主线 |
| `UE5Shader系统文档/` | 阶段二的**主教材**：Shader 编译流程、参数体系、材质代码生成 |
| `实时渲染系统文档/` | 阶段一的 Vulkan/RDG 对照教材（自研 RenderToy 视角） |
| `游戏性能分析文档/` | 阶段三的**方法论教材**：CPU/GPU/内存分析框架 |
| `Shader工具链文档/` | 阶段二的反射与元编程深度补充 |
| `移动端GPU架构文档/`、`抗锯齿技术文档/`、`NPR技术文档/` | 阶段四专题选读 |

**双线并行策略**：自研引擎 RenderToy（Vulkan）与 UE 源码**互为对照**——同一个概念（如 FrameGraph vs RDG、Bindless vs UE 的 descriptor 管理）在两个实现里各看一遍，理解深度远超单线学习。这是本计划相对普通学习路线的核心差异优势。

## 4. 每周节奏模板（可执行粒度）

每周按 **10~14 小时**有效投入设计（工作日 1.5h/天 + 周末半天）：

```
周一至周三晚（各 1.5h）：输入
  ├ 源码精读 / 论文 / 官方文档（配笔记）
  └ 规则：每读一段必产出「数据流一句话」笔记，禁止只看不写

周四晚（1.5h）：实验设计
  └ 写一个最小可运行实验（cvar 对比 / 截帧 / 微基准）

周五晚 + 周六上午（4~5h）：实践
  └ 编码落地（UE 插件 / RenderToy 特性 / Shader）

周六下午（2h）：产出固化
  ├ 写文档篇目或更新已有文档
  └ 更新里程碑看板（见 05 篇）

周日：休息或补欠账；每月末一个周日做月度复盘
```

**三条铁律**：

1. **输入必产出**：任何超过 30 分钟的阅读必须留下笔记（哪怕 5 行），否则视为没读；
2. **实验必量化**：任何「感觉变快了」必须配 RenderDoc/Insights 数字截图，否则不算结论；
3. **代码必可跑**：每个实践成果必须能编译运行并附复现步骤，拒绝「半成品玩具」。

## 5. 里程碑总表

| 时间点 | 里程碑 | 验收物 |
|--------|--------|--------|
| M1 末 | 画出 UE 5.8 延迟渲染主线全图（含 Pass 依赖） | 一张自绘数据流图 + 源码行号索引笔记 |
| M2 末 | 在 UE 中落地一个自定义 RDG Pass（如自定义遮挡剔除或全屏效果） | 可运行插件 + RenderDoc 截帧分析 |
| M3 末 | 读懂 UE Vulkan RHI 的一次 Draw 完整路径（RDG→RHI→vkCmd） | 调用链文档 + 断点验证记录 |
| M4 末 | 复现材质从节点图到 HLSL 到 PSO 的完整链路 | 链路文档 + 一个自定义 Shader 类型落地 |
| M5 末 | 建成 Shader 变体治理工具（统计/裁剪/缓存预热） | 工具 + 包体/编译时间对比数据 |
| M6 末 | 完成一套工业级光照方案对比实验（Lumen vs 烘焙 vs MegaLights） | 对比报告（画质+性能双维度） |
| M7 末 | 掌握 Unreal Insights 全工作流（Trace/CPU/GPU/Memory） | 一次完整 profile 解读报告 |
| M8 末 | 完成一个真实场景的帧时间优化闭环（如 16.6ms 预算分解） | 优化前后对比 + 方法论复盘 |
| M9 末 | GPU 优化专项：从 Nsight 指标反推瓶颈并修复 ≥2 例 | 案例集 |
| M10 末 | Nanite + VSM 源码级精读完成 | 两篇专题文档 |
| M11 末 | Lumen + VT + 纹理映射专题完成；GDC/论文精读 ≥15 篇 | 专题文档 + 精读笔记库 |
| M12 末 | **Capstone**：在 UE Vulkan RHI 上落地一个新渲染特性并量化评估 | 代码 + 技术报告 + 简历级项目描述 |

## 6. 风险与对策

| 风险 | 信号 | 对策 |
|------|------|------|
| 源码阅读陷入细节黑洞 | 一周没有产出笔记/代码 | 退回「地图式阅读」纪律：先问数据归属，分支能跳就跳 |
| 阶段膨胀、进度延误 | 月末里程碑未达成 | 砍深度不砍验收：缩小实验规模，保住「可运行+可量化」底线 |
| 只学不练 | 连续两周无 commit | 启动 48h 最小实验冲刺（见 05 篇「欠账清偿机制」） |
| UE 版本漂移 | 5.9/UE6 发布 | 以源码为准更新笔记；版本敏感结论一律标注日期 |
| 工作与学习冲突 | 周投入 <6h | 降级为「保线模式」：只保每周 1 篇笔记 + 1 次实验，不断档即可 |
