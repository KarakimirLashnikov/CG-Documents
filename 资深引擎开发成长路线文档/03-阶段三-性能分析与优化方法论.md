# 阶段三（M7–M9）— 性能分析与优化方法论

> 本文档是「资深引擎开发成长路线」系列文档的第 **3** 篇。覆盖能力域 **D（性能分析与优化）**。目标：从「会用工具截帧看耗时」升级为「有方法论闭环」——预算分解 → 假设 → 定位 → 修复 → 量化验证。已有 RenderDoc / Nsight Graphics / Snapdragon Profiler 经验是本阶段的加速器，重点补齐 **Unreal Insights** 与**优化决策框架**。
>
> ⚠️ stat 命令与 cvar 以 UE 5.8.2 本地引擎帮助文本为准（`cvar` 语义历版有变，旧教程常错）。

---

## 1. 方法论总纲：优化闭环

```
┌─────────────────────────────────────────────────────┐
│ ① 预算分解：16.6ms = GT + RT + RHIT + GPU(并行交叠)  │
│         先分清「谁 bound」——帧时间 ≠ GPU 时间          │
├─────────────────────────────────────────────────────┤
│ ② 提出假设：瓶颈在 X（数据支持，不是感觉）             │
├─────────────────────────────────────────────────────┤
│ ③ 最小验证：关掉/降级 X → 帧时间变化是否符合预期        │
│    （如 r.SetRes 50：若帧时间不变 → 非分辨率 bound）   │
├─────────────────────────────────────────────────────┤
│ ④ 修复 + 回归：改代码/资源 → 同场景同视角重测          │
├─────────────────────────────────────────────────────┤
│ ⑤ 固化：写入性能预算表 + 加自动化监控（防回退）         │
└─────────────────────────────────────────────────────┘
```

**三条纪律**：

1. **先 bound 分类，再选工具**：CPU bound 开 Insights/VTune，GPU bound 开 Nsight/RenderDoc，内存开 Insights Memory/LLM2——拿错工具浪费一周；
2. **一次只改一个变量**，否则归因不可信；
3. **优化必有回归基线**：每个优化合并前留「前后同机同场景」数字。

## 2. M7：Unreal Insights 全工作流（里程碑 M7）

### 2.1 周计划

| 周 | 主题 | 动作 | 产出 |
|----|------|------|------|
| W25 | Trace 体系与采集 | `UnrealInsights.exe` + `-trace=cpu,gpu,memory,frame`；开销认知（trace 本身有成本） | 采集流程笔记 |
| W26 | Timing/Fencing 视图 | GT/RT/RHIT 三线程时序读法；找 bubble 与长尾 | 时序解读练习 ×3 |
| W27 | Frame/Memory 轨道 | 帧分解、内存分配热点、LLM2 tag | 内存热点报告 |
| W28 | **里程碑 M7**：完整解读 | 对一个真实关卡出一份 profile 解读报告（瓶颈假设 ≥3 条，附验证实验设计） | 解读报告 |

### 2.2 读图要点（时序视图）

```
GT  ──[Tick 4.2ms]────[Wait for RT]──────────[SendCommands]──►
RT  ──────[InitViews 2.1][MeshCommands 1.8]──[Wait GPU]──────►
RHIT ─────────────────────[Submit 0.9]───────────────────────►
GPU ════════════════[BasePass 3.2][Lumen 2.8][Post 1.5]══════►
       ▲
       └─ 判读：GT 在等 RT → RT bound；GPU 总长 < 16.6 → 非 GPU bound
          下一步：Insights 里展开 InitViews 找长尾任务
```

⚠️ 坑：`stat unit` 的 Frame/GT/RT/GPU 四个数**不是相加关系**（并行交叠），新人最常误读；以 Insights 时序图为准。

## 3. M8：帧时间优化闭环实战（里程碑 M8）

### 3.1 实战设计

选一个**真实复杂场景**（市场免费大场景或自建压力场景），目标：在 RTX 3050 上从 ~12ms GPU 优化到 8ms 以内（目标自定，必须可测）。

| 周 | 动作 |
|----|------|
| W29 | 预算分解 + 瓶颈假设清单（至少 5 条候选，按预期收益排序） |
| W30 | 逐条最小验证实验（每条 ≤2h，记录「假设/实验/结果/结论」四列） |
| W31 | 实施 Top2 修复 + 回归测试 |
| W32 | **里程碑 M8**：优化复盘报告（含失败假设——负结果同样有价值） |

### 3.2 优化手段速查（按瓶颈分类）

| 瓶颈 | 典型信号 | 首选手段 |
|------|---------|---------|
| Draw/状态提交 | RT `MeshDrawCommands` 长尾 | 静态 MDC 缓存命中检查、合并、instance |
| 顶点/几何 | Nsight: SM 忙、Prim 吞吐高 | LOD 策略、Nanite 化、LOD 屏幕尺寸调优 |
| 像素/带宽 | Nsight: L2/DRAM 吞吐饱和 | 降分辨率/GBuffer 瘦身/半分辨率 Pass |
| ALU | SM issue 高、带宽低 | 材质指令审计、半精度、查找表化 |
| 同步/气泡 | 时序图 RT/GPU 互相等待 | Pass 重排、异步 compute 填空、减少 fence |
| 遮挡缺失 | 不可见物体仍绘制 | 预计算可见性/HiZ/距离剔除调参 |

### 3.3 ⚠️ 反模式清单

| 反模式 | 为什么错 |
|--------|---------|
| 先优化后测量 | 改的常不是瓶颈，还引入回归 |
| 编辑器里测性能 | 编辑器开销淹没真实数据；必须 standalone/打包 |
| 用「帧率提升 %」汇报 | 帧率非线性；一律用 **ms** 汇报 |
| 只看均值 | 卡顿在长尾；看 P95/P99 与 hitching |
| 一次性大改 | 无法归因；小步快走 |

## 4. M9：GPU 优化专项 + 移动端迁移（里程碑 M9）

### 4.1 Nsight Graphics 指标驱动优化

把已有的截帧经验升级为**指标反推法**：

```
Nsight 指标 → 瓶颈翻译 → 动作
─────────────────────────────────────────
SM Throughput 高 + Memory 低      → ALU bound   → 减指令/半精度
Memory Throughput 高 + SM 低      → 带宽 bound  → 减采样/压缩格式/降 RT
Warp Stall: Long Scoreboard 高    → 访存延迟    → 合并访存/预取/重排
Warp Stall: Barrier 高            → 同步过多    → 减 group 同步/调 workgroup
Draw 间 gap 大                    → 提交开销    → 减 Pass 数/合并
```

**实战（W33–W35）**：从阶段一/二的实验工程里挑 ≥2 个真实瓶颈，走完「指标→假设→修复→回归」全流程，形成案例集。

### 4.2 移动端/异构迁移（W36，选做但强烈推荐）

把 CUDA/异构背景转化为差异化优势：

- 用 Snapdragon Profiler 在 Android 上重跑一个 UE 移动场景，对照桌面 TBR vs IMR 差异（教材：`移动端GPU架构文档/`）；
- 输出一篇「桌面优化经验在移动端失效清单」（如：Overdraw 容忍度、带宽优先级、GMEM 行为差异）——这是资深移动端渲染岗的核心竞争力，也是简历差异化素材。

## 5. 自动化与防回退（贯穿 M7–M9）

| 机制 | 做法 |
|------|------|
| 性能预算表 | 每 Pass 分配 ms 预算（如 BasePass ≤3ms、Lumen ≤3ms），入版本库 |
| 定期回归 | 每周固定场景自动采集 `stat gpu/unit` + Insights trace，超预算报警 |
| 变更门禁 | 渲染相关 PR 必须附前后对比数字 |
