十大高频坑

#现象根因
1找不到 include 文件插件未注册虚拟路径
2参数读出来永远是 0C++ 字段名 ≠ HLSL 变量名（或变量被 DCE）
3编译报改用 FVector3f用了 LWC 的 double 类型
4全屏 Pass 无输出缺 RENDER_TARGET_BINDING_SLOTS()
5Compute 结果错乱缺越界检查 / 组数算错 / 用了非 RDG 的 UAV
6GetShader<T>() 返回空Permutation 被 ShouldCompilePermutation 裁掉
7改了 USF 不生效DDC 缓存命中 → recompileshaders changed
8运行时莫名卡顿改了 Static Parameter 触发重编译
9Metal / GL 路径失败直接写了 Texture2D.Sample() 而未用抽象宏
10shader 编译几小时Static Switch / VF / Permutation 未裁剪
最本质的认知：UE 的 shader 只有一份 HLSL 源码，靠宏展开成海量变体。 理解了"宏 → 变体 → DDC key → 编译"这条链，绝大多数问题都能自己定位。

落地路线图

阶段做什么产出
P0配好开发环境（3 个 CVar + RenderDoc）编译错误可定位
P1照抄 04 篇跑通一个全屏 Pass第一个自定义 shader
P2加 Compute Pass + Permutation掌握变体机制
P3用 MPC 与内置 UB 组织参数参数体系熟练
P4做 05 篇的 Mesh Pass掌握 VF + MeshPassProcessor
P5接共享 DDC + PSO 采集编译与加载提速
P6变体审计与裁剪编译时间可控
一句话总结：UE 只写 HLSL → 宏展开成变体 → 跨进程编译 → DDC 缓存 → ShaderMap 查找 → RDG 绑定。掌握这条链，你就能在 UE 里自由地加任何 Pass。
