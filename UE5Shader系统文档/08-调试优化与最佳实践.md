# 调试、优化与最佳实践

> 系列第 **8** 篇（终篇）。写 shader 的一半时间在调试，另一半在等编译。本文给出 UE shader 开发的调试配置、三层排查法、变体与编译时间优化、运行时性能要点，以及一份可落地的最佳实践清单。

---

## 1. 开发模式：先把环境配好

### 1.1 必开的控制台变量

在 `Engine/Config/ConsoleVariables.ini`（或项目的 `DefaultEngine.ini` 的 `[ConsoleVariables]`）中：

```ini
; ---- Shader 开发必备 ----
r.ShaderDevelopmentMode=1        ; 出错时保留调试信息，支持快速迭代
r.DumpShaderDebugInfo=1          ; 转储编译中间产物
r.DumpDebugShaderText=1          ; 转储预处理后的完整 HLSL

; ---- RDG 调试（按需开）----
r.RDG.Debug=1                    ; 1=基础校验 2=详细
r.RDG.DumpGraph=1                ; 导出 RDG 图（Debug 构建可用）

; ---- PSO 收集（用于打包前采集）----
r.ShaderPipelineCache.Enabled=1
r.ShaderPipelineCache.LogPSO=1
r.ShaderPipelineCache.SaveBoundPSOLog=1
```

| 变量 | 作用 | 代价 |
|------|------|------|
| `r.ShaderDevelopmentMode` | 编译错误更友好、保留中间文件 | 轻微 |
| `r.DumpShaderDebugInfo` | 转储到 `Saved/ShaderDebugInfo/` | 磁盘 |
| `r.DumpDebugShaderText` | 转储**展开后**的 HLSL（含所有 include 与宏展开） | 磁盘、编译变慢 |
| `r.RDG.Debug` | 校验 RDG 资源的读写声明是否一致 | 运行时开销 |
| `r.RDG.ImmediateMode` | 关闭 RDG 的异步/延迟执行，便于断点 | 性能下降明显 |

> ⚠️ **发布构建务必关掉**：这些变量会显著增加编译时间与磁盘占用。

### 1.2 常用控制台命令

```
recompileshaders changed           # 只重编变化的（最常用）
recompileshaders all               # 全量
recompileshaders global            # 只重编全局 shader
recompileshaders material <Name>   # 重编指定材质

stat ShaderCompiling               # 查看编译队列与进度
stat GPU                           # GPU 耗时
ProfileGPU                         # 抓取一帧的 GPU 分解

DumpMaterialShaderTypes            # 列出所有材质 shader 类型及其变体数（排查变体爆炸）
```

## 2. 编译错误：三层排查法

### 2.1 第一层：读错误信息

UE 的 shader 错误信息长这样：

```
[2026.08.30-11.02.15:123][  0]LogShaderCompilers: Error: MyShader.usf(42,15): error X3004: undeclared identifier 'Foo'
```

| 部分 | 含义 |
|------|------|
| `MyShader.usf(42,15)` | 报错位置（**行号是展开后的**） |
| `error X3004` | 平台编译器的错误码（FXC 用 X 前缀） |
| `undeclared identifier 'Foo'` | 具体问题 |

> ⚠️ **行号是预处理后的**，与你写的 `.usf` 不一定对应。这时需要第二层。

### 2.2 第二层：看展开后的源码

开启 `r.DumpShaderDebugInfo=1` 后，到：

```
<Project>/Saved/ShaderDebugInfo/
├── <Platform>/
│   └── <ShaderType>/
│       └── <Hash>/
│           ├── Output.usf        ← ★ 展开后的完整 HLSL（含所有 include）
│           ├── Output.d3dasm     ← 反汇编（平台相关）
│           └── DirectCompile.txt ← 直接编译的命令行
```

**做法**：
1. 用错误信息里的文件名找到对应目录
2. 打开 `Output.usf`，跳到报错行号
3. 往上找——通常是某个 `#include` 展开进来的代码，或者是宏展开的结果

**最实用的一招**：把 `Output.usf` 复制出来，用编辑器的搜索找到你的代码片段，就能确认"我的宏展开成了什么"。

### 2.3 第三层：手工复现编译

`DirectCompile.txt` 里记录了完整的编译器命令行。你可以：

```bash
# 在命令行里直接跑，快速迭代
dxc -T ps_6_6 -E MainPS -spirv -fspv-target-env=vulkan1.3 -Fo out.spv Output.usf
```

好处：**不用重启编辑器，改一行立刻看结果**。

### 2.4 错误类型速查

| 错误 | 常见原因 |
|------|---------|
| `undeclared identifier` | ① 变量名拼错 ② 缺少 include ③ Permutation 宏未定义（应为 `#if` 的分支没进来） |
| `redefinition` | 头文件重复包含（缺 `#pragma once` 或 include 守卫） |
| `cannot convert from X to Y` | 类型不匹配；常见于 `float3` 当 `float4` 用 |
| `array index out of bounds` | 常量数组越界（编译期常量能检查出来） |
| `Sampler limit exceeded` | 材质/Shader 用了太多采样器 |
| `register limit exceeded` | 资源槽位超限（减少纹理数量或用 Bindless） |
| `Failed to find include file` | 虚拟路径未注册或路径写错 |
| `Entry point not found` | `IMPLEMENT_*` 里的入口函数名与 USF 里不一致 |

## 3. 运行时问题排查

### 3.1 "参数读出来永远是 0"

**这是最高频的问题**，排查顺序：

| 步骤 | 检查 |
|------|------|
| ① | C++ 字段名与 HLSL 变量名**逐字**一致（含大小写） |
| ② | 参数结构体里有没有遗漏该字段 |
| ③ | 是否用了 RDG Pass 但填的是裸 RHI 资源（类型不匹配会静默失败） |
| ④ | 开 `r.DumpShaderDebugInfo`，在转储里搜该变量名，确认它真的被编译进去了 |
| ⑤ | 确认变量在 shader 里**真的被使用**——未使用的变量会被编译器优化掉，ParameterMap 里就没有它 |

> ⚠️ 第 ⑤ 条特别隐蔽：你在 HLSL 里声明了 `float Intensity;` 但没有用到 → 编译器 DCE → 绑定失败 → 看起来"参数没生效"。

### 3.2 "画面全黑" 排查链

```
① Pass 真的执行了吗？
   → 加 RDG_EVENT_SCOPE，用 RenderDoc 抓帧看有没有这个 Pass
   → 检查 CVar 开关 / ViewExtension 的 IsActiveThisFrame
                │
② RenderTarget 绑了吗？
   → RENDER_TARGET_BINDING_SLOTS() 有没有
   → PassParameters->RenderTargets[0] 填了吗
                │
③ 输入纹理有数据吗？
   → RenderDoc 里看输入纹理的内容
   → 采样 UV 对不对（用 SvPositionToBufferUV 还是手写除法）
                │
④ 深度/混合/剔除状态
   → SetDepthStencilState / SetBlendState / Cull Mode
   → 全屏 Pass 通常要关深度测试
                │
⑤ shader 真的执行了吗？
   → 把 OutColor 强制设为红色，看是否变红（二分定位）
```

> **最有效的一招**：强制输出一个固定颜色。变红说明 Pass/RT/管线都通了，问题在你的计算；不变红说明问题在更前面的环节。

### 3.3 "首帧卡顿 / 换场景卡顿"

| 原因 | 排查 | 解法 |
|------|------|------|
| PSO 首次创建 | `stat GPU` 看是否有长时间 stall | PSO 预热（见 §6） |
| Shader 同步编译 | 日志里是否有 `FinishAllCompilation` | 改为异步/预编译 |
| 材质首次加载 | 加载日志 | 预加载 + DDC |
| 纹理流式加载 | `stat Streaming` | 预流式加载 |

## 4. 图形调试器

| 工具 | 平台 | 强项 |
|------|------|------|
| **RenderDoc** | Windows / Linux / Android | UE 有内置插件；抓帧、看资源、shader 单步 |
| **PIX** | Windows (D3D12) | 微软官方，D3D12 深度分析 |
| **Nsight Graphics** | Windows / Linux | 源码级 shader 断点、占用率分析 |
| **Xcode GPU Frame Capture** | macOS / iOS | Metal 平台唯一选择 |
| **Radeon GPU Profiler** | AMD | ISA 级分析 |

### 4.1 UE + RenderDoc 要点

```ini
; 让 UE 输出可被 RenderDoc 识别的调试信息
r.ShaderDevelopmentMode=1
; D3D12 需要保留 shader 的调试信息
-D3D12.TrackAllAllocations=1
```

- RenderDoc 插件在 `Plugins/RenderDocPlugin`，启用后可在编辑器里直接抓帧
- **shader 单步需要调试信息**：Release 构建里若 strip 了，只能看到反汇编
- **RDG 的 Pass 名**会作为 RenderDoc 里的 marker（所以 `RDG_EVENT_SCOPE` 要写清楚）

### 4.2 `stat GPU` 与 `ProfileGPU`

```
stat GPU          # 实时显示各 Pass 的 GPU 耗时
ProfileGPU        # 抓一帧，输出完整的 Pass 耗时分解
```

输出示例（概念）：

```
0.82ms  BasePass
0.31ms  ShadowDepths
0.24ms  PostProcessing
0.15ms  MyCustomPass      ← 你的 Pass
```

> **命名你的 Pass**：一定要用 `RDG_EVENT_SCOPE(GraphBuilder, "MyPass")`，否则在 profile 里只看到一堆匿名的 `AddPass`。

## 5. 变体与编译时间优化

### 5.1 变体数量的来源与治理

| 来源 | 治理手段 | 收益 |
|------|---------|------|
| Permutation 维度 | `ShouldCompilePermutation` 裁剪 | ⭐⭐⭐⭐⭐ |
| 材质 Static Switch | 减少数量；改用 MPC / uniform | ⭐⭐⭐⭐⭐ |
| 顶点工厂类型 | `ShouldCompilePermutation` 按 VF 名裁剪 | ⭐⭐⭐⭐ |
| FeatureLevel / 平台 | 减少支持的目标 | ⭐⭐⭐ |
| 材质数量 | 合并材质、用材质实例 | ⭐⭐⭐ |
| 光照/投影变体 | 项目设置中的 Permutation Reduction | ⭐⭐ |

### 5.2 编译速度优化

| 手段 | 说明 |
|------|------|
| **共享 DDC** | 团队/本机跨分支共享，收益最大 |
| **本地 DDC 足够大** | 保留时间长一些（默认 7 天可延长） |
| **分布式编译** | XGE（Incredibuild）/ SN-DBS / UBA，让 SCW 跑在多台机器上 |
| **足够的编译线程** | 引擎会自动根据 CPU 核数决定 SCW 数量 |
| **减少被大量引用的 `.ush`** | 改一个公共头文件 = 全量重编 |
| **开发期关优化** | 编译参数降低优化等级（用控制台变量控制） |

### 5.3 包体优化

| 手段 | 位置 |
|------|------|
| Share Material Shader Code | Project Settings → Packaging |
| Shared Material Native Libraries | 同上 |
| Reduce Shader Permutations | 同上（移动端/静态光照场景） |
| 只 Cook 需要的平台 | Cook 配置 |

## 6. PSO 收集与预热

### 6.1 流程

```
① 开发/QA 阶段：开启 PSO 记录跑一遍游戏
   r.ShaderPipelineCache.Enabled=1
   r.ShaderPipelineCache.LogPSO=1
   r.ShaderPipelineCache.SaveBoundPSOLog=1
        │
        ▼
② 退出后记录写入 Saved/CollectedPSOs/*.upipelinecache + .stablepc.csv
        │
        ▼
③ 把记录文件放到 Content/ShaderPipelineCache/ 随包发布
        │
        ▼
④ 玩家启动：后台批量预热 → 运行期不再同步创建 PSO
```

### 6.2 注意事项

| 项 | 说明 |
|----|------|
| **要覆盖所有画质档** | 不同档位用不同 PSO，都要采集 |
| **要覆盖所有平台** | PSO 不可跨平台复用 |
| **材质变更要重新采集** | shader 变了，PSO 也变 |
| **记录文件会过时** | 引擎有版本号校验，不匹配的记录会被忽略 |

## 7. 运行时性能要点

### 7.1 RDG 相关

| 要点 | 说明 |
|------|------|
| **只对真正需要的资源声明读写** | 多声明一个 UAV 写就会多一次屏障 |
| **Pass 合并** | 相同输入输出特征的 Pass 合并成一个，减少 RT 往返 |
| **避免 Immediate Mode** | `r.RDG.ImmediateMode` 只用于调试 |
| **用 `RDG_EVENT_SCOPE` 命名** | 便于 profile |
| **资源复用** | RDG 会自动做资源别名，不要手动建过多中间 RT |

### 7.2 Shader 相关

| 要点 | 说明 |
|------|------|
| **Permutation vs uniform** | 分支开销小 → 用 uniform；差异大且分支昂贵 → 用 Permutation |
| **避免每帧切 Permutation** | 会导致 PSO 切换、破坏批处理 |
| **Compute 越界检查** | 必须有，且越界直接 return |
| **线程组大小** | 8×8 或 64×1 是常用起点，按硬件实测调整 |
| **减少采样次数** | 纹理采样是带宽大户 |
| **精度** | 移动端用 `MaterialFloat`（half）；PC 上 `half` 无收益 |
| **避免动态循环内采样** | 会导致展开或梯度丢失 |

### 7.3 参数相关

| 要点 | 说明 |
|------|------|
| **Uniform Buffer 数量** | 每帧创建的 UB 数量要控制（每个 UB 都有绑定开销） |
| **`UniformBuffer_SingleFrame`** | 一帧有效的用这个，让引擎及时回收 |
| **避免每帧改 Static Parameter** | 触发重编译 |
| **批量设置** | 用 MPC 或材质实例的批量接口 |

## 8. 最佳实践清单

### 8.1 该做 ✅

| # | 实践 | 理由 |
|---|------|------|
| 1 | 开发期常开 `r.ShaderDevelopmentMode` / `r.DumpShaderDebugInfo` | 错误可定位 |
| 2 | 每个 Pass 加 `RDG_EVENT_SCOPE` 命名 | profile 时能看到自己 |
| 3 | 用 CVar 开关自定义 Pass | 便于 A/B 与紧急关闭 |
| 4 | 参数结构体用 `SHADER_PARAMETER_RDG_*` | 自动屏障 |
| 5 | HLSL 用 `TEXTURE2D` / `Texture2DSample` 抽象宏 | 跨平台 |
| 6 | `ShouldCompilePermutation` 尽量严 | 编译时间的最小投入 |
| 7 | 全局参数走 MPC | 不产生变体 |
| 8 | 团队共享 DDC | 最大幅度降低编译等待 |
| 9 | 发布前采集 PSO | 消除首帧卡顿 |
| 10 | 打包前验证 shader 全部 Cook 成功 | 避免运行时缺 shader |
| 11 | Compute shader 必写越界检查 | 避免越界写坏内存 |
| 12 | 参数名与 HLSL 变量名保持一致（最好复制粘贴） | 避免"参数全 0" |
| 13 | 为自定义 Pass 写单元/截图测试 | 防止回归 |
| 14 | 记录 shader 工具链版本矩阵（引擎版本、平台 SDK） | 复现问题 |

### 8.2 不该做 ❌

| # | 反模式 | 后果 |
|---|--------|------|
| 1 | 在运行时调用 `FinishAllCompilation()` | 明显卡顿 |
| 2 | 运行时改 Static Parameter | 触发 shader 重编译 |
| 3 | 在 Custom 节点里写 `#include` | 编译失败 |
| 4 | 直接写 `Texture2D.Sample()` | Metal/GL 路径失败 |
| 5 | 用 `FVector` / `FMatrix` 做 shader 参数 | LWC 编译错误 |
| 6 | 大量 Static Switch（>5 个） | 变体爆炸 |
| 7 | 修改被引用的公共 `.ush` 不评估影响 | 全量重编 |
| 8 | 忘记 `RENDER_TARGET_BINDING_SLOTS()` | 全屏 Pass 无输出 |
| 9 | `numthreads` 与 C++ 的 GroupSize 不一致 | 计算覆盖不全 |
| 10 | 用非 RDG 的 UAV 宏 | 读写竞态 |
| 11 | 每帧构造 `TShaderMapRef` | 浪费（虽然便宜但没必要） |
| 12 | 发布构建保留 `r.DumpShaderDebugInfo` | 磁盘爆炸、编译慢 |

### 9.2 八条核心结论

| # | 结论 |
|---|------|
| 1 | **UE 的 shader 只写 HLSL**，靠 DXC + ShaderConductor 翻译成各平台语言 |
| 2 | **材质不产 shader，只产 HLSL 片段 + 编译环境**；真正的编译由 `FShaderCompilingManager` 统一调度 |
| 3 | **三类 Shader 按"依赖什么"选择**，直接决定变体数量 |
| 4 | **参数结构体是唯一推荐的参数方式**：宏生成元数据，编译期校验布局 |
| 5 | **Permutation 是编译期分支，用 `#if` 不用 `if`**；裁剪比缓存更重要 |
| 6 | **名字必须逐字对应**：参数结构体字段名 ↔ HLSL 变量名 |
| 7 | **跨平台必须走抽象宏**：`TEXTURE2D` / `Texture2DSample` / `MaterialFloat` |
| 8 | **变体爆炸是 UE 项目的头号敌人**：静态开关、VF、Permutation 是三大来源 |
