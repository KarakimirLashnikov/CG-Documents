# UE5 Shader 系统 — 总览与架构

> 本文档是「UE5 Shader 系统」系列的第 **0** 篇。UE 的着色器系统是一套**分层极深、宏驱动、跨平台**的体系：从材质编辑器的节点图，到自动生成的 HLSL，再到各图形 API 的字节码。本文给出全景地图与核心概念，为后续各篇建立统一坐标系。

---

## 1. 文档目的与读者对象

### 1.1 目的

UE5 的 shader 系统常被诟病"黑盒"：材质连几下就能出效果，但要加一个自己的 Pass 却无从下手。本系列的目标是**把这层黑盒拆开**：

- 讲清 **shader 从哪来**（材质图 → HLSL → 编译 → 缓存 → 绑定）
- 讲清 **C++ 与 shader 如何对接**（类型体系、参数体系、宏体系）
- 给出**可直接落地**的自定义 shader 模板（Global / Mesh / Compute / 后处理）
- 汇总**日常开发绕不开的宏**（参数宏、Permutation 宏、HLSL 跨平台宏、材质编译宏）

### 1.2 读者对象

| 读者 | 预期收获 |
|------|---------|
| UE 渲染初学者 | 建立从材质到 GPU 的完整链路认知 |
| 有 TA / 材质经验的开发者 | 理解变体、Permutation 与性能之间的关系 |
| 做过 UE4 的开发者 | 补齐 UE5 的变化（LWC、RDG、参数结构体现代化） |
| 需要写自定义 Pass 的引擎程序 | 拿到可直接抄的 Global / Mesh / Compute Shader 骨架 |

### 1.3 版本说明

> 本系列以 **UE 5.3 ~ 5.5** 为准。UE 的渲染与 shader API 在小版本间会有改名与重构（例如 UE 5.3 起材质着色器容器从 `FMaterialShaderMap` 演进为 `FMaterialShaders`，RDG 参数绑定宏持续更新）。文中会标注易受版本影响的点，请以你手上的引擎源码为最终依据。

## 2. UE Shader 系统在引擎中的位置

```
┌──────────────────────────────────────────────────────────────┐
│                        游戏层 / 编辑器                          │
│   材质资产 (.uasset) · 材质实例 · 材质参数集合 · C++ 渲染代码     │
└───────────────────────────┬──────────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────────┐
│                    L4：材质系统（Engine）                       │
│   UMaterial / UMaterialInstance / FMaterialResource            │
│   UMaterialExpression（节点图）→ FHLSLMaterialTranslator        │
│   → 生成 HLSL 代码 + FMaterialCompilationOutput                 │
└───────────────────────────┬──────────────────────────────────┘
                            │  HLSL 源码 + 编译环境（宏定义集合）
┌───────────────────────────▼──────────────────────────────────┐
│                 L3：Shader 编译系统（ShaderCompiler）            │
│   FShaderCompilingManager → ShaderCompileWorker（多进程）        │
│   → 平台编译器（FXC / DXC / Metal / glslang) → 字节码            │
│   → 编译结果写回 FShaderMap / 落入 DDC                          │
└───────────────────────────┬──────────────────────────────────┘
                            │  编译后的 Shader 资源
┌───────────────────────────▼──────────────────────────────────┐
│              L2：Shader 类型系统（RenderCore / Renderer）         │
│   FShader → FGlobalShader / FMaterialShader / FMeshMaterialShader│
│   FShaderType 反射注册表 · Permutation 维度 · ShaderMap 查找      │
└───────────────────────────┬──────────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────────┐
│          L1：参数绑定与渲染图（RDG: Render Dependency Graph）     │
│   FShaderParametersMetadata · Uniform Buffer                   │
│   FRDGTexture / FRDGBuffer · AddPass · Shader Bindings          │
└───────────────────────────┬──────────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────────┐
│                    L0：RHI（Render Hardware Interface）          │
│   D3D12 / Vulkan / Metal / OpenGL(ES) / 主机平台私有实现          │
│   PSO 缓存 · Shader 库 · 描述符 / Root Signature                 │
└──────────────────────────────────────────────────────────────┘
```

**核心分层原则**：

| 原则 | 含义 |
|------|------|
| **材质不直接产 shader** | 材质只产 HLSL 片段 + 编译环境；真正的编译由 L3 统一调度 |
| **C++ 侧只描述"我要什么"** | 通过参数结构体与 Permutation 维度声明，绑定细节由框架推导 |
| **平台差异下推到 RHI** | 用 HLSL 跨平台宏（`TEXTURE2D` / `Texture2DSample` 等）屏蔽 API 差异 |
| **编译结果可缓存** | DDC 以"shader 输入哈希"为 key，跨机器共享 |

## 3. 三类 Shader 与它们的适用场景

UE 把 shader 按"**它依赖什么**"分成三类，这决定了它的编译方式、查找方式与参数来源：

```
                      FShader（基类：序列化、编译、绑定）
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
   FGlobalShader        FMaterialShader       FMeshMaterialShader
   ├─ 不依赖材质        ├─ 依赖材质            ├─ 依赖材质
   ├─ 不依赖顶点工厂    ├─ 不依赖顶点工厂      ├─ 依赖顶点工厂
   │                    │                     │
   │ 用途：             │ 用途：               │ 用途：
   │ · 后处理 Pass      │ · 后处理材质         │ · 深度/阴影 Pass
   │ · 全屏 Pass        │ · Light Function     │ · BasePass（GBuffer）
   │ · Compute Pass     │ · 材质驱动的无网格   │ · 自定义网格 Pass
   │ · 全局工具 shader  │   渲染（如 Simple    │ · 自定义 Shading Model
   │                    │   Element 材质）     │   的绘制路径
```

| 维度 | `FGlobalShader` | `FMaterialShader` | `FMeshMaterialShader` |
|------|----------------|------------------|----------------------|
| 是否依赖材质 | ❌ | ✅ | ✅ |
| 是否依赖顶点工厂 | ❌ | ❌ | ✅ |
| 变体数量 | 最少（仅 Permutation） | 材质 × Permutation | 材质 × VF × Permutation |
| 查找方式 | `TShaderMapRef<>` | `Material.GetShaderMap()->GetShader<>()` | 同左 + `VertexFactoryType` |
| 典型宏 | `DECLARE_GLOBAL_SHADER` | `DECLARE_SHADER_TYPE(..., Material)` | `DECLARE_SHADER_TYPE(..., MeshMaterial)` |
| **入门推荐度** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ |

> **选择口诀**：
> 你的 shader 需要读材质节点的输出（BaseColor / Roughness / 自定义输出）吗？
> - 不需要 → **FGlobalShader**
> - 需要，但不画网格（屏幕空间） → **FMaterialShader**
> - 需要，且要画网格 → **FMeshMaterialShader**

## 4. 一条完整链路（先有个印象）

以"材质编辑器里拖了一个 Texture Sample 节点，最后屏幕上出现这张贴图"为例：

```
① 材质图 (UMaterialExpression)
      │  UMaterial::Translate() / FHLSLMaterialTranslator
      ▼
② 生成 HLSL 片段（MaterialTemplate.ush 为骨架 + 节点代码）
      │  同时产出 FMaterialCompilationOutput（用了哪些属性、是否半透明...）
      ▼
③ FMaterialResource 为每个 (Feature Level, 质量等级, 顶点工厂类型) 组合
   生成一份 FShaderCompilerInput（含宏定义集合 = 材质属性 + Permutation）
      ▼
④ ShaderCompileWorker 子进程调用平台编译器
   （Windows: FXC for SM5 / DXC for SM6；Mac/iOS: Metal；Android: glslang）
      ▼
⑤ 字节码 + 参数元数据写回 ShaderMap，哈希落入 DDC
      ▼
⑥ 运行时：MeshPassProcessor 查 ShaderMap 取 shader 变体 → 填充参数
   → FMeshDrawCommand → RHI → PSO → GPU
```

每一步的详细机制分别在 [01](01-Shader工作原理与编译流程.md)（①②③④⑤）与 [02](02-Shader类型体系与C++绑定.md)/[03](03-Shader参数体系.md)（⑥）展开。

## 5. 核心概念速查

### 5.1 USF / USH

| 扩展名 | 全称 | 用途 |
|--------|------|------|
| `.usf` | Unreal Shader File | 可独立编译的着色器源文件（含入口函数） |
| `.ush` | Unreal Shader Header | 被 `#include` 的头文件（公共函数、结构体、宏） |

存放位置与**虚拟路径**（shader 里 `#include` 用的是虚拟路径，不是磁盘路径）：

| 磁盘位置 | 虚拟路径 |
|---------|---------|
| `Engine/Shaders/Private/*.usf` | `/Engine/Private/xxx.usf` |
| `Engine/Shaders/Private/*.ush` | `/Engine/Private/xxx.ush` |
| `Engine/Shaders/Public/*.ush` | `/Engine/Public/xxx.ush` |
| `MyPlugin/Shaders/Private/*.usf` | `/Plugin/MyPlugin/Private/xxx.usf`（需注册映射） |

```cpp
// 插件 StartupModule 中注册虚拟路径映射
FString ShaderDir = FPaths::Combine(
    IPluginManager::Get().FindPlugin(TEXT("MyPlugin"))->GetBaseDir(),
    TEXT("Shaders"));
AddShaderSourceDirectoryMapping(TEXT("/Plugin/MyPlugin"), ShaderDir);
```

### 5.2 Permutation（变体维度）

UE 用 C++ 侧的 **Permutation Dimension** 声明编译期分支，每个维度的一组取值组合出一个 shader 变体：

```cpp
class FMyShader : public FGlobalShader {
public:
    DECLARE_GLOBAL_SHADER(FMyShader);
    SHADER_USE_PARAMETER_STRUCT(FMyShader, FGlobalShader);

    class FUseHDRDim : SHADER_PERMUTATION_BOOL("USE_HDR");
    class FQualityDim : SHADER_PERMUTATION_INT("QUALITY_LEVEL", 3);
    using FPermutationDomain = TShaderPermutationDomain<FUseHDRDim, FQualityDim>;
};
// → 2 × 3 = 6 个变体（再经 ShouldCompilePermutation 裁剪）
```

### 5.3 ShaderMap

`FShaderMap` 是"某个资源（全局 / 材质）在某个平台与 Feature Level 下，所有已编译 shader 变体的容器"。

| 类型 | 归属 | 获取方式 |
|------|------|---------|
| 全局 shader map | 引擎 | `GetGlobalShaderMap(FeatureLevel)` |
| 材质 shader map | 材质资源 | `MaterialResource.GetShaderMap()` |
| 顶点工厂 shader map | VF 类型 | 随材质一起查找 |

### 5.4 Uniform Buffer

UE 的参数传递以 **Uniform Buffer** 为核心抽象（对应 D3D 的 cbuffer / Vulkan 的 UBO / Metal 的 argument buffer）：

```
C++ 结构体  ──(宏生成元数据)──▶  Uniform Buffer 布局  ──▶  HLSL 中的同名变量
BEGIN_SHADER_PARAMETER_STRUCT(FParams,)                ...
    SHADER_PARAMETER(float, Intensity)  ──────────────▶  float Intensity;
```

参数绑定的三个阶段：

| 阶段 | 做什么 |
|------|-------|
| **声明** | 用宏描述结构体成员 → 生成 `FShaderParametersMetadata`（编译期反射） |
| **填充** | C++ 侧给结构体字段赋值 |
| **绑定** | RDG / RHI 按元数据把值写进 Uniform Buffer 并绑定到槽位 |

### 5.5 RDG（Render Dependency Graph）

UE5 的渲染 Pass 组织方式。你只需声明"读什么、写什么"，RDG 负责资源生命周期、屏障推导与 Pass 排序：

```cpp
FParameters* PassParameters = GraphBuilder.AllocParameters<FParameters>();
PassParameters->InputTexture = InputTexture;   // FRDGTextureRef
PassParameters->OutputTexture = GraphBuilder.CreateUAV(OutputTexture);

FPixelShaderUtils::AddFullscreenPass(
    GraphBuilder, View.ShaderMap,
    RDG_EVENT_NAME("MyPass"),
    PixelShader, PassParameters, ViewRect);
```

> **RDG 与 shader 的关系**：RDG 只管资源与调度，**shader 参数仍然由参数结构体描述**。两者通过 `SHADER_PARAMETER_RDG_*` 系列宏衔接——这些宏让 RDG 资源在 Pass 内自动完成绑定。

### 5.6 LWC（Large World Coordinates）

UE5 引入双精度世界坐标后，**shader 侧的坐标仍是单精度**。因此：

- C++ 侧传给 shader 的向量要用 **`FVector3f` / `FVector4f` / `FMatrix44f`**（float32）
- shader 侧通过 `Primitive.LocalToWorld`（已做"相对相机"平移）拿到可用的单精度变换
- HLSL 里 `LWCToFloat()` / `LWCPromote()` 等辅助函数用于显式转换

> ⚠️ **最常见的编译错误**：把 `FVector` / `FMatrix`（double）放进参数结构体。UE 会直接编译报错提示你改用 float 版本。

## 8. 术语约定

| 术语 | 标准含义 | 常见误用 |
|------|---------|---------|
| **USF / USH** | Unreal Shader File / Header | ❌ 当成"Unreal Shader Function" |
| **Permutation** | 一个 shader 的编译期变体（由维度组合决定） | ❌ 与"Material Instance"混为一谈（后者是运行期参数） |
| **ShaderMap** | 某资源在某平台/FeatureLevel 下所有 shader 变体的容器 | ❌ 当成"shader 源码的映射表" |
| **Uniform Buffer** | UE 的参数块抽象（≈ cbuffer / UBO） | ❌ 当成"全局常量"（它有生命周期与作用域） |
| **RDG** | Render Dependency Graph，UE5 的渲染 Pass 图 | ❌ 与"Render Graph"通用概念混用（UE 的 RDG 是具体框架） |
| **Feature Level** | 硬件能力分级（ES3_1 / SM5 / SM6） | ❌ 当成"画质档位"（画质档位是 Scalability） |
| **VF** | Vertex Factory（顶点工厂，决定顶点数据如何喂给 shader） | ❌ 当成"顶点缓冲" |
| **LWC** | Large World Coordinates，UE5 的双精度世界坐标 | ❌ 认为 shader 里也是 double（实际仍是 float） |
| **DDC** | Derived Data Cache，派生数据缓存 | ❌ 只当"shader 缓存"（它缓存所有派生资产） |
