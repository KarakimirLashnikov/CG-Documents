# 05. UE 卡通渲染实战路径 —— 后处理 / Unlit / 改源码三选一

> 本文档是「NPR技术文档」系列文档的第 5 篇（进阶篇）。Unreal Engine **没有内置卡通 Shading Model**，这是所有 UE 卡渲工程的出发点。本篇横评三条落地路径——后处理量化、Unlit 手动光照、源码级 Custom Shading Model——并给出描边与决策方案。

## 1. 出发点：UE 的光照架构为什么「不欢迎」卡渲

```
UE 延迟渲染主路径（5.x）：
  BasePass ──► GBuffer（BaseColor/Normal/Roughness/Metallic/ShadingModelID...）
      │
      ▼
  Lights（逐光源，按 ShadingModel 分支算 BSDF）──► SceneColor
      │
      ▼
  反射/AO/Lumen ──► Tonemap ──► 后处理链
```

关键事实：

| 事实 | 推论 |
|------|------|
| 材质只能选引擎内置 Shading Model（Default Lit、Clear Coat、Hair…） | **没有 Toon 选项**，卡渲光照无法从材质编辑器直达 |
| 光照计算在引擎 C++/HLSL 深处，材质节点只能改输入参数 | 想改「光怎么算」只有三条路：截获结果（后处理）、绕开光照（Unlit）、改引擎（源码） |
| GBuffer 通道已满（UE 长期痛点） | 自定义 Shading Model 想传自定义参数，常要挪用现有通道 |

## 2. 路径一：后处理量化（零侵入，最快上线）

### 2.1 原理

在 Post Process Material 里把「带光照的 SceneColor」除以「无光照的 BaseColor」，反解出光照强度，量化后乘回去：

```
SceneColor ──┐
             ├─► 除法 ──► 光照强度 L ──► 量化 Q(L) ──┐
BaseColor ───┘                                       ├─► Q(L)·BaseColor ──► 输出
              ⚠️ Blendable Location 选 Before Tonemapping（在色调映射前操作 HDR 数据）
```

### 2.2 材质节点骨架（概念）

```
SceneTexture:PostProcessInput0  ──► Divide ──┐
SceneTexture:BaseColor (DiffuseColor) ───────┘
        │（光照强度）
        ▼
   分离阴影(<1)与高光(>1) → 各自 ×bands → Ceil/Floor → ÷bands  ← 量化
        │
        ▼
   × BaseColor → Emissive 输出
   可叠加 Lerp（量化结果, 原 SceneColor, 0.2）保留部分细节
```

### 2.3 能力边界（这是本路径的真实价值清单）

| ✅ 能做 | ⚠️ 不能做/有坑 |
|---------|---------------|
| 全屏统一色阶，10 分钟出效果 | **0/0 除法**：BaseColor 纯黑处信息丢失，需 clamp 补救 |
| 用 Custom Depth 限定只对角色生效 | 高光/自发光被一并量化 → 彩色高光出现怪色（需去饱和或 HSV 空间处理） |
| 与现有光照/阴影/Lumen 天然兼容（它们照常算，你只改显示） | 间接光/天空光也被阶梯化 → 暗部「塑料感」，难做暗部染色 |
| | 与 Bloom、SSR、雾效叠加顺序敏感；分辨率缩放时色阶闪烁 |
| | 无法 per-材质定制（皮肤/布料/金属共用一条量化曲线） |

**定位**：原型验证、Game Jam、整体风格统一的低多边形项目。**不是**商业二游方案。

## 3. 路径二：Unlit + 手动光照（全控但「裸奔」）

### 3.1 原理

材质设为 **Unlit**，自己在材质里写完整光照：`dot(N, L)` → Ramp → 输出 Emissive。

光照数据从哪来：

| 来源 | 方式 | 覆盖 |
|------|------|------|
| 主平行光 | `Atmosphere Sun Light Vector` 节点 或 Material Parameter Collection 同步 | 太阳 |
| 点/聚光 | 蓝图每帧遍历灯光写入 MPC | 有限几盏 |
| 阴影 | 最痛：Unlit 不接收动态阴影，需手动采 Shadow Map 或接受无阴影 | — |
| 环境光 | 手算 SH / 采 Reflection Capture | 近似 |

### 3.2 横评

- ✅ **完全自由**：第 01~04 篇所有技术都能实现，逐材质定制无上限；前向渲染，移动端友好（《原神》移动端角色管线在概念上就是这条路）
- ⚠️ **放弃 UE 光照生态**：多光源、阴影、Lumen、光照探针全部要自己重建或放弃——工程量随场景灯光复杂度爆炸
- ⚠️ 材质里拿不到逐光源循环 → 多灯叠加要写死数量或走 Custom HLSL + MPC

**定位**：角色为主、灯光简单的二次元项目（角色一套 Unlit 卡渲材质 + 场景走标准管线，正是二游经典分工）。

## 4. 路径三：源码级 Custom Shading Model（最强集成，最重维护）

### 4.1 原理

Fork 引擎源码，注册新 Shading Model（社区常见命名 `SHADINGMODELID_TOON`），在 `ShadingCommon.ush` / `DeferredLightingCommon.ush` 的 BSDF 分支里接入卡通量化。社区已有成熟 fork（4.20~5.x 均有人维护），典型设计：

- 材质输入新增：Shadow Color / Highlight Color / Offset（明暗交界位置）/ Range（交界软度）/ 分离的 Diffuse 与 Specular 控制
- 明暗交界 Offset 可用顶点色/贴图逐像素驱动（推走面部阴影）——效果上等价于把第 06 篇 SDF 思路的「控制权」开进 GBuffer

### 4.2 真实成本清单

| 成本 | 说明 |
|------|------|
| **GBuffer 通道** | UE GBuffer 早已打满；新参数只能挪用（如 Clear Coat 通道复用）或牺牲其他 Shading Model 共存 |
| 引擎升级 | 每次升级 UE 版本要 rebase 渲染模块改动——社区 fork 普遍滞后官方 1~2 个小版本 |
| 新特性兼容 | Lumen/Nanite/Substrate 与自定义 Shading Model 的交互**官方不保证**，需自行验证 |
| 团队门槛 | 需要能改引擎渲染模块的 TA/图形程序常驻 |
| 打包分发 | 项目绑定源码版引擎，CI/构建机成本上升 |

- ✅ 回报：卡渲光照参与**标准光照循环**——阴影、多光源、Light Mass、Lumen GI 全部自然工作；美术在材质编辑器里所见即所得
- 典型用户：有引擎组的中大型二游项目

## 5. UE 中的描边实现（三路径通用）

| 方案 | 机制 | 备注 |
|------|------|------|
| 后处理描边 | SceneDepth + WorldNormal 差分（第 02 篇路线二） | 配合 Custom Depth/Stencil 限定对象；建议放在 TAA 之前让线被平滑 |
| Inverted Hull | 网格体添加第二个材质槽，材质里 `World Position Offset` 沿法线外扩 + `Two Sided` + 反转法线 | UE 无内置「反向剔除材质开关」，常用技巧：材质输出负的 WPO 或依赖 Overlay |
| **Translucent Overlay Materials（UE 5.1+）** | 引擎原生 Overlay pass，直接在材质里做顶点外扩 + 纯色输出，等价 Inverted Hull 且**无需复制网格** | 当前官方推荐的描边路线 |
| Fresnel 描边 | 材质内 `Fresnel` 节点输出到 Emissive | 最廉价但精度差，仅适合远景/小物件 |

## 6. 决策表

| 你的情况 | 推荐路径 |
|----------|---------|
| 原型/独立项目，想先看效果 | 后处理量化 + 后处理描边 |
| 二次元角色驱动，灯光简单，有 TA 无引擎组 | Unlit 手动光照（角色）+ 标准管线（场景）+ Overlay 描边 |
| 中大型二游，有引擎组，要 Lumen/阴影完整集成 | 源码 Custom Shading Model + Overlay/几何描边 |
| 移动端为主 | Unlit 手动光照（前向，避开延迟渲染 GBuffer 带宽） |
| 目标「原神级」 | 任意路径都只是一半——另一半是资产管线（Ramp/LightMap/SDF 制作规范），见第 06 篇 |

## 7. 小结

| 要点 | 说明 |
|------|------|
| 起点 | UE 无内置 Toon Shading Model；三路径 = 截获结果 / 绕开光照 / 改引擎 |
| 后处理 | 最快但 per-材质失控、间接光被阶梯化、0/0 除法与后处理链冲突 |
| Unlit | 自由度上限，代价是放弃阴影与多光源生态；角色+场景分管线是二游标准分工 |
| 改源码 | 集成度上限；GBuffer 通道、版本 rebase、Lumen 兼容是三大持续成本 |
| 描边 | UE5.1+ 首选 Translucent Overlay Materials，等价 Inverted Hull 且免复制网格 |
| 版本时效 | 本篇基于 UE 5.x（2026-09 视角）；Overlay Materials、Substrate 等以所用版本引擎源码为准 |
