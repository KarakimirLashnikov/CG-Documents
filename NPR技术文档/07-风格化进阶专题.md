## 2. 铅笔素描：Tonal Art Maps（TAM）

**出处**：Praun et al., *Real-Time Hatching* (SIGGRAPH 2001)。

**问题**：排线（hatching）密度要随笔触表达明暗，且笔触必须「贴着表面」而非「贴在屏幕上」。

**方案**：预生成一组 mipmap 式纹理塔——每一级对应一个明度区间，**暗处线条多、亮处线条少**；相邻明度级的线条是**超集关系**（暗级包含亮级全部线条再加新线），保证连续调光时笔触「生长」而非「跳变」。

```
明度 ↓ 亮                                          暗
级0:  （空白）
级1:  ╱        ╱          ╱
级2:  ╱   ╲   ╱    ╲     ╱    ╲        ← 线条数递增
级3:  ╲╱ ╲╱ ╲╱  ╲╱  ╲╱ ╲╱         ← 含上一级全部线条
运行时：按 N·L 在相邻两级间 lerp（需解决交叉线条的对应）
多方向：多张 TAM 图集轮换方向，模拟交叉排线 cross-hatching
```

| 项 | 说明 |
|----|------|
| 成本 | 资产：每级手工/程序生成；运行时：2~3 次纹理采样 + lerp |
| 坑 | 纹理在表面拉伸 → 笔触粗细不均；需 tone-dependent UV 或按曲率补偿 |
| 适用 | 学术可视化、独立解谜、过场插画化演出 |

## 3. 半调网点与漫画风格（Halftone / Screentone）

**原理**：把明度映射为网点**面积覆盖率**（AM 调幅网点）——印刷术的数字复刻。

```hlsl
// 屏幕空间半调骨架（漫画/印刷风后处理）
float gray  = Luminance(sceneColor);
float2 grid = frac(uv * _ScreenParams.xy / _DotSize);   // 网点晶格
float dist  = length(grid - 0.5);                        // 到格心距离
float dot_  = step(dist, gray * 0.7);                    // 明度→圆点半径
color = lerp(_PaperColor, _InkColor, dot_);
```

| 变体 | 特征 | 案例 |
|------|------|------|
| 屏幕空间网点 | 网点钉在屏幕上，物体移动时「网点不动内容动」——漫画感强但有人嫌「滑动感」 | 《Hi-Fi RUSH》局部 |
| 物体空间网点 | 网点贴 UV/世界坐标，随物体移动 | 更稳定，失去印刷感 |
| 色调分离+网点 | 先量化再网点化，色块内网点密度均匀 | 《女神异闻录 5》UI/演出 |
| 排线 screen-tone | 网点换成平行线/交叉线 | 日漫阴影标准件 |

⚠️ 网点频率与像素频率会产生摩尔纹——`_DotSize` 需按分辨率缩放，且网点图案应避开 Nyquist 频率附近。

## 4. ArcSys 手绘流：赛璐璐的极限形态

**出处**：Arc System Works《Guilty Gear Xrd》GDC 2015 演讲（*GuiltyGearXrd's Art Style : The X Factor Between 2D and 3D*）。

**核心发现**：普通 3D 卡渲「转起来就露馅」——因为顶点法线是几何平均，而 2D 动画师画的光影从不遵守几何。ArcSys 的对策是**把每一帧 2D 光影的判断权交给美术**：

| 技术 | 内容 |
|------|------|
| 逐顶点手工法线 | 美术在 DCC 里**逐顶点编辑法线方向**（不是画贴图，是改法线数据本身），让 N·L 的明暗交界在任何光位下都符合 2D 分镜审美 |
| 本村式线（UV 控线） | 描边线的粗细/断续/交叉加重全部通过 UV 布局与贴图控制；线条在特写下有「手绘笔压」 |
| 限帧动画 | 动画按 2D 动画的「拍二/拍三」（12/8 fps）抽帧，渲染 60fps 但关键帧节奏对齐手绘 |
| 软图像式轮廓 | 特写镜头用预绘制的轮廓贴图替换实时描边 |

**启示**（比技术本身更重要）：当目标风格是「以假乱真的 2D 动画」时，**瓶颈不在渲染算法，在资产制作管线**——ArcSys 方案 80% 的成本在美术工具链与人力。此路线只适合：格斗/特写驱动、角色数量少、有顶级美术的项目。

## 5. 水彩与油画：图像空间滤波路线

| 技术 | 原理 | 视觉 | 代表 |
|------|------|------|------|
| Kuwahara 滤波 | 邻域分 4 个子窗，取方差最小窗的均值 → 保边平滑，色块化 | 油画/海报化 | 后处理通用 |
| 各向异性 Kuwahara | 沿结构张量方向拉长滤波窗 → 笔触沿物体流向 | 梵高式流动笔触 | 风格化独立游戏 |
| 水彩边缘暗化 | 检测色彩边界 → 边界处加深 + 纸纹叠加 + 颜料抖动（wobble：UV 低频扰动） | 水彩晕染 | 《Okami》式 |
| 颜料物理 | 在 GPU 上模拟水彩扩散/干燥（Shallow Water 类方程） | 真·水彩物理 | 研究级，罕见商用 |

⚠️ 图像空间路线的共性坑：**时间稳定性**——逐帧滤波在镜头移动时笔触「游泳」。对策：滤波锚定到世界空间投影坐标，或接受游动作为风格（《大神》就是接受并利用了它）。

## 6. Matcap 与光照 Rig（补遗）

第 04 篇讲过 matcap 作为高光技巧；在精通层面它是一种**全局风格工具**：整个场景用 2~3 张 matcap（皮肤/金属/布料）替代实时光照——《Gris》类插画级项目常见。代价是完全失去动态光照响应，镜头旋转时高光不动。适用：固定/半固定镜头、以色彩构图为核心的作品。

## 7. 选型决策：从「参考图」到「技术栈」

```
拿到艺术总监的参考图，按序问五个问题：
① 媒介是什么？（赛璐璐/漫画印刷/素描/水彩/油画）
   → 决定主路线（第 01~06 篇 / §3 / §2 / §5）
② 边界是线条还是色块？
   → 线条 → 描边体系（第 02 篇）+ 网点/排线；色块 → 滤波路线（§5）
③ 笔触贴表面还是钉屏幕？
   → 表面 → 物体空间（UV/世界坐标）；屏幕 → 后处理
④ 镜头运动剧烈吗？
   → 剧烈 → 警惕 matcap/屏幕空间方案的时间稳定性
⑤ 角色多吗、特写多吗？
   → 少+多特写 → ArcSys 手绘流可行；多 → 走原神式数据驱动管线
```

## 8. 小结

| 要点 | 说明 |
|------|------|
| TAM | 明度分级纹理塔 + 线条超集关系，解决排线密度连续性（Praun 2001） |
| 网点 | 明度→面积覆盖率；空间归属（屏幕/物体）决定风格与稳定性 |
| ArcSys | 「以假乱真 2D」的答案是逐顶点手工法线+UV 控线+限帧——成本在美术管线而非算法 |
| 绘画滤波 | Kuwahara 家族保边平滑；时间稳定性（笔触游动）是最大坑 |
| 选型 | 从参考图出发五问：媒介/边界/笔触空间/镜头/角色规模 |
| 共性 | 越靠近「手绘感」，成本越从 GPU 转移到美术与工具链 |
