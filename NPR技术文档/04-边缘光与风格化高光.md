# 04. 边缘光与风格化高光 —— 工业级卡渲的「细节层」

> 本文档是「NPR技术文档」系列文档的第 4 篇（进阶篇）。有了卡通着色 + 描边 + Ramp，角色已经有「动画感」，但离商业级还差一层细节：轮廓处的**边缘光（Rim Light）**与**风格化高光**。本篇讲清两大边缘光流派、三类风格化高光，以及它们在《原神》方案中的位置。

## 1. 边缘光 Rim Light：不是描边，是补光

先划清边界（新手最常混）：

| | 描边 Outline | 边缘光 Rim Light |
|---|-------------|------------------|
| 视觉 | 轮廓外侧的**深色线** | 轮廓内侧的**亮色带** |
| 作用 | 勾勒形状、分离层次 | 强调剪影、模拟逆光、增加体积感 |
| 实现 | 额外几何/后处理 | 主光照 pass 内加法项 |
| 成本 | 几何翻倍或全屏 pass | 几乎免费（几个 dot） |

## 2. 流派一：视角边缘光（Fresnel 式）

### 2.1 原理

法线与视线垂直处（`N·V ≈ 0`）即轮廓——在该处补一条亮带：

```hlsl
float rim     = 1.0 - saturate(dot(N, V));          // 轮廓处 → 1
float rimMask = pow(rim, _RimPower);                 // 控制带宽（越大越窄）
rimMask       = smoothstep(_RimMin, _RimMax, rimMask); // 卡渲化：软阈值切边
float3 col    = base + rimMask * _RimColor * rimIntensity;
```

### 2.2 卡通化要点

| 要点 | 说明 |
|------|------|
| **切边** | 裸 `pow` 是写实的柔和 Fresnel；卡渲要 `smoothstep` 切出明确边界，与身体色阶风格统一 |
| **受光关联** | 经典做法：rim 只在亮部出现（`rimMask *= step(θ, H)`），暗部边缘光会显脏；逆光演出时才允许暗部 rim |
| **宽度方向性** | 可用 `(N·V)` 与光照方向组合，让 rim 偏向光源一侧（模拟真实逆光） |

⚠️ 视角 rim 的最大缺陷：**与光照无关**——角色站在没有背光的环境里轮廓照样发光，物理上说不通，风格化项目可接受，但《原神》选择了下一种。

## 3. 流派二：深度边缘光（《原神》式，屏幕空间）

### 3.1 原理

不依赖视角，而是比较**当前像素深度与轮廓外侧背景深度**：轮廓像素的外侧邻居深度突变（物体→背景），说明此处是真实几何边缘，补光只出现在这里。

```
屏幕空间示意（侧视物体）：
  背景 ──────┐
             │深度突变
        ┌────┘
        │ 物体 ←── 边缘像素：外侧邻居深度 ≫ 自身深度 → 补 rim 光
        │
        └── 内部像素：邻域深度连续 → 无 rim
```

```hlsl
// 深度边缘光骨架（需 DepthNormals 或线性深度，社区复现共识）
float sceneDepth = LinearEyeDepth(_CameraDepthTexture, uv);
float rim = 0;
for (int i = 0; i < 8; i++)                              // 8 方向圆环采样
{
    float2 off   = dir8[i] * _RimWidth * _ScreenParams.zw;
    float  d     = LinearEyeDepth(_CameraDepthTexture, uv + off);
    float  diff  = d - sceneDepth;                        // 邻居比我还远
    rim = max(rim, smoothstep(_RimDepthThresh, _RimDepthThresh * 2, diff));
}
// 只叠加在受光面上，并乘光照色
col += rim * _RimColor * lightColor * toonLit;
```

### 3.2 两流派横评

| 维度 | 视角 Rim（Fresnel） | 深度 Rim（原神式） |
|------|--------------------|--------------------|
| 几何真实性 | 视角相关，**非真实边缘也亮**（凹陷处） | 只在真实轮廓亮 |
| 光照关联 | 无（需手动叠加光照条件） | 天然与场景光统一（乘 lightColor） |
| 成本 | 几乎零 | 需深度纹理 + 8 次邻域采样/像素 |
| 依赖 | 无 | DepthNormals pass（前向需额外 pass） |
| 适用 | 小品级、演出镜头 | 开放世界、对光统一性要求高的场景 |

## 4. 风格化高光：三种形态

### 4.1 离散 Blob 高光（赛璐璐标准件）

把 Blinn-Phong 高光量化成 1~2 个「色块」，模拟动画里头发/肩甲上的白色高光块：

```hlsl
float spec   = pow(saturate(dot(N, H_half)), _SpecSize);
spec         = step(_SpecThreshold, spec) * _SpecIntensity;   // 二值化
// 或 smoothstep 软边；形状细节可用 LightMap 的通道当阈值扰动（见第 06 篇）
col += spec * _SpecColor;
```

⚠️ 与 PBR 高光的本质区别：PBR 高光位置/大小由 roughness 物理决定；卡渲高光的**位置、大小、形状全是美术参数**，甚至可以用贴图画出固定形状（「永远在这个位置有一块高光」——这在 PBR 里不允许，在卡渲里是日常）。

### 4.2 各向异性发丝高光（Kajiya-Kay 卡通化）

头发高光沿发丝切线方向拉伸（天使环）。Kajiya-Kay 模型：

```
spec = (T·H')^n   —— T = 发丝切线，H' = 半角向量在切平面投影
```

卡通化处理：① 两层高光（主环 + 偏移副环，错位制造层次）；② 每层各自 `smoothstep` 切边；③ 副环染色（通常偏发色互补色）。

⚠️ 需要正确的切线数据：头发发卡的 T 应顺发丝方向；用 UV.x 当切线方向是廉价替代但只在发片 UV 展得好时成立。

### 4.3 Matcap（球面环境贴图）—— 金属的廉价答案

```hlsl
float2 uv = mul((float3x3)MATRIX_V, N).xy * 0.5 + 0.5;   // 视空间法线 → UV
float3 matcap = tex2D(_Matcap, uv).rgb;
col = lerp(col, matcap, metalMask);                       // 或乘算/叠加
```

- 原理：假设光照环境球对称，用「视空间法线」直接查一张预烘焙的球面光照图
- ✅ 一次采样得到「以假乱真的金属/丝绸光泽」，零实时光照计算
- ⚠️ 与视角绑定——转动相机时高光不动（穿帮感），所以只用于**视觉权重低的小件**（《原神》的金属配饰、神之眼）
- 《原神》中金属区域由 LightMap 的 R 通道（金属强度）控制 matcap 混合权重（社区共识）

## 5. 在完整卡渲 Shader 中的位置

```
逐像素数据流（身体通用 pass）：
  baseColor（贴图）
    │ × Ramp(H, row)                 ← 第 03 篇：明暗色阶
    │ + Blob 高光（step 量化）        ← §4.1，金属区走 matcap 分支
    │ + 深度 rim × lightColor         ← §3，仅真实轮廓
    ▼
  身体着色完成 ──► 后续还有：描边 pass（第 02 篇）、面部独立 pass（第 06 篇）
```

## 6. 效果与适用场景

| 技术 | 视觉效果 | 适用场景 |
|------|---------|---------|
| 视角 rim | 轮廓亮边，逆光演出感 | 特写、演出、低成本项目 |
| 深度 rim | 真实轮廓补光，与光照统一 | 开放世界角色（《原神》） |
| Blob 高光 | 色块高光，动画感 | 头发、肩甲、武器 |
| 各向异性双环 | 天使环发丝高光 | 长发角色必备 |
| Matcap | 廉价金属/丝绸 | 小配饰、金属件；忌大面积主材质 |

## 7. 小结

| 要点 | 说明 |
|------|------|
| 描边≠边缘光 | 一个画线一个补光，分属不同 pass，参数分开调 |
| Rim 两流派 | 视角 rim 便宜但与光无关；深度 rim 真实但需深度纹理与邻域采样 |
| Rim 卡通化 | `pow` 之后必须 `smoothstep` 切边；默认只在亮部叠加 |
| 高光哲学 | 卡渲高光的位置/形状是美术参数，不受物理约束——这是特性不是缺陷 |
| 发丝 | Kajiya-Kay 双环 + 各自切边；切线数据质量决定成败 |
| Matcap | 小件金属的最优解；视角绑定决定它不能用于大主体 |
