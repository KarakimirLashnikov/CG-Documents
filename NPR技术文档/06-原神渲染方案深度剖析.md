# 06. 原神渲染方案深度剖析 —— 商业级二游卡渲的完整拼图

> 本文档是「NPR技术文档」系列文档的第 6 篇（进阶篇）。以《原神》为案例拆解一套**经过大规模商业验证**的卡通渲染方案：角色侧四大模块（Toon 光照 + Ramp、SDF 面部阴影、LightMap 材质分区、描边与边缘光）与场景侧风格化（GDC 2021 官方分享）。
>
> **资料基调说明**：角色侧细节主要来自技术社区的逆向/复现共识（非官方完整方案），场景侧来自米哈游 GDC 2021 官方演讲《Genshin Impact: Crafting an Anime Style Open World》。涉及具体通道语义处会标注「社区共识」，以抓帧验证为准。

## 1. 总体架构：一张图看懂

```
┌──────────────────────── 角色渲染 ────────────────────────┐
│ 资产（DCC 产出）                Shader（运行时）           │
│ ┌──────────────┐                                       │
│ │ BaseColor 贴图 │──► 基础色                              │
│ ├──────────────┤                                       │
│ │ LightMap      │──► R:金属强度 G:AO B:高光形状 A:材质ID   │──┐
│ ├──────────────┤     （社区共识）                        │  │
│ │ Ramp 贴图      │──► 多行=材质分区×昼夜 → 暗部色阶        │  │
│ ├──────────────┤                                       ├──┼─► Toon 合成
│ │ FaceLightMap   │──► SDF 面部阴影（仅脸部 pass）         │  │
│ ├──────────────┤                                       │  │
│ │ 顶点色/平滑法线 │──► 描边粗细/颜色控制                   │  │
│ └──────────────┘                                       │  │
│ 描边 pass：Inverted Hull（颜色按材质 ID 分区） ◄──────────┘  │
│ 边缘光：深度差分 rim（乘光照色，仅真实轮廓）                  │
└──────────────────────────────────────────────────────────┘
┌──────────────────────── 场景渲染 ────────────────────────┐
│ 风格化 PBR：保留 PBR 参数框架，替换光照响应（GDC 2021）      │
│ 树：球形法线 / 草：VAT+贴地形色 / 岩：三层笔触纹理按距离混合    │
│ 云：手绘关键帧→渐变图插值+双 lightmap+rim highlight          │
└──────────────────────────────────────────────────────────┘
```

核心设计哲学（GDC 2021 原话精神）：**让场景风格匹配角色，而不是反过来**。角色是赛璐璐标准，场景围绕它做「风格化 PBR」。

## 2. 模块一：Toon 光照 + Ramp

- 改良 Lambert（半兰伯特）→ Ramp 贴图查色阶（第 03 篇已讲机制）
- 关键差异：**每种材质一条 Ramp 曲线**——皮肤、布料、金属暗部色各不相同，靠 LightMap 的 A 通道（材质 ID）选行
- Ramp 分上下半区：上=白天暗部、下=夜晚暗部，随 TOD（时间系统）插值
- 高光：离散化 Blob（第 04 篇 §4.1），形状由 LightMap B 通道扰动阈值 → 同一材质高光也有细节变化

> 设计要点：明暗交界的**位置**由公式（阈值）保证全角色统一，交界的**颜色**由 Ramp 保证 per-材质定制——职责分离是整套系统可调的前提。

## 3. 模块二：SDF 面部阴影（招牌技术）

### 3.1 为什么面部必须独立处理

| 通用方案在面部的失败 | 原因 |
|---------------------|------|
| 实时 Shadow Map | 面部几何小，阴影精度不足，鼻翼/刘海投影全是锯齿与自遮挡 acne |
| N·L 阈值 | 面部法线平滑，明暗交界随光角度变化呈几何正确但**审美错误**的形状（颧骨处怪异分块） |
| 手绘法线修正 | 缓解但无法根治——美术要的是「任何光位下阴影形状都像手绘分镜」 |

### 3.2 SDF 方案原理

**资产侧**：美术绘制 N 张（社区资料常示 8 张）不同水平光位下的面部阴影图（光源从背后绕侧面转到正面），合成一张 SDF 形式的 **FaceLightMap**——像素值编码「该点由暗转亮时，光与面部朝向点积的临界值」。

**运行时**：

```hlsl
// SDF 面部阴影骨架（社区复现共识，非官方源码）
// 约定模型空间：y=forward, -x=up, -z=right（依导出设置，以项目为准）
float3 front = TransformObjectToWorldDir(float3(0, 1, 0));
float3 right = TransformObjectToWorldDir(float3(0, 0, -1));
float3 L     = SafeNormalize(float3(lightDir.x, 0, lightDir.z));  // 投影到水平面

float FDotL  = dot(front.xz, L.xz);
float RDotL  = dot(right.xz, L.xz);

float2 uv    = faceUV;
uv.x         = RDotL > 0 ? uv.x : 1.0 - uv.x;      // 光在左侧 → 镜像采样
float sdf    = tex2D(_FaceLightMap, uv).r;          // 临界阈值

// Func(F,L) = -0.5·F·L + 0.5：光从正后(0)转到正面(1)
float angle  = saturate(-0.5 * FDotL + 0.5);
// 硬阴影：angle 超过该像素临界值 → 受光
float shadow = step(sdf, angle);
// 或 smoothstep(sdf - w, sdf + w, angle) 得软边
```

```
光绕面部旋转：     背面 0°    侧面 90°     正面 180°
angle 值：        1.0   ────►  0.5   ────►  0.0
FaceLightMap 值： 每个像素存「翻转点」
判定：angle < sdf → 亮；angle ≥ sdf → 暗   （等价 step 方向约定）
```

### 3.3 工程要点

| 要点 | 说明 |
|------|------|
| 只有水平旋转 | L 投影到 XZ 平面——俯视/仰视时阴影不动，用**头部仰角额外偏移**或接受（二游通例） |
| 镜像复用 | 只存半张脸的 SDF，另一侧 `1-uv.x` 镜像 → 贴图省一半 |
| 与身体衔接 | 面部用 SDF、脖子以下用 Ramp，交界处靠顶点色/遮罩过渡，避免两套阴影「打架」 |
| 成本 | 每角色一张手绘 SDF 贴图（TA 绘制维护）——这是该方案真实成本所在 |
| 普及度 | SDF 面部阴影已是**二游通用技术**（《崩坏》系、《明日方舟：终末地》等均有类似方案），非原神独有 |

## 4. 模块三：LightMap 材质分区（一张贴图的四个通道）

社区复现共识的通道语义（⚠️ 不同逆向资料说法有出入，以抓帧验证为准）：

| 通道 | 语义 | 用途 |
|------|------|------|
| R | 金属强度 | 控制 matcap 混合（第 04 篇 §4.3） |
| G | AO / 阴影权重 | 叠加到 Ramp 输入，控制暗部深度 |
| B | 高光形状与细节 | 作为高光阈值的扰动 → 高光形状有手绘感 |
| A | 材质 ID | ① 选 Ramp 行 ② 描边颜色分区（皮肤/布料/金属描边色不同） |

**设计启示**：单 Shader 多材质行为 = 逐像素 if-else 太贵 → 用贴图通道把「分支」变成「查表」。这是数据驱动 Shader 设计的经典范式。

## 5. 模块四：描边与边缘光

- **描边**：Inverted Hull（第 02 篇路线一）；描边色 = BaseColor 采样 × 暗化系数，按材质 ID 分区调整；配合 Stencil 管理描边与特效/半透明的层叠关系
- **边缘光**：深度差分 rim（第 04 篇 §3），乘光照色、仅真实轮廓出现
- 头发：matcap 风格化高光（SphereTex 类贴图）

## 6. 场景侧风格化（GDC 2021 官方内容）

| 对象 | 技术 | 解决的审美问题 |
|------|------|--------------|
| 树冠 | **球形法线**（叶团法线朝外球面化）+ 弱化叶间高光与阴影 + 设最低光强（min light intensity，防晨昏时树死黑） | 树叶细碎法线导致的「噪点感」，树在动画里是一个色块 |
| 草 | VAT（顶点动画纹理）摆动；每组草单一颜色且**默认贴地形色**（美术可改）；多套随机密度/尺寸/朝向防重复；移动端简化模型 | 大草地色彩统一、不闪烁 |
| 岩石/山 | Substance Painter 笔触化滤镜处理纹理；**近/中/远三层不同细节纹理**按距离混合 | 攀爬游戏山占比高，要「笔触」感且资产可复用 |
| 云 | 美术画剪影与生长关键帧 → 工具插值为**渐变图**；两张基础 lightmap + 一张 rim highlight 图实现 24 小时光照；渐变图+噪声实现动态变形 | 云的 24 小时色彩是**预设调色**而非物理计算 |
| 地形 | 每层限混 8 层；自定义 tint 函数在不加层的前提下增加色彩变化 | 开放世界地编效率 |
| TOD | 全场景 24 小时调色为美术预设（非物理日光模型） | 任何时刻画面都「像原画」 |

> 反复出现的手法：**用预设/手绘资产替代实时物理计算**（云的光照、TOD 调色、面部阴影）——物理计算是「下限兜底」，手绘预设是「上限达标」。这是原神方案最值得带走的方法论。

## 7. 方案总评：能学什么，不能学什么

| ✅ 值得学 | ⚠️ 别盲目学 |
|-----------|------------|
| SDF 面部阴影的思路（手绘控制阴影形状） | 全量资产管线（每角色 LightMap+SDF+多行 Ramp）需要专职 TA 团队 |
| 明暗「位置公式管、颜色贴图管」的职责分离 | 全平台适配设计（高端效果+手机可跑）显著抬高工程复杂度 |
| 场景匹配角色、预设替代物理的哲学 | 逐细节复刻——先确定你的游戏镜头距离与玩法是否真需要 |
| LightMap 通道查表替代 Shader 分支 | — |

## 8. 小结

| 要点 | 说明 |
|------|------|
| 角色四模块 | Toon+Ramp / SDF 面部 / LightMap 分区 / Inverted Hull+深度 rim |
| SDF 本质 | 把「阴影形状」从几何计算变成美术手绘资产，`-0.5F·L+0.5` 与贴图值比较判定 |
| LightMap 范式 | 贴图通道查表替代 Shader 分支，单 Shader 多材质行为 |
| 场景哲学 | 风格化 PBR = PBR 参数框架 + 替换光照响应；场景风格匹配角色 |
| 方法论 | 物理计算保下限、手绘预设保上限 |
| 资料性质 | 角色侧=社区共识（以抓帧验证为准），场景侧=GDC 2021 官方 |
