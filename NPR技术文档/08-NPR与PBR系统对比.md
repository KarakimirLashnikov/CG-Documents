# 08. NPR 与 PBR 系统对比 —— 五维差异分析与渲染方案选型

> 本文档是「NPR技术文档」系列文档的第 8 篇（精通篇，末篇）。NPR 与 PBR 不是「高低画质」关系，而是两种**目标函数不同**的渲染哲学。本篇从光照模型、材质表达、渲染管线、性能开销、适用场景五个维度系统对比，并给出混合路线与选型决策框架。

## 1. 根本差异：目标函数不同

```
PBR：minimize  |渲染结果 - 物理真实|
      手段：基于物理的 BRDF、能量守恒、真实材质参数

NPR：minimize  |渲染结果 - 目标艺术风格（参考图/分镜）|
      手段：离散化、手绘 LUT、美术可控参数

→ 两者优化的是不同的损失函数，因此没有「谁更高级」，
  只有「谁更接近你的项目目标」。
```

## 2. 维度一：光照模型

| 维度 | PBR | NPR（卡通渲染为例） |
|------|-----|---------------------|
| 数学形态 | 连续 BRDF：`f = Diffuse + D·F·G/(4(N·V)(N·L))` | 离散映射：`Q(N·L)`，Q 为阶梯/Ramp LUT |
| 参数来源 | 可测量的物理量（albedo、metalness、roughness、IOR） | 不可推导的艺术决策（色阶数、边界位置、阴影色相） |
| 能量守恒 | 硬约束 | 无需遵守（暗部可以比物理更亮，高光可以悬浮） |
| 多光源响应 | 线性叠加，物理一致 | 逐光源量化会丢层次；常简化为「主光 + 环境」两层 |
| 间接光 | GI / 光照探针 / Lumen，与直接光统一框架 | 通常单独艺术化处理（Ramp 行、环境染色），与直接光「分而治之」 |
| 控制权归属 | 物理公式（美术调参数） | **美术直出**（Ramp 图、SDF 图就是光照本身） |

**关键洞察**：PBR 的光照模型是「推导出来的」，NPR 的是「画出来的」。前者保证任何条件下**不出错**，后者保证任何条件下**够好看**——当你无法容忍「物理正确但丑」时选 NPR。

## 3. 维度二：材质表达方式

| 维度 | PBR | NPR |
|------|-----|-----|
| 材质定义 | 一组物理参数贴图（BaseColor/Normal/ORM） | 一组**控制信号**贴图（LightMap 通道：金属度/AO/高光形状/材质 ID） |
| 语义 | 通道语义全球统一（业界标准） | 通道语义**项目自定义**（原神的 R/G/B/A 语义只在原神成立） |
| 资产复用 | 跨项目/跨引擎可复用（glTF 标准） | 与自家 Shader 强耦合，基本不可复用 |
| DCC 工作流 | Substance/Quixel 标准化流程 | 手绘 + 自定义工具链，规范靠文档与人 |
| 法线贴图 | 核心输入（微观几何） | 常被弱化甚至禁用（赛璐璐要「平」），或改为逐顶点手工法线（ArcSys） |
| 美术技能要求 | 材质科学知识 | 传统绘画/动画分镜功底 |

## 4. 维度三：渲染管线

```
PBR 管线（UE 延迟渲染典型）：
  BasePass → GBuffer(6~8 RT) → 逐光源光照 → Lumen/反射 → Tonemap → 后处理
  特点：材质与光照解耦；光照复杂度不随物体数增长；GBuffer 带宽是瓶颈

NPR 卡渲管线（二游角色典型，前向为主）：
  深度预 Pass（可选）→ 主体 Pass（Unlit 光照 + Ramp + 高光 + rim）
    → 描边 Pass（Inverted Hull，几何量×2）→ 后处理（可选网点/调色）
  特点：材质自含光照；Pass 少但每物体渲染 2 次；后处理轻
```

| 维度 | PBR | NPR |
|------|-----|-----|
| 主流架构 | 延迟渲染（GBuffer） | **前向渲染**（光照简单，不值得 GBuffer） |
| 与引擎集成 | 一等公民（引擎默认路径） | 二等公民（Unlit 绕过 / 后处理截获 / 改源码，第 05 篇） |
| 阴影 | Shadow Map / 虚拟阴影贴图，标准集成 | 常需定制：面部 SDF 替代实时阴影（第 06 篇） |
| MSAA | 延迟路径下代价高（GBuffer×N） | 前向路径下 MSAA 便宜（尤其移动端 TBR 片上 resolve） |
| 扩展性 | 加灯、加材质类型即插即用 | 每个新效果都是一次「定制开发」 |

## 5. 维度四：性能开销

⚠️ 「NPR 比 PBR 省」是流传最广的误读。分项看：

| 项 | PBR | NPR 卡渲 | 谁赢 |
|----|-----|---------|------|
| 像素着色 ALU | 重（GGX、多 BRDF 项、GI 采样） | 轻（半兰伯特 + 查表） | NPR |
| 顶点/几何吞吐 | ×1 | ×2（Inverted Hull 第二遍） | PBR |
| 全屏带宽 | GBuffer 读写巨大（延迟） | 前向无 GBuffer；但描边 pass 有深度填充，深度 rim/后处理描边另计 | 视情况 |
| 阴影系统 | Shadow Map（重但通用） | 角色可用 SDF 省掉面部 shadow map；场景仍需要 | NPR（角色） |
| 后处理 | 重链（Tonemap/Bloom/TAA/SSR…） | 可极简化（色阶本身抗噪，对后处理需求低） | NPR |
| 资产制作成本 | 标准化管线，工具成熟 | 手绘贴图 + 逐角色 TA 投入，**人力成本高一个量级** | PBR |

**结论**：GPU 侧 NPR 通常更省（尤其移动端前向 + 无 GBuffer）；但「性能」若算上人力与管线，PBR 的工业化成熟度碾压。商业项目算总账时，**资产制作成本往往超过渲染成本**。

## 6. 维度五：适用场景

| 场景 | 推荐 | 理由 |
|------|------|------|
| 3A 写实、影视级 | PBR（+路径追踪） | 目标即真实 |
| 二次元角色驱动（二游） | NPR 卡渲（角色）+ 风格化 PBR（场景） | 原神范式，第 06 篇 |
| 独立游戏（小团队） | 强风格化 NPR | 风格化「抗衰老」——《风之杖》20 年不过时；且回避与 3A 拼资产 |
| 医学/工业可视化 | NPR（Gooch/素描） | 形体可读性 > 真实感 |
| VR（重性能预算） | 风格化 NPR | 前向 + MSAA 友好；低纹理细节不「露馅」 |
| 需要大量真实材质库复用 | PBR | Quixel/资产商店生态只在 PBR 侧 |
| 强光照动态变化（昼夜/天气） | PBR 或混合 | 纯 NPR 每换一种光照环境都要补美术预设（原神用昼夜 Ramp 双行解决，成本可见） |

## 7. 混合路线：风格化 PBR（实战主流）

纯 NPR 与纯 PBR 之间是连续光谱，商业项目多在中间：

```
混合的三个层级（侵入度递增）：
① 参数层：PBR 框架 + 压平 roughness 动态范围 + 饱和色调校
           （《堡垒之夜》早期——「PBR 的皮，卡通的魂」）
② 响应层：保留 PBR 参数接口，替换光照响应
           （原神场景：GDC 2021 明确说 "PPR pipeline, then tweak"）
③ 分区层：角色纯 NPR、场景风格化 PBR、特效 PBR
           （原神整体 / 多数二游——按对象类型分管线）
```

**判据**：混合层级的选择 = 「你的美术参考图离物理真实有多远」×「你的团队能维护多重的定制管线」。

## 8. 选型决策框架

```
开始
  │ Q1: 目标画面 = 照片级真实？
  ├─ 是 ──► PBR（结束）
  │ 否
  │ Q2: 风格参考是手绘/动画媒介？
  ├─ 否（抽象/扁平/UI 化）──► 极简 NPR / Unlit 平色
  │ 是
  │ Q3: 角色特写驱动 + 角色数量少？
  ├─ 是 ──► ArcSys 手绘流（第 07 篇 §4）
  │ 否
  │ Q4: 开放世界 / 多光照环境？
  ├─ 是 ──► 原神式分区管线：角色 NPR + 场景风格化 PBR + 昼夜 Ramp
  │ 否
  │ Q5: 引擎改动能力？
  ├─ 有引擎组 ──► Custom Shading Model（UE 路径三）
  └─ 无 ──────► Unlit 手动光照（角色）+ 引擎标准管线（场景）
```

## 9. 常见误区终审

| 误区 | 事实 |
|------|------|
| 「NPR 是 PBR 的降级」 | 目标函数不同；NPR 的艺术控制成本常高于 PBR |
| 「NPR 一定更省性能」 | 着色省、几何翻倍、人力成本数量级上升——算总账 |
| 「用了 PBR 就只能写实」 | 参数层混合（压 roughness、调色）即可风格化，PBR 不背锅 |
| 「卡通渲染不需要灯光师」 | 恰恰相反——物理不管了，每一束光的效果都要人负责 |
| 「两者必须二选一」 | 商业主流是分区混合（角色/场景/特效各走各的管线） |

## 10. 小结

| 要点 | 说明 |
|------|------|
| 本质差异 | PBR 逼近物理、NPR 逼近风格参考；损失函数不同，无高下 |
| 光照 | PBR 推导、NPR 手绘；控制权归属是分水岭 |
| 材质 | PBR 语义标准化可复用；NPR 通道语义项目自定义、强耦合 |
| 管线 | PBR 延迟一等公民；NPR 前向 + 双 pass 描边，引擎里二等公民 |
| 性能 | GPU 侧 NPR 常省，人力侧 PBR 碾压；商业决策算总账 |
| 主流答案 | 分区混合：角色纯 NPR + 场景风格化 PBR（原神范式） |
| 选型 | 五问决策框架：真实？媒介？特写？光照动态？引擎能力？ |
