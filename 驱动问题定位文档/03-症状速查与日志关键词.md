# 症状速查与日志关键词

> 本文档是「驱动问题定位」系列文档的第 **3** 篇。全系列的「实战查询页」：左边是用户/测试报告的现象，右边是怀疑方向和第一条命令。建议把第 1、2 节的两张表**打印出来贴在工位上**——定位直觉本质上就是把这两张表内化成条件反射。

---

## 1. 症状 → 可能驱动原因 → 先查什么（总表）

| 现象 | 可能驱动层原因 | 先查什么 |
|---|---|---|
| 黑屏但 SSH 能进 | KMS modeset、Connector、EDID、Atomic Commit | `dmesg \| grep -iE 'drm\|edid\|link training'` |
| 随机花屏/闪烁 | Plane、带宽、VRR、显存压缩（DCC） | `dmesg`、合成器日志、`modetest` |
| 游戏崩溃 `VK_ERROR_DEVICE_LOST` | GPU hang、ring timeout、fence 超时、UMD 提交 | `dmesg \| grep -iE 'ring\|reset\|fence\|page fault'` |
| 进程被杀/显存分配失败 | GEM/TTM、VRAM 不足、reclaim、OOM | `dmesg \| grep -iE 'ttm\|vram\|oom'` |
| 性能突然掉（无报错） | 电源管理、频率、PCIe 降链、调度器、驱动 fallback | `intel_gpu_top`/`radeontop`、`pp_dpm_sclk`、PCIe `lnksta` |
| 多显示器/热插拔问题 | KMS Connector、Atomic、PRIME | `dmesg`、`modetest`、`xrandr` |
| Wayland 下闪烁/卡顿 | dma-buf、隐式/显式同步、合成器 | 合成器日志、`WAYLAND_DEBUG=1` |
| 休眠唤醒黑屏 | KMS 状态保存恢复、Firmware、PM | `dmesg` 中 suspend/resume 段 |
| 特定游戏/着色器崩溃 | UMD 着色器编译、ICD、Mesa 版本 | Validation、`RADV_DEBUG`、Mesa 版本二分 |
| 启动卡死/黑屏 | KMS early modeset、Firmware 缺失 | `dmesg \| grep -i firmware`、内核参数 `nomodeset` 验证 |

**读表方法**：「现象」列只做初筛；「先查什么」列的命令执行完，你应该能把怀疑范围从 5 层收窄到 1~2 层。收窄之后转第 4 篇的二分流程。

## 2. 厂商错误日志关键词字典

看到下列关键词出现在 `dmesg` / `journalctl -k` 里，基本可以判断问题不在你的 Shader，而在驱动/硬件/显示栈：

### 2.1 AMD（amdgpu）

| 关键词 | 含义 | 方向 |
|---|---|---|
| `GPU reset begin` | GPU 已挂死，驱动开始重置 | 看上文找触发原因（ring/page fault） |
| `ring gfx timeout` | 图形 ring 执行超时（hang） | 挂死的命令流；配合 `RADV_DEBUG=hang` 抓现场 |
| `VM_L2_PROTECTION_FAULT` | GPU 访问了未映射/无权限的虚拟地址 | 悬空 descriptor/BO、VM_BIND 页表错误 |
| `[drm] Cannot allocate memory` / TTM 相关 | 显存/迁移失败 | VRAM 用量、GTT 大小 |
| `*ERROR* ... link training` | DP 链路训练失败 | 线缆/显示器/固件，与渲染无关 |

### 2.2 Intel（i915 / xe）

| 关键词 | 含义 | 方向 |
|---|---|---|
| `i915: GPU HANG` | GPU 挂死（含 ring 名与 fault 地址） | 读完整 hang 记录定位引擎 |
| `Resetting chip for ...` | 触发 GPU reset | 同 AMD，看上文 |
| `GuC` / `HuC` 相关报错 | 固件（调度微码/认证微码）加载或运行异常 | 固件版本与内核版本匹配性 |
| `fence timeout` | 等待 fence 超时 | 找被等的执行方 |

### 2.3 NVIDIA（NVRM，闭源内核模块）

| 关键词 | 含义 | 方向 |
|---|---|---|
| `NVRM: Xid` | NVIDIA 统一错误码体系（数字定因） | 查 Xid 编号对照表（官方文档） |
| Xid 13 | Graphics Engine Exception | 常为非法命令/Shader 触发，偏软件 |
| Xid 31 | MMU fault（GPU 页错误） | 非法地址访问，配合 fault 地址排查 |
| Xid 48 | 双比特 ECC 错误 | **硬件级**：显存可靠性问题 |
| Xid 79 | `GPU has fallen off the bus` | **硬件级**：供电/散热/PCIe 链路，几乎可排除软件 |
| Xid 119 / 120 | GSP 固件 RPC 超时/错误 | GSP 固件与驱动版本匹配 |

> ⚠️ Xid 编号语义以 NVIDIA 官方文档《Xid Errors》为准；上表只列最常见的六个。总体规律：**Xid 小数字偏软件，大数字（尤其 48/63/79/92 以上）偏硬件**。

### 2.4 通用关键词

| 关键词 | 指向 |
|---|---|
| `page fault`（GPU 上下文） | 非法 GPU 地址访问，≈ 进程段错误 |
| `fence timeout` / `timed out waiting` | 同步等待超时 |
| `link training failed` | DP/HDMI 链路协商失败（显示通路） |
| `EDID` | 显示器识别问题 |
| `firmware` + `failed/error` | 固件加载失败（版本不匹配/文件缺失） |

## 3. 日志样例精读：一段真实形态的 hang 现场

```
[  +0.000012] amdgpu 0000:03:00.0: [drm] *ERROR* ring gfx timeout,
              signaled seq=12345, emitted seq=12346        ← ① 谁挂了
[  +0.000003] amdgpu 0000:03:00.0: [drm] GPU reset begin!   ← ② 驱动开始自救
[  +1.234000] amdgpu 0000:03:00.0: [drm] GPU reset succeeded,
              trying to resume                             ← ③ reset 完成
[  +0.000100] [drm] GPU recovery end                        ← ④ 恢复完毕
```

读法：

1. **① 是源头**：gfx ring 上有一条命令流没按时执行完。此刻应用层会收到 DEVICE_LOST——记住，那是 ② 的下游，不是根因。
2. **①→③ 之间的 1.2 秒**就是玩家感知的「卡死瞬间」。
3. 如果 ① 前面还有 `VM_L2_PROTECTION_FAULT` 或 `page fault`，则**fault 是因、timeout 是果**，排查方向从「调度」改为「谁访问了非法地址」。
4. 想要挂死时的 GPU 寄存器现场：以 `RADV_DEBUG=hang` 重新运行复现，Mesa 会把 dump 写到 `$HOME/radv_dumps_`（详见第 4 篇）。

## 4. 「先怀疑哪一层」速判卡

```
现象到手，按顺序问：

Q1. dmesg 有 GPU fault / reset / Xid 吗？
    有 → KMD/硬件方向，收集日志 + 版本信息，第 4 篇流程
    无 ↓

Q2. Validation Layers 开起来有报错吗？
    有 → 应用/API 用法问题，先修红字
    无 ↓

Q3. 换 Mesa / 驱动版本，问题出现或消失吗？
    是 → UMD 方向（编译器/命令生成），附版本对报上游
    否 ↓

Q4. 只在特定内容（场景/Shader）下出现吗？
    是 → 应用层或 UMD 对该内容的处理，RenderDoc 抓帧对比
    否 ↓

Q5. 随机出现、与温度/负载相关吗？
    是 → 硬件/电源方向：频率、温度、PCIe 链路、ECC/Xid
```

## 5. 常见误判警示

| 误判 | 真相 |
|---|---|
| 看到 DEVICE_LOST 就报「驱动崩溃」 | DEVICE_LOST 是结果不是原因；不带 dmesg 的崩溃报告对驱动团队几乎无用 |
| 看到 page fault 就改自己的指针 | GPU page fault 的地址是 **GPU 虚拟地址**，不是 CPU 指针，先确认是哪类 BO |
| 花屏直接 RMA 显卡 | 先换线、换口、关 VRR、换驱动版本；纯软件花屏远多于硬件花屏 |
| `nomodeset` 能亮 = 问题解决 | 那只是绕开 KMS（无加速的兜底路径），用于验证归属，不是修复 |
| 重启后日志没了就当没事 | `journalctl -k -b -1` 可以看**上一次启动**的内核日志，现场还能找回来 |

## 6. 小结

| 要点 | 说明 |
|---|---|
| 总表用法 | 现象初筛 → 执行「先查什么」→ 收窄到 1~2 层 → 转二分流程 |
| AMD 三连 | ring timeout → GPU reset → 应用 DEVICE_LOST |
| Intel 重点 | `GPU HANG` 记录完整，含 ring 名与 fault 地址 |
| NVIDIA Xid | 小数字偏软件、大数字偏硬件；79/48 基本排除软件 |
| 通用词 | page fault / fence timeout / link training / EDID / firmware |
| 读日志顺序 | 先找第一个 ERROR（因），timeout/reset 常为果 |
| 报告最小集 | dmesg 全文 + 内核/Mesa/固件/合成器版本 + 复现步骤 |
