# 工具与二分定位流程

> 本文档是「驱动问题定位」系列文档的第 **4** 篇（末篇）。把前三篇的模型、概念、关键词落成日常操作：一套命令速查、一组环境变量、一张工具表、一条二分验证流程，最后附 Windows WDDM 对照。环境变量语义**以 Mesa 官方文档为准（2026-10 核实）**。

---

## 1. 必会命令速查

```bash
# ── 第一刀：内核日志（最重要，没有之一）──────────────────
dmesg -T | grep -iE 'drm|gpu|amdgpu|i915|xe|nvidia|firmware|ring|fence|reset|page fault'
journalctl -k -b          # 本次启动的内核日志
journalctl -k -b -1       # ⚠️ 上一次启动（重启丢现场的救星）

# ── 设备与拓扑 ──────────────────────────────────────────
ls -l /dev/dri/           # cardN（显示+特权）vs renderD12N（纯渲染）
vulkaninfo --summary      # 枚举物理设备、驱动版本、ICD 路径
lspci -nnk | grep -A 3 -i vga   # 显卡型号 + 当前绑定的内核驱动

# ── 运行时状态 ──────────────────────────────────────────
cat /sys/class/drm/card0/device/pp_dpm_sclk    # AMD 当前/可用频率档
cat /sys/kernel/debug/dri/*/clients            # 谁在用 GPU（需 root）
modetest                  # 列出 KMS 的 Connector/CRTC/Plane 状态
```

## 2. 环境变量速查（Vulkan / Mesa）

| 变量 | 作用 | 典型场景 |
|---|---|---|
| `VK_LOADER_DEBUG=all` | 打印 Loader 找 ICD 的全过程 | 应用找不到 GPU / 加载错驱动 |
| `VK_INSTANCE_LAYERS=VK_LAYER_KHRONOS_validation` | 强制开验证层 | 复现期常开 |
| `RADV_DEBUG=hang` | 检测到 GPU hang 时把现场 dump 到 `$HOME/radv_dumps_` | DEVICE_LOST 复现取证 |
| `RADV_DEBUG=noumr` | 配合 hang 用：禁用 dump 中的 UMR 寄存器转储 | dump 太大/太慢时 |
| `RADV_DEBUG=zerovram` | 分配的 VRAM 清零 | 排查「读到未初始化显存」类花屏 |
| `RADV_DEBUG=nocache` | 禁用着色器缓存 | 排除缓存导致的「玄学」编译差异 |
| `RADV_DEBUG=vm` | VA 分配之间加间隔，便于暴露 page fault | VM 错误精确定位 |
| `RADV_PERFTEST=...` | 实验特性开关（如 `sam`、`emulate_rt`） | 只做对照实验，勿当修复手段 |
| `AMD_DEBUG=...` | radeonsi（OpenGL）调试选项 | OpenGL 应用同思路 |
| `MESA_DEBUG=1` / `LIBGL_DEBUG=verbose` | Mesa/GL 通用诊断输出 | 加载与上下文创建问题 |

> ⚠️ 全部以 `docs.mesa3d.org/envvars` 为准；选项随 Mesa 版本增删。NVIDIA 闭源驱动另有 `__GL_*` / `__NV_*` 系列变量，以 NVIDIA 官方 README 为准。

## 3. 工具箱

| 工具 | 层 | 用途 |
|---|---|---|
| RenderDoc | 应用/API | 抓帧看 draw 级管线状态、资源内容；**画面错误的第一工具** |
| Vulkan Validation Layers | API | 抓用法违规（VUID）；开发期常开 |
| `intel_gpu_top` / `radeontop` / `nvidia-smi` | KMD/硬件 | GPU 各引擎占用率、频率、功耗、显存 |
| `umr` | KMD/硬件 | AMD GPU 寄存器级调试；配合 `RADV_DEBUG=hang` 的 dump 分析挂死现场 |
| `modetest`（libdrm） | KMD/显示 | KMS 对象枚举与模式设置验证 |
| `WAYLAND_DEBUG=1` | 合成器协议 | 看 Wayland 消息流与 buffer 提交/同步时序 |
| `apitrace` | API | GL 调用录制回放（Vulkan 用 RenderDoc/gfxreconstruct） |

**分工直觉**：画面错先 RenderDoc；崩溃先 dmesg；卡顿先 `*_gpu_top` 看频率和占用；显示问题先 `modetest`。

## 4. 二分验证流程

定层的本质是**控制变量**。每换一次只改一个维度，问题的出现/消失就是证据：

```
问题复现
   │
   ▼
① 换内容：最小场景能复现吗？
   │   能 → 与场景无关，偏驱动/环境；不能 → 应用/资产方向
   ▼
② 换 Mesa / 驱动版本（升级 + 降级各试一次）
   │   行为变化 → UMD 方向，记下「好版本 vs 坏版本」对
   ▼
③ 换内核版本（发行版仓库里相邻两个大版本）
   │   行为变化 → KMD 方向
   ▼
④ 换合成器 / 会话类型（Wayland ↔ X11，或裸 Weston）
   │   行为变化 → 合成器/WSI 方向（闪烁类问题尤其有效）
   ▼
⑤ 换 API 路径（Vulkan ↔ OpenGL 同引擎，或开关某扩展）
   │   行为变化 → 缩小到具体驱动路径
   ▼
⑥ 换机器（同 GPU 型号 / 不同 GPU 型号）
       同型号复现 → 软件；都复现 → 应用；仅原机 → 硬件/固件
```

> ⚠️ 两条纪律：**一次只换一个变量**；**每一步都记录「改了什么、现象如何」**。没有记录的实验等于没做——报 bug 时这份记录就是最值钱的附件。

## 5. 一份合格的驱动 bug 报告该带什么

| 项 | 怎么拿 |
|---|---|
| dmesg / journalctl -k 全文（含故障时刻） | 复现后立即导出；重启过用 `-b -1` |
| 版本四件套 | 内核 `uname -r`、Mesa `vulkaninfo \| grep -i version`、固件 `dmesg \| grep -i firmware`、合成器及版本 |
| GPU 型号与 PCI ID | `lspci -nnk \| grep -A 3 -i vga` |
| 复现步骤 + 最小用例 | 能给出 RenderDoc 抓帧或 apitrace 最佳 |
| 二分结果 | 哪个版本好、哪个版本坏（bisect 信息是黄金） |
| hang dump（AMD） | `RADV_DEBUG=hang` 复现后 `$HOME/radv_dumps_/` 内容 |

## 6. Windows 对照（WDDM 侧的同构概念）

Linux 直觉基本可以平移，只是名字换了：

| Linux | Windows | 说明 |
|---|---|---|
| GPU reset（ring timeout 触发） | TDR（Timeout Detection & Recovery，默认约 2 秒） | 「显示器驱动程序已停止响应，并且已恢复」就是 TDR |
| `dmesg` / `journalctl -k` | 事件查看器：System 日志，来源 `Display` / `nvlddmkm` / `dxgkrnl` | dxgkrnl = Windows 的「DRM」 |
| UMD（Mesa） / KMD（amdgpu） | 用户态 DLL（`vulkan-1.dll`+ICD、nvoglv64.dll 等） / 内核态 miniport（nvlddmkm.sys、amdkmdap.sys、igdkmdn64.sys） | WDDM 同样 UMD/KMD 分工 |
| DEVICE_LOST（reset 下游） | D3D `DXGI_ERROR_DEVICE_REMOVED` / Vulkan DEVICE_LOST | 同样是 TDR 的下游翻译 |
| `/dev/dri` 节点权限 | 无对应概念（图形设备由会话/桌面管理） | 但「选错 GPU」同样存在：双显卡本用 Windows 图形设置/驱动面板指定 |
| `intel_gpu_top` | GPU-Z / 任务管理器 GPU 页 / PresentMon | 频率、占用、帧时间 |

排查同构：Windows 上遇到 DEVICE_REMOVED，同样先问「TDR 是不是被触发了」（事件日志），同样用「换驱动版本二分」定 UMD/KMD。差异在于：**Windows 闭源栈日志更少，更依赖厂商工具（Nsight、厂商崩溃上报通道）与驱动版本二分**。

## 7. 小结

| 要点 | 说明 |
|---|---|
| 第一命令 | `dmesg -T \| grep -iE 'drm\|gpu\|ring\|reset\|fault'` |
| 崩溃取证 | `RADV_DEBUG=hang` → `$HOME/radv_dumps_` |
| 卡顿取证 | `*_gpu_top` 看频率/占用；RenderDoc 看不到降频 |
| 二分六步 | 内容 → Mesa → 内核 → 合成器 → API 路径 → 机器 |
| 实验纪律 | 一次一个变量，每步留记录 |
| 报告四件套 | 日志全文 + 版本 + PCI ID + 二分结果 |
| Windows 同构 | TDR ≈ GPU reset；dxgkrnl ≈ DRM；DEVICE_REMOVED ≈ DEVICE_LOST |
| 最终心法 | 哪一层？dmesg 说什么？版本是什么？能否二分？ |
