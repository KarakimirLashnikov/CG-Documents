# UE渲染源码导读 — 系列总览与渲染知识地图

> 本文档是「UE渲染源码导读」系列文档的第 **0** 篇（总览篇）。本系列面向 **UE 渲染源码阅读**，目标不是逐行讲解实现细节，而是帮你建立一张**可索引的渲染知识地图**：核心类型是什么、数据从哪来、每个 Pass 在主线的什么位置、哪些分支可以跳过。全部结论均来自 **UE 5.8.2 本地源码树实测**（`Engine/Source/Runtime/Renderer`、`Engine/Source/Runtime/Engine`），文中路径均相对 `Engine/Source` 并附行号。
>
> ⚠️ **版本声明**：本系列以 UE 5.8.2 源码为准。UE 渲染器每个版本都有重构（5.8 中可见性已任务化、若干旧类型已移除），阅读其他版本或旧教程时请以文中「旧名勘误表」对照。

---

## 1. 为什么需要「地图式」阅读

UE 渲染源码的劝退点不在于某个算法多难，而在于：

1. **数据隐藏**：你在某个 Pass 里看到 `View.Foo` / `Scene->Bar`，却不知道这个字段是谁、在什么时候填进去的；
2. **入口分散**：可见性、剔除、绘制命令生成、光照分散在十几个文件里，看不出先后逻辑；
3. **分支爆炸**：头发、Substrate、MegaLights、Lumen、Nanite 都在主线里插一脚，注意力被迅速稀释；
4. **版本漂移**：旧教程里的 `InitViews`、`FMeshDrawCommandSharedState` 在 5.8 已不存在，按图索骥会扑空。

本系列的应对策略是**先建索引再下钻**：

```
第一遍（本系列）：类型职责 → 数据流向 → 主线顺序 → 分支边界
        │
        ▼  只对「与你目标相关」的点下钻
第二遍（按需）：单 Pass 源码精读（配 RenderDoc 截帧 + 断点验证）
```

**阅读纪律**：
- 永远先问「这个数据是谁在什么时候填的」，而不是「这段代码在算什么」；
- 主线函数只有一条（`FDeferredShadingSceneRenderer::Render`，约 2600 行），其余都是它的旁枝；
- 遇到功能分支先查开关（cvar / ShowFlag / 空实例短路），确认可跳过就跳过，标记书签后回来。

## 2. 渲染知识地图（全图）

```
┌──────────────────────────── 游戏线程 (GT) ────────────────────────────┐
│                                                                        │
│  UWorld ──持有──► FSceneInterface* Scene                               │
│     │                ▲                                                 │
│     │   UPrimitiveComponent ──注册/更新──► FScene::AddPrimitive        │
│     │                                                                    │
│     └─ 每帧: FRendererModule::BeginRenderingViewFamily                │
│              (SceneRendering.cpp:5354)                                 │
│              构造 FSceneViewFamily + FSceneView[]                      │
│                          │ ENQUEUE_RENDER_COMMAND                      │
└──────────────────────────┼─────────────────────────────────────────────┘
                           ▼
┌──────────────────────────── 渲染线程 (RT) ────────────────────────────┐
│                                                                        │
│  FScene（跨帧持久）◄──借用── FSceneRenderer（每帧创建→Render()→销毁） │
│   ├ Primitives[] / Lights[] / StaticMeshes[]                           │
│   ├ CachedDrawLists / GPUScene / SceneLODHierarchy                     │
│   └ ViewStates[]（跨帧持久视图状态）                                    │
│                                                                        │
│  FDeferredShadingSceneRenderer::Render  (DeferredShadingRenderer.cpp) │
│   │  每帧拥有 TArray<FViewInfo> Views（FViewInfo : FSceneView）       │
│   ▼                                                                    │
│  ① 可见性任务（剔除/Relevance/动态网格收集）→ 填 FViewInfo 各 Map      │
│  ② MeshDrawCommand 组织（静态缓存 + 动态新建）                          │
│  ③ PrePass/Nanite → BasePass(GBuffer) → 阴影 → Lumen                   │
│  ④ RenderLights / MegaLights → 半透明 → 后处理                         │
│                          │ 全部经 FRDGBuilder 录制                     │
└──────────────────────────┼─────────────────────────────────────────────┘
                           ▼
                    RDG 执行 → RHI → GPU
```

**三层时间尺度**是理解一切数据归属的钥匙：

| 时间尺度 | 代表对象 | 存活期 | 谁拥有 |
|---------|---------|--------|--------|
| 跨帧持久 | `FScene`、`FPrimitiveSceneInfo`、`FSceneViewState`、静态 MDC 缓存 | 与 UWorld/组件同寿 | UWorld / FScene |
| 每帧临时 | `FSceneViewFamily`、`FViewInfo`、`FSceneRenderer`、`FDynamicMeshDrawCommandStorage` | 一帧 | 渲染管线（用完即弃） |
| Pass 内临时 | `FRDGTexture`（SceneDepth/GBuffer/SceneColor） | 帧图执行期内 | FRDGBuilder（池化别名复用） |

## 3. 统一阅读指引格式

本系列对每个主题（类型 / Pass / 子系统）都用同一张**导读卡**组织，方便你养成固定的提问顺序：

| 栏目 | 回答的问题 |
|------|-----------|
| **是什么** | 一句话定义 + 所在文件 |
| **何时需要关注** | 什么调试/开发场景下才需要读它 |
| **依赖哪些数据** | 输入字段清单 |
| **数据从哪来** | 谁在什么时机写入（函数名+文件） |
| **何时执行** | 在帧主线的哪个环节被触发 |

拿到任何一个陌生类型，先把这五格填满，再决定要不要读实现。

## 5. 旧名勘误表（5.8 vs 旧教程）

旧教程/旧代码里的这些名字在 5.8.2 已**不存在**，按旧名搜索会一无所获：

| 旧名字 | 5.8 等价物 | 说明 |
|--------|-----------|------|
| `FSceneRenderer::InitViews` / `ComputeViewVisibility` | `BeginInitViews` / `EndInitViews` + `FVisibilityTaskData`（SceneVisibility.cpp:4456） | 可见性已重构为任务图，由 Begin/End 两段夹持 |
| `FSceneRenderer::GatherDynamicMeshElements` | `FVisibilityTaskData::GatherDynamicMeshElements`（SceneVisibility.cpp:4608） | 汇合点 `FinishGatherDynamicMeshElements`（DeferredShadingRenderer.cpp:2218） |
| `GetSceneViewStateInterface()` | `FSceneView::State` 成员 / `FViewInfo::ViewState` | 函数已移除，改为直接成员访问 |
| `FMeshDrawCommandSharedState` | 状态并入 `FMeshDrawCommand` 本身 + `FMeshDrawShaderBindings` | UE4 时代类型，5.8 全树零匹配 |
| `CachePathPrimitives` | `FPrimitiveSceneInfo::StaticMeshes / StaticMeshRelevances / StaticMeshCommandInfos` | PrimitiveSceneInfo.h:297-303 |
| `PrimitiveIdBufferIndex` | `FMeshDrawCommand::PrimitiveIdStreamIndex` / `FVisibleMeshDrawCommand::PrimitiveIdBufferOffset` | MeshPassProcessor.h:1319/1804 |
| `StaticMeshBatchVisibility`（FViewInfo 成员） | `FViewInfo::StaticMeshVisibilityMap` | SceneRendering.h:1302 |
| `EnqueueUniqueRenderCommand` | `ENQUEUE_RENDER_COMMAND`（RenderingThread.h:1087） | 宏已统一 |

## 6. 验证手段：让地图落在地上

| 手段 | 用法 |
|------|------|
| 断点 | 在 `Render()` 主线 11 个锚点下断，单步确认顺序与分支条件 |
| cvar 开关 | `r.Substrate 0`、`r.MegaLights.EnableForProject 0`、`r.HairStrands.Enable 0`、`r.Nanite 0` 逐一关掉观察主线「瘦身」 |
| RenderDoc/PIX 截帧 | 用事件名（RDG Pass 名）与源码中的 `RDG_EVENT_NAME` 对照，反向定位 Pass 代码 |
| 全局搜索字段写入点 | 对陌生字段搜 `FieldName =` / `FieldName.`，找到唯一/少数写入函数即数据源头 |
