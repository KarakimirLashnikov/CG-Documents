# UE渲染源码导读 — 渲染数据的来源与组织

> 本文档是「UE渲染源码导读」系列文档的第 **4** 篇。回答读源码时最频繁的困惑：「**这个数据到底是谁、在什么时候填进去的？**」本篇给出统一答案模型：一个统一容器（FScene）+ 三种数据时态 + 一张延迟路径各 Pass 的输入输出表。基于 UE 5.8.2 源码实测。

---

## 1. 统一答案模型

读渲染源码时遇到任何陌生数据，按这个顺序问：

```
Q1: 它挂在哪个容器上？          → 大概率是 FScene / FViewInfo / FRDGBuilder 三者之一
Q2: 它属于哪种时态？            → 注册时缓存 / 每帧可见性任务填充 / Pass 内即时产出
Q3: 写入它的函数是哪个？        → 全局搜索 "字段名 =" 定位唯一写入点
```

**三个统一容器**（没有第四个）：

| 容器 | 装什么 | 生命周期 |
|------|--------|---------|
| `FScene` | 世界镜像：图元/灯光/静态命令缓存/GPUScene/持久 UB | 跨帧持久 |
| `FViewInfo` | 每视图渲染态：可见性结果/可见灯光/动态网格/视图 UB | 每帧重建 |
| `FRDGBuilder` | 帧内纹理与 Pass 依赖：SceneDepth/GBuffer/SceneColor | 帧图执行期 |

## 2. 三种数据时态（数据「何时产生」的分类法）

```
时态 A: 注册时缓存（跨帧复用）
   组件注册 → Proxy 创建 → DrawStaticElements → CacheMeshDrawCommands
   例: StaticMeshes、StaticMeshCommandInfos、CachedDrawLists、PrimitiveOctree

时态 B: 每帧可见性任务填充（每帧重算，CPU 侧）
   BeginInitViews → FrustumCull/OcclusionCull/ComputeRelevance/ComputeLightVisibility
                 → GatherDynamicMeshElements → SetupMeshPasses
   例: PrimitiveVisibilityMap、VisibleLightInfos、DynamicMeshElements、
       VisibleMeshDrawCommands、FSortedLightSetSceneInfo

时态 C: Pass 内即时产出（每帧重算，GPU/RDG 侧）
   各 Render* Pass 录制 → FRDG 纹理经黑板(FRDGBuilder 黑盒传递)流转
   例: SceneDepth、GBuffer、ShadowMaps、HZB、SceneColor
```

**时态判定口诀**：看写入点出现的位置——在 `AddPrimitive`/`UpdateStaticMeshes` 里是 A；在 `SceneVisibility.cpp` / `SceneRendering.cpp` 的 InitViews 系函数里是 B；在 `*Rendering.cpp` 的 Render 系函数里是 C。

---

## 3. 时态 A：注册时缓存（源头在游戏线程）

| 数据 | 写入函数 | 触发时机 |
|------|---------|---------|
| `FScene::Primitives` / `PrimitiveSceneProxies` | `FScene::AddPrimitiveSceneInfo_RenderThread`（RendererScene.cpp:1069） | 组件 `CreateRenderState_Concurrent` |
| `FScene::StaticMeshes` | `FPrimitiveSceneInfo::AddStaticMeshes`（PrimitiveSceneInfo.cpp:1604） | 注册时；重建走 `UpdateStaticMeshes`（:2130） |
| 静态 MDC 缓存（`StaticMeshCommandInfos` / `CachedDrawLists`） | `CacheMeshDrawCommands`（PrimitiveSceneInfo.cpp:583） | 注册/材质变更 |
| `FScene::Lights` | AddLight 系列（RendererScene.cpp） | 灯光组件注册 |
| `PrimitiveOctree` / `SceneLODHierarchy` | AddToScene 内同步维护 | 注册/变换更新 |
| `GPUScene` 数据 | 注册/更新时累积，每帧 `UpdateAllPrimitiveSceneInfos` 时上传 | 帧初（OnRenderBegin） |

⚠️ 注意「游戏线程触发、渲染线程执行」的跨界：`AddPrimitive` 系列内部 `ENQUEUE_RENDER_COMMAND`（RendererScene.cpp:1507），所以断点要下在渲染线程。

---

## 4. 时态 B：可见性任务填充（每帧 CPU 重算）

| FViewInfo 字段 | 写入函数 → 文件 | 输入 |
|---------------|----------------|------|
| `PrimitiveVisibilityMap` / `StaticMeshVisibilityMap` | `FrustumCull`（SceneVisibility.cpp:860）、`OcclusionCullTask`（:3372） | Scene->Primitives + 视锥/上帧遮挡 |
| `PrimitiveViewRelevanceMap` / `PrimitivesLODMask` | `FRelevancePacket::ComputeRelevance`（:1520） | 可见图元 + 材质属性 |
| `VisibleLightInfos` | `ComputeLightVisibility`（:5671-5680） | Scene->Lights + 视锥 |
| `ViewMeshElements` / `DynamicMeshElements` | `GatherDynamicMeshElements`（:4608）→ Proxy->GetDynamicMeshElements | 可见动态图元 |
| `VisibleMeshDrawCommands` | `SetupMeshPasses`（:4721）→ `SetupMeshPass`（SceneRendering.cpp:5010） | 静态缓存 ∩ 可见性 + 动态收集 |
| `FSortedLightSetSceneInfo` | `GatherAndSortLights`（LightRendering.cpp:1409） | VisibleLightInfos + MegaLights 划分 |

## 5. 时态 C：延迟路径各 Pass 的数据来源表（本篇核心）

下表按主线顺序给出**每个 Pass 读什么、写什么**。纹理类数据全部经 `FSceneTextures`（RDG 黑板）流转：

| # | Pass（入口文件） | 输入（数据从哪来） | 输出（数据落到哪） |
|---|-----------------|-------------------|-------------------|
| 1 | PrePass 深度（DepthRendering.cpp:523） | 可见 MDC（时态B） | SceneDepth + HiZ 输入 |
| 2 | Nanite（DeferredShadingRenderer.cpp:1449；可见性 NaniteVisibility.cpp:352） | Nanite 流送数据 + 可见性任务 | VisBuffer + SceneDepth |
| 3 | 阴影深度（ShadowDepthRendering.cpp:1836；VSM→Shadows/ShadowSceneRenderer.cpp:743） | 每灯可见 MDC + 光锥剔除 | ShadowMaps / VSM 页表 |
| 4 | Lumen 场景光照（Lumen/LumenSceneLighting.cpp:216） | SurfaceCache + 距离场 + 硬件 RT | Lumen 间接光中间量 |
| 5 | BasePass（BasePassRendering.cpp:934） | 可见 MDC + Nanite ShadingCommands（NaniteShading.cpp:654）+ 材质 UB | GBufferA–F（+ Substrate bitstream） |
| 6 | 头发 PrePass/BasePass（HairStrands/HairStrandsRendering.cpp:129/201） | Groom 实例（bookmark 收集） | 发束深度/属性缓冲 |
| 7 | 遮挡/HZB（SceneOcclusion.cpp:1451；BuildHZB SceneTextureReductions.cpp:111） | SceneDepth | 本帧遮挡结果（下帧用）+ HZB |
| 8 | 间接光/AO（IndirectLightRendering.cpp:1073） | GBuffer + Lumen/DF/SSAO | SceneColor 间接项 + AO |
| 9 | 直接光 RenderLights（LightRendering.cpp:1627） | GBuffer + ShadowMaps + SortedLights 传统区间 | SceneColor 直接光 |
| 10 | MegaLights（MegaLights/MegaLights.cpp:2428） | GBuffer + SortedLights MegaLights 区间 + 追踪数据 | SceneColor 直接光 |
| 11 | 半透明（TranslucentRendering.cpp:2145） | 半透明 MDC（按距离排序）+ SceneColor + 光照体积 | SceneColor |
| 12 | 天空/云/雾（SkyAtmosphereRendering.cpp 等） | 大气参数（Scene 侧 proxy） | SceneColor |
| 13 | 后处理（PostProcess/PostProcessing.cpp:412） | SceneColor + GBuffer + ViewState 历史（TAA/曝光） | ViewFamilyTexture（最终输出） |

**用表方法**：读某个 Pass 代码时，先在本表查它的输入行——输入里的每一项都能继续向上追溯到某个时态 A/B 的写入函数。链条最多三层：`Pass 输入 ← 时态B 字段 ← 时态A 容器`。

## 6. 数据流转的两个「黑盒」

### 6.1 GPUScene：CPU 容器到 GPU 的桥

`FScene::GPUScene`（ScenePrivate.h:1933）把图元的变换/包围体/自定义数据打包成 GPU 结构化缓冲，MDC 里的 `PrimitiveIdStreamIndex` 就是索引它的钥匙。上传时机：帧初 `UpdateAllPrimitiveSceneInfos` 之后（DeferredShadingRenderer.cpp:2233 附近）。

### 6.2 RDG 黑板：Pass 间纹理流转

`FSceneTextures` 是帧内纹理的登记表（Depth/GBuffer/Velocity/SceneColor），由 `FSceneTextures::InitializeViewFamily`（DeferredShadingRenderer.cpp:2118）建立。Pass 之间不显式传指针，而是通过 RDG 参数结构体引用——**所以你在 Pass A 里找不到「谁写了这张纹理」的显式赋值时，去查 RDG 事件名/参数结构体**（配 RenderDoc 事件名对照最有效）。

## 7. 实战：三类「数据来源困惑」的拆解示范

| 困惑 | 拆解 |
|------|------|
| 「BasePass 里的 MeshDrawCommand 哪来的？」 | 时态B：`SetupMeshPasses`（SceneVisibility.cpp:4721）← 静态缓存（时态A）+ 动态收集（时态B） |
| 「RenderLights 里 SortedLights 哪来的？」 | `GatherAndSortLights`（LightRendering.cpp:1409）← `VisibleLightInfos`（时态B）← `Scene->Lights`（时态A） |
| 「TAA 的历史帧数据哪来的？」 | 不在这三个容器里——在 `FSceneViewState`（跨帧持久视图状态，见 01 篇 §3.4） |

---

## 8. 小结

| 要点 | 说明 |
|------|------|
| 三个容器 | FScene（世界）/ FViewInfo（视图）/ FRDGBuilder（帧纹理），没有第四个 |
| 三种时态 | 注册时缓存 / 每帧可见性任务 / Pass 内即时产出 |
| 追溯链 | Pass 输入 ← 时态B 字段 ← 时态A 容器，最多三层 |
| 两个黑盒 | GPUScene（CPU→GPU 桥）、RDG 黑板（Pass 间纹理流转） |
| 例外飞地 | 跨帧视图数据在 FSceneViewState，不在三容器内 |
| 定位手段 | 全局搜「字段名 =」找唯一写入点；断点下渲染线程 |
