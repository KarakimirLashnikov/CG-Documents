核心概念辨析

每个类型一张导读卡：职责、数据成员、所有权、在流程中的角色。

01

Scene 与 View

  • FScene = UWorld 的渲染线程镜像，跨帧持久的统一容器
  • View 三层：ViewFamily → FSceneView → FViewInfo
  • 持久飞地 FSceneViewState；拧合者 FSceneRenderer
  • 划分三问：换相机还要吗 / 下帧还要吗 / 游戏线程改吗
02

Primitive 与 MeshDrawCommand

  • 数据链：Component → Proxy → SceneInfo → MeshBatch → MDC → Visible
  • 静态缓存 vs 动态收集两条生成路径
  • EMeshPass 39 个：一套几何、多套命令
  • SortKey 排序语义：BasePass 材质聚类 / 半透明 back-to-front
03

Substrate 与 MegaLights

  • Substrate：BSDF Slab 材质重构，r.Substrate 默认 0
  • MegaLights：统一采样直接光照，默认关且 Experimental，不支持平行光
  • 各自的主线分叉点与开关判定链
  • 第一遍阅读：双双跳过，但要认得调用点

数据与主线

消除「数据来源隐秘」与「代码迷宫」两大困惑。

04

渲染数据的来源与组织

  • 三个统一容器：FScene / FViewInfo / FRDGBuilder，没有第四个
  • 三种数据时态：注册时缓存 / 每帧可见性任务 / Pass 内即时产出
  • 延迟路径 13 个 Pass 的输入输出对照表
  • 两个黑盒：GPUScene 桥、RDG 黑板
05

延迟渲染路径主线

  • 唯一主干：FDeferredShadingSceneRenderer::Render（约 2600 行，线性五段）
  • 20 个主线锚点行号表：断点逐行走一遍即建主干
  • 旁路三暗门：SceneViewExtension / SceneExtension / MeshPassProcessor
  • 反直觉时序：遮挡跨帧复用、阴影在 BasePass 后、动态收集异步
