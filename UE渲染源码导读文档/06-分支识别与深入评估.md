# UE渲染源码导读 — 分支识别与深入评估

> 本文档是「UE渲染源码导读」系列文档的第 **6** 篇（末篇）。解决两个收尾问题：① 读主线时如何**快速识别并跳过**头发等特定功能分支，避免注意力稀释；② 对 Nanite 这类复杂子系统，给你**足够的信息自行判断是否深入、从哪入手**。基于 UE 5.8.2 源码实测。

---

## 1. 识别功能分支的四种信号

主线代码里的一段「旁枝」，几乎总被下列四种信号之一守卫。看到它们 = 看到分支边界：

| 信号 | 形态 | 例子 |
|------|------|------|
| **cvar 开关** | `static TAutoConsoleVariable<int32> CVar...` + `CVarX.GetValueOnRenderThread()` | `r.HairStrands.Enable`、`r.Substrate`、`r.MegaLights.EnableForProject` |
| **ShowFlag** | `ViewFamily.EngineShowFlags.X` | `EngineShowFlags.NaniteMeshes` |
| **空实例短路** | `bEnabled = Params.HasInstances() && ...` | 头发：`HairStrandsBookmarkParameters.HasInstances()`（DeferredShadingRenderer.cpp:2446）——场景没 Groom 资源时整段跳过 |
| **平台/特性检查** | `IsHairStrandsEnabled(Type, Platform)`、`MegaLights::IsEnabled()` | HairStrandsInterface.cpp:192；MegaLights.cpp:546 |

**跳过操作法**：
1. 遇到疑似分支，先找守卫条件；
2. 确认当前项目配置下条件为假（或场景无实例）→ 整段跳过，在锚点表上标注「分支@行号」；
3. 若为真但不相关 → 只读它的**输入输出**（04 篇方法），不读实现；
4. 想物理瘦身：`r.HairStrands.Enable 0`、`r.Substrate 0`、`r.Nanite 0` 等逐一下掉，主线立刻变瘦。

## 2. 实例：头发（Groom）分支的完整识别

头发是最典型的「主线里一坨、其实可整体跳过」的分支：

```
识别信号:
  总开关  IsGroomEnabled()              GroomVisualizationData.cpp:18
          = 插件启用 && r.HairStrands.Enable(默认1)
  分类开关 IsHairStrandsEnabled()       HairStrandsInterface.cpp:192
          = r.HairStrands.Strands/.Cards/.Meshes
  短路    bHairStrandsEnable = BookmarkParameters.HasInstances() && ...
                                     DeferredShadingRenderer.cpp:2446

主线挂接点（无独立 RenderHairStrands 函数，走 bookmark 机制）:
  LOD/模拟  RunHairStrandsBookmark(ProcessTasks/ProcessStrandsInterpolation)
            调用点 :2410/:2932/:3153（LOD 选择更早在 OnRenderBegin, SceneRendering.cpp:4343）
  渲染      RenderHairPrePass / RenderHairBasePass
            HairStrands/HairStrandsRendering.cpp:129/201
            调用点 :3156-3157（BasePass 后、光照前）
  光照/合成 RenderLightsForHair(:3565) / SceneColorScattering(:3540) /
            HairStrandsComposition.cpp

结论: 场景无 Groom → HasInstances()=false → 全部短路，跳过零成本。
      有 Groom 但不研究毛发 → 只记「它在 BasePass 后写自己的深度/属性，光照单独算」。
```

## 4. Nanite 深入评估卡

读源码前先用这张卡自评，决定投入程度：

### 4.1 它是什么（30 秒版）

软件/硬件混合的**虚拟化几何管线**：把 mesh 预处理成 cluster 层级（BVH），运行时按屏幕误差选 cluster，用**两级光栅**（小三角形走软件 raster、大的走硬件）写 **VisBuffer**（存 cluster/三角形 ID 而非 GBuffer），再在 BasePass 阶段按材质把 VisBuffer 解析成 GBuffer。结果：几何密度几乎不再受三角形数量限制，实例/LOD/剔除全部 GPU 驱动。

### 4.2 与主线的接口（不管深入与否都该知道）

| 环节 | 位置 | 说明 |
|------|------|------|
| 可见性查询 | `FNaniteVisibility::BeginVisibilityQuery`（Nanite/NaniteVisibility.cpp:352），Render() :1990 启动 | 依赖 ComputeRelevance 完成 |
| 光栅 | `RenderNanite`（DeferredShadingRenderer.cpp:1449），:2485 调用于 PrePass 阶段 | 内部 `NaniteCullRaster.cpp` 的 CullRasterize 任务链 |
| 材质命令 | `Nanite::BuildShadingCommands`（Nanite/NaniteShading.cpp:654），:2697 | 按材质生成解析命令 |
| GBuffer 合成 | BasePass 阶段消费 `Scene->NaniteShadingCommands[ENaniteMeshPass::BasePass]`，:3059 | VisBuffer → GBuffer |
| 开关 | `r.Nanite`（默认1，StaticMeshSceneProxy.cpp:109）；`UseNanite()`（RenderUtils.cpp:1478）；`ShouldRenderNanite()`（NaniteShared.cpp:572） | 临时关掉可回退经典路径 |

### 4.3 自评：你是否需要深入？

| 你的情况 | 建议 |
|---------|------|
| 只想理解渲染主线 / 自研引擎参考管线结构 | **不深入**。知道「Nanite 接管了不透明几何的深度与 GBuffer 写入」即可，按经典路径读主线（可 `r.Nanite 0` 辅助） |
| 要做 GPU-driven 渲染 / cluster 剔除 / 虚拟化几何 | **深入**。前置：GPU 剔除、software raster、原子操作与间接绘制 |
| 要做 Nanite 材质/自定义 pass 适配 | **部分深入**：只读 `NaniteShading.cpp` + `NaniteMaterials.cpp` 的接口层 |
| 研究流送/显存 | **部分深入**：`NaniteShared.cpp` + GStreamingManager 相关 |

### 4.4 若深入，推荐路径

```
入口:  Nanite/NaniteShared.cpp        (概念与全局状态, ShouldRenderNanite :572)
  ↓
可见性: Nanite/NaniteVisibility.cpp    (BeginVisibilityQuery :352)
  ↓
剔除+光栅: Nanite/NaniteCullRaster.cpp (两级光栅核心, 体量最大)
  ↓
着色: Nanite/NaniteShading.cpp        (BuildShadingCommands :654)
  ↓
材质: Nanite/NaniteMaterials.cpp      (VisBuffer→GBuffer 解析)
辅助: Nanite/NaniteRayTracing.cpp / NaniteEditor.cpp (按需)
```

⚠️ 提示：`NaniteCullRaster.cpp` 是全渲染器最密的文件之一，建议**配 RenderDoc 截帧 + Nanite 可视化模式**（`r.Nanite.Visualize`）对照读，单读源码性价比低。

## 5. 其他子系统速评卡

| 子系统 | 一句话 | 深入前置 | 入口文件 | 建议 |
|--------|--------|---------|---------|------|
| Lumen | 软件/硬件 RT 混合的动态 GI：SurfaceCache + 屏幕探针 + 距离场 | GI 理论、probe 插值、距离场 | Lumen/LumenSceneRendering.cpp、LumenSceneLighting.cpp:216 | 做 GI 才深入；否则记「间接光来自 Lumen 中间量」 |

```
第 1 天: 00+01+02 篇 → 建类型地图（Scene/View/Primitive/MDC）

```

## 7. 小结

| 要点 | 说明 |
|------|------|
| 分支四信号 | cvar / ShowFlag / 空实例短路 / 平台特性检查 |
| 头发案例 | `HasInstances()` 无实例即零成本短路；bookmark 机制而非独立函数 |
| 跳过清单 | 头发/Substrate/MegaLights 默认零成本；Lumen/Nanite 默认开，注意它们接管的数据来源 |
| Nanite 决策 | 主线阅读不深入；GPU-driven 方向按 §4.4 五步路径深入 |
| 值得早深入 | RDG——它是所有 Pass 的公共载体，理解后每个 Pass 都好读 |
| 收尾方法 | 每下钻一个子系统，回填其输入输出到自己的数据地图 |
