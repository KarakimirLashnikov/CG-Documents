01 ORIGIN · NGG

Mesh 管线的起源与设计目标

  • 硬件内部早已在做：AMD NGG primitive subgroup ≈ meshlet
  • 顶点复用实测：bunny duplication 4.13 → 1.40 → 1.24
  • Khronos 为什么否掉"给 VS 加分组"与"用 GS 顶替"两个方案

  • RDNA2 隐藏线程 vs RDNA3 exp wave 级偏移（N=128）
  • Vulkan API 事实清单：features / properties / 三维派发 / 两个 query

02 PIPELINE

使用流程与传统管线迁移

  • 离线 → 运行时的完整流程图与顺序纪律
  • Vulkan + GLSL 骨架：pVertexInputState = NULL、三维派发
  • VB/IB 三种组织：间接索引 / 迷你 VB / 压缩 GTS
  • 微索引 8-bit 与4 字节对齐打包
  • 剔除迁移：物体 → 簇（Task）→ 图元（Mesh），三类簇剔除对照
  • LOD 迁移：per-object → per-cluster，lod_error + 屏幕空间误差
  • 回退陷阱：微索引是簇内局部的，不能直接 DrawIndexed
03 MESHLET

Meshlet 结构设计与权衡

  • 三条硬约束 → 顶点冗余的来源（周长/面积）
  • 三角关系：簇变大 = 冗余↓ / 剔除精度↓ / export 占用↑
  • cone_weight：0（不用锥剔除）· 0.25（默认）· →1（剔除优先）
  • 规律 V < T < 2V；AMD 128/256+128 线程 vs NVIDIA 64/126
  • 126 的由来：3×126+4 = 382 ≤ 384（128B 粒度）
  • 分配粒度（常 32）→ V/T 取其整数倍
  • 必做后处理：裁剪超额数组 + optimizeMeshlet
04 MESHOPTIMIZER

meshoptimizer 设计理念与关键模块

  • 五条理念：离线一次、近似可测、顺序敏感、零依赖、有损显式化
  • 流水线顺序图 + 三条顺序红线
  • 三个指标：ACMR / overfetch / overdraw（最优值与分析器）
  • 简化取舍：保拓扑 vs Sloppy（快 5–6×）；选项位掩码
  • 压缩：2–4×（顶点）/ 5–6×（索引），codec 无损、量化才有损
  • 四个 meshlet builder：默认 / Scan / Flex / Spatial(SAH)
  • 工程纪律：padding 清零、stride 4 的倍数、pin 编码版本
05 BINDLESS

描述符与 Bindless 统一 DrawCall

  • 载体选择矩阵：SSBO / UBO / BDA / push constant / IUB
  • Bindless 三件套：descriptor indexing flags + nonuniformEXT + 大 pool
  • set 划分：set0 每帧 ×3、set1 几何、set2 材质（整帧只绑一次）
  • 统一 DrawCall 四层：direct → multi-draw → 全场一次 → DGC
  • stride > 12 可在 indirect 记录间穿插每 draw 数据
  • PSO 影响：不再需要顶点输入布局，变体数反而下降
  • 四个高危点：更新时序、空槽、缺 nonuniform、对齐

06 PERF · PITFALLS

性能优化与常见隐患

  • 五类隐患：发散 / 访存 / 占有率 / 寄存器 / SMEM
  • wave64 → wave32 切换会让占用率假性升高
  • AMD 关键结论：简单 MS ~25% 占用即可打满光栅器
  • 寄存器：压低 max_vertices/primitives 声明最有效
  • SMEM 与 payload 共享预算；Bank 冲突的 padding / swizzle
  • 度量：两个 statistic 位 + MESH_PRIMITIVES_GENERATED + RGP/NSight
  • 五步排查顺序 + 15 条优化清单（标了优先级）

速查

贴在工位上的两张卡。

参数

先按这套默认值起手

  • 线程组 = V̂；i 号线程写 i 号元素，超出用步长
  • NVIDIA：V=64, T=126；AMD：V=128, T=256 + 128 线程
  • max_vertices/max_primitives = 实际 meshlet 上限，不留余量
  • 微索引：uint8，每个三角形打包成 4 字节
  • cone_weight：不用锥剔除 = 0，否则 0.25
  • Task payload：< 108 B（退而求其次 < 236 B）
  • 图元剔除优先 CullPrimitiveEXT，不是紧凑化
  • 所有设备相关数值一律运行时查询，禁止硬编码
误区

八个必须纠正的说法

  • 「Mesh Shader 一定更快」→ 小场景/简单几何可能更慢
  • 「Vulkan 的 draw 是 1D 的」→ EXT 是三维，1D 是 NV 形态
  • 「剔了图元就省了空间」→ 输出区按声明上限预留
  • 「占用率越高越好」→ 简单 MS 约 25% 就够
  • 「占有率高 = 优化有效」→ 可能是 wave32 的假象
  • 「SMEM 用得越多越快」→ 它与 payload 共享预算，直接压占用率
  • 「Mesh 自动减少 draw call」→ 靠的是 Bindless + indirect
  • 「meshlet 数据能直接当 IB 画」→ 是簇内局部索引，必须线性化
