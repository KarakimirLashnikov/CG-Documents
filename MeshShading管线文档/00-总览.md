# 总览：Mesh Shading 管线（Vulkan 视角）

> 本文档是「Mesh Shading 管线文档」系列的第 0 篇（总览）：给出整套文档的地图、阅读路径、版本时效与必须先统一的术语。
> 面向已经写过 Vulkan 图形管线、知道 IA/VS/GS 怎么走、但还没把几何阶段搬到 Task/Mesh 上的引擎开发者。**不是入门教程。**

---

## 1. 这个系列回答什么问题

Mesh Shading 不是"少写几个 API 调用"的语法糖，它是**把几何阶段从固定功能装配（Input Assembler + Vertex Fetch + Vertex Shader）换成一次可编程的 workgroup 计算**。
一旦换掉，下面四件事会同时改变：

```
┌──────────────────────────────────────────────────────────────┐
│  换了 Mesh Shading 之后，谁负责？                              │
├────────────────────┬─────────────────────────────────────────┤
│ 顶点复用            │ 硬件 post-transform cache → meshlet 生成器 │
│ 图元装配            │ IA + Primitive Assembler → Mesh Shader    │
│ 剔除粒度            │ 逐物体（CPU） → 逐簇（Task Shader / GPU）  │
│ LOD 选择            │ 逐物体（CPU） → 逐簇（Task Shader / GPU）  │
│ 顶点数据输入        │ VkVertexInputAttribute → SSBO / BDA 自取   │
│ DrawCall 参数       │ vkCmdDrawIndexed → vkCmdDrawMeshTasksEXT   │
└────────────────────┴─────────────────────────────────────────┘
```

因此本系列按"**为什么 → 怎么用 → 数据怎么切 → 数据怎么生 → 描述符怎么绑 → 性能怎么调**"六步组织，每步一篇。

## 3. 三条贯穿全系列的主线

### 3.1 主线一：几何阶段变成了"计算"

Mesh Shader 的编程模型就是 compute：workgroup、LocalInvocationIndex、subgroup、shared memory、barrier 全部可用。
差别只有一个——它**能把结果直接交给光栅器**，不需要绕一圈 global memory。

```
传统： VB/IB ──IA──▶ VS ──▶(HS/DS/GS)──▶ PA ──▶ Raster
Mesh： SSBO/BDA ──▶ Task(可选) ──▶ Mesh ──▶ PA ──▶ Raster
                     ↑workgroup         ↑workgroup
                     EmitMeshTasksEXT   SetMeshOutputsEXT
```

⚠️ 代价：驱动不再替你做"顶点取数 + 缓存 + 重索引"。你要自己写好，**写不好会比顶点管线更慢**。

### 3.2 主线二：meshlet 是唯一的数据契约

硬件只认三件事：这个 workgroup 输出多少顶点、多少图元、图元索引指向本 workgroup 的哪个顶点。
所以"meshlet"不是 meshoptimizer 发明的概念，而是**硬件限制在数据侧的投影**：

| 约束 | 来源 | 数据侧后果 |
|------|------|-----------|
| 图元索引只能指向本工作组的顶点 | Mesh Shader 输出语义 | 簇边界顶点必须重复 → 顶点冗余 |
| 单个工作组顶点/图元有上限 | `maxMeshOutputVertices/Primitives` | meshlet 尺寸上限 |
| 输出区在启动前就预留 | 几何引擎分配 shader export | 声明的 `max_vertices/max_primitives` 越大，占用率越低 |

### 3.3 主线三：CPU 端的目标是"常量开销"

Mesh Shading 的收益并不主要来自"顶点变换更快"，而来自**把几何决策搬到 GPU 之后，CPU 每帧开销与场景复杂度解耦**：

```
传统 GPU-driven（仍有 IA）：
  CPU: 剔除 → 写 indirect 参数 → 每类材质一个 draw call
Mesh + Bindless + Indirect：
  CPU: 每帧 1~N 个 vkCmdDrawMeshTasksIndirectEXT，参数由 GPU 填
```

要做到这一步，描述符必须 Bindless（第 05 篇），否则"一次绑定画全场"根本不成立。

## 4. 版本与事实时效（重要）

| 事实 | 状态（2026-10 核实） |
|------|---------------------|
| Vulkan 侧扩展名 | `VK_EXT_mesh_shader`（Extension Number 329，Revision 1，2022-03-08 初版） |
| 是否已进核心 | **否**：截至 Vulkan 1.4 / SDK 1.4.341 refpage，仍是 device extension，未列入 1.4 提升清单 |
| 厂商前身 | `VK_NV_mesh_shader`（NVIDIA 早期）、`VK_AMD_mesh_shader` 系（AMD 早期，Vulkan 侧以 EXT 为主） |
| D3D12 对应 | Amplification Shader + Mesh Shader（AMD 官方文章记为 2019 年引入 D3D12） |
| SPIR-V | `SPV_EXT_mesh_shader`，ExecutionModel `TaskEXT` / `MeshEXT` |
| GLSL | `GL_EXT_mesh_shader`（`#extension GL_EXT_mesh_shader : require`） |
| 依赖 | 与 Vulkan 1.1 交互；indirect count 变体需要 Vulkan 1.2 或 `VK_KHR_draw_indirect_count` |
| 硬件门槛 | NVIDIA Turing+ / AMD RDNA2+ / Intel Arc 及部分移动端 GPU；**必须在设备创建时查询 `VkPhysicalDeviceMeshShaderFeaturesEXT`** |

⚠️ 上表之外的具体数值（如某个 `maxMeshOutputVertices` 的值）**一律以运行时查询为准**，不要硬编码。文中出现的示例数值都标了出处或标了"示例"。

## 5. 术语表（全系列统一口径）

| 术语 | 本系列中的含义 |
|------|---------------|
| **Meshlet** | 一个 mesh 的一小块：少量顶点（V）+ 局部索引的微索引缓冲（T 个三角形）。一个 meshlet ↔ 一个 Mesh Shader workgroup |
| **Micro index buffer** | meshlet 内部的三角形索引，索引值 ∈ [0, V)，通常用 `uint8_t` 存储 |
| **Cluster** | 与 meshlet 基本同义；Nanite / cluster culling 语境下更常用 cluster |
| **Task Shader (AS)** | 可选的"放大"阶段：决定派发多少 Mesh workgroup，做粗粒度剔除与 LOD |
| **Mesh Shader (MS)** | 输出顶点数组 + 图元索引数组的阶段 |
| **Payload** | Task → Mesh 传递的共享数据（`taskPayloadSharedEXT`，SPIR-V `TaskPayloadWorkgroupEXT`） |
| **Shader export** | AMD 术语：几何阶段写出去、供 Primitive Assembler 读取的那块片上缓冲 |
| **Primitive subgroup** | AMD NGG 内部把索引流切成的"小组"，概念上等价于硬件自己生成的 meshlet |
| **Duplication factor** | 被变换的顶点数 ÷ 原始顶点数，衡量顶点冗余（越低越好，理论下界 1.0） |
| **ACMR / ATVR** | meshoptimizer 的顶点缓存指标：平均每三角形顶点调用数 / 平均每顶点被变换次数 |
| **Cone culling** | 用 meshlet 的法线锥（axis + cutoff）判断整簇是否背向相机，一次性剔除 |
| **Bindless** | 描述符数组 + 运行时索引，使一次 `vkCmdBindDescriptorSets` 覆盖所有资源 |

## 6. 必须先纠正的八个说法

| 常见说法 | 事实 |
|---------|------|
| "Mesh Shader 一定比顶点管线快" | 不一定。**只在几何量大、剔除/LOD 粒度细、或几何程序化时**才划算；简单场景可能更慢（AMD：别用 mesh shader 去模拟固定管线） |
| "Mesh Shader = 顶点着色器 + 索引缓冲" | 错。没有 Vertex Input、没有 IA、`pVertexInputState`/`pInputAssemblyState` 必须为 NULL |
| "meshlet 想切多大切多大" | 受 `maxMeshOutputVertices/Primitives` 限制，且**声明的最大值直接吃掉 shader export 空间**，影响占用率 |
| "64/126 是通用最优解" | 它是 NVIDIA 的推荐值；AMD 公开推荐 **128 顶点 / 256 图元 + 128 线程**。要按厂商与实测选 |
| "Task Shader 一定要有" | 可选。没有 Task 时 `vkCmdDrawMeshTasksEXT` 直接派发 Mesh workgroup |
| "Vulkan 的 draw 是 1D 的" | `vkCmdDrawMeshTasksEXT(groupCountX, Y, Z)` 是**三维**网格（和 `vkCmdDispatch` 一致）；1D 的 `taskCount/firstTask` 是 `VK_NV_mesh_shader` 的形态 |
| "剔除了图元就不用分配空间了" | 错。输出区按**声明的最大值**预留；`CullPrimitiveEXT` 只是让 PA 跳过，空间照占；真要省空间得做紧凑化（compaction） |
| "Bindless 只是少几次 vkUpdateDescriptorSets" | 不止。它是让 **一个 PSO + 一次绑定 + 一个 indirect draw** 成立的前提，直接决定 CPU 每帧开销是否随场景增长 |

## 7. 全系列小结

| 要点 | 说明 |
|------|------|
| Mesh Shading 的本质 | 把 IA/VS/HS/DS/GS 换成两个 compute-like 阶段，几何生成可编程 |
| 它换来的 | 簇级剔除/LOD、顶点复用可控、几何可压缩/可程序化、CPU 开销与场景解耦 |
| 它要求的 | meshlet 数据、Bindless 描述符、GPU-driven 的命令生成、更严格的 shader 编写纪律 |
| 最大风险 | 用 mesh shader 重造固定管线：冗余 + 更慢；AMD/NVIDIA 官方均明确反对 |
| 尺寸选择 | NVIDIA 64/126；AMD 128/256；线程组 = 每 meshlet 顶点数上限；**实测优先** |
| 数据侧 | meshoptimizer：重映射 → 简化(LOD) → 顶点缓存 → overdraw → vertex fetch → 量化 → 编码 → meshlet + bounds |
| 描述符侧 | SSBO/BDA + `VK_EXT_descriptor_indexing`（partially bound / variable count / update-after-bind）+ 帧级一次绑定 |
| DrawCall 侧 | 单 PSO + `vkCmdDrawMeshTasksIndirect(EXT/Count)EXT`，参数由 compute/DGC 生成 |
| 性能抓手 | 别让输出数组写穿 shared memory（i 号线程写 i 号元素）、别把整个 meshlet 缓存进 SMEM、尽早 `SetMeshOutputCounts` |
| 度量手段 | `VK_QUERY_PIPELINE_STATISTIC_{TASK,MESH}_SHADER_INVOCATIONS_BIT_EXT` + `VK_QUERY_TYPE_MESH_PRIMITIVES_GENERATED_EXT` + RGP/NSight + meshopt analyzers |
