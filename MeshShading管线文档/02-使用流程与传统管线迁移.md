# 02-使用流程与传统管线迁移：VB/IB、剔除与 LOD 怎么搬

> 本文档是「Mesh Shading 管线文档」系列的第 2 篇。给出端到端工程流程与 Vulkan/GLSL 骨架，并逐项分析它对传统网格模型（顶点缓冲 + 索引缓冲）、剔除与 LOD 的影响。
> 上一篇：[01-Mesh管线的起源与设计目标](01-Mesh管线的起源与设计目标.md)

## 1. 端到端流程

```
┌───────────────── 离线（构建期 / 加载期）─────────────────┐
│  源网格                                                   │
│    │  meshopt_generateVertexRemap  去重                   │
│    │  meshopt_optimizeVertexCache  顶点缓存               │
│    │  meshopt_simplify × N         LOD 链                 │
│    │  meshopt_optimizeVertexFetch  内存局部性             │
│    │  meshopt_quantize* / encode*  量化与压缩             │
│    ▼                                                      │
│  meshopt_buildMeshlets  →  meshlets[] / verts[] / tris[]  │
│  meshopt_computeMeshletBounds → 每簇 bounds（球+锥）      │
│    │                                                      │
│    ▼  上传为 3~4 个 device-local buffer（不再有 IB/VB 语义）│
└──────────────────────────────────────────────────────────┘
                              │
┌───────────────── 运行时（每帧）──────────────────────────┐
│ 1. CPU：绑定 1 个 PSO + 1 组 bindless descriptor set      │
│ 2. CPU：vkCmdDrawMeshTasksIndirectEXT(...)  参数 GPU 填   │
│    （或 DGC 生成命令流）                                  │
│ 3. GPU：Task Shader   逐簇剔除（视锥/锥/遮挡）+ LOD 选择  │
│ 4. GPU：Mesh Shader   变换顶点 + 逐图元剔除 + 输出        │
│ 5. 固定功能：PA → 剔除 → Raster → PS                      │
└──────────────────────────────────────────────────────────┘
```

⚠️ 顺序纪律：`buildMeshlets` 必须在 `optimizeVertexCache` **之后**（meshlet 生成器要吃一个拓扑良好的索引顺序）；`optimizeVertexFetch` 会重排顶点，必须在 `buildMeshlets` **之前**（否则 meshlet 里的顶点索引全失效）。详见第 04 篇。

## 2. 最小可用的 Vulkan 骨架

### 2.1 设备与管线

```c
// ── 1) 查询 ───────────────────────────────────────────────
VkPhysicalDeviceMeshShaderFeaturesEXT   meshFeat = { .sType = VK_STRUCTURE_TYPE_PHYSICAL_DEVICE_MESH_SHADER_FEATURES_EXT };
VkPhysicalDeviceMeshShaderPropertiesEXT meshProp = { .sType = VK_STRUCTURE_TYPE_PHYSICAL_DEVICE_MESH_SHADER_PROPERTIES_EXT };
VkPhysicalDeviceFeatures2 feat2 = { .sType = ..., .pNext = &meshFeat };
VkPhysicalDeviceProperties2 prop2 = { .sType = ..., .pNext = &meshProp };
vkGetPhysicalDeviceFeatures2(phys, &feat2);
vkGetPhysicalDeviceProperties2(phys, &prop2);

if (!meshFeat.meshShader) { /* 走传统管线 fallback，见 §6 */ }

// 用查询到的上限决定离线 meshlet 尺寸（不要硬编码！）
uint32_t V_HAT = min(128, meshProp.maxMeshOutputVertices);
uint32_t T_HAT = min(256, meshProp.maxMeshOutputPrimitives);

// ── 2) 建设备时挂上 feature ────────────────────────────────
// meshFeat.taskShader = VK_TRUE; meshFeat.meshShader = VK_TRUE; → pNext

// ── 3) 管线 ───────────────────────────────────────────────
// pVertexInputState = NULL; pInputAssemblyState = NULL（见第 01 篇 §4.2）

// ── 4) 派发 ───────────────────────────────────────────────
vkCmdBindPipeline(cmd, VK_PIPELINE_BIND_POINT_GRAPHICS, meshPipeline);
vkCmdBindDescriptorSets(cmd, VK_PIPELINE_BIND_POINT_GRAPHICS, layout,
                        0, 1, &frameSet, 0, nullptr);       // 整帧一次
vkCmdDrawMeshTasksIndirectEXT(cmd, indirectBuf, 0, maxBatch, stride);
```

### 2.2 GLSL：Task（簇剔除）+ Mesh（发射）

```glsl
#version 450
#extension GL_EXT_mesh_shader     : require
#extension GL_EXT_scalar_block_layout : require

/* ===================== Task Shader ===================== */
layout(local_size_x = 32) in;

struct TaskPayload {
    uint  firstMeshlet;   // 本批起始
    uint  count;          // 本批可见簇数
    float lod;            // 本批采用的 LOD 误差阈值
};
taskPayloadSharedEXT TaskPayload pl;

layout(set = 0, binding = 0) readonly buffer MeshletBounds { vec4 b[]; }; // xyz=center, w=radius
layout(set = 0, binding = 1) readonly buffer MeshletCones  { vec4 c[]; }; // xyz=axis, w=cutoff
layout(set = 0, binding = 2) uniform Frame { vec4 frustum[6]; vec3 camPos; uint totalClusters; };

void main() {
    uint gi = gl_GlobalInvocationID.x;
    if (gi != 0) return;                       // 简化：单线程组单线程决策（真实实现见 §4）

    // 1) 计算本帧 LOD 阈值
    // 2) 紧凑写入可见簇列表（用 atomic 追加到可见簇缓冲）
    // 3) 把可见数量写进 payload，按 maxPreferred 切批
    pl.count = visibleCount;
    pl.firstMeshlet = 0;
    EmitMeshTasksEXT((pl.count + MESHLETS_PER_GROUP - 1) / MESHLETS_PER_GROUP, 1, 1);
}

/* ===================== Mesh Shader ===================== */
layout(local_size_x = 64) in;                  // = V̂
layout(triangles) out;
layout(max_vertices = 64, max_primitives = 126) out;   // = (V̂, T̂)，必须贴近真实值

layout(set = 1, binding = 0) readonly buffer Meshlets   { uvec4 m[]; };  // (vertOffset, vertCount, triOffset, triCount)
layout(set = 1, binding = 1) readonly buffer MeshVerts  { uint mv[]; };  // 到全局 VB 的索引
layout(set = 1, binding = 2) readonly buffer MeshTris   { uint8_t mt[]; };// 微索引（8 bit）

void main() {
    uint meshletId = payload.firstMeshlet + gl_WorkGroupID.x;
    uvec4 m = m[meshletId];
    SetMeshOutputsEXT(m.y, m.w);               // ⚠️ 尽早、且在写之前

    uint tid = gl_LocalInvocationIndex;

    // 顶点：1 线程 → 1 顶点（prefersLocalInvocationVertexOutput 友好）
    if (tid < m.y) {
        uint vi = mv[m.x + tid];
        gl_MeshVerticesEXT[tid].gl_Position = Transform(FetchVertex(vi));
    }

    // 图元：步长写入（V=64 / T=126 → 2 轮）
    for (uint i = 0; i < 2; ++i) {
        uint pi = tid + i * 64;
        if (pi < m.w) {
            uvec3 idx = LoadMicroTriangle(m.z + pi * 3);
            gl_PrimitiveTriangleIndicesEXT[pi] = idx;
        }
    }
}
```

⚠️ `SetMeshOutputsEXT(v, p)` 的 `v`/`p` 是**实际输出数**；`layout(max_vertices/max_primitives)` 是**预留上限**。两者不是一回事，见第 01 篇 §3.3。

## 3. 对传统网格模型的影响：VB / IB 怎么配合

### 3.1 三种数据组织方案

```
方案 A（间接索引，meshoptimizer 默认产出）
  meshlet.vertex_offset → meshlet_vertices[] → 全局 vertex buffer
  ┌────────┐   ┌──────────────────┐   ┌──────────────────┐
  │ Meshlet│──▶│ meshlet_vertices │──▶│ global vertex buf │
  └────────┘   └──────────────────┘   └──────────────────┘
  优点：顶点全局唯一，内存最省；缺点：两级间接（gather 两次）

方案 B（每 meshlet 迷你 VB）
  meshlet → 自带 64 个顶点副本
  优点：一次连续读，缓存友好；缺点：边界顶点重复 → 内存膨胀

方案 C（压缩：GTS / 量化 / 位打包）
  meshlet → 压缩流 → Mesh Shader 内解压到 shared memory
  优点：带宽最省（AMD 论文口径：条带化即可 ~3:1）
  缺点：ALU 成本 + 解压必须并行化（见 §3.4）
```

| 方案 | 显存 | 带宽 | ALU | 适用 |
|------|------|------|-----|------|
| A 间接索引 | 最省 | 两次 gather（随机） | 低 | 默认；顶点属性宽时更优 |
| B 迷你 VB | 膨胀 ~1.2–2× | 一次连续读 | 低 | 顶点属性窄、簇小、带宽敏感（移动端） |
| C 压缩 | 最省 | 最省 | 高 | 海量几何 / 流式加载（Nanite 路线） |

⚠️ meshoptimizer 明确提示：`meshlet_vertices` 是"到原始顶点缓冲的索引"，要不要生成迷你 VB 是**引擎自己的取舍**；簇内顶点空间高度一致，因此**压缩顶点数据往往很划算**。

### 3.2 微索引缓冲：8 bit 与对齐

- meshlet 内顶点数 ≤ 256 → 索引可用 `uint8_t`（GLSL：`readonly buffer ... { uint8_t mt[]; }`）。
- **对齐要求**：Vulkan 侧 SSBO 的 `uint8_t` 数组读取要注意 stride；AMD 给的实践是**把每个三角形的 3 字节打包到 4 字节**，或在 D3D 侧用 `R8_UINT` + 两次对齐的 16-bit load（`Load(triOffset & ~1)` 再按 `triOffset & 1` 移位）。
- meshoptimizer 建议的裁剪收尾：`meshlet_triangles.resize(last.triOffset + ((last.triCount*3 + 3) & ~3))` —— 即**按 4 字节对齐补齐**。

```glsl
// 从 uint8_t 流里取一个三角形（4 字节对齐布局）
uvec3 LoadMicroTriangle(uint byteOffset) {
    uint base = byteOffset & ~3u;
    uint shift = (byteOffset & 3u) * 8u;
    uint w = mt[base >> 2] >> shift;              // ⚠️ 跨 4 字节边界时要拼两个字
    return uvec3(w & 0xFFu, (w >> 8) & 0xFFu, (w >> 16) & 0xFFu);
}
```

⚠️ 上面是示意；跨字边界的打包方案必须在离线与 shader 之间**严格对齐**（推荐按"每三角形 4 字节"落盘，彻底消掉边界判断）。

### 3.3 传统 VB/IB 并没有消失，只是退居二线

| 组件 | 传统管线 | Mesh 管线 | 备注 |
|------|---------|----------|------|
| 顶点缓冲 | IA 按属性格式读取 | 变成 SSBO/BDA，你自己 gather | 属性格式解耦（可自定义压缩格式） |
| 索引缓冲 | `vkCmdBindIndexBuffer` + `vkCmdDrawIndexed` | 变成 `meshlet_triangles`（微索引） | 全局 IB 仍可作为 LOD0 的 fallback |
| 顶点属性格式 | `VkFormat` 枚举 | 任意位宽（如 12 bit UV、octahedral 法线） | **这是最大的自由度** |
| 实例化 | `vkCmdDrawIndexed(..., instanceCount)` | 用 `gl_WorkGroupID` 编码实例 | DrawID/InstanceID 需自己传（push constant 或 payload） |

⚠️ `gl_DrawIndex`、`gl_InstanceIndex` 在 Mesh 阶段仍可用（EXT_mesh_shader 把它们标为 modified built-in），但**语义取决于你用 indirect 的第几条记录**；更稳的做法是把实例数据塞进 payload 或 per-draw 数据区（第 05 篇）。

### 3.4 压缩数据的解压必须并行化（GTS 案例）

AMD 的 meshlet 压缩方案把每个 meshlet 存为**广义三角形条带（GTS）**：

- 条带化本身给出 **3:1** 的索引量压缩（每个新三角形只需 1 个新索引）。
- 每个三角形额外 1 bit 的 L/R 标志表示复用哪条边；条带重启用**退化三角形**（面积为零，光栅器自动丢弃）表示，避免额外分支。
- 顶点顺序按条带递增排列 → 前三个索引 (0,1,2) 固定，不必存储。
- 并行解码的关键：`findMSB`/`firstbithigh` 在 L/R 位掩码里回溯，定位"扇形起点"；配合 `countbits` 做增量前缀和（reuse packing）。
- 位掩码与索引数据**一次性载入 group shared memory**（示例中 `groupshared uint IndexBufferCache[8 + 64]`，8 个 dword 存标志 + 64 个 dword 存 8-bit 索引）。

⚠️ AMD 明确指出：Nanite 最初设想的"每帧在 GPU 上解压"在当时解压性能不达标，**实际只在从 CPU 流式加载后解压一次**（2021 年口径，以 Epic 官方最新资料为准）。这说明：**压缩省了带宽，但解压的 ALU 成本必须实测**。

## 4. 剔除的迁移路径

### 4.1 粒度阶梯

```
粗 ─────────────────────────────────────────────────▶ 细
物体级        簇级（Cluster）        图元级          子像素级
CPU frustum   Task Shader            Mesh Shader     硬件/软光栅
+ occlusion   frustum / cone / Hzb   退化/背面/小三角
```

| 层级 | 在哪做 | 判据 | 成本 |
|------|--------|------|------|
| 物体 | CPU 或 compute pre-pass | 包围球 vs 视锥/遮挡 | 极低 |
| **簇** | **Task Shader（推荐）** 或独立 compute dispatch | 包围球 / 法线锥 / 屏幕空间包围盒 vs HZB | 低 |
| 图元 | Mesh Shader | 背面、退化、投影后面积极小 | 中（每图元都算） |
| 固定功能 | PA / Raster | 背面、零面积、视口裁剪 | 免费 |

⚠️ meshoptimizer 的建议：**簇剔除的运行频率应低于 mesh shading**（要么放 Task Shader，要么单独一个 compute dispatch），不要每帧让 Mesh Shader 自己先算一遍整簇 bounds。

### 4.2 三类簇级剔除

```glsl
// ① 视锥：包围球 vs 6 平面
bool SphereOutside(vec3 c, float r) {
    for (int i = 0; i < 6; ++i)
        if (dot(frustum[i].xyz, c) + frustum[i].w < -r) return true;
    return false;
}

// ② 法线锥：整簇所有三角形都背向相机时剔除
//    meshopt_Bounds 给出 cone_apex / cone_axis / cone_cutoff
bool ConeCulled(vec3 apex, vec3 axis, float cutoff, vec3 camPos) {
    return dot(normalize(apex - camPos), axis) >= cutoff;
}

// ③ 遮挡：屏幕空间 AABB vs 上一帧深度金字塔（HZB）
//    需要两遍：prepass 写深度 → 主 pass 用 HZB 剔除
```

| 剔除方式 | 需要的数据 | 剔除率 | 陷阱 |
|---------|-----------|--------|------|
| 视锥 | 包围球（center+radius） | 中 | 大物体横跨视锥时无效 |
| **法线锥** | cone axis + apex + cutoff | 对闭合曲面高 | 薄壳/双面几何**不能**用 |
| 遮挡（HZB） | 深度金字塔 + 前一帧重投影 | 城市/室内场景高 | 延迟一帧 → 快速移动相机漏剔（需保守膨胀） |

### 4.3 图元级剔除的两种做法

| 做法 | 机制 | 空间占用 | 适用 |
|------|------|---------|------|
| `gl_CullPrimitiveEXT = true` | PA 读取时丢弃 | **仍占**声明的图元配额 | 顶点很"胖"（属性多）时更划算 |
| 紧凑化（compaction） | wave 内前缀和重排索引，只输出幸存图元 | 少占 | `prefersCompactPrimitiveOutput = true` 的设备；顶点便宜时 |

AMD 的实验结论：**多数情况下 `SV_CullPrimitive`（即 `CullPrimitiveEXT`）更划算**，除非顶点属性非常宽（那时省空间更值）。

⚠️ 紧凑化要"修正导出索引"（wave-wide scan），即 AMD 文档里说的 *"Need to fix export indices via a wave-wide scan"* —— 这本身有成本，且会破坏"i 号线程写 i 号元素"的最优路径。

## 5. LOD 的迁移路径

### 5.1 从 per-object 到 per-cluster

```
传统：                         Mesh Shading：
 LOD0 ─┐                        LOD0 的簇 ─┐
 LOD1 ─┼─ CPU 按距离选一个        LOD1 的簇 ─┼─ Task Shader 逐簇选
 LOD2 ─┘                        LOD2 的簇 ─┘   （同一帧可混用不同 LOD！）
```

关键差异：**同一物体的不同部分可以处于不同 LOD**，靠的是簇之间有层级关系（cluster hierarchy，Nanite 路线）。

### 5.2 用 meshoptimizer 的误差做 LOD 选择

```c
// 离线：简化时拿到归一化误差（相对网格包围盒尺寸）
float lod_error = 0.f;
lod.resize(meshopt_simplify(&lod[0], indices, index_count, &vertices[0].x,
                            vertex_count, sizeof(Vertex),
                            target_index_count, target_error,
                            /* options= */ 0, &lod_error));
// lod_error 可用 meshopt_simplifyScale 换算到物体空间
```

```c
// 运行时：屏幕空间误差判定（meshoptimizer README 的公式）
float d = max(0.f, distance(camera_position, mesh_center) - mesh_radius);
float e = d * (tan(camera_fovy / 2) * 2 / screen_height); // 1 像素在网格空间的长度
bool  lod_ok = e * lod_factor >= lod_error;                // lod_factor 可调整激进度
```

| 参数 | 含义 | 建议 |
|------|------|------|
| `target_error` | 归一化偏差上限（1e-2 ≈ 网格尺度的 1%） | 从 1e-2 起调 |
| `lod_error`（出参） | 实际达到的偏差 | 存进资产，运行时选级 |
| `lod_factor` | 激进度乘子 | 1.0 起步，画面糊了调小 |
| `meshopt_SimplifySparse` | 输入是稀疏子集时加速 | **逐簇简化**时用（配合 `ErrorAbsolute`） |
| `meshopt_SimplifyLockBorder` | 锁定边界不塌缩 | 分块地形/分块 LOD 拼接防裂 |

### 5.3 LOD 迁移的三个坑

| 坑 | 现象 | 对策 |
|----|------|------|
| **裂缝** | 相邻簇选了不同 LOD，接缝裂开 | 简化时 `LockBorder`；或构建层级时让相邻簇共享边界（cluster hierarchy 的 group 边界锁定） |
| **LOD 抖动** | 相机微动导致簇在两级间反复跳 | 误差阈值加滞回（hysteresis）；或对误差做时间平滑 |
| **多 LOD 共用顶点缓冲** | 移动端只能顺序扫描 VB 区段的架构上，粗 LOD 也要读整个 VB | 每个 LOD 单独 `optimizeVertexCache` → 从**最粗** LOD 开始拼成一个大 IB → 最后整体 `optimizeVertexFetch`（meshoptimizer 明确建议） |

## 6. 兼容性与回退

| 情况 | 处理 |
|------|------|
| 设备不支持 `VK_EXT_mesh_shader` | **必须**准备传统管线 fallback：meshlet 数据可以线性拼回一个普通 index buffer（NVIDIA 早期资料即建议"把 meshlet 转成常规 IB 以回退"） |
| 只有 `VK_NV_mesh_shader` | 1D 派发 + `taskCount/firstTask`，需单独的 shader 变体与派发路径 |
| 工具链不支持 GLSL mesh 扩展 | 用 HLSL（DXC `-T ms_6_x` / `as_6_x`）编译到 SPIR-V，或 Slang；Vulkan 侧只认 SPIR-V |
| 调试 | 抓帧工具需支持 mesh 阶段；`VK_QUERY_TYPE_MESH_PRIMITIVES_GENERATED_EXT` 用于验证"到底发出去多少图元" |

⚠️ **不要**在 fallback 路径里用同一份 meshlet 数据直接 `vkCmdDrawIndexed` —— 微索引是**簇内局部索引**，直接当全局索引画会得到完全错误的网格。必须线性化（把 `meshlet_vertices[meshlet_triangles[...]]` 展开成全局索引）。

## 7. 小结

| 要点 | 说明 |
|------|------|
| 流程 | 离线：remap → cache → simplify → fetch → 量化/编码 → meshlet + bounds；运行时：单 PSO + 单绑定 + indirect 派发 |
| VB/IB | 顶点属性格式完全自由（可压缩/自定义位宽）；全局 IB 退化为 fallback 或不再需要 |
| 微索引 | 8 bit 足够；**按 4 字节对齐**落盘，消除 shader 里的跨字判断 |
| 三种组织 | A 间接索引（省内存，两次 gather）/ B 迷你 VB（省带宽，内存膨胀）/ C 压缩（最省带宽，ALU 贵） |
| 剔除迁移 | 物体级 → 簇级（Task Shader）+ 图元级（Mesh Shader）；**簇剔除频率应低于 mesh shading** |
| 图元剔除 | 优先 `CullPrimitiveEXT`；紧凑化只在顶点很宽或 `prefersCompactPrimitiveOutput=true` 时用 |
| LOD 迁移 | per-object → per-cluster；用 `meshopt_simplify` 的 `lod_error` + 屏幕空间误差公式选级 |
| LOD 三坑 | 裂缝（`LockBorder`）、抖动（滞回）、粗 LOD 读整 VB（先拼再 `optimizeVertexFetch`） |
| 回退 | 微索引是簇内局部的，**不能**直接拿去 `vkCmdDrawIndexed`，必须线性化 |
| 反模式 | 用 Mesh Shader 重造 VS+IA；AMD/NVIDIA 官方均明确反对 |
