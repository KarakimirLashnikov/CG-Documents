07 CROSS-PLATFORM

与主机端的优化差异对照

  • 先修正前提：「移动端 vs 主机端」不是二元的——掌机是中间态
  • 三堵墙 vs 三道闸：被迫削峰 vs 自己设定的包线
  • 能效拐点：陡区近似 P ∝ f³ → 目标函数是能效比
  • 纠正「降频在 55℃ 触发」→ 多区域多级阈值
  • 相同点十条：分块光栅化、片上存储、固定功能压缩、早期 Z、时间超分、DRS、带宽瓶颈、GPU-driven、帧时间一致性、方法论
  • 但分块边界不同：NVIDIA 自 Maxwell 起是 tile-based immediate，只在单个 draw call 内生效
  • 每像素可用带宽分析：手机 1080p 约为主机 4K 的 3/4
  • 纠正「UMA 是移动端特性」→ 主机也是 UMA
  • 纠正「移动端无光追单元」→ 已有硬件 RTU，但不加速 BVH 遍历
  • 八个结构性差异：SKU/驱动成熟度、持续 vs 峰值、热预算漂移、CPU 异构、FP16、RT 层级、认证矩阵、目标函数
  • 移动端独有的可编程热管理：Sustained Performance Mode、独占核心、ADPF、thermalState
  • 热管理状态机：降级快、升级慢、带滞回；先调分辨率（可被超分掩盖）
  • 移植判据：这条优化省的是能效还是时间

速查

动手前扫一眼，避免把桌面经验平移到移动端。

误区

十四个必须纠正的说法

  • 「移动端一定要分箱」→ Adreno 有 Direct Mode
  • 「分箱只关心图元不含顶点」→ 必须跑 Position Shading
  • 「分箱在完整 VS 之后」→ 夹在两段着色之间
  • 「分箱零主存访问」→ Visibility Stream 在主存
  • 「Tile 固定 16×16」→ Adreno 可变
  • 「跨 Tile 三角形会被裁开」→ 不裁，整片重复光栅化
  • 「Mali 只有 Early-Z」→ 官方有 HSR
  • 「延迟渲染是天作之合」→ 有明确适用边界
  • 「全屏 draw 破坏局部性」→ 采样方式才是关键
  • 「GMEM 溢出导致 Direct Mode」→ 首要原因是 VS 纹理采样
  • 「1.3 弃用了 VkRenderPass」→ 是 1.4
  • 「tile_shading 能强制 TBDR」→ 它是 per-tile 附件访问能力
  • 「UMA 是移动端特性」→ 主机也是 UMA，PC 独显才分离
  • 「移动端没有光追单元」→ 已有硬件 RTU，但不加速 BVH
铁律

三条铁律 + 诊断口诀

  • 铁律 ① 每个「渲染到贴图」都有 Resolve 成本
  • 铁律 ② 中间结果留在片上：BY_REGION + input attachment + DONT_CARE
  • 铁律 ③ 清空/丢弃要显式声明，绝不依赖 LOAD 默认值
  • ALU 低 + 停滞高 → 带宽问题
  • ALU 高 + 停滞低 → 计算问题
  • ALU 低 + 停滞低 → CPU-bound / 同步问题
  • 分箱高 + 其他正常 → 可能并发分箱生效，不必管
